# 이어하기 (session-resume)

> 설계 근거 = 2026-09-13 세션 `d44c5db2`·`f41da8bc` (CC 작업로그). 사용자는 새 세션을 열 때 무슨 말로 이어받게 할지 매번 몰랐다 — 이 스킬 하나로 고정한다.

## 원칙

- **읽기·대조·보고만 한다.** 작업 착수 · 작업로그 수정 · 소급 기록은 하지 않는다(기록은 `work-close`). 사용자가 이전 작업을 끝내기(또는 중단 확정)로 고르면 `work-close` 로 이어진다.
- **배너가 주입한 ⏸·▶ 는 낡을 수 있다** — 반드시 실제 상태로 대조한다(2026-09-13 배너가 이미 끝난 디스크 정리를 대기로 띄웠다).
- **「진행중」 세션은 거부하지 않고, 멈춘 지점을 읽은 뒤 한 번 묻는다** — 「다른 창에서 작업 중인가요, 떠난 세션인가요?」. 🔑 **끝난 흔적 조건** = 편집한 계획서가 1개 이상이고 커밋 스텝이 전부 커밋됨 · 작업로그에 없는 커밋 0건 · 작업로그 기재 있음 — 셋 다일 때만 「끝난 세션으로 보입니다(근거)」를 붙여 묻는다. 계획서가 없거나 판단 불가면 붙이지 않는다(마무리 뒤 같은 세션에서 다른 작업을 이어가는 경우를 끝났다고 오보하지 않게). 판정은 사용자가 한다(2026-09-14 첫 실사용에서 끝난 세션을 작업 중처럼 보고). 작업 중이면 건드리지 않는다(두 세션이 같은 기록을 쓰면 겹친다). 떠났으면 기록 안 끝난 세션과 같은 길로 이어받는다 — 컨텍스트가 차서 **바로** 새 세션을 여는 경우가 가장 흔하다(2026-09-14 사용자).
- **시간을 먼저 본다** — 지금 현지 시각과 이전 세션 마지막 활동의 경과(오늘/어제)를 보고 첫 줄에 쓴다. 세션 시작일로 날짜를 판단하지 않는다.

## 절차

### 1. 원격 확인

```bash
cd "$CLAUDE_PROJECT_DIR" && for r in . Rpi5; do git -C "$r" fetch -q 2>/dev/null; echo "$r: $(git -C "$r" status -sb | head -1)"; done
```

뒤처졌으면(`behind`) 보고에 적고 pull 을 추천에 포함한다.

### 2. 지난 작업 모으기

**두 작업로그 최신 블록의 ⏸·▶** — 마무리한 세션의 공식 기록:

```bash
cd "$CLAUDE_PROJECT_DIR" && for f in docs/작업로그.md docs/claude-code-작업로그.md; do echo "== $f"; awk '/^## /{c++} c==1{print} c>=2{exit}' "$f" | grep -E '^## |^-? *(⏸|▶)'; done
```

**보존 색인 — 최근 7일 기록 안 끝난 세션(미기재·부분기재)과 진행중 세션:**

```bash
P="${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}"
python3 "$P/.claude/hooks/session_archive.py" --unlogged 7
I=~/lab/session-archive/INDEX.tsv
if [ ! -f "$I" ]; then echo "보존 색인 없음 — 작업로그 기준으로만 판단"; else
date '+지금 %Y-%m-%d %H:%M (현지)'
awk -F'\t' -v me="${CLAUDE_CODE_SESSION_ID:0:8}" 'NR>1 && $6=="진행중" && substr($2,1,8)!=me {print "진행중", substr($2,1,8), "마지막 활동", $7, "· 첫 지시", $3}' "$I"; fi
```

🔑 **부분기재** = 세션 번호는 작업로그에 있지만 그 세션 커밋 중 **해시가 로그에 없는 것**이 남음 — 마무리 뒤에 한 작업이 있다는 **후보**다. 내용은 서술됐고 해시만 빠진 경우도 있으므로(2026-09-14 W1 표본 2건) 3단계에서 대조한다.
🔑 **진행중**(마지막 대화 60분 내)은 방금 떠난 세션일 수도, 다른 창에서 도는 세션일 수도 있다 — **멈춘 지점을 읽고 보고에서 한 번 묻는다.** 색인은 세션 시작 스캔 기준이라 최대 30분 늦다. 🔴 awk 끝의 문장은 색인 3열 **첫 지시**다 — 마지막 지시로 옮기지 않는다(마지막 발화는 아래 `--pending`).

**그 세션들이 멈춘 지점** — 찾은 기록 안 끝난 세션과 진행중 세션 **각각**(진행중도 묻기 전에 읽는다 — 읽기만 한다. `<ID8 …>` 를 찾은 번호들로 채운다):

```bash
P="${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}"; for id in <ID8 …>; do echo "== $id"; CLAUDE_PROJECT_DIR="$P" python3 "$P/.claude/hooks/session_archive.py" --pending "$id" | sed -E 's/^(.{220}).*/\1…/'
u=$(awk -F'\t' -v id="$id" 'substr($2,1,8)==id {print $2; exit}' ~/lab/session-archive/INDEX.tsv 2>/dev/null); [ -n "$u" ] && grep -qF "$u" "$P/docs/작업로그.md" "$P/docs/claude-code-작업로그.md" && echo "## 작업로그 기재 있음" || echo "## 작업로그 기재 없음(또는 색인에 없음)"; done
```

🔑 작업로그 기재 줄은 모든 세션에 찍히지만 **판정에 쓰는 것은 진행중 세션뿐**이다 — 색인이 「진행중」을 기재 판정보다 먼저 매겨 기재·부분기재 여부가 가려진다(미기재·부분기재 세션은 색인 판정과 같다).

출력 = 마지막 활동(현지)·경과·오늘/어제 · **작업로그에 없는 커밋** · 편집한 계획서의 **커밋 스텝 x/y · 첫 미완 커밋**(계획서에 적힌 커밋 제목을 실제 커밋과 대조 — 이 프로젝트는 체크박스를 쓰지 않는다) · 마지막 발화 3개 · 응답 꼬리. 🔴 「해시 못 찾은 커밋 명령」은 실패한 시도·고쳐 쓰기·다른 저장소일 수 있다 — 판정에 쓰지 않는다.

**커밋 안 된 변경:**

```bash
cd "$CLAUDE_PROJECT_DIR" && git status --short && git -C Rpi5 status --short
```

### 3. 실제 상태와 대조

⏸·▶ 항목마다 **끝났다는 흔적**을 찾는다 — 최신 블록 날짜 이후의 커밋 제목(`git log --since=<블록 날짜> --oneline`, 두 저장소), 항목이 가리키는 파일·설정의 현재 상태. 판정은 넷 중 하나:

| 판정 | 뜻 |
|---|---|
| 대기 | 끝난 흔적이 없다 |
| 실물 준비 필요 | 결선·촬영·실HW 관문처럼 사용자가 현장에서 해야 한다 |
| 낡음 | 이미 끝났다 — **근거 한 줄**(커밋 해시나 파일 상태) |
| 미대조 | 확인 비용이 크다 — 추측으로 「낡음」 판정 금지 |

### 4. 보고하고 멈춘다 (형식 고정)

CLAUDE.md §1 답변 방식을 따른다(결론 먼저 · 새 용어 풀기).

```
지금 <YYYY-MM-DD HH:MM 현지> · 이전 작업 마지막 활동 <시각> (<경과> · 오늘/어제)
지난번 — <3~4줄: 무엇을 했고 지금 어디. 기준 블록 날짜 명시>

남은 작업
| 항목 | 상태 | 근거 |

🔓 기록 안 끝난 작업 — <ID8 · 멈춘 지점 한 줄 · 미기록 커밋 N · 계획서 커밋 스텝 x/y>   (있을 때만)
❓ 진행중 세션 — <ID8 · 마지막 활동 N분 전 · 마지막 발화 『…』 · 계획서 커밋 스텝 x/y(없으면 「계획서 없음」) · 미기록 커밋 N · 작업로그 기재 있음/없음> — (원칙의 끝난 흔적 조건을 셋 다 만족할 때만 「끝난 세션으로 보입니다 — 근거」) 다른 창에서 작업 중인가요, 떠난 세션인가요?   (있을 때만)
🔄 원격 — <동기화 / behind N / 로컬변경>

추천 — <하나> · 이유 <한 줄> · 실물 준비 <필요 / 불필요>
```

**추천 규칙** — ①기록 안 끝난 작업이 있으면 1순위 = 「이 작업을 이어서 끝낼까요, 중단으로 확정할까요?」(이어서 → 남은 태스크 → 공동 확인 → `work-close` / 중단 확정 → `work-close` 🛑) ②그 작업의 계획서 커밋 스텝이 전부 커밋됐고 정본 기록만 없으면 「**공동 확인 후 `work-close`**」 — 떠난 세션의 작업은 공동 확인을 거치지 않았을 수 있다(CLAUDE.md §2, 2026-09-14 리뷰 I7) ③둘 다 없으면 남은 작업 중 하나. 진행중 세션이 「떠났다」로 확정되면 — 끝난 흔적 조건을 만족하면 이어받을 것이 없으니 ③, 아니면 기록 안 끝난 작업으로 보고 ①·②.

**그리고 멈춘다.** 사용자가 고르면 그때 시작한다 — 비자명 작업이면 `superpowers:brainstorming` 부터(CLAUDE.md §2).

## 주의

- 보존 색인은 세션 시작 스캔 기준이라 **최대 30분 늦을 수 있다.** 방금 끝난 세션이 안 보이면 그 때문이다.
- 최신 블록이 어제 이전 것일 수 있다 — 보고에 **블록 날짜**를 적어 기준을 드러낸다.
- 추천은 **하나만** 한다(CLAUDE.md §1⑤). 나머지는 남은 작업 표로 충분하다.
- **긴 한글 줄 자르기는 문자 단위(`sed`)로** — `cut -c` 는 바이트 단위라 한글을 반쪽으로 잘라 깨진 글자를 만든다(2026-09-13 시험에서 발견).
