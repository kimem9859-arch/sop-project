# 작업 마무리 (work-close)

> 설계 = spec `2026-09-14-작업마무리-이어받기` §3·§4. 정본 미기록이 새어 나간 세 경로 — 계획 없이 한 작업(카메라 세로 전환) · 실패로 중단(CH5) · 무효로 중단(`tool_v4`) — 를 **작업이 끝나는 한 지점**에서 막는다.

## 원칙

- **끊지 않는다** — 1~5 를 한 번에 수행한다. 사람 관문(공동 확인·중단 합의)은 이 스킬 **앞**에서 끝났다.
- **원천에서 옮긴다** — 코드·로그·원본 대화·측정 파일에서 옮기고, 점검 문서·작업로그·대화 속 요약에서 옮기지 않는다. 2026-09-14 ③ 리뷰에서 요약을 옮긴 곳 4곳의 날짜·강도가 바뀌었다.
- **날짜 = 작업한 날(현지 시각)** — 세션 시작일이 아니다(ESP32 검토 08-12 ↔ 실제 08-20 오기).
- **작업 단위마다** 한 번 — 한 세션에서 여러 번 불릴 수 있다.

## 1. 결말 확인

| 결말 | 조건 | 표시 |
|---|---|---|
| 완료 | 공동 확인이 끝났다 | ✅ |
| 실패 | 목표 미달·판정 무효로 끝내기로 합의했다 | ❌ 실패 |
| 중단 | 도중에 멈추기로 합의했다 — 재개할 수 있다 | 🛑 중단 |

합의한 사용자 발화 한 줄을 끝 보고에 인용한다. **합의가 없으면 시작하지 않고 묻는다** — 결말은 함께 정한다(CLAUDE.md §2 역할 분담).

## 2. 정본 기록

### 2.1 대상 문서

| 작업 | 기록할 문서 |
|---|---|
| 프로젝트(비전·인터락·음성·HW·시연) | `docs/통합문서.md` |
| Claude Code 인프라(훅·스킬·규칙) | `docs/claude-code-작업문서.md` |
| 결과 사실이 없는 작업(조사·질문) | 건너뛴다 — 끝 보고에 「정본 기록 없음 — 이유」 |

### 2.2 경우별 형식

| 경우 | 정본에 쓰는 것 | 과정이 있는 곳 |
|---|---|---|
| **A. spec·plan 있음** | ①결과 사실을 **제자리**(2.3)에 ②결과의 **중심 자리 한 곳**에 작업 요약 2~3줄 + `spec: <경로> · plan: <경로>` ③나머지 자리에는 `(작업: <plan 경로>)` 포인터만 | spec(설계) · plan(제작) |
| **B. 계획 문서 없이 끝남**(brainstorming 짧은 설계) | 결과 사실은 A 와 같이 제자리에 + 중심 자리에 **정리된 진행 내용 전체** — 무엇을·어떻게·왜 · 커밋 해시 | 정본 |
| **C. 실패·중단** | 결과 자리에 **❌ 실패** / **🛑 중단** + 이유(원인 규명 여부) + 현재 상태 + 재개 조건. 재개할 일이면 §10 🔓 미결 표에 행 | spec·plan 머리 상태 줄 `🛑 중단(날짜) — 이유 · 멈춘 태스크` |

요약은 **한 곳에만** 쓴다 — 여러 자리에 쓰면 복제가 되어 낡는다.

### 2.3 결과 사실의 제자리 (통합문서 — CLAUDE.md §3)

측정값 → §10 새 절(제목 다음 줄 유효성 마커 `✅ CURRENT-AS-OF <날짜>`) + §10 머리 `[CURRENT]` 표 + **§10 갈래 색인** · 부품 → §11.1 · 핀·채널·차단 대상 → §12 「핀·채널 배정」 표 · 설계값 → 해당 절 · 남은 일 → §10 🔓 미결 표. 수치에는 **조건을 함께** 쓴다.

### 2.4 완료 전환 — 전에 ❌·🛑 였던 것이 끝났을 때

| 자리 | 처리 |
|---|---|
| §10 측정 절 | 새 결과 절을 쓰고 옛 절 마커를 `⛔ SUPERSEDED-BY §10.N` 으로 |
| §11·§12 같은 현행 사실 절 | 완료 사실로 덮어쓰고 이력 한 줄 — `2026-09-05 ❌ 결선 실패 → <날짜> 완료` |
| 🔓 미결 표 | 행을 지우고 근거 절에 결론을 적는다 |
| spec·plan 상태 줄 | `🛑 중단 → ✅ 완료(<날짜>)` |

### 2.5 자가 점검 (커밋 전)

```bash
P="${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}"; cd "$P" && git diff HEAD -U0 -- docs/통합문서.md | grep -E '^[-+]' | grep -vE '^(\+\+\+|---)' | head -40   # 바뀐 줄 눈으로 확인
python3 - <<'EOF'
import re
L = open("docs/통합문서.md", encoding="utf-8").read().splitlines()
a10 = next(i for i, l in enumerate(L) if l.startswith("## 10. ")); a11 = next(i for i, l in enumerate(L) if l.startswith("## 11. "))
def sec(i):
    return next((L[k] for k in range(i, -1, -1) if re.match(r"^#{2,3} ", L[k])), "")
bad = [i + 1 for i, l in enumerate(L) if not (a10 <= i < a11 or i < 50) and (
      (re.search(r"D7|IN5|IN1~4|CH1~4|GPIO ?(5|6|13|19|26)\b|공통 GND 한 가닥", l) and not sec(i).startswith("## 12."))
   or (re.search(r"[48]채널|[48]ch\b", l) and not (sec(i).startswith("### 11.1") or ("통합 작동 테스트" in l and "2026-07-15" in l))))]
secs = {int(m) for m in re.findall(r"^### 10\.(\d+) ", "\n".join(L), re.M)}
idx = "\n".join(L)[ "\n".join(L).index("## 🧭 §10 갈래 색인"): "\n".join(L).index("## 🎯 현재 확정값")]
got = set()
for a, b in re.findall(r"10\.(\d+)(?:~10\.(\d+))?", idx): got |= set(range(int(a), int(b or a) + 1))
print("구성 사실 복제", "✅ 없음" if not bad else "❌ %s" % bad, "| 색인 누락", sorted(secs - got) or "✅ 없음")
EOF
```

- 기존 §10.x 본문은 **마커 줄 외 바뀌지 않았다** · 🔓 행의 근거 절이 실재한다 · 새 §10 절이 색인에 올랐다.
- CC작업문서 기록이면 위 스크립트 대신 바뀐 줄 확인만.

### 2.6 커밋

경로를 지정해 add 하고 `docs(정본): <결과 한 줄>` 로 커밋한다(CC작업문서면 `docs(CC정본): …`).

## 3. 세션 마무리

`session-wrap` 절차를 그대로 수행한다. 🛑 중단 작업은 작업로그 ⏸ 에 **재개 조건** 한 줄을 남긴다. 🔴 **🔗 커밋 줄에 2단계의 `docs(정본)`·`docs(CC정본)` 커밋 해시를 반드시 넣는다** — 빠지면 다음 세션 색인이 이 세션을 부분기재로 띄운다(2026-09-14 리뷰 I4).

## 4. push — 한 번

**4-1. 올라갈 커밋 확인** — 저장소마다 원격과 비교해 목록을 본다:

```bash
P="${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}"; cd "$P" && for r in . Rpi5; do
  git -C "$r" fetch -q 2>/dev/null
  b=$(git -C "$r" rev-list --count 'HEAD..@{u}' 2>/dev/null || echo 0)
  echo "== $r · 원격에만 있는 커밋 ${b}건"; git -C "$r" log --oneline '@{u}..HEAD' 2>/dev/null
done
```

- 🔴 **원격에만 있는 커밋이 있으면 push 하지 않고 멈춰 보고한다** — 병합 판단은 사람이 한다(데스크톱이 먼저 올린 경우).
- 🔴 **목록에 이번 작업 단위 커밋이 아닌 것이 섞여 있으면 push 하지 않고 멈춰 보고한다** — 자동 push 가 허용된 것은 이번 작업분뿐이다(다른 세션이 일부러 안 올린 커밋일 수 있다 · 2026-09-14 리뷰 I2).

**4-2. push** — 위 두 조건을 통과한 저장소만, **종료 코드로 성공을 판정**한다:

```bash
P="${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}"; cd "$P" && for r in <통과한 저장소 …>; do
  if out=$(git -C "$r" push -q origin HEAD 2>&1); then echo "$r: push 완료"; else echo "$r: 🔴 push 실패 — $out"; fi
done
```
- 커밋 안 한 변경은 대상이 아니다 — 끝 보고에 적기만 한다.
- 실패하면 작업로그는 그대로 두고 끝 보고에 오류와 재시도 방법을 적는다.

## 5. 끝 보고 (형식 고정)

```
작업 마무리 — <작업 이름> · 결말 <✅ / ❌ 실패 / 🛑 중단> (합의: 「…」)
정본 — <문서> · <절: 무엇을> · …   (없으면 「정본 기록 없음 — 이유」)
작업로그 — <블록 제목> · ⏸ N건 · ▶ <첫 항목>
push — <저장소: N건 / 올릴 커밋 없음 / 🔴 멈춘 이유>
남은 로컬 변경 — <저장소: 파일> 또는 없음
```

정본 기록에서 **사용자가 말하지 않았는데 Claude 가 정한 것**은 해당 줄에 ✋ 로 표시한다(CC작업문서 §2.7 요약 보고 형식). 사용자가 틀린 곳을 지적하면 고쳐 커밋하고, 그 push 는 요청할 때 한다.

## 이어받기에서 불릴 때

`/이어하기` 가 이전 세션의 멈춘 지점(`session_archive.py --pending <ID8>`)을 보고하고 사용자가 고르면:
- **「이어서 끝낸다」** — 남은 태스크 → 공동 확인 → 이 스킬 1부터.
- **「중단으로 확정」** — 이 스킬 1부터(🛑 중단). 원천은 이전 세션의 커밋·편집·보존본이다.
- 작업로그 블록에는 이전 세션 번호(소급 표기)와 현재 세션 번호를 함께 적는다.

## 주의

- push 는 **4단계에서만** 한다 — 작업 도중 push 는 사용자가 요청할 때만(CLAUDE.md §4).
- brainstorming 없이 한 작업(미계획 작업)의 정본 기록 형식은 아직 없다 — 결과 사실이 있으면 3단계 작업로그에 `- ⏸ ⚠️ **정본 미기록(미계획 작업)**: <사실 한 줄>` 을 남긴다.
