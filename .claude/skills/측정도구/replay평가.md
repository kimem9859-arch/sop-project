# replay 평가 — 절차와 판정 논리

> 🔑 **이 절차는 이미 한 번 완료됐다**(결과는 통합문서 §12). 여기 남긴 이유는 **판정 논리가 재사용 가치가 있어서**다. 「지금 할 일」이 아니다.
> ⚠️ 아래 실행 예의 세션 이름은 **현재 파이에 없다** — `test/raw/` 에 실제로 있는 세션으로 바꿔 쓴다. raw 는 git 에 없고 파이 로컬에만 있다.

## 무엇인가

**「싸게 파국을 거르는 안전핀」이지 성능 측정이 아니다.** 몇 분이면 끝나고 **실패할 때만 강한 정보**를 준다.

## 실행 (cwd 중요)

```bash
cd ~/sop-project/Rpi5/Demo          # 🔴 반드시 Demo/ 에서 — 아래 경로가 전부 상대경로
ls models/console_v2.hef            # 배포 확인
ls test/raw/                        # 🔴 raw 는 git 에 없다 — 파이 로컬에만 존재

python3 test/replay_raw.py test/raw/<저조도 세션> --hef models/console_v2.hef
python3 test/replay_raw.py test/raw/<정반사 세션> --hef models/console_v2.hef
python3 test/replay_raw.py test/raw/<기준선 세션> --hef models/console_v2.hef
```

`--hef` 가 런타임에 `config.HEF_MODEL_PATH` 를 덮으므로 **config 수정은 불필요**하다. 🔴 **기준선 세션을 꼭 같이 돌려야 세션 간 비교가 된다.**
※ **HailoRT 는 4.x** 여야 한다(DFC 3.33.1 로 만든 `.hef` 호환 · 5.x 금지).

## 🔴 판정 기준 — 「v1 대비 검출률 상승」을 쓰지 말 것

`test/raw/<세션>` 이 곧 **학습 데이터의 출처**라 **학습에 쓴 장면으로 시험 보는 구조**다. 게다가 v1 은 파랑 스티커를 학습한 적이 없어 애초에 분포 밖이다.

⚠️ **두 개의 「B4 0%」를 혼동하지 말 것** — ①검정 B4 의 0회(원인 = 카메라 입력 품질) ②파랑 프레임에서 v1 의 0%(단순 분포 밖). **다른 현상이다.**

## ✅ 이것만 본다

1. **하한선** — v2 가 **자기 학습 데이터에서조차** B4 를 못 잡으면 → **즉시 중단·원인 재분석.** 🔑 **실패 = 강한 증거 / 통과 = 약한 증거인 비대칭 테스트.**
2. **⭐ 세션 간 비교 (핵심)** — 누출이 여러 세션에 **균등**해 상쇄된다. **저조도만 기준선 대비 무너지면 = 조명 탓**(진짜 신호).
3. **rawdet 을 볼 것** — 저신뢰 구간은 트래킹 이전 raw 검출에서만 드러난다.

## ❌ 이것으로 답할 수 없는 것

- **정답(ground truth)이 없다** — 출력은 검출 수·프레임율·median/max confidence 뿐이다. **「B4 검출」이 올바른 위치·클래스인지 알 수 없다.**
- 실전 성능·일반화 — 같은 날·조명·모조 콘솔, 실시간 AE·움직임 없음, 트래킹 연속성도 없다.
- **`.hef` vs `.pt` 양자화 손실 대조는 파이에서 불가**하다.

## 결과 처리

🔴 **`.pt` mAP · `.hef` HAR 검증 · 이 평가 통과, 그 무엇으로도 「B4 해결」을 선언하지 말 것** — v1 도 앞 두 관문은 전부 통과했고 에뮬레이션에서 B4 를 고신뢰로 검출했다.
