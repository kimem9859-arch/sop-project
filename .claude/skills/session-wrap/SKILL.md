# 세션 마무리 (session-wrap)

## 언제
**`work-close` 3단계에서만 불린다**(2026-09-14 — 마무리 입구는 `work-close` 하나, 사용자가 "세션 마무리"라고 해도 그쪽으로 간다). 기록 시점은 **한 작업 단위(A작업)가 논리적으로 끝난** 때.
**하루의 끝·작업 종료가 아니다** — 한 세션 동안 여러 번 일어날 수 있다. "이제 그만"이 아니라 "이 갈래를 매듭짓고 기록한다"는 뜻.

## 절차

### 0. (2026-09-14 삭제 — 마무리 입구는 `work-close`)

### 1. session_id 확보
SessionStart 브리핑 훅(`session-worklog-brief.sh`)이 주입한 **현재 session_id(전체 UUID)** 를 쓴다.
컨텍스트에 없으면 사용자에게 묻거나 브리핑 출력에서 찾는다. **짧은형 금지 — 전체 UUID**(그대로 `claude --resume`에 쓸 수 있어야 함).

### 2. 미기록 커밋 소급 점검 (이전 세션 누락 구제 — 2026-07-18 신설)
마무리 전에 **이전 세션이 마무리를 안 하고 남긴 커밋**이 있는지 점검한다(SessionEnd 자동매핑 훅은 2026-07-17 폐기 — 이 단계와 보존·색인(`~/lab/session-archive/INDEX.tsv`)이 안전망):
1. **양 repo**(sop-project·Rpi5)에서 `git log`로 최근 커밋 해시를 뽑는다(범위 = 작업로그 최신 블록 날짜 이후, 최소 2주).
2. 각 해시(7자리)를 `docs/작업로그.md` + `docs/claude-code-작업로그.md`에서 grep — **어느 쪽에도 없으면 미기록 후보**.
3. 제외: 현재 세션 커밋(이번 블록에서 다룸) · 기록 행위 자체 커밋(`docs(세션마무리)`·작업로그 자동기록·훅 매핑류) · **"해시 미기입" 커밋**(마무리된 블록이 내용을 서술로 이미 커버하는 경우 — 소급 블록 대상 아님. 대신 **그 블록 🔗줄에 해시만 보충**해 재검출 노이즈를 없앤다. 2026-07-18 첫 실검증에서 8건 확인).
4. 미기록이 있으면 **확인 없이 소급 블록을 쓴다**(2026-09-13 변경 — 사실 기재는 판단이 아니다. spec 2026-09-13-하네스 §6.7). 원인 해석처럼 **판단이 갈리는 것만** 사용자에게 확인한다. 🆕 `~/lab/session-archive/INDEX.tsv` 의 「미기재」·「부분기재」 세션도 소급 후보로 보고(부분기재는 작업로그에 없는 커밋만 — `session_archive.py --pending <ID8>`), 그 세션의 보존본(`<시작일>_<ID8>.md`)을 근거로 쓴다.
5. **별도 소급 블록**으로 기록: `## <커밋 날짜> · session <이전ID> (소급 — 커밋 기반)`. 이전 세션 ID는 세션파일(`~/.claude/projects/…`)·resume 목록·커밋 시각으로 추정하고, 불확실하면 `session 미상(소급)`으로 표기. 블록 첫 줄에 한계를 명시한다 — 커밋 기반이면 **"커밋 메시지 기반 소급 — 무커밋 작업·중단 사유는 유실"**, 보존본 기반이면 **"보존본(발화·편집·커밋) 기반 소급 — 판단·결론은 추정"**(현 세션 블록과 섞지 말 것). 🔴 INDEX 의 「진행중」 세션은 소급하지 않는다 — 그 세션이 스스로 마무리한다. 사용자가 이 대화에서 **기록 불필요로 정한 세션**도 소급하지 않는다(2026-09-14 1e79f4c8 — 한이음 서류 검토).

### 3. 이번 세션 작업을 4분류로 정리
| 표기 | 뜻 |
|---|---|
| ✅ 완료 | 이번 세션에 끝낸 것 |
| ⏸ 중단 | 하다 만 것(재개 대기) |
| ▶ 다음 | 다음에 이어할 것 |
| 🔗 커밋 | 관련 커밋 해시(있으면) |

각 항목은 **사람이 읽고 이해할 의미 요약**으로 쓴다(기계적 커밋 나열 아님).

### 4. 성격에 따라 라우팅
- **프로젝트 작업**(비전 모델·인터락·통합문서·발표 등) → **`docs/작업로그.md`**
- **Claude Code 인프라 작업**(훅·스킬·도구·작업방식 개선) → **`docs/claude-code-작업로그.md`**
- 한 세션에 **둘 다** 있으면 **양쪽에 각각** 해당 부분만 적는다.

### 5. 블록 형식 (기존 항목과 동일하게)
최신이 위로 오게 삽입:
```
## <YYYY-MM-DD> · session <full-uuid> (<한줄 제목>)
- ✅ ...
- ⏸ ...
- ▶ 다음: ...
- 🔗 커밋: <hash> · <hash>
```
날짜는 절대표기(상대날짜 금지). 상대 날짜가 나오면 실제 날짜로 변환. **날짜 = 작업한 날(현지 시각)** — 세션 시작일이 아니다(보존본·`--pending` 의 현지 시각 기준, 2026-09-14 ESP32 날짜 오기 재발 방지).

> 🔴 **⏸·▶는 반드시 위 형식대로 `- ⏸` / `- ▶` 평면 불릿으로 쓴다 (2026-07-30 신설).**
> SessionStart 훅(`session-worklog-brief.sh`)이 **`docs/작업로그.md`의** 최신 블록에서 `^-? *(⏸|▶)` 로 뽑아 배너에 띄우는데, **헤딩(`### ▶ 다음`)이나 중첩 불릿으로 쓰면 못 집어낸다.** (훅이 읽는 것은 `작업로그.md` 하나뿐 — CC 로그는 배너에 안 뜬다. 다만 형식은 두 로그 모두 통일한다.) 실제로 2026-07-28·07-30 블록이 그렇게 쓰여 배너에 **"미완 작업 없음"** 이 떴고, 그 결과 방향 정보가 CLAUDE.md에만 남아 그 문서가 저널로 비대해지는 원인 하나가 됐다.
> - 상세는 `### ⏸ 중단` / `### ▶ 다음` 소제목 아래 자유롭게 쓰되, **블록 머리에 요약 평면 불릿 1줄씩을 반드시 얹는다.**
> - ⚠️ **한 줄을 짧게** — 배너가 그 줄 길이만큼 넓어진다. 100자 안팎으로.
> - 확인: `awk '/^## /{c++} c==1{print} c>=2{exit}' docs/작업로그.md | grep -E '^-? *(⏸|▶)'`

### 6. 커밋
로그 파일 수정을 커밋한다(사양·설계 문서 → `sop-project`).
**커밋 서명은 `CLAUDE.md` §4 커밋이 정본** — 그 규칙을 따른다(모델명을 여기 적지 않는다).
push 는 여기서 하지 않는다 — `work-close` 4단계가 한 번.

> ⚠️ **여기에 모델명을 하드코딩하지 말 것 (2026-07-30).** 종전에 `Opus 4.8`이 박혀 있었는데 주 작업 모델이 `Opus 5`로 바뀌면서 **stale이 됐다**(CLAUDE.md만 갱신됨). 모델명은 바뀌는 값이라 **정본 한 곳(CLAUDE.md)에만** 두고 여기서는 가리키기만 한다.

## 주의
- 로그 = **시간순 저널**. **정본**(통합문서·CC작업문서)과 역할이 다르다 — 결과 사실은 `work-close` 2단계가 정본에 쓰고, 여기는 시간순 요약이다.
- 의미 기록은 **이 요약**이 한다(SessionEnd 자동 커밋매핑은 2026-07-17 폐기).
- 과거 저널 항목은 고치지 않는다(그때의 기록) — **🔗 줄 해시 보충(§2 의 3항) 외에는**. 새 블록만 추가.
