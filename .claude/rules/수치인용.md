# 수치를 쓰거나 인용할 때

> 전부 **한 번 이상 실제로 물렸던 것**이다. 수치 자체는 여기 담지 않는다 — 정본은 통합문서 §12 `[CURRENT]` 표다.

## 어느 값을 쓰나

- 🔴 **프레임 단위 손 검출률을 성능 지표로 쓰지 말 것** — 손이 없는 프레임이 분모에 섞여 값이 오염된다. 의미 있는 값은 **눌림 근처** 기준이다.
- 🔴 **지표 이름을 혼용하지 말 것** — 체류 구간 수 / 눌림 프레임 적중 / 선행시간 / 사전 감지율 / 개입 감지율은 **서로 다른 것을 잰다.** 인용 시 어느 지표인지 반드시 명시.
- 🔴 **사후 층화(post-hoc stratification) 값을 성능으로 쓰지 말 것** — 데이터를 보고 구간을 좁혀 얻은 값은 낙관 편향이 있다. 새 촬영으로 확인해야 성능 주장이 된다.
- 🔴 **단일 세션 값 금지 — 통합값으로 인용한다.** 같은 구도를 반복해도 세션 간 편차가 크다.

## 조건 없는 단정 금지

- 🔴 **"console_v2 검증 완료"로 쓰지 말 것** — 정확히는 **"클린룸 형광등·모조 콘솔 조건에서"**. 실콘솔 2차 test 가 최종 판정이며 미실시(§12 🔓 미결).
- 🔴 **감지율을 성능 상수로 쓰지 말 것** — **착용 위치에 따라 크게 흔들린다.** 구도 조건을 함께 밝힌다.
- ⚠️ **NFR-1 은 충족됐으나 "안정 처리"까지 단정하지 말 것** — 실측은 **손 없는 정지 장면·단일 조건**이고 최저 구간이 남아 있다. 조건을 병기한다.
- 🔴 **E2E 오경보 인용 시 시뮬레이션 정책 4종을 병기**한다 — 실제 GUI 운용과 다르다.
- 🔴 **FPS 를 인용할 때는 PNG 저장 빈도를 병기한다** — `bench_detector --save-raw` 는 **런타임에 없는 부하**다. XGA 에서 매 프레임 저장하면 FPS 가 깎이고(§12.72-(10) · PNG 한 장 45ms), 7월 VGA 에서도 매 프레임 저장이 5프레임에 1장보다 약 4fps 낮았다(`bench_detector.py` 머리말). **저장하며 잰 FPS 를 「런타임 FPS」로 인용하지 않는다.** 표기 예 = 「매 프레임 PNG 저장 중」 · 「10프레임에 1장 저장 중」 · 「저장 없음」.

🔑 **제출문서는 다르다** — 기능·설계값은 완성형으로 쓰되 **측정 수치는 위 규칙대로 조건을 병기**한다.

## 결과를 해석할 때

- ⚠️ **놓친 눌림은 세 종류다** — ①손 자체 미검출(구도) ②손끝이 ROI 밖(구도·판정) ③**구역 안에 있었는데 체류 임계 미달(시간)**. **대응이 다르므로 한 덩어리로 세지 말 것.**
  - 🔴 **③이 지배 원인이다** — 실측에서 ①+②는 소수였고 ③이 대부분이었다. **①만 떠올리고 「구도 문제」로 결론내는 것이 이 함정의 실제 형태다.**
