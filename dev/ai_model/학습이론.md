## 1. YOLO가 배우는 것 — 구조·손실 함수·정답 박스 배정

> **세 줄 요약**
> 1. YOLO는 크기가 다른 격자 3개에서 박스와 클래스를 **직접** 예측한다(작은 물체 = 촘촘한 P3).
> 2. 손실은 박스 겹침(`box`) · 클래스(`cls`) · 박스 경계(`dfl`, YOLO26 은 `l1`) 세 가지의 합이다.
> 3. 「물체 있음」 출력이 없어 **배경은 「어떤 클래스도 아님」으로만 배운다** — 학습에 없던 배경은 배울 기회가 없다.

**요점**

1. **세 부분 구조** — 백본(특징 추출) → 넥(여러 크기의 특징 합치기) → 헤드(박스·클래스 출력). 출력은 **보폭 8·16·32 의 세 격자(P3·P4·P5)** 이고, 촘촘한 P3 가 작은 물체, P5 가 큰 물체를 맡는다. YOLO11·YOLO26 설정 파일도 `Detect(P3, P4, P5)` 에 `P3/8-small · P5/32-large` 로 표시돼 있다. [1][9][3]
2. **앵커 프리(anchor-free, 「미리 정한 박스 틀 없음」)** — 옛 방식처럼 정해 둔 박스 모양들과 비교하지 않고 **격자점마다 박스를 직접 예측**한다. 그래서 박스 틀 관련 설정값이 사라진다. 헤드는 **박스 갈래와 클래스 갈래가 따로(분리형)** 돈다. [1][2][7][4]
3. **손실 = 세 항목의 가중합** — `box_loss`: 예측·정답 박스의 겹침 정도(**CIoU** = 겹친 넓이·중심 거리·가로세로 비율) [5][10] · `cls_loss`: 클래스 맞히기(**BCE**, 클래스마다 「맞다/아니다」 따로 판정) [5][3] · `dfl_loss`: 박스 네 변 위치를 **16칸짜리 확률 분포로** 예측(**DFL**) [5][7][11]. 기본 가중치는 `box 7.5 · cls 0.5 · dfl 1.5` [8].
4. 🔑 **「물체 있음」 전용 출력(objectness)이 없다** — 정답에 배정되지 않은 **모든 격자점은 클래스 목표가 전부 0** 으로 `cls_loss` 에 들어간다. 즉 **배경은 「어떤 클래스도 아님」으로 배운다.** 유지보수자도 「v8 에선 예측 클래스 점수가 v5 의 objectness 역할」이라고 답했다. [5][6][15][3]
5. **정답 박스 배정(TAL, Task-Aligned Learning)** — 정답 박스 **안에** 중심이 있는 격자점 중 `클래스 점수^α × IoU^β` 가 큰 **상위 k개**를 양성(학습 대상)으로 뽑는다. 한 점이 여러 정답에 걸리면 IoU 가 큰 쪽. 클래스 목표는 1이 아니라 **맞춤 정도에 비례한 부드러운 값**이다. [6][5][12]
   - ⚠️ **출처 간 불일치**: TOOD 논문은 `α=1 · β=6 · m(=k)=13` [12]. Ultralytics 가 **실제로 쓰는 값은 `α=0.5 · β=6 · k=10`** 이다(`v8DetectionLoss` 에서 지정). `tal.py` 클래스 기본값 13·1.0 은 검출 학습에서 쓰이지 않는다 [5][6]. *(초안의 「상위 13개·α=1」 은 이 클래스 기본값을 옮긴 것이라 정정)*. MMYOLO 문서는 식을 합(`s^α + u^β`)으로 적었으나 논문·코드는 곱이다 [3][12][6].
6. **아주 작은 물체도 양성을 보장(STAL)** — 정답 박스의 가로·세로가 기준보다 작으면 **후보를 고를 때만** 박스를 키워 격자점이 하나도 안 걸리는 일을 막는다(실제 학습 목표 박스는 원래 크기). 현행 main 코드에선 **YOLO26 전용이 아니라 모든 검출 손실에 적용**된다. [6][14][13]
   - ⚠️ **출처 간 불일치**: 논문은 「8px 미만 → 16px」 [14], 현행 코드는 「**16px(P4 보폭) 미만 → 16px**」 이다 [6]. 이 부분은 2026-08-24 에 코드가 바뀌었다 [18] → 설치 버전마다 동작이 다를 수 있다.
7. **YOLO26 의 변경** — ① DFL 제거(`reg_max: 1`) → 박스 변 위치를 직접 예측하고 그 자리의 손실이 **L1**(로그 이름 `l1_loss`, 가중치는 `dfl` 값 공유) [9][5][8][1][14]. ② **헤드 두 벌**: 「여러 개 배정(k=10)」 헤드 + 「물체당 하나 배정(k=7→1)」 헤드를 함께 학습하고, 손실 비중을 **0.8:0.2 → 0.1:0.9** 로 옮긴다(ProgLoss) [5][17][14]. ③ 추론 시 `nms=False` 로 **NMS(중복 박스 후처리 제거) 없이** 출력 가능 [13][1]. YOLOv8·YOLO11 = DFL + NMS [7][3][15].

**우리 상황 적용**

- **손톱 오검출** — 요점 4 때문에 모델은 **학습 이미지에 나온 배경만** 「아님」으로 배운다. 손·손톱이 버튼 근처에 있는데 버튼 라벨이 없는 장면이 학습에 충분히 없으면 손톱을 「아님」으로 배울 기회가 없다 → ②데이터에서 확인. *(적용 추론 — 원인 확정 아님)*
- **작은 버튼·라벨 품질** — 요점 5 의 IoU 6제곱 때문에 **헐겁거나 조각난 박스는 양성 선택 자체를 흔든다**. 작은 박스는 요점 6 이 양성을 보장하지만 그 기준이 버전마다 달라 **ultralytics 설치 버전을 고정·기록**해야 한다.
- **YOLO 버전 선택** — 요점 7 이 손실 구성·후처리를 바꾸므로 **Hailo 가 어느 버전(특히 DFL 없음·NMS 없음 출력)을 지원하느냐(8절)로 먼저 좁힌다.**

## 2. 데이터 — 양·다양성·분할·누출·라벨 품질

> **세 줄 요약**
> 1. 권고 규모는 클래스당 이미지 1,500장 · 물체 10,000개 이상이고, **라벨 품질이 양보다 앞선다.**
> 2. 같은 영상의 프레임은 한 세트에만 — **영상(세션) 단위로 나눈다.**
> 3. 모든 물체를 빠짐없이 딱 맞게 라벨하고, 가림 규칙은 하나로 정해 문서로 남긴다.

**요점**

1. **양**: Ultralytics 는 안정적인 실사용 성능을 위해 **클래스당 이미지 ≥1,500장·인스턴스(라벨된 물체 개수) ≥10,000개**를 권고하고, 전이학습(사전학습 모델을 이어 학습) 실험 시작은 클래스당 수백 개 물체로 충분하다고 한다 [1][2]. Roboflow 는 첫 모델 버전에 50~100장으로 시작해 운영 모델은 수백~수천 장으로 늘리라고 한다 [9](블로그). ⚠️ 출처 간 불일치: 수치 기준이 다르다 — Ultralytics 는 「신뢰할 만한 성능」 목표치, Roboflow 는 「첫 버전 시작점」이다.
2. **라벨 품질이 양보다 앞선다**: 일관되고 딱 맞는 라벨로 클래스당 1,500장 학습한 모델이 엉성한 라벨 5,000장 모델을 이긴다 [3]. 라벨마다 사람이 검토하고, 신뢰도가 높은 자동 검출도 조용히 자동 승인하지 말 것 [3].
3. **다양성**: 데이터는 **실제 배포 환경을 대표**해야 한다 — 시간대·조명·각도·출처를 다르게 [1]. Roboflow 도 「시스템이 마주칠 모든 조명·카메라 각도·배경」과 흐림·일부 가려짐·경계 사례까지 넣으라고 한다 [9](블로그). 학습한 장소에서는 성능이 좋아도 **새 장소(배경)로의 일반화는 나쁘다**는 실증이 있다 [10].
4. **분할과 누출**: 흔한 비율은 train 70 / val 20 / test 10 [4][8](Academy 는 70/15/15, 이미지 수가 아니라 **물체 수 기준**으로 [5]). 분할은 **증강(augmentation) 전에** 하고 증강은 train 에만 적용한다 [4]. 클래스 비율이 세 세트에 고르게 가도록 층화(stratification)한다 [4][5]. test 는 마지막에 한 번만 쓴다 [5].
5. **영상 프레임 누출**: 연속 프레임은 서로 거의 같아서 **이미지 단위 무작위 분할은 누출**되어 val 점수가 부풀려진다 → **영상(장면) 단위로 묶어 한 세트에만** 넣는다 [5]. 논문도 같은 문제를 지적하고, 비슷한 프레임을 먼저 군집으로 묶은 뒤 분할하는 방법을 제안한다 [11].
6. **빠짐없이·딱 맞게**: 모든 이미지의 모든 대상 물체를 라벨해야 하며 부분 라벨은 안 된다. 박스는 물체를 빈틈 없이 감싸야 한다 [1][3]. 라벨이 빠진 물체는 학습 중 **배경(음성 예)으로 취급**되어 검출기를 잘못 벌점 준다 [12][13](블로그). PASCAL VOC 지침도 「보이는 픽셀을 모두 포함」·「대상 범주의 모든 물체 라벨」을 규칙으로 둔다 [6].
7. **가려진 물체·배경 이미지**: VOC 는 **보이는 영역**에 박스를 친다(가려진 전체 크기를 추정하지 않음), 보이는 부분이 10~20% 미만이면 라벨하지 않는다 [6]. Academy 는 「≥50% 보이면 라벨」 같은 **규칙 하나를 정해 문서화하고 지키라**고 한다 [3]. ⚠️ 출처 간 불일치: 라벨 여부 문턱(VOC 10~20% vs Academy 예시 50%)이 다르다 — 공통점은 「규칙을 정해 일관되게」. 배경(라벨 없는) 이미지는 오검출(FP) 감소용으로 **0~10%** 권고 [1]; Roboflow 는 비율 없이 「null 이미지가 없으면 몇 장 추가를 고려」라고만 한다 [7]. ⚠️ 0~10% 수치의 독립된 두 번째 출처는 미확인(찾아본 곳: Roboflow docs Health Check·블로그, Ultralytics Academy, context7 Ultralytics, GitHub 이슈 #22888).

**우리 상황 적용**

- 분할은 **촬영 영상(세션) 단위**로 한다 — 같은 영상의 프레임이 train·val·test 에 나뉘면 점수가 부풀려진다 [5][11]. 시연 콘솔(EMO 위치가 다른 배치)·새 배경은 학습에 없는 장소로 보고 별도 test 로 둔다 [10].
- 라벨 지침서(클래스 정의·그리기 규칙·가림 규칙·애매한 경우·건너뛸 것)를 먼저 쓴다 [3] — 가운데를 쥔 렌치는 VOC 규칙상 **보이는 픽셀 전체(머리~손잡이 끝)**를 감싸야 하므로 머리만 박스는 규칙 위반이다 [6]. 손을 쥔 공구·손톱 유사 장면·빈 콘솔 배경은 배경 이미지(0~10%)와 가림 규칙으로 다룬다 [1][3].

## 3. 입력 — 해상도·종횡비·작은 물체

> **세 줄 요약**
> 1. 학습 · 추론 모두 **비율을 유지하고 여백을 채운다**(늘리지 않는다) → Roboflow 「Stretch」는 쓰지 않는 것이 맞다.
> 2. 🔴 우리 런타임은 640×640 으로 **늘려** 넣는다고 기록돼 있어 코드 확인이 필요하다.
> 3. 작은 물체 대응 = 입력 해상도 올리기 · P2 층 · 조각 추론 · 큰 모델(모두 속도와 맞바꿈).

**요점**

1. **학습 `imgsz` 는 정수 하나(정사각형)만 받는다.** `[h, w]` 를 주면 큰 값으로 바뀐다. 추론(predict)과 내보내기(export)는 `(높이, 너비)` 튜플도 받는다 [1][2]. PyTorch 가 아닌 형식으로 내보낸 모델을 검증(val)하려면 정사각형이어야 한다는 경고가 코드에 있다 [3].
2. **학습 기본값(`rect=False`, 증강 켬)은 비율을 지키고 늘리지 않는다.** 이미지는 긴 변을 `imgsz` 에 맞춰 비율대로 줄인다. 그다음 모자이크(mosaic)와 무작위 원근 변환이 `imgsz×imgsz` 정사각형으로 만들고, 빈 곳은 회색(114)으로 채운다 [4][5]. 문서도 YOLO 는 "비율을 유지한다"고 적는다 [2].
3. **`rect=True` 로 학습하면 모자이크·믹스업(mixup)·컷믹스(cutmix)가 꺼진다.** 배치마다 모양이 다르면 셔플도 꺼진다(경고 출력) [6][7]. 검증은 기본으로 `rect` 를 쓴다. 다만 PyTorch 가 아니고 입력 크기도 고정된 모델에서는 `rect` 가 자동으로 꺼진다 [7][8].
4. **추론은 항상 레터박스(letterbox: 비율 유지 + 여백)다.** 여백을 최소로 줄이는 모드는 조건이 모두 맞을 때만 켜진다: `rect` 켬, 입력 이미지 크기가 모두 같음, PyTorch 모델이거나 입력 크기가 바뀌는 모델. 그 밖에는 `imgsz` 전체 크기까지 여백을 채운다 [9][1]. 늘림(stretch)은 `LetterBox(scale_fill=True)` 옵션으로만 쓰이고, 기본값은 꺼져 있다 [4]. 검증 때는 확대하지 않는다(`scaleup=False`) [6].
5. **학습과 추론의 전처리가 다르면 성능이 떨어진다(1차 근거는 블로그뿐).** Roboflow 는 늘린 이미지로 학습하면 "배포에 없는 형태를 배운다"고 경고한다. 늘려서 학습했다면 운영 이미지도 똑같이 늘려야 한다고 한다 (블로그) [10]. Ultralytics 는 해상도를 기준으로 "학습과 같은 `--img` 로 추론할 때 결과가 가장 좋다"고 권고한다 [11]. ⚠️ 미확인: "늘려서 학습 → 레터박스로 추론" 조합을 정량으로 잰 1차 자료는 못 찾았다(찾아본 곳: ultralytics/yolov5 #209·#11350·ultralytics #7053 — 유지보수자 답변이 페이지에 없음).
6. **Roboflow 의 크기 조정 옵션과 Ultralytics 의 관계.** 「Stretch to」는 이미지를 찌그러뜨린다. 「Fit (black/white/reflect edges)」는 비율을 유지하고 여백을 채운다. 「Fit within」은 비율 유지에 정사각형이 아니다. 「Fill (center crop)」은 가장자리를 잘라낸다. Roboflow 는 축소만 지원한다 [12]. Ultralytics 는 `imgsz` 가 크기를 알아서 맞추므로 미리 줄여 둘 필요가 없다고 한다 [13]. 두 단계의 조합은 추론이다: Roboflow 에서 Stretch 로 내보내면, 찌그러진 이미지가 Ultralytics 레터박스에 그대로 들어간다.
7. **작은 물체 대응 권고는 네 가지다.**
   - 입력 해상도 올리기: 작은 물체가 많으면 원본 이상 해상도로 학습하라(예: 1280) [11][14].
   - P2 헤드: stride 4 출력층(P2/4)을 더한 `yolov8-p2` 구성이 있다 [15]. 유지보수자는 작은 물체에 유리하지만 느릴 수 있다고 답했다 [16]. 논문에서도 예측 헤드 추가가 쓰였다 [17].
   - 조각 추론(SAHI·타일링): 이미지를 조각내 추론·미세조정하면 작은 물체 AP 가 올랐다고 보고됐다 [18][19]. Roboflow 도 타일 크기를 모델 입력 크기에 맞추라고 권한다 [12].
   - 모델 크기: 큰 모델일수록 대체로 결과가 좋다 [11].
   - ⚠️ 출처 간 불일치: 유지보수자 답변 [16]은 P2 를 "stride 2"라고 했다. 구성 파일 [15]에는 `P2/4`(stride 4)로 적혀 있어 코드를 따른다.

**우리 상황 적용**

- 480×640 세로 프레임을 640×640 으로 레터박스하면 축소 없이 좌우에 여백 160px(양쪽 80px씩)이 붙는다(계산). 학습에서도 긴 변 640 기준 비율 유지라 두 경로의 기하가 일치한다. 그러니 **Roboflow 에서는 Stretch 를 쓰지 말고, 크기 조정을 끄거나 비율 유지(Fit) 계열을 쓴다**. Hailo 모델 저장소(Model Zoo)의 YOLO 전처리도 레터박스(여백 114)다 [20]. 단, ⚠️ 우리 파이 런타임 코드가 실제로 레터박스인지는 코드로 대조해야 한다(이 조사 범위 밖). 🔴 **통합문서 §7.1 「프레임 방향」은 현 런타임이 세로 프레임을 640×640 으로 「늘려」 넣는다고 적고 있다** — 이론(비율 유지)과 반대이므로 ④에서 코드로 먼저 확인한다. 8절 요점 7 의 직사각형 입력(`imgsz=(640,480)`)이 이 불일치를 없애는 선택지다.
- 버튼·먼 공구가 작은 물체 문제라면 후보는 세 가지다: ①`imgsz` 상향 ②P2 구성 ③타일링. 셋 다 속도·Hailo 입력 크기(고정 컴파일, `preprocessing.input_shape` 수정 필요 [21])와 맞바꾸는 것이라 ④학습·검증 단계에서 비교 실험으로 정한다.

## 4. 증강 — 도움이 될 때와 해가 될 때

> **세 줄 요약**
> 1. 기본 증강(색 · 모자이크 · 좌우 뒤집기 등)은 켜진 채 학습되고, 마지막 10 에폭은 모자이크를 끈다.
> 2. **색이 곧 클래스면 색 증강이 라벨을 오염시킬 수 있다** — 다만 출처끼리 의견이 갈린다.
> 3. Roboflow 증강과 학습 중 증강은 겹치므로 **한쪽만** 쓴다.

**요점**

1. **기본 증강은 "켜진 채로" 학습된다.** 현행 `default.yaml` 기본값: 색(HSV — 색상·채도·밝기) `hsv_h 0.015`·`hsv_s 0.7`·`hsv_v 0.4`, 모자이크(4장을 1장으로 합성) `mosaic 1.0`, 좌우 뒤집기 `fliplr 0.5`, 이동 `translate 0.1`, 크기 `scale 0.5`. 꺼져 있는 것: `flipud`(상하 뒤집기)·`degrees`(회전)·`shear`·`perspective`·`mixup`·`cutmix`·`copy_paste`·`bgr` = 0 [1][2]
2. **`close_mosaic`(기본 10) = 마지막 N 에폭 동안 모자이크를 끈다.** 소스상 그 시점에 `mosaic`·`copy_paste`·`mixup`·`cutmix` 를 함께 0으로 만들고 변환을 다시 짠다 [1][3][2]. 강한 증강을 학습 끝무렵에 끄는 방식은 YOLOX 논문에도 있다(마지막 15 에폭) [4]
3. **색이 클래스를 정하면 색 증강이 라벨을 오염시킬 수 있다.** Albumentations 공식 문서는 "빨강→초록 색조 변환은 익음 라벨을 오염시킨다", "신호등 상태는 전적으로 색", "색이 주 신호면 이 변환들은 라벨 노이즈"라고 적는다 [5]. 논문도 색 지터가 색 특징을 훼손해 색이 중요한 클래스에서 성능을 떨어뜨림을 보인다(자기지도학습 맥락) [6]. 증강 효과는 클래스마다 달라 평균은 올라도 특정 클래스는 크게 떨어질 수 있다 [7]
   - ⚠️ 출처 간 불일치: Ultralytics 공식 가이드는 "색·밝기의 약한 변화는 대부분 이롭고 hsv 기본값이 좋은 출발점"이라고만 하고, 색 의존 클래스에 대한 경고 문장은 원문(markdown 소스)에 **없다** [2]. 반대로 Ultralytics 유지보수자(pderrenger)는 모양으로 구분해야 하는데 색에 과의존할 때 **색 지터로 색 의존을 낮추라**고 답했다 [8] — 색이 방해 신호인 경우의 조언이다
4. **Hue(색조) 크기 감각:** 코드상 색조는 `±hsv_h × 180`(OpenCV 0~180 색상환)만큼 무작위 이동, 채도·밝기는 `×(1±gain)` 배율 [9]. 기본 0.015 = 약 ±2.7 단위로 작고, **채도 0.7·밝기 0.4는 폭이 크다** [1][9]
5. **Roboflow 오프라인 증강 + YOLO 학습 중 증강은 겹친다.** Roboflow 증강은 버전 생성 시 **Train 이미지에만** 적용되고 원본 + 증강 사본(예: 3x = 원본 + 2장)으로 저장된다 [10]. YOLO 는 학습 중 매 에폭 자체 증강을 또 적용하므로 증강된 이미지가 다시 증강된다 — Ultralytics 팀 답변은 둘 중 하나를 끄거나 서로 보완하게 조정하라고 권한다 [11]. Roboflow 는 **증강 없이 시작해 원본 데이터 품질부터 평가**하라고 권장한다 [10]
6. **과하면 과소적합, 부족하면 과적합.** 작은 모델은 공격적 증강에 압도돼 학습 손실이 높게 남고 과소적합, 큰 모델은 약한 증강으로는 과적합을 못 막는다 [5]. YOLOX 도 작은 모델(Nano·S)에선 MixUp 을 빼고 모자이크 스케일 범위를 줄였다 [4]. 증강은 과적합을 줄이는 수단이다 [2]
7. **선택 원칙 = 배포 환경을 반영하고 단순하게.** "배포 시 만날 데이터 분포를 반영", "작게 시작해 필요할 때 추가", 시점이 일정하면 회전·이동·스케일 등 기하 증강은 생략 가능, 모자이크는 가림·다물체가 라벨을 바꾸지 않을 때만 [2]. 증강 이미지를 전문가가 망설임 없이 같은 라벨로 붙일 수 있어야 안전하다 [5]. 상하 뒤집기는 물체가 거꾸로 나타날 수 있을 때 쓰는 증강이다 [2]

**우리 상황 적용**

- 버튼(색=클래스)은 `hsv_h` 를 기본 이하로 두거나 끄는 쪽을 검토 후보로, 조명 변화 대응은 밝기(`hsv_v`) 중심으로 — 공구(형상=클래스)는 오히려 색 변화가 도움이 될 수 있어 두 성격이 한 모델에 섞인 점이 설계 쟁점이다 [5][8]
- 머리 착용이라 상하 반전이 없으므로 `flipud`·큰 회전은 끈 기본값 유지가 원칙에 맞다 [2]. Roboflow 증강과 학습 중 증강 중 **한쪽만** 쓰는 것을 기본으로 하고, 첫 학습은 Roboflow 증강 없이 [10][11]

## 5. 학습 설정 — 전이학습·모델 크기·에폭·학습률·배경 이미지

> **세 줄 요약**
> 1. 사전학습 가중치에서 시작하고 **n 크기부터**, 지표가 정체될 때만 키운다.
> 2. 기본값 함정 — `optimizer=auto` 는 `lr0` 를 무시하고, `patience` = `epochs` 라 조기 종료가 사실상 꺼져 있다.
> 3. 오검출은 **배경 사진 0~10%** 로 줄이되 정검출도 함께 준다 · Colab 이 끊기면 `last.pt` + `resume=True`.

**요점**

1. **전이학습(사전학습 가중치에서 출발)이 기본값이다.** `pretrained=True`가 기본이고 [1], 작거나 중간 규모 데이터셋이면 사전학습 가중치에서 시작하라고 권고한다. 처음부터 학습(scratch)은 COCO급 대형 데이터셋용이다 [3][4]. **`freeze`(앞쪽 N개 층을 학습하지 않고 고정)**는 GPU 메모리를 줄이고 학습을 빠르게 하지만, 정확도는 대체로 전체 층 학습이 가장 높다 [5]. 가이드는 데이터가 적고 COCO와 비슷한 영역이면 `freeze=10`(백본 고정), COCO와 먼 영역이면 고정하지 말라고 권한다 [4]. 기본값은 고정 없음이다 [1].
2. **모델 크기 n/s/m은 작은 것부터 시작하고, 검증 지표가 정체될 때만 키운다** [4]. 데이터가 적으면 큰 모델이 과적합되기 쉽다 [4]. 반면 데이터가 충분하면 큰 모델이 "거의 모든 경우" 더 좋다 [3]. Hailo-8 공개 표에서는 크기가 커질수록 FPS가 급격히 떨어진다(YOLO26 n→m, 배치 1, 640×640, COCO 기준) [6]. 크기는 정확도와 속도의 교환 관계로 고른다.
3. **현행 기본값(소스 `default.yaml`)**: `epochs=100`, `batch=16`, `lr0=0.01`, `lrf=0.01`(최종 학습률 = lr0×lrf), `optimizer=auto`, `cos_lr=False`(기본은 선형 감소), `warmup_epochs=3.0` [1]. 워밍업(warm-up, 초반에 학습률을 낮은 값에서 서서히 올리는 구간)은 `warmup_epochs × 배치 수`만큼의 반복 동안 진행된다. `cos_lr=True`이면 코사인 곡선으로 감소한다 [7]. ⚠️ 출처 간 불일치: 기본값은 100 에폭이지만 학습 팁 문서 두 곳은 "300 에폭에서 시작하고, 과적합이 없으면 늘린다"고 권한다 [2][3]. 미세조정 가이드는 "적당히 시작하라"고만 한다 [4].
4. **`optimizer=auto`이면 사용자가 준 `lr0`·`momentum`을 무시한다.** 총 반복 수가 10,000 이하면 AdamW에 클래스 수로 계산한 낮은 학습률을 쓰고, 초과하면 MuSGD(lr 0.01)를 쓴다 [7][8]. 수백~수천 장 규모에서는 대개 AdamW 쪽이 선택된다. `lr0`를 직접 정하려면 optimizer를 명시해야 한다. 미세조정이 불안정할 때의 예시는 `optimizer=AdamW, lr0=0.001`이다 [4].
5. **`patience`(조기 종료: 검증 지표가 N 에폭 연속으로 개선되지 않으면 학습을 멈춤)의 기본값은 100이다** [1][8]. 기본 `epochs=100`과 같은 값이라 기본 설정에서는 사실상 작동하지 않는다. 미세조정 가이드는 10~20으로 줄이라고 권한다 [4]. 개선 판단 기준인 fitness(적합도 점수)는 검출에서 **mAP50-95만**(가중치 1.0)으로 계산된다 [9]. 조기 종료가 보는 지표는 오검출 자체가 아니라 이 점수라는 뜻이다.
6. **오검출을 줄이는 공식 권고는 배경 이미지(찾는 물체가 하나도 없는 이미지)를 추가하는 것이다.** 권장 비율은 약 0~10%이며, 참고로 COCO는 약 1%다 [3]. 라벨 파일 없이 넣으면 된다 [10]. Roboflow에서는 null 주석(∅ 표시)으로 처리한다 [11](Roboflow 공식 블로그). 유지보수자 답변: **배경 이미지를 늘리면 오검출(FP)은 줄지만 정검출(TP)도 줄어든다** [12]. 오검출이 난 이미지를 대량으로 넣어 재학습하는 하드 네거티브 마이닝(hard-negative mining, 모델이 틀린 어려운 음성 사례를 골라 다시 학습시키는 방법)도 제안됐다 [13]. 논문에서도 어려운 사례를 골라 학습하면 검출 성능이 꾸준히 오른다고 보고한다 [14]. ⚠️ 비슷하게 생긴 물체를 "배경"으로 넣을지 별도 클래스로 둘지에 대한 공식 답은 찾지 못함(찾아본 곳: ultralytics 이슈 #16908 — 유지보수자 답변 없음, 데이터 수집 가이드 [15] — 언급 없음).
7. **T4·Colab 제약과 세션 회수 대비.** T4 메모리는 16 GB이고 FP16 혼합정밀을 지원한다 [16]. `amp=True`가 기본이며, AMP 점검 코드의 제외 목록에 T4는 없다 [1][17]. `batch=-1`은 GPU 메모리의 약 60%를 쓰도록 배치를 자동으로 고르고, 첫 에폭에 메모리 부족이 나면 배치를 절반으로 줄여 다시 시도한다 [2][18]. `cache=True`(RAM)가 가장 빠르지만 메모리를 많이 쓰고 [18], 재현성이 필요하면 `'disk'`를 쓰라는 경고가 있다(기본 `deterministic=True`) [19]. **체크포인트**: `last.pt`는 매 에폭 저장되고 `best.pt`는 개선될 때 저장된다 [7]. `resume=True`는 가중치·옵티마이저·스케줄러·에폭을 복원하며, 최소 1에폭은 끝나야 이어서 학습할 수 있다 [8][20]. 이어서 학습할 때는 `last.pt`에 `resume=True`만 주고 다른 인자는 바꾸지 않는다. 인자를 바꾸려면 `best.pt`에서 새로 미세조정한다 [21]. Colab은 세션이 끊길 수 있으니 Drive에 저장하라고 권한다 [22].

**우리 상황 적용**

- 사전학습 가중치에서 출발하고, n→s 순서로 검증 지표가 정체될 때만 키운다. 크기는 Hailo-8 FPS 표 [6]와 함께 정한다(표는 640×640·COCO 기준이라 480×640 입력에서는 다시 재야 한다).
- `optimizer=auto`이면 `lr0` 설정이 무시된다는 점을 학습 기록에 남긴다. `patience`는 에폭 수보다 작게 잡는다. Colab 회수에 대비해 `project`를 Drive 경로로 두고, 끊기면 `last.pt`에 `resume=True`만 준다.
- 손톱·키보드·파우치·벽 오검출에는 그 장면을 담은 **배경 이미지(물체 없음)를 약 10% 이내로** 넣는다. 늘릴수록 TP가 줄어드는 교환 관계가 있으므로 [12] 평가 세트에서 오검출과 미검출을 함께 확인한다.

## 6. 학습 곡선 읽기 — 손실 세 가지·과적합/과소적합

> **세 줄 요약**
> 1. `results.csv` 에 에폭마다 손실 3종 · 정밀도 · 재현율 · mAP · 학습률이 쌓인다.
> 2. 손실은 크기끼리 비교하지 말고 **흐름**을 본다 — train↓ val↑ = 과적합, 둘 다 높게 멈춤 = 과소적합.
> 3. `best.pt` 는 **mAP50-95 하나**로 골라진다.

**요점**

1. `results.csv` 는 에폭마다 한 줄씩 쌓인다. 열 순서는 `epoch`·`time` → `train/<손실>` → 검증 지표 `metrics/precision(B)`·`metrics/recall(B)`·`metrics/mAP50(B)`·`metrics/mAP50-95(B)` → `val/<손실>` → 학습률 `lr/pg0`·`lr/pg1`…(옵티마이저 파라미터 묶음마다 한 열)이다. `results.png` 는 이 CSV에서 이름에 "loss"·"metric"이 든 열만 골라 원래 값과 부드럽게 한 선을 함께 그린다 [1][2][3].
2. 검출 손실 세 가지는 `box_loss`(박스 위치)·`cls_loss`(클래스 분류, BCE)·세 번째 항이다. 세 번째 항은 DFL을 쓰는 모델(`reg_max>1`)이면 `dfl_loss`, DFL을 뺀 YOLO26이면 `l1_loss` 로 이름이 바뀐다. DFL은 박스 경계를 값 하나가 아니라 확률 분포로 예측하는 손실이다 [4][5][6][7].
3. 기록되는 손실 값에는 이득 계수(box 7.5·cls 0.5·dfl 1.5 기본값)가 곱해져 있다. 그래서 **손실끼리 크기를 비교하면 안 되고, 각 손실이 시간에 따라 어떻게 흐르는지를 본다** [4][8]. `val/` 손실은 학습 중 검증할 때 EMA(가중치 이동평균) 모델로 검증 세트에서 같은 손실 함수를 누적해 구한다 [9].
4. **과적합**(학습 데이터를 외워 버림)은 train 손실은 계속 내려가는데 val 손실이 올라가기 시작하는 모양이다. **과소적합**(덜 배움)은 두 곡선이 모두 높은 채로 멈춘 모양이다. 잘 된 학습이면 두 곡선이 대체로 나란히 간다 [10][11]. ⚠️ 출처 간 불일치: 테스트 가이드 [12]는 손실이 아니라 "학습 정확도는 높은데 검증 정확도가 낮음"(과적합), "학습 세트에서도 정확도가 낮음"(과소적합)으로 설명한다. 진단 방향은 같다.
5. `best.pt` 는 매 검증의 fitness(적합도 점수)가 이전 최고보다 높을 때 갱신되고, `last.pt` 는 매번 덮어써진다. 검출 fitness 가중치는 현행 소스에서 `[P 0, R 0, mAP50 0, mAP50-95 1]`, 즉 **mAP50-95만** 본다 [13][14][15]. 조기 종료(`patience`, 기본 100)도 같은 fitness로 판단한다 [3][8]. ⚠️ 출처 간 불일치: 학습이 아닌 단독 검증에서 COCO·LVIS 데이터일 때만 `0.9×mAP50-95 + 0.1×mAP50` 식을 쓰는 코드가 따로 있다 [16]. 커스텀 데이터 학습에는 해당하지 않는다.
6. 학습 폴더에 남는 산출물과 용도는 다음과 같다.
   - `args.yaml`: 학습 설정 전체 [3]
   - `labels.jpg`: 학습 라벨의 클래스·박스 분포 [17][18]
   - `train_batch*.jpg`: 증강 뒤 라벨이 맞는지 **학습 전에** 확인 [18][19]
   - `confusion_matrix(_normalized).png`: 어느 클래스끼리 헷갈리는지 [1][20][21]
   - `BoxPR/F1/P/R_curve.png`: 임계값에 따른 정밀도·재현율 균형 [1][20]
   - `val_batch*_labels/pred.jpg`: 정답과 예측을 눈으로 비교 [20]

**우리 상황 적용**

- 학습마다 `results.csv`·`results.png`·`args.yaml`·혼동행렬·PR/F1 곡선·`labels.jpg`·`train_batch*.jpg` 를 통째로 보관한다. 이것들은 `plots=True`(기본값)일 때 생긴다 [8].
- 버튼 5종은 색으로 클래스가 갈리므로 `cls_loss` 곡선과 정규화 혼동행렬에서 색끼리 헷갈리는지를 먼저 본다. 작은 물체이므로 박스 손실은 따로 보고, `best.pt` 가 mAP50-95 하나로 골라진다는 점을 전제로 둔다.
- 검출기가 YOLO26이면 세 번째 손실 열 이름이 `l1_loss` 로 바뀌므로, 곡선을 읽는 도구가 열 이름을 하드코딩하지 않게 한다 [4][6].

## 7. 검증 — mAP·정밀도/재현율·임계값·홀드아웃

> **세 줄 요약**
> 1. mAP 는 모든 신뢰도를 훑은 값이라 **운용 임계에서의 성능이 아니다.**
> 2. 운용 임계는 val 에서 오경보 · 놓침 비용을 보고 정하고, **test 는 마지막에 한 번만** 쓴다.
> 3. 데이터셋 점수 ≠ 실제 영상 성능 — **Hailo 변환본으로 영상 시험을 따로** 한다.

**요점**

1. **정의** — 정밀도(precision)=검출한 것 중 맞은 비율, 재현율(recall)=실제 물체 중 찾아낸 비율, 박스 겹침(IoU)이 임계 이상이어야 정답(TP)으로 센다 [1][3]. 클래스마다 정밀도-재현율 곡선 아래 면적이 AP, 클래스 평균이 mAP다 [3]. **mAP50**=IoU 0.5 한 점, **mAP50-95**=IoU 0.50~0.95(0.05 간격 10개) 평균 [1][2][3]. Ultralytics 는 best.pt 를 고를 때 mAP50-95 만 본다(가중치 P·R·mAP50 = 0) [6].
2. **검증 `conf` 기본값은 운용값이 아니다** — `val` 기본 0.001, `predict` 기본 0.25 [4][5]. 유지보수자 답변: mAP 는 모든 신뢰도 구간을 훑는 지표라 conf 를 올리면 값이 왜곡되고, 0.25 는 예측용 일반값이다 [7]. YOLOv5 는 0.001 초과 시 "invalid results" 경고를 낸다 [17]. → **mAP 는 운용점 하나의 성능이 아니다.**
3. **val 이 출력하는 P·R 은 "F1 최대 신뢰도" 한 점의 값**이다(전 클래스 평균 F1 곡선을 평활한 뒤 최댓값 위치) [6][8]. Roboflow 도 신뢰도 전 구간 P·R·F1 곡선과 F1 최적 임계값을 클래스별로 준다 [9]. 다만 F1 은 정밀도·재현율을 같은 무게로 두는 선택일 뿐이고, 운용 임계는 오경보·놓침 비용으로 정하는 **응용 판단**이며 **학습에 쓴 데이터로 조정하면 과적합**된다 [10].
4. **`iou` 인자 두 가지를 구분** — `val`/`predict` 의 `iou`(기본 0.7)는 **중복 박스 제거(NMS) 임계**다 [4][5]. mAP50 의 0.5 는 **정답 매칭 임계**로 별개다 [1][2]. ⚠️ 출처 간 불일치: YOLOv5 이슈에서 유지보수자가 `--iou-thres` 를 "TP 판정 IoU(기본 0.5)"라 답했으나 [8], 같은 저장소 val.py 기본값은 0.6 이고 [17] Ultralytics 문서·설정은 NMS 임계로 명시한다 [4][5] — 문서·코드를 따른다.
5. **홀드아웃(test) 운용** — 학습→val 로 설정 조정→**마지막에 한 번 test** 로 일반화 성능을 잰다; test 로 설정을 고르면 test 정보가 모델에 새어 지표가 더는 일반화를 말하지 못한다 [11]. 같은 출처(환자 등)에서 나온 **서로 의존하는 표본은 한 그룹으로 묶어 학습·평가에 동시에 들어가지 않게** 나눠야 한다 [11]. Ultralytics 는 데이터 YAML 에 `test:` 를 두고 `model.val(data=..., split="test")` 로 평가한다 [4][12]; Roboflow 권장 시작 비율은 train/valid/test 70/20/10 [13].
6. **클래스별 AP·혼동행렬** — 클래스별 AP 는 약한 클래스를 짚어 데이터 보강 대상을 알려준다 [1]. 탐지용 혼동행렬은 **배경 행·열이 하나 더(nc+1)** 있어 오경보(배경→클래스)와 놓침(클래스→배경)이 따로 보이고 [6], 자주 헷갈리는 클래스 쌍을 드러낸다 [9]. 혼동행렬 클래스의 기본 임계는 conf 0.25·IoU 0.45 로, 전 구간을 훑는 mAP 와 기준이 다르다 [6].
7. **데이터셋 지표 ≠ 실사용 영상 성능** — Ultralytics 는 "라벨 데이터셋 평가"와 "배포 조건과 닮은 새 데이터 시험"을 구분하고, 통제된 데이터셋은 움직임·조명 변화·가림 문제를 놓칠 수 있다고 한다 [12]. 영상 탐지는 모션 블러·초점 흐림·드문 자세로 프레임 단위 정확도가 떨어지고 [15], 사람 눈엔 거의 같은 인접 프레임에서도 분류 정확도 중앙값이 두 데이터셋에서 16·10 떨어졌다(분류기 대상 연구) [14]. INT8 양자화도 정확도를 떨어뜨릴 수 있어 변환 후 재평가가 필요하다 [16].

**우리 상황 적용**

- test 는 **촬영 세션(영상) 단위로 통째 분리**하고 수동 라벨만 쓴다(인접 프레임 = 한 그룹 [11]). 운용 conf 는 val 곡선에서 오경보/놓침 비용으로 정한 뒤 **고정해 test 에서 한 번** 확인한다 [10][11].
- 보고는 mAP50-95·클래스별 AP·배경 포함 혼동행렬 + **운용 conf 에서의 P·R**(val 기본 출력 P·R 은 F1 최대점이라 운용값 아님 [6]). 작은 버튼은 mAP50 과 mAP50-95 차이를 함께 본다.
- 데이터셋 지표는 관문일 뿐, **Hailo INT8 변환본으로 영상 스트림 E2E 시험을 별도로** 한다 [12][15][16].

## 8. 배포 — Hailo 양자화·지원 모델·캘리브레이션

> **세 줄 요약**
> 1. Hailo-8 은 Model Zoo v2.x · DFC 3.x 에서 **YOLOv8 · 11 · 26(n·s·m)** 을 모두 지원한다.
> 2. 변환은 **GPU + 캘리브레이션 사진 1024장 이상**이어야 최적화 수준이 낮아지지 않는다.
> 3. 양자화 손실은 **v8 이 가장 작고**, 세로 입력으로 직접 내보낼 수 있다.

**요점**

1. **지원 모델** — Hailo-8/8L 은 Model Zoo **v2.x + DFC 3.x** 계열에서만 지원된다. master(v5.x)는 Hailo-10/15 전용이다 [1][2]. v2.19.0 의 Hailo-8 검출 목록에는 **YOLOv8 n~x, YOLO11 n~x, YOLO26 n·s·m** 이 640×640 입력으로 올라 있다 [3]. YOLO26 검출 모델(n·s·m)은 v2.18.0 에서 추가됐다 [4][5]. Ultralytics 문서도 Hailo-8 검출 대상으로 v8·11·26 을 적는다 [6].
2. **변환 흐름** — 순서는 파싱(ONNX→Hailo 내부 표현) → 최적화(부동소수→정수로 양자화해 HAR 생성) → 컴파일(HEF 생성)이다. 사용자 캘리브레이션 이미지는 `--calib-path` 로 넣는다 [7][8].
3. **캘리브레이션 수·GPU** — 권장은 **1024장 이상, GPU 머신에서** 최적화하는 것이다 [9][6]. GPU 가 없거나 이미지가 1024장보다 적으면 DFC 가 경고를 내고 optimization_level 을 **0**(정확도 보정·압축 없음)으로 낮춘다. Hailo 직원 답변과 사용자 로그에서 확인했다 [10][11]. Ultralytics 내보내기 코드는 `optimization_level=2` 와 finetune(양자화 후 미세조정)을 스크립트에 고정한다 [12].
   ⚠️ 출처 간 불일치: Ultralytics 문서는 「GPU 없이 CPU 로도 된다, 느릴 뿐」이라고 쓴다 [6]. DFC 경고는 「GPU 없으면 수준 0」이다 [10]. 스크립트에 수준 2를 고정했을 때 GPU 없이도 그 수준이 유지되는지는 ⚠️ 미확인이다(찾아본 곳: Ultralytics 문서·exporter.py, Hailo 커뮤니티 #224·#18194. DFC 사용자 가이드는 로그인이 필요해 열람 불가).
4. **ONNX 내보내기 조건** — Model Zoo 의 YOLOv8 재학습 문서는 `imgsz=640 format=onnx opset=11` 로 내보낸다. 해상도를 바꿨다면 yaml 의 `preprocessing.input_shape` 도 같이 고치라고 한다 [13]. Ultralytics 의 Hailo 경로도 opset 을 11 로 고정하고, HEF 는 고정된 imgsz 로 컴파일된다 [12][6].
5. **NMS 처리 위치** — YOLOv8/11 은 HailoRT 의 YOLO NMS 가 파이프라인에 포함된다. Ultralytics 스크립트는 `nms_postprocess(meta_arch=yolov8, engine=cpu)` 로 **호스트 CPU** 에서 돌린다 [6][12]. Model Zoo yolov8 설정도 NMS 를 켜 둔다(`nms: true`, IoU 0.7) [14]. YOLO26 은 원출력 텐서로 컴파일하고, 호스트에서 NMS 를 하거나 NMS 없는 출력(`nms=False`)을 쓴다 [6].
6. **양자화 전후 정확도·손실 줄이기** — Hailo-8 표준 모델의 mAP 하락 폭은 YOLOv8·YOLO11 은 0.5~1.5, YOLO26 은 1.6~2.2 수준이다 [3]. Ultralytics 는 INT8 에서 mAP50 유지율을 v8n 약 100%, 11n 약 96%, 26n 약 93% 로 보고한다. 원인은 어텐션 블록이 INT8 에 민감한 구조라서다 [6]. Hailo 직원 권고는 세 가지다. ①캘리브레이션 데이터는 **사용 현장을 대표하는 다양한 이미지**로 한다. ②원본·양자화 모델을 **정답 기준 지표로 함께** 비교한다. ③필요하면 HAR 로 QAT(양자화 인지 학습)를 한다 [15]. 문헌상으로도 8비트는 대개 PTQ(학습 후 양자화)만으로 부동소수 정확도에 근접하고, QAT 는 그보다 낮은 비트용이다 [16]. 손실이 크면 층별로 쪼개 원인 층을 찾는 분석이 유효하다(Hailo 저자 논문) [17].
7. **직사각형 입력** — 지원된다. Hailo 모더레이터는 재학습 없이 `imgsz=[640,480]` 로 **ONNX 를 다시 내보내라**고 답했다 [18]. Ultralytics 도 imgsz 에 (높이, 너비) 튜플을 받는다 [19]. Hailo 경로는 NMS 설정의 `image_dims` 와 캘리브레이션 입력 모양에 imgsz 를 그대로 쓴다 [12]. 다만 Model Zoo 공개 모델은 전부 640×640 이다 [3]. 해상도를 바꾸면 yaml `input_shape` 수정 [13], 출력 노드(`--end-node-names`) 명시 [20], 후처리의 좌표 정규화 차원 확인이 따로 필요하다.

**우리 상황 적용**

- Hailo-8 은 DFC 3.x + Model Zoo v2.x 계열을 유지해야 한다(v5.x 는 Hailo-8 불가). 이 조합에서 YOLOv8·YOLO11·YOLO26(n·s·m) 모두 선택지다. 작은 버튼 검출이 목적이므로 양자화 손실이 가장 작다고 보고된 v8 을 기준선으로 두는 근거가 있다 [3][6].
- 캘리브레이션은 **실제 1인칭 촬영 프레임 1024장 이상**을 **GPU 환경**(예: Colab T4)에서 쓴다. 과거의 「GPU 없음 → 최적화 수준 저하」는 공식 경고 동작과 일치한다 [10][11].
- 480×640 세로 프레임은 `imgsz=(640,480)` 로 내보내면 정사각 패딩 없이 컴파일할 수 있다 [18][19]. 단, 학습 해상도·yaml·후처리 차원을 같이 맞춰야 한다.

> 대조한 가이드: Ultralytics Guides 색인(https://docs.ultralytics.com/guides/) 중 *Defining Project Goals* · *Steps of a CV Project* · *Data Collection and Annotation* · *Model Training Tips* · *Hyperparameter Tuning* · *K-Fold Cross Validation* · *Knowledge Distillation* · *Model Testing* · *YOLO Common Issues* · *Model Deployment Best Practices* · *Model Monitoring & Maintenance* · *SAHI Tiled Inference* · Modes *Track* / Roboflow Docs *Dataset Health Check* · Roboflow 블로그 *How to Label Image Data* / Hailo Community 공식 답변(양자화 정확도 저하). ⚠️ Hailo DFC 사용자 가이드 원문 목차는 로그인 필요로 미대조(8절 담당 범위).

### 누락 점검
- **목표 정의(SMART)** — 문제 서술·경계·측정 가능한 목표를 먼저 정하고 그에 맞춰 과제·지표를 고른다. 8절에는 「무엇을 달성해야 성공인가」가 없다 [https://docs.ultralytics.com/guides/defining-project-goals/] (관련 작업: ③평가 체계)
  - 우리 적용: 「mAP」가 아니라 「누르려는 버튼의 클래스를 맞히는가」 같은 판정 목표를 먼저 문장으로 정한다.
- **평가(evaluation) ≠ 테스트(testing)** — 평가는 라벨 데이터 지표, 테스트는 「배포와 닮은 조건(움직임·어두움·부분 가림)」에서 학습 행동이 유지되는지 확인. 누출 원인으로 카메라 차이·타임스탬프·공간 불균형을 명시 [https://docs.ultralytics.com/guides/model-testing/] (관련 작업: ③평가 체계)
  - 우리 적용: 7절 홀드아웃과 별도로 「시연 조건 테스트 세트」를 둔다.
- **모니터링·드리프트·재학습** — 입력 분포가 바뀌면(data drift) 성능이 떨어지며, 성능 하락·드리프트 감지 시 재학습 후 별도 테스트 세트로 재검증 [https://docs.ultralytics.com/guides/model-monitoring-and-maintenance/] (관련 작업: ③평가 체계 / ④학습·검증)
  - 우리 적용: 시연장 조명·콘솔이 바뀌면 재학습 조건으로 본다.
- **K-Fold 교차검증** — 작고·잡음 많고·변동 큰 데이터에서 가장 가치 있음. 근접 중복·같은 영상 시퀀스는 같은 fold에 묶어야 누출이 없다 [https://docs.ultralytics.com/guides/kfold-cross-validation/] (관련 작업: ③평가 체계)
  - 우리 적용: 세션(촬영 영상) 단위로 fold 를 나눈다.
- **하이퍼파라미터 자동 탐색 `model.tune()`** — 유전 알고리즘, 기본 300회 반복·28개 파라미터(HSV 증강 포함), 적합도=mAP50-95. 「짧은·소규모 튜닝 결과는 실제 학습에 최적이 아닌 경우가 많다」 [https://docs.ultralytics.com/guides/hyperparameter-tuning/] (관련 작업: ④학습·검증)
  - 우리 적용: T4 시간 제약상 전체 탐색은 비현실적 — 탐색 공간을 좁혀서만 고려.
- **지식 증류(knowledge distillation)** — `distill_model`로 큰 교사 모델의 특징을 작은 학생 모델에 전달, 추론 비용 증가 없이 정확도 개선(동일 YOLO 세대 필요, 검출만 실험 검증) [https://docs.ultralytics.com/guides/knowledge-distillation/] (관련 작업: ④학습·검증)
  - 우리 적용: Hailo 에 올릴 작은 모델의 정확도 보강 수단. 단 Hailo 지원 세대와 맞는지 8절과 대조 필요.
- **라벨링 지침 작성·작업자 간 일치도** — 예시·그림이 있는 지침, 정기 갱신, 작업자 간 일치(inter-annotator agreement)로 지침 명확성 확인, 오류 발견 시 지침부터 고친다 [https://docs.ultralytics.com/guides/data-collection-and-annotation/] (관련 작업: ②데이터 확보)
  - 우리 적용: 「박스 규칙 미전달」 사고의 직접 대응 — 규칙을 그림 예시 문서로 만들고 표본 교차 검수.
- **배포 전처리 일치** — 학습 때 전처리(크기 조정·정규화·변환)를 배포에서도 똑같이 적용하고, 통제된 데이터로 학습 단계 결과와 먼저 비교 [https://docs.ultralytics.com/guides/model-deployment-practices/] (관련 작업: ③평가 체계)
  - 우리 적용: 회전(640×480→480×640)·색 채널 순서가 학습 이미지와 파이 런타임에서 같은지 확인 항목으로.
- **시간축 안정화(tracking)** — 추적기는 칼만 필터로 일시적 검출 누락을 메우고, `track_buffer`가 클수록 긴 가림을 견딘다 [https://docs.ultralytics.com/modes/track/] (관련 작업: ④학습·검증)
  - 우리 적용: 한두 프레임 깜빡임은 모델 재학습이 아니라 시간축 처리로 흡수 가능한지 분리해 본다.
- **주석 위치 편향 점검(Annotation Heatmap)** — 주석이 이미지 특정 위치에 몰리면 「그 위치에서만 찾도록」 과적합될 수 있다; null(무객체) 이미지도 점검 [https://docs.roboflow.com/datasets/versions/dataset-health-check] (관련 작업: ②데이터 확보)
  - 우리 적용: 모조 콘솔의 고정 배치 → 시연 콘솔 EMO 위치 차이 문제를 학습 전에 히트맵으로 확인.
- **SAHI 타일 추론** — 이미지를 조각내 추론 후 병합, 작은 물체에 유리하나 분할·병합 단계만큼 지연 증가 [https://docs.ultralytics.com/guides/sahi-tiled-inference/] (관련 작업: ④학습·검증)
  - 우리 적용: 실시간·Hailo 조건에선 부적합 가능성 높음 — 「기각 근거」로 기록할 대안.

- (관점 ②) **작은 물체: 픽셀 수가 적어 특징이 부족하고 깊은 층에서 위치 정보 소실; 가림·배경 간섭·클래스 불균형 동반** [https://arxiv.org/abs/2503.20516] (관련 작업: ④학습·검증)
- (관점 ②) **이미지 손상(블러·잡음·밝기)에서 표준 검출기 성능이 원래의 30~60%까지 하락; 스타일화 학습이 강건성 개선** [https://arxiv.org/abs/1907.07484] (관련 작업: ③평가 체계)
  - 우리 적용: 머리 흔들림 블러는 8절 어디에도 없음 — 블러 조건별 테스트 세트를 따로 두는 근거.
- (관점 ②) **모션 블러가 YOLO 검출을 떨어뜨리고 디블러링으로 회복됨을 검출 과제로 평가; 합성 블러 생성법 제공** [https://arxiv.org/abs/1711.07064] (관련 작업: ②데이터 확보)
  - 우리 적용: 합성 블러 증강 후보(단, 실촬영 블러로 검증).
- (관점 ②) **색상(hue) 이동만으로 CNN 분류가 틀린다(예: 색 바뀐 곰→테니스공)** — ImageNet-C 류가 다루지 않은 색 변화 강건성을 별도 연구 [https://doi.org/10.2352/EI.2022.34.15.COLOR-156] (관련 작업: ④학습·검증)
  - 우리 적용: 「색이 곧 클래스」인 우리는 색 강건성과 색 구별력이 **서로 반대 방향** — hue 증강의 허용 폭을 조명 실측 범위로 제한해야 함(4절과 연결). ⚠️ 본문 수치는 1쪽만 확인.
- (관점 ②) **하드 예제 채굴(OHEM)** — 검출 데이터는 쉬운 예제가 압도적이고 어려운 예제가 적다; 어려운 예제를 자동 선택해 학습 효율·성능 개선 [https://arxiv.org/abs/1604.03540] (관련 작업: ④학습·검증)
  - 우리 적용: 손톱·키보드 같은 「어려운 음성」을 의도적으로 모으는 이론 근거.
- (관점 ②) **개방 집합(open-set) 오검출** — 학습에 없던 물체가 알려진 클래스로 오검출됨; Dropout Sampling 불확실도로 오검출 감소 [https://arxiv.org/abs/1710.06677] (관련 작업: ③평가 체계)
  - 우리 적용: 키보드·벽·손톱은 「학습 안 한 물체」 문제 — 음성 데이터만으로 다 막을 수 없음을 전제로 평가.
- (관점 ②) **신뢰도 과신(calibration)** — 현대 신경망은 예측 확률이 실제 정답률과 어긋나며 temperature scaling 으로 보정 [https://arxiv.org/abs/1706.04599] (관련 작업: ③평가 체계)
  - 우리 적용: conf 임계를 「확률」로 해석하지 말 것 — 임계는 실측 곡선으로 정한다(7절 보강).
- (관점 ②) **모조→실물 격차(reality gap)와 도메인 무작위화** — 렌더링 변화(질감 등)를 충분히 주면 합성 학습 모델이 실환경·방해물·부분 가림에 전이 [https://arxiv.org/abs/1703.06907] (관련 작업: ②데이터 확보)
  - 우리 적용: 모조 콘솔→시연 콘솔 배치 차이를 「배치 다양화」로 대응하는 이론적 근거.
- (관점 ②) **Random Erasing** — 임의 사각 영역을 지워 가림 수준을 다양화, 검출에서도 일관 이득 [https://arxiv.org/abs/1708.04896] (관련 작업: ②데이터 확보)
- (관점 ②) **INT8 정수 양자화는 대부분 FP 대비 1% 이내 유지, 단 MobileNet 등 일부 구조는 어렵다** [https://arxiv.org/abs/2004.09602] (관련 작업: ③평가 체계)
  - 우리 적용: 구조에 따라 저하 폭이 다름 — 모델 선택 시 양자화 후 지표로 비교(8절 보강).
- (관점 ②) **라벨 규칙: 가려진 물체는 「완전히 보이는 것처럼」 박스, 모든 인스턴스 라벨, 박스는 타이트하되 물체를 자르지 않음, 구체적 클래스명** (Roboflow 블로그) [https://blog.roboflow.com/tips-for-how-to-label-images/] (관련 작업: ②데이터 확보)
  - 우리 적용: 손이 버튼을 반쯤 가린 프레임의 박스 규칙을 이 원칙으로 먼저 정하고 문서화. ⚠️ Roboflow 공식 Docs 라벨링 가이드는 404(이동됨).

### ⚠️ 합칠 때 확인한 출처 간 불일치·판단

- **가려진 물체 박스 규칙이 출처마다 반대다** — PASCAL VOC 지침은 「**보이는 부분만**」(2절 요점 7), Roboflow 블로그는 「**완전히 보이는 것처럼 전체 범위**」(위 관점 ②). 공식 문서 기준 결론 없음 → ②데이터 확보에서 한쪽으로 정해 라벨 지침에 문서화한다(관련 작업: ②데이터 확보)
- **「hue 증강 폭을 조명 실측 범위로 제한」은 문헌 결론이 아니라 조사원 판단이다** — 근거 문헌은 분류 과제 연구뿐. 4절 요점 3·「출처 간 불일치」와 함께 ④에서 실험으로 정한다(관련 작업: ④학습·검증)

### 절별 조사 중 발견 (각 절 조사원이 올린 후보 — 절 번호별)

#### 절1 후보
- **배경(음성) 이미지는 빈 `.txt` 라벨 파일과 함께 넣기를 권장**. 물체가 섞인 이미지의 배경은 따로 할 일이 없고 「라벨 있는 것/없는 것의 대비」로 배운다 — 유지보수자 답변 [https://github.com/ultralytics/ultralytics/issues/8889] (관련 작업: ②데이터 확보)
- **같은 대상이 반복해 오검출되면 학습 때 임시 별도 클래스로 두고 추론 때 무시·병합하는 방법** — 유지보수자 제안(손톱 오검출 대응 후보, 효과 미검증) [https://github.com/ultralytics/ultralytics/issues/8889] (관련 작업: ②데이터 확보 / ④학습·검증)
- **클래스 불균형 가중 옵션 `cls_pw`**(0=끔, 1=빈도 역수) · 다른 데이터셋에서 이어 학습할 때 클래스 이름으로 헤드 행을 맞추는 `cls_remap: True` 가 현행 기본 설정에 있다 [https://github.com/ultralytics/ultralytics/blob/main/ultralytics/cfg/default.yaml] (관련 작업: ④학습·검증)
- **정답 배정 코드(TAL·STAL)가 2026-06~09 사이 여러 번 바뀜** → 학습 재현을 위해 ultralytics 버전을 고정·기록해야 한다 [https://github.com/ultralytics/ultralytics/commits/main/ultralytics/utils/tal.py] (관련 작업: ④학습·검증)
- **YOLO26 의 「물체당 하나」 헤드는 학습 중 백본에 기울기를 보내지 않는다**(`x.detach()`) — 백본은 「여러 개 배정」 헤드로만 학습 [https://github.com/ultralytics/ultralytics/blob/main/ultralytics/nn/modules/head.py] (관련 작업: ④학습·검증)
- **원조 YOLOv8 레시피: 마지막 10 에폭은 모자이크 증강 끔**(OpenMMLab 재구현 문서 기준 — 현행 기본값은 ④에서 `close_mosaic` 로 재확인) [https://github.com/open-mmlab/mmyolo/blob/main/docs/en/recommended_topics/algorithm_descriptions/yolov8_description.md] (관련 작업: ④학습·검증)
- 유저 보고(유지보수자 아님): v8 손실 구성이 AP 는 올렸지만 실사용에서 놓침(FN)이 늘었다는 경험담 — 근거로는 약함, 평가 시 놓침을 따로 볼 이유 [https://github.com/ultralytics/ultralytics/issues/3039] (관련 작업: ③평가 체계)

#### 절2 후보
- 분할은 증강 전에 하고 증강은 train 에만 — 증강을 먼저 하면 val/test 정보가 학습에 새어 점수가 부풀려짐 [https://docs.ultralytics.com/guides/preprocessing_annotated_data/] (관련 작업: ④학습·검증)
- 학습 시작 시 `train_batch*.jpg` 를 열어 라벨이 올바르게 보이는지 확인 [https://docs.ultralytics.com/yolov5/tutorials/tips_for_best_training_results/] (관련 작업: ④학습·검증)
- 이미지마다 물체 개수가 다양하도록 구성 권고(Health Check) [https://docs.roboflow.com/datasets/versions/dataset-health-check] (관련 작업: ②데이터 확보)
- Roboflow 버전은 생성 시점에 고정(frozen) — 재현·비교용으로 버전을 남길 것 [https://docs.roboflow.com/datasets/versions/dataset-versions/create-a-dataset-version] (관련 작업: ③평가 체계)
- Roboflow 리밸런스 옵션에 「업로드 배치/라벨 작업 단위로 섞기」가 있음 — 영상 단위 분할 구현 수단 후보(누출 방지 효과는 문서에 명시 없음) [같은 URL] (관련 작업: ③평가 체계)
- VOC 는 작음·흐림·심한 가림을 'difficult' 로 표시해 평가에서 구분 [https://www.robots.ox.ac.uk/~vgg/projects/pascal/VOC/voc2006/guidelines.html] (관련 작업: ③평가 체계)
- 흐림·일부 가려짐·경계 사례를 일부러 포함(블로그) [https://blog.roboflow.com/how-much-training-data/] (관련 작업: ②데이터 확보)

#### 절3 후보
- 증강 `scale` 은 "카메라와의 거리가 다른 물체를 흉내 낸다" — 먼 공구 미검출 대응 후보 [https://docs.ultralytics.com/usage/cfg/] (관련 작업: ④학습·검증)
- 작은 데이터셋에서는 강한 증강이 오히려 해가 될 수 있다 → `mosaic=0.5` 또는 `0.0` 시도 권고 [https://docs.ultralytics.com/guides/finetuning-guide/] (관련 작업: ④학습·검증)
- `close_mosaic` 기본 10 — 마지막 N 에폭은 모자이크를 끈다. `multi_scale` 은 배치마다 imgsz 자체를 바꾼다 [https://github.com/ultralytics/ultralytics/blob/main/ultralytics/cfg/default.yaml] (관련 작업: ④학습·검증)
- 검증은 기본 `rect`·`scaleup=False` 이고 배포(Hailo, 640 고정·여백 전체)와 전처리가 다르다 → 평가는 배포와 같은 입력 조건으로 따로 재는 것을 검토 [validator.py·dataset.py] (관련 작업: ③평가 체계)
- Hailo Model Zoo 재학습 시 입력 크기를 바꾸면 `preprocessing.input_shape` 도 고쳐야 한다. 기본 export 는 `imgsz=640` [https://github.com/hailo-ai/hailo_model_zoo/blob/master/training/yolov8/README.rst] (관련 작업: ④학습·검증)
- Roboflow 타일링은 작은 물체에 유익하고 타일 크기를 모델 입력(예: 640×640)에 맞추라고 권한다 [https://docs.roboflow.com/datasets/versions/dataset-versions/image-preprocessing] (관련 작업: ②데이터 확보)

#### 절4 후보
- 기하 증강(회전·이동·스케일 등)은 카메라 시점이 배포 후 일정하면 생략 가능 — 1인칭 착용은 시점이 흔들리므로 해당 여부 판단 필요 [https://raw.githubusercontent.com/ultralytics/ultralytics/main/docs/en/guides/yolo-data-augmentation.md] (관련 작업: ④학습·검증)
- Ultralytics 유지보수자는 색 과의존 오검출 대응으로 "색 비슷한 비대상 물체·다양한 배경을 학습에 포함, 오검출 물체를 negative(배경)로 추가"를 권함 — 버튼과 비슷한 색의 콘솔 외 물체 데이터 [https://github.com/orgs/ultralytics/discussions/8722] (관련 작업: ②데이터 확보)
- Roboflow 증강은 Train 분할에만 적용 — 분할(split)을 증강 전에 확정해야 증강 사본이 검증·테스트로 새지 않음 [https://docs.roboflow.com/datasets/versions/dataset-versions/image-augmentation] (관련 작업: ②데이터 확보 / ③평가 체계)
- 증강 효과는 클래스별로 크게 달라 평균 지표만으로 판단하면 특정 클래스 하락을 놓침 → 클래스별 지표 필요 [https://arxiv.org/abs/2401.01764] (관련 작업: ③평가 체계)
- Albumentations: 증강 없는 기준선부터 시작해 학습 손실이 정체될 때까지 강도를 올린 뒤 약간 되돌리는 보정 절차 제안 [https://albumentations.ai/docs/3-basic-usage/choosing-augmentations/] (관련 작업: ④학습·검증)
- `bgr`(RGB↔BGR 채널 교환) 증강은 기본 0 — 색=클래스 과제에서 켜면 색이 뒤바뀌므로 유지 필요, 파이프라인의 채널 순서 불일치(카메라 → Hailo 입력) 점검 항목 [https://raw.githubusercontent.com/ultralytics/ultralytics/main/docs/en/guides/yolo-data-augmentation.md] (관련 작업: ④학습·검증)

#### 절5 후보
- 라벨 일관성: "모든 이미지의 모든 클래스 인스턴스를 전부 라벨링해야 한다. 부분 라벨링은 안 된다." 박스는 물체에 딱 맞게 [https://docs.ultralytics.com/yolov5/tutorials/tips_for_best_training_results/] (관련 작업: ②데이터 확보)
- 데이터 규모 권고: 클래스당 이미지 ≥1500장, 인스턴스 ≥10000개 [https://docs.ultralytics.com/yolov5/tutorials/tips_for_best_training_results/] (관련 작업: ②데이터 확보)
- 작은 물체는 원본 해상도(640) 이상으로 학습하라는 권고 [https://docs.ultralytics.com/yolov5/tutorials/tips_for_best_training_results/] (관련 작업: ④학습·검증)
- 매우 작은 데이터셋이면 `mosaic`를 0.5 또는 0.0으로 줄이는 것을 고려. 기본은 마지막 10 에폭에 모자이크를 끔(`close_mosaic=10`) [https://docs.ultralytics.com/guides/finetuning-guide/ · default.yaml] (관련 작업: ④학습·검증)
- 파국적 망각(catastrophic forgetting, 새로 학습하면서 이전에 배운 것을 잊는 현상) 방지의 "유일하게 신뢰할 수 있는 방법"은 원래 클래스 예시를 섞어 학습하는 것. 공개 데이터셋+자체 촬영을 섞는 공구 학습에 해당 [https://docs.ultralytics.com/guides/finetuning-guide/] (관련 작업: ②데이터 확보 / ④학습·검증)
- `time` 인자(최대 학습 시간, 설정하면 epochs보다 우선)는 Colab 시간 제한에 대응할 때 쓸 수 있음 [default.yaml] (관련 작업: ④학습·검증)
- YOLO26은 작은 물체용 라벨 할당 STAL(Small-Target-Aware Label Assignment)과 ProgLoss를 도입 [https://docs.ultralytics.com/models/yolo26/] (관련 작업: ④학습·검증)
- Hailo-8 공개 표에서 양자화 후 mAP("Hardware mAP")가 float mAP보다 낮음. INT8 배포 뒤 재평가가 필요하다는 근거 [https://github.com/hailo-ai/hailo_model_zoo/blob/master/docs/public_models/HAILO8/HAILO8_object_detection.rst] (관련 작업: ③평가 체계)
- 유지보수자: 배경 이미지는 위치를 맞출 필요가 없어 서로 비슷한 프레임이어도 과적합 위험이 상대적으로 낮음(단, 중복 제거·증강 권고) [https://github.com/ultralytics/ultralytics/issues/1369] (관련 작업: ②데이터 확보)
- 편향 방지: 소수 클래스 오버샘플링, 공개+자체 데이터 혼합 권고 [https://docs.ultralytics.com/guides/data-collection-and-annotation/] (관련 작업: ②데이터 확보)

#### 절6 후보
- YOLOv5 학습 팁은 기준선으로 "클래스당 이미지 ≥1,500장·인스턴스 ≥10,000개"를 권장하고, **먼저 기본 설정으로 학습**하라고 한다(YOLOv5 문서라 현행 YOLO에 그대로 맞는지는 ⚠️) [https://docs.ultralytics.com/yolov5/tutorials/tips-for-best-training-results] (관련 작업: ②데이터 확보 / ④학습·검증)
- 사용자 보고: `best.pt` 가 실제 최고 fitness 에폭보다 한 에폭 앞의 가중치로 저장된다는 이슈가 있다(v8.4.8, 유지보수자 답변 없이 stale로 닫힘 — 1차 확인 아님 ⚠️) [https://github.com/ultralytics/ultralytics/issues/23464] (관련 작업: ④학습·검증)
- 체크포인트의 가중치는 EMA(`"model": None`, `"ema": ema`)이고, 학습이 끝나면 `best.pt` 로 최종 평가한다(`final_eval`) [https://github.com/ultralytics/ultralytics/blob/main/ultralytics/engine/trainer.py] (관련 작업: ③평가 체계)
- 트레이너에 클래스 불균형용 `class_weights` 훅(`set_class_weights`)이 생겼다. 검출 손실에서 BCE에 곱해진다 [https://github.com/ultralytics/ultralytics/blob/main/ultralytics/utils/loss.py] (관련 작업: ④학습·검증)
- 사용자 fitness 함수를 `train()` 인자로 받게 해 달라는 기능 요청이 열려 있다. 현재 방법은 `validate()` 재정의다 [https://github.com/ultralytics/ultralytics/issues/23870][https://docs.ultralytics.com/guides/custom-trainer] (관련 작업: ③평가 체계)
- 성능 지표 가이드의 진단 기준: 정밀도가 낮으면 없는 물체를 많이 검출하고, 재현율이 낮으면 실제 물체를 놓친다 [https://docs.ultralytics.com/guides/yolo-performance-metrics/] (관련 작업: ③평가 체계)

#### 절7 후보
- Ultralytics best.pt 선택 기준(fitness)은 mAP50-95 100% 가중 — 운용 목표(특정 conf 에서의 재현율)와 다를 수 있음 [https://github.com/ultralytics/ultralytics/blob/main/ultralytics/utils/metrics.py] (관련 작업: ④학습·검증)
- COCO 면적 구분: small < 32², medium 32²~96², large > 96² 픽셀 — 작은 버튼이 small 에 해당하는지 확인 가치 [https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py] (관련 작업: ③평가 체계)
- `model.val()` 결과에 이미지별 P·R·F1·TP·FP·FN(`results.box.image_metrics`) 제공 — 세션별 편차 확인에 활용 가능 [https://docs.ultralytics.com/modes/val/] (관련 작업: ③평가 체계)
- 데이터 누출 원인 예시: 카메라 차이·타임스탬프/오버레이·클래스별 박스 위치 편중·라벨 불일치, 분할은 전처리 전에 [https://docs.ultralytics.com/guides/model-testing/] (관련 작업: ②데이터 확보)
- Roboflow 분할 재배정 옵션 "업로드 배치/라벨링 작업 단위 셔플" — 세션 단위 분리에 쓸 수 있는지 검토 [https://docs.roboflow.com/datasets/versions/dataset-versions/create-a-dataset-version] (관련 작업: ②데이터 확보)
- Hailo Model Zoo: 최적화(양자화)는 GPU 머신·최소 1024장 데이터셋 권장, full precision vs emulator 비교 평가 절차 [https://github.com/hailo-ai/hailo_model_zoo/blob/master/docs/OPTIMIZATION.rst] (관련 작업: ④학습·검증)
- Ultralytics 작은 물체: 큰 이미지를 타일로 나눠 해상도 보존 [https://docs.ultralytics.com/guides/model-evaluation-insights/] (관련 작업: ④학습·검증)
