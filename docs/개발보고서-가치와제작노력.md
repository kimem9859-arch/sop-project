## ② 신뢰성 — 가장 강한 축

**"안전 기능이 조용히 실패하지 않게" 만든 장치가 코드에 실제로 있다.**

| 장치 | 내용 | 코드 |
| --- | --- | --- |
| **EMO NC 배선** | 비상정지를 Normally Closed 로 결선 — **단선되면 비상으로 읽힌다.** 단선 상태로 부팅하면 즉시 BLOCK | 결선도 §3.1 · `gpio_input.py` |
| **ACK 기반 차단 확인** | BLOCK 은 명령 송신으로 끝내지 않고 Arduino 의 `ACK` 로 **실행을 확인**한다. 무ACK 면 재시도, 최종 실패 시 `on_fault` 알람 — **「보냈다」와 「차단됐다」를 구분** | `interlock.py` |
| **레벨 재확인 게이트** | EMO 가 물리적으로 복귀되지 않으면 해제·초기화를 **거부**한다. GPIO 는 엣지만 발사하므로 레벨을 다시 본다 | `safety_console.py` 1309~1345 |
| **오답 불변식** | `expected_step += 1` 이 **파일 전체에 한 줄**뿐이고 정답 분기에서만 도달한다 — *"오답은 단계를 진전시키지 않는다"* 가 주석의 약속이 아니라 확인 가능한 사실 | `fsm.py:243` |
| **끊겨도 죽지 않음** | 시리얼 미연결·끊김에도 예외 없이 fallback(로그만). 재연결 시 마지막 명령을 재전송해 릴레이 상태를 FSM 과 일치시킨다 | `interlock.py` |
| **폴트 시나리오 실물 검증** | ①Arduino USB 분리 중 위반 → 무ACK 폴트 경고 + 재연결 시 BLOCK 자동 복원 ②EMO 단선 부팅 → 즉시 BLOCK ③복귀 후 ACK 회귀 — **3종 전부 통과** | 통합문서 §12 (2026-07-15) |

**이론**

- **포카요케(Poka-yoke, 실수 방지 설계)** — 이 시스템은 「경고형」을 넘어 **「강제형」**이다. 인터락이 전기 신호를 끊으므로 잘못된 조작이 물리적으로 성립하지 않는다.
- **Reason 의 인간 오류 분류** — 순서 위반은 의도는 옳고 실행이 어긋난 **slip(실수)** 이다. slip 은 교육으로 줄지 않고 **환경 설계로만 줄어든다** — 이 프로젝트의 전제.
- **스위스 치즈 모델** — 시각 경고(층1) · 청각 경고(층2) · 인터락 차단(층3)의 다중 방어선.
- **Fail-safe vs Fail-silent** — NC 배선과 ACK 확인은 「고장이 안전한 쪽으로 나게」 만드는 고전 기법이다.

## ③ 사용성

- **1인칭 웨어러블** — 고정 카메라의 가림 문제를 구조적으로 회피한다. 작업자가 보는 것을 그대로 본다
- **2단계 도넛 ROI** — 링(접근)에서는 타이머만 예열하고 **박스(위험) 안에서만 발화**한다. *"접근은 위반이 아니다"* 를 알고리즘으로 표현해 **오경보 억제와 사전 감지를 양립**시켰다
- **체류 임계 0.3초** — 스침과 의도를 가른다 (1.5 → 1.0 → 0.5 → 0.3 실측 조정, §10.23)
- **해제는 사람이** — 자동 복귀가 아니라 명시적 해제 버튼. 단 EMO 미복귀면 거부
- **화면이 다음 할 일을 알려준다** — 단계 매뉴얼 · 진행바 · 공구 게이트
- **UI 애니메이션의 FPS 영향 +0.8%** — 사실상 없음. 문턱 10% 이내로 기본 ON 유지 (§10.48)

**이론**

- **경보 피로(alarm fatigue)** — 오경보가 잦으면 작업자가 경고를 무시하게 되고, 그때 안전 시스템은 있으나 마나가 된다. 링/박스 2단계는 이 문제에 대한 직접적 대응이다.
- **신호탐지이론(SDT)** — 링과 박스는 **판단기준 β 를 구역별로 분리**한 것으로 읽을 수 있다. 접근 구역은 민감하게, 발화는 보수적으로.
- **상황인식(Endsley 3단계)** — 지각(버튼 검출) → 이해(순서 판정) → 예측(다음 단계 안내)이 화면에 그대로 대응한다.

## ④ 보안 — 있는 것만 쓴다

**있는 것**

- **온디바이스 추론** — 작업장 1인칭 영상이 클라우드로 나가지 않는다. 공정 노하우와 작업자 초상이 담긴 민감 데이터가 **로컬에 머문다**
- **LLM 도 로컬** — Ollama 를 별도 Pi 에서 구동, 음성 데이터 외부 전송 없음
- **폐쇄망 운용 가능** — 로컬 AP 기반, 인터넷 불필요
- **차단은 물리 릴레이** — 소프트웨어가 죽어도 릴레이 상태가 유지·복원된다

**이론** — Privacy by Design 의 **데이터 최소화**·**엣지 처리** 원칙. 반도체 팹 영상은 영업비밀에 해당해 외부 전송 자체가 승인받기 어렵다는 산업적 제약과도 맞는다.

> ⚠️ **없는 것은 향후 과제로 적는다** — 영상 스트림 암호화(현재 평문 TCP), 기기 인증. **여기를 부풀리면 역효과다.**

## ⑤ 알고리즘의 창작성 — 두 번째로 강한 축

| 창작 지점 | 내용 |
| --- | --- |
| **HOI 융합** | 객체검출(YOLOv8)과 손 랜드마크(BlazePalm·BlazeHandLandmark)를 **한 NPU 에서 공유**하고, 검지 끝(landmark 8)과 검출 박스의 기하 관계로 상호작용을 판정한다 |
| **ROI 가 고정좌표가 아니다** | 1인칭이라 화면이 흔들리므로 **YOLO 박스 자체를 ROI 로** 삼는다. 카메라 캘리브레이션·고정 좌표 설정이 **원천적으로 불필요** |
| **2단계 ROI + 발화 조건 C1** | 링에서 체류를 쌓되 발화는 박스 안에서만. 안쪽이 링을 이기고, 같은 단계면 작은 박스 우선 |
| **갭 메우기 0.3초** | 검출이 끊긴 프레임을 메워 체류가 깨지지 않게 — FPS 변동에 대한 강건성 |
| **프레임 수 기반 판정** | 눌림 간격 경계가 시간이 아니라 **프레임 수(5프레임)** 라는 발견. *"FPS 가 곧 허용 눌림 속도"* (§10.29) |
| **MediaPipe 우회** | 프레임워크가 Python 3.13/aarch64 에서 못 돌자 **모델만 `.hef` 로 변환**했다. *"모델은 같고 실행 경로만 다르다"* |
| **모델 분리 판단** | 공구를 버튼 모델에 합치지 않았다 — 버튼은 **색으로** 구분해 색 증강이 금지인데 공구는 색 증강이 필수라 **정면 충돌** |

**이론** — HOI(Human-Object Interaction) 검출 · 시간적 필터링으로서의 dwell · 이중 임계와 히스테리시스 · 안전 불변식을 유한상태기계(FSM)로 표현하기.

## ⑦ 프로젝트를 통한 가치창출

- **문제의 크기** — 반도체 장비 정비(PM)는 정해진 순서가 안전과 설비 보전을 좌우한다. 순서 하나가 어긋나면 챔버 손상·가스 노출로 이어질 수 있다
- **기존 대응과의 격차** — 현행은 사후 보고·조사다. **사고가 난 뒤에 배운다**
- **확장성** — 하드웨어가 아니라 **`recipe.json` 한 파일**이 공정을 정의한다. 「버튼을 검출하고 순서를 아는」 구조라 다른 공정으로 옮기는 비용이 낮다
- **숙련 전이** — 신입 작업자가 화면 매뉴얼을 따라가며 순서를 익힌다
- **사후 분석 자산** — 위반 기록·세션 통계가 남아 개선 자료가 된다

## ⑧ 제작 노력 — 여기를 제일 힘줘 쓴다

**성능 수치는 다른 팀도 낸다. 자기 결론을 뒤집은 기록은 드물다.**

> **오진을 스스로 규명한 사례** — FPS 가 13에 머무르자 원인을 **TCP 전송**으로 지목하고 *"하드웨어 한계·소프트웨어로 해결 불가"*, *"카메라 교체 필요"* 라는 결론을 **두 달간 유지**했다. 실제 병목은 **ESP32 내부 프레임 버퍼**였고 **펌웨어 3줄로 2.4배**가 됐다. 당시 네트워크 대역폭은 **1.2%만** 쓰이고 있었다. (§10.34)

함께 쓸 수 있는 것:

- **폐기 이력을 지우지 않는 문서 규율** — 유효/폐기 마커와 `[CURRENT]` 표로 *"폐기된 결론이 현행처럼 읽히는 것"* 을 막는다
- **자기 규율** — **사후 층화 값**과 **단일 세션 값**을 성능으로 인용하지 않는다는 규칙을 문서화하고 지켰다
- **운용 조건 축소를 선택한 정직성** — 옐로우등에서 B4 가 사실상 검출되지 않아 **안전 기능이 조용히 무력화**되는 것을 발견하고, 감추는 대신 **범위에서 제외**했다 (§10.18)
- **반복 개선** — 공구 모델 3세대(v1 → v2 → v3), 데이터셋 폐기(ARCAD) 후 재구축
