# Claude Code 작업문서 (설명서)

> **Claude Code를 이 프로젝트에서 어떻게 쓰고 있으며, 어떤 CC 기능·도구가 있고, 재사용 원칙이 무엇인지** 정리한 **설명서**(시간순 로그 아님).
> 목적 = Claude Code를 생산적·유용하게 쓰는 법(전역 CC 인프라 + 이 프로젝트 작업 효율).
>
> **짝 문서 · 역할 경계** (전체 지도 = `README.md`)
> - `claude-code-작업문서.md`(이 파일) = **CC 설명서 정본** — "CC 인프라가 뭐고 어떻게 일하나 + 훅 설계 원칙" (주제별·개정)
> - `claude-code-작업로그.md` = **CC 작업 로그** — "언제 어떤 CC 작업을 했나" (시간순)
> - `작업로그.md` = **프로젝트 작업 로그** (CC 제외)
> - `CLAUDE.md` = **지시사항**("~하라/하지 말 것") · `README.md` = **포인터**(무엇이 어디 있나) · `통합문서.md` = **정본**(무엇이 사실인가)

## 0. 규칙 표면 — 무엇이 어디에 있나

> 🔴 **규칙은 「Claude Code 가 로드하는 면」에만 둔다.** 일반 `.md` 는 공식이 다루지 않는 면이라 규칙을 두지 않는다 — 이 문서를 포함해 **포인터만** 남긴다.

| 면 | 무엇이 | 언제 붙나 |
| --- | --- | --- |
| `CLAUDE.md` (70줄) | 착수 판단 · 역할 분담 · 도구 발동 표 · 커밋 · 매 세션 함정 | 매 세션 |
| `Rpi5/CLAUDE.md` (80줄) | 런타임 코드 맥락 · 코드를 읽어도 안 보이는 함정 | `Rpi5/` 파일을 읽을 때 |
| `.claude/rules/` 7개 (263줄) | 훅설계 · 규칙배치(+소급) · 정본편집 · cc인프라 · 수치인용 · 문서배치 · 계획서작성 | `paths:` 글롭이 맞는 파일을 읽을 때 |
| `.claude/skills/` 7개 | work-close · session-resume · session-wrap · **작업갈래 · 촬영 · 측정도구 · 데이터셋** | 그 작업을 시작할 때(설명은 매 세션) |
| `.claude/output-styles/` | 사용자이해우선 — 답변 방식 | 🔴 **머신마다 한 번 켜야 한다**(선택값이 `settings.local.json`) |
| `.claude/settings.json` | 권한 deny · SessionStart 훅 | 항상 — **기계 강제** |
| auto memory (토픽 1) | 그 머신 고유 사실만 | 색인은 매 세션 |
| `hanium-docs/.claude/rules/` | 제출문서 작업 규칙 | 그 폴더에서 세션을 열 때 |

**자리를 정하는 규칙** = [`.claude/rules/규칙배치.md`](../.claude/rules/규칙배치.md) — 공간별 로드 시점 · 경위 금지 · 중복 금지 · 폐기 이관 · 길이 · 소급.

🔑 **연결은 `paths:` 가 기계로 보장한다** — 규칙이 다루는 문서를 열면 자동으로 붙는다. 포인터로 「읽어 달라」고 부탁하지 않는다.

🔴 **규칙을 뺄 때는 [`변경이력.md`](변경이력.md) §11 로 옮긴다.** 그냥 지우지 않는다.

## 1. 현재 CC 인프라 → `.claude/rules/cc인프라.md`

🔴 **`.claude/` 를 만지면 그 규칙이 자동으로 붙는다**(`paths:` 로 연결). 훅·스킬 목록과 판정 4종·기계 검사 4종은 거기가 정본이다.

## 2. 작업 방식 → `.claude/skills/작업갈래/`

🔴 **비자명 작업에 착수하면 그 스킬이 붙는다.** 갈래·관문·병렬성 판단·실HW 직렬 제약은 거기가 정본이다. 계획서 규약은 `.claude/rules/계획서작성.md`.

## 3. 범용 훅 설계 원칙 → `.claude/rules/훅설계.md`

🔴 **훅·설정을 만지면 그 규칙이 자동으로 붙는다.** 제1원칙·폐기 이력 3건·이벤트 타이밍·구현 관례·함정은 거기가 정본이다.
