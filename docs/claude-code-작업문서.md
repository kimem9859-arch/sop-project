> 목적 = Claude Code를 생산적·유용하게 쓰는 법(전역 CC 인프라 + 이 프로젝트 작업 효율).
>
> **짝 문서 · 역할 경계** (전체 지도 = `README.md`)
> - `claude-code-작업문서.md`(이 파일) = **CC 설명서 정본** — "CC 인프라가 뭐고 어떻게 일하나 + 훅 설계 원칙" (주제별·개정)

### 이 표면은 검증을 거쳤다 (2026-09-21)

재배치 산출물을 **기준 커밋과 대조해 전수 검증**했다 — 사라진 296줄의 행방을 추적하고, 기계 검사 9종과 사람 판정 2층을 거쳤다. **관문 9/9 · 홀드아웃 2/2 통과 · 결함 6건 수정.**
🔴 **기계 검사만으로는 못 잡는 결함이 실재했다** — 어구가 새 자리에 있으면 연결·중복·길이 검사를 모두 통과하므로, **항목 하나가 빠진 것**(도구 주의 6종 → 4종)은 사람이 원문과 대조해야만 보였다.
🔴 **세기 쉬운 단위와 재야 할 단위가 다르면 관문은 통과하면서 결함을 통과시킨다** — 보존은 행 수가 아니라 **항목 수**, 길이는 줄 수가 아니라 **문자 수**, 완전성은 올라온 행이 아니라 **올라왔어야 할 면**이 단위다.

## 1. 현재 CC 인프라 → `.claude/rules/cc인프라.md`

🔴 **`.claude/` 를 만지면 그 규칙이 자동으로 붙는다**(`paths:` 로 연결). 훅·스킬 목록과 판정 4종·기계 검사 4종은 거기가 정본이다.
