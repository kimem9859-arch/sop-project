## S12 · 시스템 구성도 ② 소프트웨어 구성

- **구분** ○ **필수** · Ⅲ 아키텍처 설계
- **넣을 이미지** `D` **[그림4] 소프트웨어 구성도** (주) + `A03_HOI_통합구조.png` (부)
- **본문 개조식**
  - 4개 층으로 구성 — **① 실행**(NPU 추론·버튼 입력·제어 신호 송신) → **② 인식**(영상 디코딩·객체 검출·손 랜드마크) → **③ 판정**(유한 상태 머신) → **④ 표시**(작업자 화면)
  - **모델 3개가 하나의 NPU를 나눠 쓴다** — 각 모델이 자체 장치를 점유하면 동시 실행이 불가능하므로 **공유 스케줄러(ROUND_ROBIN)** 로 자원을 배분한다
  - 음성 스택은 **별도 연산 장치**에 두어 비전 연산과 부하를 분리한다
  - 모델 준비(학습→변환)는 개발 단계 전용이며 시연 장비에서는 동작하지 않는다
- **배치** [그림4] 좌측 2/3, A03을 우측 1/3에 작게. A03은 「NPU 자원 공유」 설명의 근거로만.

## S29 · 알고리즘 명세서 ④ 순서 판정 FSM

- **구분** ○ **필수** · Ⅳ 기능 설계
- **넣을 이미지** 좌 = `D` **[그림6] FSM 상태전이도** / 우 = `B12_FSM_log.png`
- **표 — 상태 정의**

| # | 상태 | 의미 |
| --- | --- | --- |
| 1 | IDLE (대기) | 전원·완료 대기 |
| 2 | READY (준비) | 레시피 로드 완료, 단계 입력 대기 |
| 3 | PROCESS RUN (작업 진행) | 정상 공정 진행 중 |
| 4 | MONITOR (감시) | 손-구역 감시 — 정답/오답 분기점 |
| 5 | WARNING (경고) | 시청각 경고 출력 |
| 6 | BLOCK (차단) | 인터록으로 전기 입력 차단 |

- **시나리오(번호 개조식)**
  1. 레시피를 로드하면 대기에서 준비로 전이한다
  2. 감시를 시작하면 작업 진행으로 전이한다
  3. 손끝이 버튼 구역에 진입하면 작업 진행에서 감시로 전이한다
  4. 정답 버튼을 누르면 다음 단계로 진전하고, 마지막 단계면 대기로 돌아간다
  5. 오답 구역에서 체류 임계를 넘기면 경고로 전이한다
  6. 경고를 무시하고 오답 버튼을 누르면 차단으로 전이한다
  7. 구역을 이탈하면 감시에서 작업 진행으로 복귀한다
  8. 작업자 해제로 경고는 감시로, 차단은 준비로 복귀한다 — **기대 단계는 진전되지 않는다**
  9. 비상정지는 어느 상태에서든 즉시 차단으로 간다
- **배치** 좌 그림 / 우 상단 표 + 하단 로그 캡처.

## S34 · 알고리즘 상세 설명서 ② 체류 시간 임계

- **구분** ○ **필수** · Ⅳ 기능 설계
- **넣을 이미지** `A04_체류시간_분포.png`
- **서술(양식 샘플의 상세 설명서 형식 — 문단 + 근거 데이터)**
  - 손이 버튼을 스치기만 해도 위반으로 판정하면 오탐이 된다. 스침과 **누르려는 의도적 접근**을 가르는 기준이 체류 시간이다.
  - 물리 버튼을 실제로 눌러 재보면 버튼 위 체류 시간의 **중앙값은 0.39~0.40초**이며, 의식적으로 천천히 눌러도 값이 바뀌지 않는다(3회 재현). 사람의 동작에서 나오는 물리적 한계에 가깝다.
  - 따라서 임계를 중앙값 아래인 **0.3초**로 두어 위반을 제때 포착한다. 0.25초 이하로 더 낮추면 포착률은 소폭만 늘고 헛경고가 늘어 **0.3초가 적정점**이다.
  - 누르는 순간 손이 버튼을 덮어 검출이 끊기는 채터가 발생하므로, **0.3초 안에 다시 잡히면 구역 이탈로 보지 않고 체류 시간을 이어서 누적**한다.
- **표 — 임계값 정본**

| 값 | 확정값 |
| --- | --- |
| 체류 시간 임계 (스침 vs 위반) | **0.3초** + 갭 메우기 0.3초 |
| ROI 링(1단계) 폭 | **25 px** |
| 경고 발화 조건 | 체류 임계 도달 **+ 손끝이 박스 안(2단계)** — 링에서는 타이머만 누적 |

- **배치** 좌측 차트, 우측 서술 4문단 + 표. ⚠️ 차트의 「구 정본 0.5초」 표기는 그대로 두어도 무방하나, 본문에서 「폐기」 같은 표현은 쓰지 않는다.

## S45 · 핵심 소스코드 ② 2단 구역 판정

- **넣을 이미지** `C` `A2_roi_zones.png` — `Demo/roi_zones.py:26-56`
- **본문 개조식**
  - 검출된 **버튼 상자 자체가 판정 구역**이다 — 고정 좌표를 두지 않아 구역이 버튼을 따라다닌다
  - 상자 바깥에 25px 폭의 링을 둘러 **2단 구역**을 만든다 — 바깥 링은 접근, 안쪽 상자는 위험
  - **안쪽이 링을 이긴다** — 한 점이 A의 안쪽이면서 B의 링이면 A로 판정한다
  - 같은 단계끼리 겹치면 **더 작은(가까운) 상자를 우선**해 오판을 줄인다
  - `ring=0` 이면 링이 없어 도넛 도입 전과 완전히 동일하게 동작한다 — 롤백 스위치

## S46 · 핵심 소스코드 ③ 비전 갱신과 경고 발화

- **넣을 이미지** `C` `A3_fsm_vision.png` — `Demo/fsm.py:185-214`
- **본문 개조식**
  - 경고·차단 중에는 비전 틱으로 자동 전이하지 않는다 — **해제 버튼이 복구의 주체**다
  - 손이 구역을 벗어나면 오답 체류를 취소하고 정상으로 복귀한다
  - 정답 구역 진입은 체류를 재기지 않는다 — 진전은 실제 눌림에서만 일어난다
  - 오답 구역은 체류 타이머를 누적하되, **링에서는 누적만 하고 경고를 띄우지 않는다**
  - **체류 임계 초과 + 손끝이 상자 안** 두 조건이 함께 성립할 때만 경고로 전이한다

## S47 · 핵심 소스코드 ④ 눌림 처리와 단계 진전

- **넣을 이미지** `C` `A4_fsm_press.png` — `Demo/fsm.py:216-246`
- **본문 개조식**
  - 비상정지는 순서 판정 없이 즉시 차단으로 간다
  - 차단 중의 버튼 입력은 무시한다 — 해제 버튼만 유효하다
  - 정답 버튼 눌림은 단계 완료로 처리한다
  - **오답 버튼이 실제로 눌리면 경고를 생략하고 즉시 차단**한다
  - 마지막 단계를 마치면 기대 단계를 1로 되돌리고 대기 상태로 간다
  - 🔑 **오답은 단계를 진전시키지 않는다** — 차단을 해제해도 기대 단계는 그대로 유지된다

## S48 · 핵심 소스코드 ⑤ 차단 명령과 수신 확인

- **넣을 이미지** `C` `A5_interlock.png` — `Demo/interlock.py:224-249`
- **본문 개조식**
  - 차단 명령은 **수신 확인(ACK)까지 받아야 성립**한다 — 보냈다는 사실만으로 차단으로 보지 않는다
  - 응답이 없으면 재전송하고, 끝내 없으면 **차단 미확인으로 이상을 알린다**
  - 송신 자체가 실패하면 제어 보드 재연결을 기다리고, 차단 명령이었다면 즉시 이상으로 처리한다
  - 재연결 시 마지막 명령을 다시 보내 릴레이 상태를 판정부와 일치시킨다 — 차단 중 케이블이 빠졌다 붙어도 차단이 풀리지 않는다

## S49 · 핵심 소스코드 ⑥ 릴레이 제어 펌웨어

- **넣을 이미지** `C` `A6_arduino.png` — `console_interlock.ino:68-87, 109-123`
- **본문 개조식**
  - 릴레이 5채널을 한 번에 설정한다 — 적·황·녹·부저·**버튼 공통 GND 차단**
  - **active LOW** — 제어 핀이 LOW일 때 채널이 켜진다. 기동 시 정상 상태(녹 ON)를 명시한다
  - `RUN`·`WARN`·`BLOCK` 세 명령만 받는다 — 미지 명령은 상태를 바꾸지 않고 확인만 응답한다
  - **경고에서는 전기를 끊지 않는다** — 1차는 알리기만 하고 작업은 이어진다
  - 차단에서만 버튼 공통 GND를 끊어 **오답 버튼이 실제로 눌려도 신호가 나가지 않게** 한다
  - 모든 명령에 `ACK` 를 회신해 판정부가 수신을 확인할 수 있게 한다

## S50 · 핵심 소스코드 ⑦ 비상정지 미복귀 시 해제 거부
