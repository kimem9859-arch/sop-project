## 1. 배경

2026-09-11 점검 → 정본 전수 반영 ①정정·②구조·③사실 추가(2026-09-14 사용자 확인)로 **발견된 공백은 채웠다.** 그러나 그 방식은 「외부 자료(세션·커밋·코드)와 대조해 빠진 것을 찾는」 것이었다. 사용자는 정본이 **처음부터 끝까지 자기 생각과 현 상황에 맞는지**를 직접 확인하고 싶다(2026-09-15).

> 사용자: 「정본 외의 다른 자료를 참고, 비교하여 정본을 수정하는 것이 아닌 정본의 각 문항 순서대로 나와 같이 하나씩 검토하는 방식으로 진행하고 싶어」

## 2. 목표 / 비목표

- **목표** — 검토 범위(§3)의 모든 소절을 사용자와 함께 읽고, 합의한 수정을 장 단위로 통합문서에 반영한다.
- **비목표** — 외부 자료로 정본의 빠진 것을 찾는 감사(09-11 점검이 한 일) · §10 갈래 저널의 옛 기록을 지금 생각으로 고쳐 쓰기(저널은 당시 사실) · hanium-docs 정리.

## 3. 범위 (사용자 결정 A)

|---|---|

순서 = 문서 순서(§1 → §14). 규모 ≈ 1,450줄 · 세션 5~8회 예상.

## 4. 소절 검토 방식 (사용자 결정 A)

한 번에 **소절(`###`) 하나**. 원문 60줄 이내면 짧은 소절 2~3개를 묶는다. 보여주는 것:

1. **요약 불릿** — 이 소절이 말하는 것을 쉬운 말로(원문 붙여넣기 금지 — CLAUDE.md §1④)
2. **줄 번호 범위** — 요약이 원문을 잘못 옮길 위험 대비. 사용자가 「원문 보여줘」하면 보여준다
3. **⚠️ 정본 안의 어긋남** — 같은 정본의 다른 곳과 충돌하는 것만(외부 자료 대조 아님)
4. **확인 질문 1~3개**

판단 기준 = **사용자의 생각과 현 상황.** Claude 는 외부 자료로 「이게 맞다」를 먼저 주장하지 않는다.

## 4.5 Claude 사전 검토 — 사용자 검토 전에 전체를 먼저 (사용자 추가 지시 · 결정 B)

> 사용자: 「내가 확인하기 전에 너가 정본 전체 내용을 미리 검토하여 확인 필요한 부분을 먼저 파악했으면 좋겠어 파악해준 부분은 주의깊게 내가 볼게」

- **언제** — 공동 검토 시작 전, 검토 범위(§3) **전체**를 한 번 읽는다(세션 1~2회 예상).
- **무엇을 표시하나**
  - (가) **정본 안의 신호** — 같은 사실이 절마다 다름 · 「예정」·「진행 중」·「⚠️미확인」 · 오래된 날짜의 「현재」 서술 · 조건 없는 수치 · 단일정본 대상(수치 §10 · 부품 §11.1 · 배정 §12)의 복제
  - (나) **①순위 실물(현재 코드·설정 파일)과 명백히 다른 곳** — 표시마다 근거 파일·줄을 붙인다
  - ②순위 이하(커밋·보존본·spec·작업로그·점검 문서)는 **사전 검토에 쓰지 않는다** — 09-11 감사의 반복이 된다
- **표시만 한다** — 통합문서를 고치지 않는다. 판단·수정은 공동 검토(§4)와 장 반영(§6)에서.
- **어디에** — 기록 문서 각 장 표의 「사전 표시」 열. 표시 없는 소절은 「—」(읽었음을 드러낸다).
- **공동 검토 때** — 그 소절의 사전 표시를 **요약보다 먼저** 보여준다.
- 사전 검토를 마치면 표시 건수를 장별로 보고하고 커밋한다(`docs(정본검토): 사전 검토 — …`).

## 5. 자료를 가져와야 할 때 (사용자 추가 지시)

> 사용자: 「데이터 값과 내 기억에 나지 않는 것들은 어쩔 수 없이 이전 문서 내용을 가져와야 함으로 가져오는데 단 신뢰도가 높은 자료를 먼저 참고하고 그 자료에도 정보가 없다면 신뢰도가 낮은 자료를 참고하고 내 확인을 받아줘」

| 순위 | 자료 | 예 |
|---|---|---|
| ① | 실물·원자료 | 현재 코드 · 설정 파일 · 측정 원자료(DB·CSV·GPIO 로그) · 외부 사실은 1차 출처 원문 |
| ② | 원본 기록 | 커밋 · 세션 보존본(원본 대화) |
| ③ | 당시 설계 기록 | spec · plan |
| ④ | 요약 기록 | 작업로그 |
| ⑤ | 요약의 요약 | 점검 문서 등 파생 문서 |
| ✖ | 사용 금지 | hanium-docs(정리 전까지 — 2026-09-15 사용자 지시) |

- ① 부터 찾고, 없을 때만 다음 순위로 내려간다.
- 가져온 값은 **전부** 「출처 · 순위」를 붙여 보여주고 **사용자 확인 후에만** 기록한다. ④·⑤ 출처는 ⚠️ 표시.
- 순위 근거 = `work-close` 원칙 「원천에서 옮긴다 — 요약에서 옮기지 않는다」(2026-09-14 ③ 리뷰에서 요약을 옮긴 4곳의 날짜·강도가 바뀌었다).

## 6. 기록과 반영 (사용자 결정 — 소절마다 기록, 장마다 반영)

> 사용자: 「소절과 소절이 연관되어 있을 수도 있으니까 하나씩 고치기에는 뒷 소절에도 영향이 있을 것 같아」

### 6.1 기록 문서 `docs/정본검토-기록.md` (사용자 결정 A)

- 머리 = **「현재 위치」 한 줄**(예: `§2 · 2.3 까지 검토 · 반영 전`)
- 장마다 표 1개 · 소절마다 한 행:

| 소절 제목 | 사전 표시 | 합의(고칠 것) | 보류 | 뒤에서 만날 곳 | 가져온 값·출처 | 반영 커밋 |
|---|---|---|---|---|---|---|

- 소절은 **제목으로** 적는다 — 줄 번호는 장 반영 뒤 밀린다.
- 끝에 **보류 목록**(전 장 누적).

### 6.2 흐름

0. (한 번) 사전 검토(§4.5) → 전 장의 「사전 표시」 열을 채우고 커밋.
1. 소절 검토(사전 표시 먼저) → 합의를 기록 문서에 적고 **커밋**(`docs(정본검토): §N 소절 — …`). 통합문서는 건드리지 않는다.
2. 뒤 소절이 앞 합의를 뒤집으면 앞 행에 `→ <소절>에서 변경` 표시.
3. 장(`##`) 끝 → 그 장의 합의 전체를 **요약해 보여주고 확인** → 통합문서에 한 번에 반영 → `docs(정본): §N 공동 검토 반영 — …` 커밋 → 해시를 기록 문서에.
4. 반영 때 CLAUDE.md §3 규율(단일정본·`[CURRENT]` 표·유효성 마커·🔓 표)과 `work-close` 2.5 자가 점검을 그대로 따른다.
5. 「모르겠다」·「나중에」 = 보류 목록. 전체 검토 끝에 모아 다시 묻는다.
6. 같은 사실이 다른 절에도 있으면 「뒤에서 만날 곳」에 적고 **그 절에서** 함께 본다(앞질러 고치지 않는다 — 그 절은 아직 사용자와 읽지 않았다).
