- **왜 새 「도구 폴더」를 만들어 옮기지 않나** — 문서에 `test/<도구>.py` 경로가 **1,254줄**(sop-project `docs/`) 있고, `Demo/test/` 안의 도구 17개가 서로를, 자가 테스트 18개가 이 폴더의 도구를 경로로 불러 쓴다. 옮기면 기능은 같은데 경로만 대량으로 끊긴다. 지난 기록(작업로그·저널·옛 설계)은 고치지 않는 것이 규칙이라 끊긴 채 남는다.
- **옛 데이터 전용 도구(A)도 옮기지 않는다** — 설계 §4.3 이 「고치지 않고 옛 데이터 전용으로 적는다」로 정했고, `dwell_probe` 는 1단계-나(세기)가 나오기 전까지 XGA 근사 도구로도 쓴다(10-07 스침 분석). 지도에 표시만 한다. `fsm_sim --gate`(측정도구 스킬 관문) 경로도 그대로다.

| 대안 | 버린 이유 |
| --- | --- |
| 쓰는 도구 전부를 새 폴더(`Rpi5/도구/` 등)로 옮기기 | 경로 1,254줄·서로 불러 쓰는 도구 17개·자가 테스트 18개가 끊긴다 — 얻는 것은 폴더 이름뿐 · 지도가 한 곳에서 가리키면 같은 효과 |
| `Demo/test/` 안을 하위 폴더(측정·라벨·채점)로 쪼개기 | 같은 이유(서로 불러 쓰는 도구가 갈라진다) · 무리 나눔은 지도의 표가 한다 |
| 옛 데이터 전용 도구를 지금 백업 | 설계가 「옛 데이터 전용으로 남긴다」로 정했고 1단계-나 전까지 근사 도구로 쓴다 · 인용된 §12 값을 다시 낼 수 있어야 한다 |
| 9/24 처럼 지우기(git 이력으로만 되살림) | 사용자가 「백업 폴더」를 요청했다 · 폴더에 있으면 무엇을 뺐는지 눈으로 보인다 |
| 조사 스크립트 중 재사용되는 것(`장소차이_분석.py` 등)을 도구 폴더로 올리기 | 세션 이름이 코드에 박힌 일회성 분석이다 — 올리려면 일반화(새 기능)가 필요하다 · 다시 쓸 일이 생기면 그때 도구로 만든다 |
| `holdout_score`·`slide_charts` 등 「보관」을 모두 백업 | 자가 테스트·README·진행 중 작업이 쓴다 — 「필요 없음」이 확인되지 않았다 |

## 8. 범위 밖

- 도구 코드 수정(백업 때 같이 고칠 곳 §4 제외) · 도구 성능·정합 — 1단계-가·나.
- Rpi5 밖의 도구(sop-project `dev/llm_bench`·`dev/ai_model` · `~/lab/` · 데스크톱) — 지난 집계 범위 밖이었다 · 지도 §0 에 「다른 곳」 한 줄로 위치만.
- 데이터 폴더 정리(`Demo/test/raw/` 등) — 도구가 아니다.
