## 1. 화면 기하

| 항목 | 값 | 근거 |
|---|---|---|
| 디스플레이 | **1920×1080** (16:9) | `xrandr` 실측 (HDMI-1) |
| 카메라 | 640×480 (4:3) | ESP32-S3 OV3660 |
| 영상 표시 | **1440×1080**, 화면 가운데 | 높이를 꽉 채운 4:3 |
| 레터박스 | **좌우 각 240px, 검정** | 사이드바 UI는 채택 안 함(§8) |

**모든 UI는 영상 위 오버레이**다. 레터박스에는 아무것도 두지 않는다.

### 오버레이 배치 (화면 폭·높이 기준 %)

| 요소 | 위치 | 크기 |
|---|---|---|
| 상태 + 공정 단계 패널 | `left 14%` · `top 5%` | `width 24%` (높이는 내용에 따라, 약 42%까지) |
| 대기 게이지 | `left 41%` · `top 5%` | `width 17%` |
| 메뉴 버튼 ☰ | `right 14%` · `top 5%` | 아이콘 |
| 메뉴 패널(열림) | `right 14%` · `top 5%` ~ `bottom 5%` | `width 13%` |
| 알림 버튼 🔔 | `left 14%` · `bottom 5%` | 아이콘 + 뱃지 |
| 알림 패널(열림) | `left 14%` · `top 48%` ~ `bottom 5%` | `width 27%` |
| 경고 배너 | 가로 중앙 · `bottom 13%` | `width 44%` |
| 차단 패널 | 가로 중앙 · `top 47%` | `width 46%` |
| 작업 시작 버튼 | 화면 정중앙 | 내용에 맞춤 |

- 공정 단계 패널 `14%~38%`, 게이지 `41%~58%` — **3%p 간격으로 이어져 한 덩어리로 읽힌다.**
- 알림 패널 상단이 `48%`인 이유 = **공정 단계 패널(~42%)을 가리지 않기 위해.**
- 메뉴(우상단)와 알림(좌하단)은 **대각선 대칭**.

## 2. 폰트 — Pretendard 단일

### 2.1 🔴 먼저: 지금 코드가 잘못돼 있다

`safety_console.py`의 **7곳**이 `QFont("Consolas", ...)`인데 **이 파이에 Consolas가 없다.** Qt가 조용히 `WenQuanYi Zen Hei Mono`(중국어 폰트)로 대체하고 있었다. **지금 화면의 글꼴은 아무도 의도한 적이 없는 것**이다. Consolas는 윈도우 기본 폰트라 개발 환경 값이 남은 것으로 보인다.

### 2.2 확정

| 항목 | 값 |
|---|---|
| 폰트 | **Pretendard 1.3.9** (단일) |
| 굵기 | 400 본문 / 600 강조 / 700 제목 / 800 현재 단계 |
| 숫자 | **`tnum`(고정폭 숫자) 켠다** |
| 라이선스 | SIL OFL 1.1 — 상업 이용·수정 자유 |
| 설치 위치 | `~/.local/share/fonts/Pretendard/` (사용자 폴더, `sudo` 불필요) |
| 설치 파일 | `Pretendard-{Regular,SemiBold,Bold,ExtraBold}.otf` 4벌, 각 약 1.6MB |

**선정 이유** — ①라틴·숫자가 또렷하다(`PROCESS RUN`·`18/45s`·`14:22:07`이 화면에 상시 노출) ②한글과 라틴의 높이·굵기가 맞아 섞인 줄이 안정적 ③굵기가 4단계라 600/700/800 구분이 정확(나눔스퀘어는 2단계뿐).

### 2.3 고정폭 숫자 — Qt에서는 명시적으로 켜야 한다

기본값이 아니다. 켜지 않으면 게이지가 `18/45s → 19/45s`로 바뀔 때 **폭이 흔들린다.**

```python
f = QFont("Pretendard")
f.setFeature(QFont.Tag("tnum"), 1)
```

| | 숫자 0~9 폭 |
|---|---|
| 기본 | `11, 8, 11, 12, 12, 11, 12, 10, 12, 12` |
| `tnum` 켬 | `12` × 10 — **균일** (`18/45s`·`19/45s` 둘 다 62px) |

> ⚠️ `QFont.setFeature`는 **Qt 6.7 이상**이다. 이 파이는 6.11.0이라 동작을 확인했다. **데스크톱·sop-pi-2에서는 Qt 버전을 먼저 확인할 것.**
> 이 기능 덕분에 **별도 숫자 폰트(D2Coding 등)가 필요 없어졌다.**

### 2.4 다른 환경에 설치하는 법

```bash
FD=~/.local/share/fonts/Pretendard && mkdir -p "$FD"
B=https://cdn.jsdelivr.net/npm/pretendard@1.3.9/dist/public/static
for w in Regular SemiBold Bold ExtraBold; do
  curl -sfL -o "$FD/Pretendard-$w.otf" "$B/Pretendard-$w.otf"
done
fc-cache -f "$FD"
```

### 2.5 🔴 재발 방지 — 폰트를 config로 모으고 실제 적용을 로그에 남긴다

Consolas가 조용히 바뀐 일이 데스크톱·sop-pi-2에서 재발할 수 있다. 구현 시:
1. 폰트 이름을 `config.py` **한 곳**에 둔다(현재는 7곳에 흩어져 있다)
2. 기동 시 `QFontInfo`로 **실제 적용된 폰트를 로그에 남긴다** — 요청과 다르면 즉시 보인다

## 3. 스타일 토큰

> 가독성 4안 확정. **불투명도를 올리지 않고 글자 쪽으로 대비를 얻는다**는 것이 원칙이다.

| 토큰 | 값 | 비고 |
|---|---|---|
| 오버레이 배경 | `rgba(0, 0, 0, 0.60)` | 🔴 **순검정**. 종전 `rgb(18,20,22)`보다 같은 알파에서 더 진하다 |
| 오버레이 테두리 | `rgba(255,255,255,0.22)` | |
| 메뉴·알림 패널 배경 | `rgba(0,0,0,0.90)` | 읽고 눌러야 하므로 진하게. 상시 노출이 아니라 시야를 막지 않는다 |
| 글자 그림자 | `0 1px 2px #000`, `0 0 5px rgba(0,0,0,.95)`, `0 0 12px rgba(0,0,0,.8)` | **3겹**. 배경 밝기와 무관하게 글자를 분리 |
| 본문 글자 | `#e6e8ea` · 굵기 600 | |
| 예정 단계 | **`#c3c9cf`** | 🔴 종전 `#6d7378`은 밝은 배경에서 사실상 안 보였다 |
| 완료 | `#7dffa8` | |
| 현재 단계 | `#ffd75c` · 굵기 800 · 왼쪽 3px 색 막대 | |
| 경고 | `#ff8f2e` | |
| 위험 | `#ff5252` | |
| 작업/정보 | `#5aa8ff` | |
| 작업 시작 버튼 | `rgba(56,150,255,0.92)` + 바깥 발광 `0 0 26px` | 밝은 파랑 |
| 게이지 빈 부분 | `rgba(0,0,0,0.65)` + `inset 0 0 0 1px rgba(255,255,255,.22)` | 🔴 흰색 반투명은 밝은 배경에서 채움과 구분이 안 됐다 |
| 게이지 채움 | `linear-gradient(90deg, #e8a000, #ffd75c)` | |
| 흐림 처리 | `opacity 0.40` | 메뉴·알림 열림, 경고·차단 발생 시 다른 오버레이에 적용 |

### 유리 느낌 — (a)만 적용

**(a) 단순 반투명만 구현한다.** **(b) 배경 블러는 보류** — Qt에 `backdrop-filter`에 해당하는 기능이 없어 매 프레임 `cv2.GaussianBlur`가 필요하다. 예비 측정에서 **800×400 영역 4.92ms**(25fps 기준 +12.3%p)로 무시할 수 없다. (a)를 만들어 보고 판단한다.

## 4. 화면 상태

### 4.1 IDLE — 작업 시작 전
- 상태 `STANDBY`, 모든 단계 회색 `○`
- **작업 시작 버튼을 화면 정중앙에 크게.** 누르면 사라지고 다시 나오지 않는다
- 게이지 자리는 비어 있음 (서브 작업 없음)
- 좌하단 알림 위로 **「점검 완료」 토스트**

### 4.2 점검 중 — 작업 시작 직후
- 중앙에 점검 패널 + 진행 막대. 통과하면 자동으로 닫힘
- 🔴 **실패하면 작업을 시작하지 않는다.** 실패 항목을 빨갛게 남기고 「다시 점검」을 띄운다
- ⚠️ **「1차」·「2차」를 화면에 쓰지 않는다** — `점검 완료` / `점검 중`으로만. 차수는 내부 구분이다
- ⚠️ **「레시피 적재」는 점검 항목이 아니다** — 기동 시 이미 읽고, 실패해도 기본 순서로 돈다

### 4.3 PROCESS RUN — 정상 진행
- 좌측 패널에 상태·단계, 상단 중앙에 서브 작업 게이지. 시야 가운데는 비어 있다

### 4.4 WARNING
- **영상 영역(가운데 75%)에만** 주황 테두리 발광 `9px` + `inset 0 0 60px`. **레터박스는 빛나지 않는다**
- 다른 오버레이 전부 `opacity 0.40`
- 중앙 하단 경고 배너: 제목 「순서가 다릅니다」 + 안내 2줄
  - 2번째 줄은 **아래로 내리고 `padding-left:14px` 들여쓴다**
  - 배너 안에 **「경고 해제」 버튼** — 평소엔 화면에 없다
- 알림 뱃지가 주황으로 바뀌고 수가 오른다

### 4.5 BLOCK
- 같은 규칙, 빨강 `12px` + `inset 0 0 90px`. 영상은 `brightness .55`
- **중앙을 가린다** — 이 순간엔 시야보다 멈추게 하는 것이 우선
- 「차단 해제」 버튼 포함. 🔴 **EMO 미복귀 시 거부**하는 기존 안전 장치 유지

### 4.6 메뉴 (열림)
- 세로형, 항목: **로그 · 캘리브레이션 · CCTV 전환 · 설정**
- 아래에 **추후 항목 자리 3칸**(점선)
- 🔴 **시스템 종료는 맨 아래로 분리 + 구분선** — 비가역 동작이라 다른 항목과 섞지 않는다. 확인창 유지
- 열리면 영상을 어둡게 하고 다른 오버레이를 흐린다
- ⏸ 「공정 단계」를 메뉴에 넣을지는 **보류** (좌측 패널에 상시 표시되어 중복)

### 4.7 알림 (신설)
- **좌하단 🔔 + 안 읽은 수 뱃지.** 새 알림은 그 위로 떠올랐다 몇 초 뒤 사라진다
- 누르면 위로 패널이 펼쳐진다 (`top 48%` ~ `bottom 5%`, `width 27%`)
- **메신저 방식** — 최신이 맨 아래, 열면 최신이 보이는 위치에서 시작, **과거는 위로 스크롤**
- 종류 4가지: **점검(✓ 초록)** · **이벤트-작업(▶ 파랑)** · **이벤트-경고(⚠ 주황)** · **이벤트-위험(⛔ 빨강)**
- 🔴 **프로그램을 종료하면 초기화** — 메모리에만 두고 파일로 남기지 않는다
- ⏸ **알림 기록(파일 저장)은 보류** — 통합문서 §13 확장의 「작업 로그 기록」과 성격이 같아, 지금 만들면 나중에 둘이 겹친다

> **로그와 알림은 역할이 다르다** — 로그(메뉴 안)는 **전부**를 시간순으로 담고, 알림은 **알려야 할 것만** 골라 띄운다. 둘 다 유지한다.

## 6. 구현 방침

- 🔴 **기존 `safety_console.py`를 수정한다** (새 파일 아님). 전면 수정이 닿는 곳은 레이아웃 계열 **약 160줄**(`_init_ui` 96 + `StepFlowWidget` 65)이고, 나머지 약 560줄(FSM·인터락·GPIO 배선, 안전 3종, 녹화·캘리브레이션)은 화면이 바뀌어도 그대로 필요하다. **화면은 전면이지만 파일은 전면이 아니다.**
- 🔴 **안전 UI 3종은 건드리지 않는다** — ①BLOCK 해제 거부(EMO 미복귀) ②인터락 폴트 경고창 ③종료 확인창. **전부 사고를 겪고 만든 방어물**이다.
- **작업 브랜치는 `feature/fsm-interlock`에서 딴다.** ⚠️ Rpi5의 `origin/main`은 `075f6db "Ver 1.1"`에 멈춰 있고 실제 트렁크가 `feature/fsm-interlock`(87커밋 앞섬)이다.
- **성능 대응은 아무것도 넣지 않고** 만든 뒤 측정한다(사용자 결정). `FastTransformation`도 지금은 적용하지 않는다.
  - 근거: 예비 측정에서 Full Screen + FPS25 최악이 **GUI 스레드 점유 24.5%** — 여유가 있다. 조건·한계는 아이디어 문서 §4.

## 8. 설계 과정에서 걸러진 것

| 안 | 왜 안 됐나 |
|---|---|
| **A. HUD 띠형** (위·아래 가장자리만) | 시야는 가장 트이지만 정보를 가로로 펴야 해 **담을 양이 적다.** 단계가 늘면 하단이 빡빡해진다 |
| **사이드바 UI** (레터박스 480px 활용) | 현재 우측 패널보다 넓어 유리했으나 **글라스 관점과 어긋난다** — 정보가 영상 *위*가 아니라 *옆*에 있게 된다 |
| **5안 — 줄마다 어두운 칩** | 가독성은 가장 확실하나 **판 안에 판이 겹쳐 유리 느낌이 사라진다** |
| 불투명도 상향으로 가독성 확보 | 60%를 지키면서 **글자 쪽(순검정 판·3겹 그림자·색 상향)으로 해결**하는 편이 나았다 |
| **별도 숫자 폰트**(D2Coding 등) | Pretendard의 `tnum`으로 해결돼 **불필요해졌다** |
| Wanted Sans · SUIT | 셋 다 내려받아 같은 화면에 적용해 비교. 사용자가 **Pretendard 선택** |
