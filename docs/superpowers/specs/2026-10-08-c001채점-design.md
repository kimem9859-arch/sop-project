## 1. 왜 이 채점인가

- 지금 시연 모델(`B-full-base-s0_ours-L2` · `T-full-base-albu-s0_ours-L2`)과 그 학습 설정은 **장소1 사진(2026-09-23 하루)으로만** 고르고 채점했다 — 「장소1 조건부 · 최종 모델 아님」(저널 §12.88 · §12.90). 장소1 채점은 버튼이 천장이고(§12.88), 공구 정답은 한 세션 126개라 후보를 가리지 못했다(§12.90 · §12.92).
- c001 은 학습 모델 누구도 배우지 않은 **장소2** 사진이다. 처음으로 「처음 보는 장소」 값을 얻는다. c001 사진은 2단계 학습에 들어가므로(사용자 2026-10-07) **이 채점은 지금 모델들에만 한 번 쓸 수 있다.**
- 앞 설계(시연모델-재학습HEF §1)는 HEF 4개(시드 1개씩)로 유지·교체를 정한다고 했다. 같은 설계가 「같은 설정의 시드끼리 채점 차이가 설정 사이 차이만큼 난다」고 적었으므로, **판정은 시드 3개 `.pt` 로 하고 HEF 는 시연 실제값·변환 손실 확인에 쓴다**(출발안 2026-10-07 · 이 설계에서 확정).

### 2.2 밝기 — 사용자 지적 확인

| 사진 회색 평균 | c001 사진 | 뜻 |
|---|---|---|
| 83 미만 | **4** | 장소1 정지 장면 중앙(83)보다 어둡다 — 머리움직임 2 · 콘솔전체 1 · 어두운 조명 1 · 최저 72 |
| 83 ~ 115 | 18 | 장소1 범위(장소1 공구 세션 114.8 까지) |
| 115 초과 | 172 | 장소1 보다 밝다(장면 6 은 모두 여기) |

- **맞다 — 장소2 에는 장소1 보다 어두운 사진도 있다.** 다만 c001 은 공구 기준으로 사진을 골라 어두운 사진이 4장(2%)뿐이다. 장소2 라벨 전체 624장으로는 83 미만이 30장이고, 그중 15장이 어두운 조명 세션 `191942` 에 있다.
- 그래서 「장소2 = 밝다」로 요약하지 않는다 — **대부분 밝고(같은 장면끼리 비교 = Rpi5 `조사/실콘솔-20261006/README.md` 「장소1 ↔ 장소2 환경 차이」) 일부는 장소1 보다 어둡다.**
- 밝기 띠의 경계(83 · 115)는 결과를 보기 전에 장소1 값으로 정했다 ✋.

### 2.3 보조 채점 — 어두운 조명 세션 22장 (참고) ✋

- 대상 = 세션 `20261006_191942_장소2_1` 의 라벨 22장 전부(c001 3장 + 학습 묶음 19장) — 조명 1~2개를 끄고 콘솔·버튼·놓은 공구·쥔 공구를 한 번에 찍은 「장소1 같은 조명 + 장소2 배경」 묶음(같은 README 「어두운 조명」 · 맨손만). 고르는 기준 = **촬영 조건(세션)** 이다 — 모델·밝기 값으로 고르지 않는다.
- 라벨 = 라벨러 + 사용자 2명 검토(학습 묶음 b015·b016 의 회수본 · c001 3장은 3회). 평가 모델 모두 장소2 를 배우지 않았으므로 누출이 없다.
- **판정에 쓰지 않는다** — 22장이라 종류마다 정답이 몇 개뿐이다. 값은 「어두운 조명에서 무엇을 틀리나」의 사진 목록으로만 쓴다.

## 4. 채점 방법 — 채점 도구 · 검출기 · 계산

> 이 절의 동작은 코드를 읽어 확인했고(파일·줄은 각 칸) §4.6 의 시험과 대조로 검증했다(2026-10-08). 남은 확인은 실행 전 관문(§4.7)이다.

### 4.0 무엇을 재나

- **사진 한 장마다 검출기가 내놓은 박스**를 사람이 그린 정답과 맞춰 본다. 시연의 뒷단 — 트래킹(같은 버튼을 2프레임 연속 봐야 확정 · `YOLO_CONFIRM_HITS` · 놓쳐도 5프레임 유지 · `YOLO_MAX_MISS`) · 손-버튼 판정 · FSM — 은 이 채점에 들어가지 않는다. 그래서 「검출기 값」이고, 시연 화면의 판정 정확도와는 다를 수 있다(§8).
- 두 길로 잰다 — `.pt`(학습 결과 그대로 · 파이 CPU) = 판정용 · HEF(정수 변환 · 파이 Hailo-8 · 시연 검출기) = 시연 실제값. 정답 맞추기 계산(§4.4)은 두 길이 **같은 함수**를 쓴다.

### 4.1 사진이 모델 앞에 오기까지 (두 길 공통)

### 4.2 `.pt` 길 — 채점 도구 = 학습 체계의 채점 함수 (`학습/scoring.py`)

| 단계 | 하는 일 | 코드 |

| ③ 정답 읽기 | `scoring.gts_from_lines` — 8종 라벨 번호(B1·B2·B3·B4·EMO·driver·wrench·pliers 순)를 이름으로 바꾸고 **그 무리 이름만** 남겨 무리 번호로 · 정규화 좌표 × 사진 크기 = 픽셀 | `scoring.py` 16~26행 · 시험 [1] |

- 일회용 스크립트는 ①~⑤ 를 `score_model` 과 같은 순서로 부르고 **사진별 기록**(정답 · 0.25 이상 예측)만 더 남긴다 ✋ — 계산을 새로 쓰지 않는다. 사진별 기록이 있어야 §6 오류 분석과 §5.4 박스 대조를 할 수 있다(`score_model` 은 요약만 돌려준다).
- 좌표 ↔ 늘리기 — 정답은 정규화 좌표(0~1)라 사진을 축마다 늘려도 같은 자리를 가리킨다. 예측도 ultralytics 가 넣은 사진(640×640) 좌표로 돌려주고 정답도 그 사진 크기로 바꾸므로 둘이 같은 좌표계다(학습 체계 채점과 같음).
- 환경 = 파이 `~/env/rfenv`(ultralytics 8.4.117 · torch 2.13 CPU · fp32). 학습 체계의 채점은 데스크톱(ultralytics 8.4.171 · RTX 5060 · fp32)이었다 → **판과 장치가 달라 값이 같다고 가정하지 않고 관문 ① 로 잰다.**

### 4.3 HEF 길 — 검출기 = 시연 `detector.HailoDetector` 그대로

| 단계 | 하는 일 | 코드 |
|---|---|---|
| ① 적재 | 공유 장치(`hailo_device.configure`)에 HEF 를 올린다 · 🔴 **한 프로세스에서 같은 HEF 를 두 번 올리면 두 번째 추론이 멈춘다** → HEF 마다 프로세스 하나 | `detector.py` 81~108행 · Rpi5 `CLAUDE.md` 「추론 백엔드」 |

### 4.4 정답 맞추기 계산 — `Demo/test/score_lib.py` (두 길 공통)

| 계산 | 방법 | 줄 |
|---|---|---|
| 맞음 · 잘못 찾음 · 놓침(운용점) | 점수 0.65 이상 예측만 → **종류마다** 점수 높은 예측부터, 아직 짝 없는 같은 종류 정답 중 IoU 가 가장 큰 것과 짝 → IoU ≥ 0.5 면 맞음(tp) · 아니면 잘못 찾음(fp) · 끝까지 짝 없는 정답 = 놓침(fn) | `operating_point` 104~135행 |
| 정밀도 · 재현율 | 정밀도 = tp ÷ (tp + fp) · 재현율 = tp ÷ (tp + fn) · 전체 정밀도 = 무리 안 종류 합으로 | 같은 함수 · `scoring.summarize` |
| 혼동표 | 종류를 가리지 않고 정답마다 IoU 가 가장 큰 예측과 짝(≥ 0.5) → 정답 종류 × 예측 종류 · 짝 없는 정답 = 「놓침」 열 · 짝 없는 예측 = 「오검출」 행 · 대각선 밖 = **오분류**(예: B3 를 EMO 로) | `confusion` 138~172행 |
| mAP50(참고) | 종류별 AP(모든 점 보간 · IoU 0.5)의 평균 — `.pt` 만 인용 | `average_precision` · `evaluate` |

- ⚠️ **오분류 한 건은 운용점에서 두 번 센다** — 예측 종류의 잘못 찾음 1 + 정답 종류의 놓침 1. 그래서 재현율·정밀도와 혼동표를 함께 본다.
- 이 사진들은 종류마다 박스가 한 장에 많아야 1개라(§2.1) 「놓침」이 곧 그 사진의 그 박스다.

### 5.1 Q3 지금 기준 ↔ 옛 설정

- 계산 = `ledger.adopt(옛 설정 3개, 지금 기준 3개, 무리)` — 판정 지표마다 「위로 갈림」(옛 최저 > 지금 최고) · 「아래로 갈림」(옛 최고 < 지금 최저) · 「겹침」. 효과가 없을 때 한 지표가 우연히 위로 갈릴 확률은 1/20 이다(1단계 설계 §15).
- `학습.py 판정` 은 운용 조건이 다르면 비교를 거부한다 — 여기서는 다른 점을 알고 견주므로 `ledger.adopt` 를 직접 부르고 다른 점을 결과에 적는다 ✋:
  - 버튼 `B-early-base` ↔ `B-full-base` — 멈춤(일찍 멈춤 ↔ 120 끝까지) · 나눔(`place1_v1` ↔ `place1_v2b`) · 판(A ↔ B) **셋이 다르다** → 「설정 묶음의 차이」로만 읽는다.

| 옛 설정이 위로 갈린 지표 ≥1 · 아래로 0 | 「장소2 에서 옛 설정이 낫다(<지표>)」 | **시연 모델 그대로**(사용자 2026-10-07) · 그 지표와 사진을 2단계 학습 설계에 넘긴다 |
