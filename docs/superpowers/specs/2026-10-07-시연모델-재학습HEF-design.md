## 2. 설계

### 2.1 모델 파일

- 두 HEF 를 `Rpi5/Demo/models/` 에 새 이름으로 복사한다 — `B-full-base-s0_ours-L2.hef` · `T-full-base-albu-s0_ours-L2.hef`. git 으로 추적한다(지금 `console_v1/v2.hef` 와 같은 방식 · 저장소 밖 경로를 가리키면 다른 클론에서 깨진다). 원본은 그대로 두고 sha256 이 같은지 확인한다.
- `console_v2.hef`·`tool_v3.pt` 는 지우지 않는다 — 되돌리기용이고, 지난 측정값의 조건이다.

### 2.2 설정(`config.py`)

| 이름 | 값 | 비고 |
| --- | --- | --- |
| `HEF_MODEL_PATH` | `models/B-full-base-s0_ours-L2.hef` | 되돌리기 = `console_v2.hef` |
| 🆕 `TOOL_BACKEND` | `"hailo"` | `"cpu"` = 종전 `tool_v3.pt` CPU 워커(되돌리기 스위치) |
| 🆕 `TOOL_HEF_PATH` | `models/T-full-base-albu-s0_ours-L2.hef` | |
| 🆕 `TOOL_NAMES` | `("driver", "wrench", "pliers")` | HEF 의 클래스 순서 — §12.89 채점(`score_hef --names driver,wrench,pliers`)·`bench_detector --tool-hef` 와 같은 순서 |
| `TOOL_CONF` · `TOOL_SCAN_INTERVAL_SEC` | 0.65 · 1.0 그대로 | 공구 문턱·간격은 바꾸지 않는다 |

### 2.3 공구 NPU 경로 — `tool_gate.py` 안만 바꾼다

> `tool_gate.py` 머리말이 처음부터 정해 둔 방식이다 — 「`.hef` 전환 시 이 파일의 안만 갈아끼운다 · 바깥 인터페이스(`start`·`stop`·`available`·`request`·`poll`)는 그대로 · `camera_thread`·`safety_console` 은 한 줄도 안 고친다」(설계 2026-08-14 공구입력-A2 §3).

| 때 | Hailo 갈래가 하는 일 |
| --- | --- |
| 만들 때(프로그램 시작 · 카메라 스레드가 돌기 전) | `detector.HailoDetector(hef_path=TOOL_HEF_PATH, names=TOOL_NAMES)` 로 **한 번 적재**(버튼·손과 같은 공유 장치 — `bench_detector --tool-hef` 와 같은 방법) |
| `start()` · `stop()` | 받기를 켜고 끈다 — 장치는 그대로 둔다 |
| `request(frame, fingertip)`(카메라 스레드 · 1초에 한 번) | **그 자리에서 추론**(재압축 없음 · 640 늘리기 = 학습·§12.89 채점과 같은 입력) → `TOOL_CONF` 미만을 버리고 `(이름, 점수, x1, y1, x2, y2)` 로 바꿔 그 프레임의 손끝과 함께 보관 |
| `poll()`(매 프레임) | 보관한 결과를 **한 번** 돌려주고 비운다 — 종전과 같은 모양 `(dets, fingertip)` |
| 적재 실패(파일 없음·장치 오류) | `available = False` + 눈에 띄는 로그(종전 방침) · 🔴 **CPU 로 저절로 바꾸지 않는다** — 다른 모델이 조용히 돌면 기준이 흐려진다 |

- **왜 시작 때 적재하나** — `start()` 는 화면 스레드에서 불린다. 거기서 장치를 구성하면 카메라 스레드의 버튼 추론과 겹친다. 세 모델 동시 적재는 10-06 에 NPU 여유가 확인됐다(Rpi5 `조사/실콘솔-20261006/README.md` 「재학습 모델 3종 NPU 동시」).
- **왜 카메라 스레드에서 그 자리에서 돌리나** — 버튼 → 손 → 공구를 같은 스레드가 차례로 부르면 장치 경쟁·잠금 문제가 없다(측정 도구가 같은 구조로 돌았다). 그 대가 = 공구를 돈 프레임 하나가 공구 추론 시간만큼 늦다(10-06 정지 장면 관찰 — 1초 간격에서 평균 FPS 차이는 보이지 않았다 · 같은 README). 처리 단계별 시간은 측정 도구 정합 1단계 `tool_ms`(26)가 시연 상태에서 잰다.
- **CPU 갈래(`tool_worker.py`)는 남긴다** — `TOOL_BACKEND="cpu"` 로 되돌릴 수 있게. 지우는 것은 최종 모델 때(머리말의 「그때 삭제」를 그 시점으로 고친다).

### 2.4 함께 바뀌는 것

| 곳 | 바뀌는 것 |
| --- | --- |
| config 를 읽는 측정 도구 | 기본 버튼 모델이 새 HEF 로(`bench_detector` · `replay_raw`·`score_hef` 의 기본값) · `tool_probe` 는 `ToolGate` 를 쓰므로 공구도 NPU 로 — 「도구는 config 에서 읽는다」(측정도구 스킬) 그대로 |

## 4. 버린 대안

| 대안 | 버린 이유 |
| --- | --- |
| 공구를 별도 스레드에서 버튼과 동시에 추론 | 공유 장치 경쟁·새 잠금 위험 · 10-06 측정으로 이득이 보이지 않았다 · 필요하면 1단계 `tool_ms` 를 보고 다시 |
| 서브 작업 시작 때 적재 · 끝날 때 해제 | 화면 스레드의 장치 구성이 카메라 추론과 겹친다 · 매 단계 적재 지연 |

| 적재 실패 시 CPU 로 자동 전환 | 다른 모델이 조용히 돌아 기준이 흐려진다 |
| HEF 가 이미 있는 옛 설정 모델(`B-early-base-s0` · `T-full-base-s0`) | 버튼은 일찍 멈춤 함정이 있는 1단계 설정 · 공구는 증강 라이브러리 전 판 — 사용자 「설계가 부족한 모델 말고 · 최고 성능」 · 장소2 채점 때 대조군으로만 |
| 원본 경로(`~/data/학습실험/…`)를 config 가 직접 가리키기 | 저장소 밖 — 다른 클론·파이2 에서 깨진다 · `console_v2.hef` 와 같은 자리에 둔다 |
