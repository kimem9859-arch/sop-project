## 1. 목적과 범위

**목적** — 9/28 사용자 결정대로 **글라스 ESP32 1장 + LLM 을 쓰는 음성비서가 시연에서 실패 없이 돈다.** 시연자가 절차서만 따라 하면 켜지고, 묻고 답하는 동안 귀가 먹지 않고, 순서 위반을 권하는 답을 내지 않는다.

**범위** — 4단계로 나눈다. 실행 순서는 **1 → 3 → 2**(2단계의 굽기는 실물 세션 · 4단계 일부는 10/03 완료).

## 4. 1단계 — 음성 런타임 안정화 (파이1 코드)

### 4.1 마이크 수신 분리 — P1·P5·Q7
- **수신 스레드**가 업링크 소켓을 늘 읽어 **시각이 붙은 버퍼**(링 · 최근 `WINDOW_SEC + LAG_LIMIT`)에 쌓는다. 메인 루프는 LLM·합성·재생 중에도 수신이 멈추지 않는다 → 커널 수신 큐가 차지 않아 펌웨어가 업링크를 끊지 않는다.
- **대답 중 들어온 소리 버리기(G11)** — 대답을 시작한 시각 ~ 재생이 끝난 시각 사이의 소리는 시각 기준으로 버린다(지금 `del buf[:]` 대체). 띠링·답 반향도 함께 걸러진다.
- **반열림 감지** — 수신 스레드가 **연속 무수신 N초**(펌웨어는 접속 중 32KB/s 를 쉬지 않고 보냄 → N = 3초)면 재접속한다. 재접속 뒤 명령 채널을 미리 붙인다(Q3).
- **VAD 효율화** — 새 소리가 `VAD_HOP_SEC`(0.25초) 쌓였을 때만 판정하고, `find_utterance` 에 리스트가 아니라 배열을 넘기며 `_frame_rms` 를 한 번만 계산한다(R2 실측 — 배열 전달만으로 한 자릿수 배 이상 감소). 같은 녹음에서 **같은 발화를 잡는지** 시험으로 지킨다.
- `LAG_LIMIT` 는 실제 지연(도착 시각 대비)을 재도록 고친다(R2 M3).

### 4.2 LLM 가용성 — P2·Q6 (D1)
- **예열** — 데몬이 켜질 때 배경에서 예열 요청 1회(타임아웃 ≥ 90초 · 실제 요청과 **같은 `options`**(`num_ctx` 등) — 다르면 재적재). 예열 전 질문은 「준비 중」 고정 문장 또는 A 갈래.
- **상주** — 모든 요청에 `keep_alive: -1`(D1). 데몬 종료 때 해제는 하지 않는다(파이2 = LLM 전용).
- **연속 실패 건너뛰기** — LLM 실패가 3회 이어지면 60초 동안 LLM 을 건너뛰고 A 갈래로 답한 뒤 배경 예열로 회복을 시도한다(질문마다 15~17초 기다리지 않게).
- **매 요청 적재 시간의 원인 조사** — 데운 상태인데 `load_duration` 이 매번 나온다(R3·10/03 실측). 옵션 불일치·컨텍스트 재사용 여부를 파이2 에서 확인하고, 줄일 수 있으면 줄인다. prefill 은 카드·SYSTEM 을 줄여 낮춘다.
- **타임아웃** — 질문 세트 실측(§4.7)의 LLM 시간 p99 + 여유로 다시 정한다. 길이 상한(§4.3)이 펌웨어 한도를 막으므로 타임아웃을 늘려도 P4 가 넓어지지 않는다.

### 4.3 답 길이 — P4·Q5 (D2 · C2)
1. **SYSTEM 규칙** — 「한 문장 · 60자 안팎」. `num_predict` 를 그에 맞춰 줄인다(시작값 40 · 질문 세트로 조정).
2. **문장 경계 자르기** — 첫 문장 끝(마침표·물음표·느낌표)에서 자르고, 그래도 길면 60자 근처 어절 경계에서 자른 뒤 마침표를 붙인다. 카드 표기(`[사실]`·`🔴` 등)를 지운다.
3. **전송 전 표본 수 검사** — 합성 결과가 `MAX_SAMPLE`(240,000)를 넘거나 레이트가 8,000~24,000 밖이면 보내지 않고 A 갈래로 답한다. 한도는 펌웨어와 **같은 상수**를 쓰도록 한 곳에 둔다.

### 4.4 답 안전·정확성 — P3·Q4·Q5 (C3)
- **카드** — 「지금 눌러야 할 버튼 B2」 유지 · 「그 다음 단계 … 버튼 B3」 는 **「현재 단계가 끝난 뒤에만 누른다」**를 같은 줄에 붙인다. 서브 작업 진행 여부·남은 초·공구 충족을 카드에 넣는다.
- **상태 파일** — `safety_console._publish_state` 가 서브 작업의 **진행 상태**(진행 중/멈춤/남은 초/공구 충족)를 싣고, 공구 판정이 바뀔 때도 공개한다(R2 M5).
- **검산 규칙 추가** — 답에 `B1~B4`/`EMO` 가 나오고 그것이 현재 버튼이 아니며 「누르」 계열 동사가 함께 있으면 버리고 **「지금은 {현재 버튼} 차례입니다.」**(짧은 합성)로 답한다. 허가 표현(`llm_gate._PERMIT` 목록)이 있으면 버린다. 「두 번째 단계」·「2번 단계」 같은 표기도 단계 대조에 넣는다(R2 M4).
- **카드에 없는 진행 사실** — 「끝났습니다」·「완료됐습니다」류가 카드의 진행 상태와 어긋나면 버린다.

### 4.5 재생 견고성 — Q1·Q2·Q3
- LLM 답 재생이 실패하면 A 갈래 답을 **한 번** 재생한다(펌웨어 FAIL 이면 채널을 다시 붙인 뒤).
- `Speaker` 는 주소를 **매번 다시 읽는다**(마이크가 실제로 붙은 주소를 공유).
- 명령 채널 EOF 를 즉시 감지해 재접속하고, 로그 문구를 사실대로(EOF/시간 초과 구분).
- `_drain` 은 요청에 대한 응답만 확인으로 받는다(엉뚱한 `[재생 완료]` 거부).

### 4.6 상시 가동 — Q8 (D1′)
- 음성비서를 **시연 프로그램과 함께 자동 시작**하고 죽으면 다시 띄운다. 방식은 계획서에서 정한다(후보: `run_demo.sh` 가 함께 띄우고 감시 · 사용자 systemd 유닛). 시연 프로그램 없이 음성비서만 띄우는 기존 경로(`run_voice.sh`)는 남긴다.
- 메인 루프 반복마다 예외를 잡아 로그를 남기고 계속한다.
- 기동 로그에 **준비 상태 한 줄**(마이크 연결 · 명령 채널 · STT · TTS · LLM 예열 결과)을 남긴다 — 절차서가 이 줄을 확인한다.

## 5. 2단계 — 펌웨어 `glass_voice` (컴파일까지 · Q12·P4)
- **카메라 이식** — `camera_stream_tcp` 의 5fb728b(XGA · 부팅 노출 `0x3A0E=2`) · bf5e62f 중 `printExposure`(부팅·5초 상태) · bd6826d(센서 식별 로그). 🔴 **시리얼 진단 명령(`R:`·`W:`·`EXP:`)은 옮기지 않는다** — 오디오 명령 태스크와 시리얼을 나눠 읽어 섞인다. 노출 쓰기 **결과를 출력**한다(⏸ 「0x3A0E 쓰기 로그」 해소). 머리 주석에 「마지막 동기화 = camera_stream_tcp 5fb728b」.
- **`W` 거절 시 본문 처리** — 범위를 벗어나면 `n×2 + 4` 바이트를 읽어 버린 뒤 `[FAIL]` — 남은 PCM 이 명령으로 실행되는 것을 막는다(파이 쪽 §4.3 과 이중 방어).
- **시리얼 충돌** — `loop()` 의 시리얼 읽기를 없애고 `RESET_WIFI` 를 오디오 명령 문법 안으로 옮긴다(시리얼 읽는 곳을 한 곳으로). 응답은 모두 `io->` 로(M1). PSRAM 할당 실패 검사(M11).
- **업링크 write 실패** — 끊지 말고 그 조각을 버린다(C1 이중 방어 · 파이 수신 스레드가 주 처방).
- 검증 = `arduino-cli compile`(출력 = 임시 폴더) 통과. 🔴 **굽기는 실물 세션** — 시리얼번호(메인 `3C:0F:02:DD:5E:58`) 확인 · 비밀번호 변경(D5) 뒤 새 자격 증명으로.
