# 공구 검출 모델 `tool_v1` — 데이터 준비 + 학습(.pt) 설계

- **날짜**: 2026-08-10
- **범위**: 데이터 준비 + 학습(.pt) + 검증(눈 확인 + ARCAD 자동 mAP). **.hef 변환·파이 배포·판정 규칙 설계는 이 세션 범위 밖**(다음 세션).
- **선행**: §10.35(외부 데이터셋 조사 + 도메인 갭 사전 측정 — 판정 "go"). 이 설계는 그 ▶다음 #1 "ARCAD로 직접 학습"의 실행 설계다.
- **정본 주의**: 이 문서엔 논의·결정·미결만 둔다. **확정 측정 수치(mAP 등)는 통합문서 §10(신설 §10.36 예정)에만** 기록한다(drift 방지, CLAUDE.md §3).

## 1. 목표·성공기준

ARCAD 3클래스 데이터로 `yolov8n@640`을 학습해 `tool_v1.pt`를 만든다. 공구 서브작업(`recipe.json` `wait_tool`)에 필요한 **공구 검출 모델의 첫 산출물**이다.

**성공기준**
- `tool_v1.pt`가 생성된다.
- 학습의 부산물로 **ARCAD valid mAP**가 나온다(라벨링 0 — ARCAD가 검증 정답을 이미 보유).
- 파이 `tools-baseline`(360장, §10.35) 영상에 `.pt`를 돌려 **눈 확인**에서 스패너·드라이버가 잡힌다.

🔴 **과장 금지 (CLAUDE.md §5)**
- ARCAD valid mAP는 **ARCAD 도메인 점수**지 우리 ESP32 카메라 성능이 아니다.
- 파이 영상엔 **스패너·미니드라이버 2종뿐, 렌치가 없다** → 렌치는 이번 눈 확인 대상이 아니다.
- 이 세션은 "학습된 모델이 동작한다"까지다. "검증 완료"로 쓰지 않는다.

## 4. 증강 — console_v2와 정반대 (이 설계의 핵심)

버튼(console)은 **색이 클래스 정의**라 `hsv_h=0`으로 색 흔들기를 금지했다. 공구는 **색이 클래스와 무관**하고 조명·재질이 다양하므로 **색·기하 증강을 켠다.**

| 항목 | console_v2 | **tool_v1** | 이유 |
|---|---|---|---|
| `hsv_h`(색상) | 0 (금지) | **켬**(Ultralytics 기본 0.015 수용) | 공구는 색이 클래스 아님 |
| `hsv_s`/`hsv_v` | 소폭 | 기본 유지 | 조명·채도 다양성 |
| 좌우 뒤집기 `fliplr` | — | 켬(기본 0.5) | 공구는 좌우 방향 자유 |
| 상하 뒤집기 `flipud` | 꺼짐 | **켬(예: 0.5)** | 1인칭 시점에서 공구가 뒤집혀 보임 |
| 회전 `degrees` | ±15° | **넓게(예: ±30°)** | 공구는 회전 자유 |
| 저조도 커스텀 albumentations | 사용 | **초기 미사용(YAGNI)** | ESP32 실평가(다음 세션)에서 약점 보이면 그때 추가 |

- 구현: console_v2와 동일하게 **Ultralytics 공식 `augmentations=`/하이퍼파라미터로 주입**(몽키패치 금지 — console_v2 가이드 2026-07-16 정정 참조). 다만 tool은 대부분 **기본값이 이미 맞아** override가 적다(색·좌우뒤집기 기본 ON).
- 🔴 **미결**: `flipud`·`degrees` 정확한 값은 스모크 후 조정 가능. 확정값은 학습 후 §10.36에 기록.

## 6. 검증 (라벨링 없음)

두 갈래로 확인한다. **둘 다 라벨링 0.**

1. **ARCAD 자동 mAP** — ARCAD valid에 정답이 이미 있어 Ultralytics가 학습 종료 시 mAP50/recall/precision을 자동 산출. 우리 작업 0. → 학습이 정상적으로 배웠는지 **빠른 산정(sanity)**.
2. **파이 영상 눈 확인** — `tools-baseline` 360장(§10.35, 파이 로컬·gitignore)에 `tool_v1.pt`를 돌려(Ultralytics, CPU 가능·Hailo 불필요) 스패너·드라이버가 **화면에서 옳게 잡히는지 눈으로 확인**. 숫자 채점 아님.

**왜 이 단계에서 정식 채점(라벨링)을 안 하나** — 이번 목표는 "학습된 모델이 우리 도메인에서 동작하나"까지이고, 그건 눈 확인으로 답한다. 정식 mAP 채점은 ①tool_v2 재학습과의 비교 ②임계 정밀 튜닝 ③"검증 완료" 기록 주장이 필요할 때 값을 한다(그때 파이 영상 일부 수동 라벨링). 지금은 불필요 → YAGNI.

## 9. 거부한 대안

- **console_v2에 공구를 합쳐 8클래스로**: 색 증강 정면 충돌(버튼은 hsv_h=0, 공구는 색 필요) + 학습→DFC→replay 사슬 전체 무효화 + 미판정 B4까지 재교란 → **별도 모델로 확정**(§10.35 log).
- **자체 촬영·라벨링으로 데이터 구축**: 시간 최대. 도메인 갭 사전 측정이 "외부 데이터로 충분(go)"을 보여 불필요(§10.35).
- **로컬 GPU 강제**: RTX 5060은 DFC가 막히고, 학습은 Colab로 충분(검증된 console_v1 경로). GPU는 필수 아님.
- **이번 세션 정식 채점(라벨링)**: 우리 영상 라벨이 없고, 목표가 "동작 확인"이라 눈 확인으로 대체. 정식 채점은 값을 할 때로 미룸.
