## 1. 목적과 성공 기준

- **목적** — 실콘솔(시연용 콘솔 · 버튼 B1~B4·EMO · 아두이노 인터락 · 타워램프)과 카메라 안경을 펼치는 **하루 한 번**에, 그것이 있어야만 할 수 있는 대기 작업을 빠뜨리지 않고 끝낸다.
- **성공 기준**
  1. 장소2·3 사진이 현장 장수 세기에서 모두 ✅(정본 = `capture_dataset.py` 의 `MIN_KEEP`).
  2. 아래 §2 「넣은 것」마다 결과가 **통과 / 미달 / 못 함(이유)** 중 하나로 남는다. 미달·못 함도 결과다.
  3. 철수할 때 안경 펌웨어가 들어올 때와 같다(XGA · `[카메라] 1024×768`).
  4. 결과 자료(로그·장수 세기·점검표)가 커밋되고, 공동 확인 뒤 `work-close` 로 정본에 들어간다.

## 3. 제약

- **🔴 안경 펌웨어를 굽지 않는다** — 장소1 사진과 같은 XGA · 노출 9ms 조건이어야 한다(촬영지시서 §1). 이번 범위에 굽기는 아두이노(CH5) 하나뿐이다.
- **🔴 음성·소리 끔** — 모든 실행에 `SOP_VOICE=0 SOP_VOICE_ALERTS=0` ✋. 타워램프 부저는 콘솔 장치이고 CH5 회귀 확인(§11.5-7) 대상이라 그대로 둔다 ✋.
- **실HW 는 한 번에 하나** — 카메라(8888 손님 하나) · Hailo · GPIO 가 각 하나다. 촬영 도구·시연 프로그램·측정 도구를 겹쳐 띄우지 않는다.
- **🔴 CH5 는 펌웨어 먼저, 가닥은 나중** — 반대면 버튼이 전부 죽는다(2026-09-05). 실패하면 콘솔 버튼이 먹통이 될 수 있어 **하루의 맨 끝**에 둔다.
- **디스크** — 2026-10-06 `/` 여유 3.7G(조사 값). 장소2 2~4G + 장소3 1~2G(촬영지시서) + `run_scenario` 녹화 + 여유 → **출발 전 9G 이상** ✋.

## 4. 하루 순서

| 순서 | 작업 | 시간(추정 ✋) | 끝 조건 |
|---|---|---|---|
| S0 | 설치·점검 — 공유기 먼저 → 1분 → 안경 → 시리얼 `3C:0F:02:DD:5E:58` 확인 → 안경 보드 통째 백업(읽기만) → `read_esp32_ip.sh` → 디스크 | 30분 | `192.168.1.x` · 백업 md5 · 9G 이상 |
| S1 | A 장소2 — 장소 고르기 → 촬영(약 29분) → 장수 세기 → 모자라면 더 찍기 | 50분 | 장수 세기 ✅ |
| S2 | B 장소3 — 장소1·2 와 배경·조명이 가장 다른 곳 → 촬영(약 13분) → 장수 세기 | 40분 | 장수 세기 ✅ · 🔒 봉인 |
| S3 | C·D 콘솔 확인 — `run_scenario.sh 2` 한 번에 | 45분 | Task 6 ⓐ~ⓓ · D 세 가지 결과 |
| S4 | E 처리 속도 — 카메라 고정 거치 · S2 3회 · S6 2회 | 30분 | 합격선(§12.72 머리) 판정 |
| S5 | G 발표 사진(폰) | 5분 | 사진 2장 |
| S6 | F CH5 — §11.7 의 0~6 | 60~90분 | 7항목 · 40/40 · 자가 테스트 |
| S7 | 철수 전 — `[카메라] 1024×768` · 결과 파일 목록 · 커밋 | 15분 | §1 성공 기준 3·4 |

합계 약 4.5~5.5시간 — 하루에 여유를 둔다.

**순서 이유** — ①촬영이 가장 크고 다음 작업(장소2 라벨링 → 2단계 학습)이 기다린다 ②장소3 은 장소2 를 본 뒤 「가장 다른 곳」을 고를 수 있다 ③콘솔 확인·처리 속도는 펌웨어·배선을 바꾸지 않는다 ④CH5 는 실패하면 버튼이 죽으므로 맨 끝 ✋.

**시간이 모자라면** — 뒤에서부터 미룬다(G → E → F 순으로 버림 ✋ · A·B 는 버리지 않는다). 미룬 것은 `work-close` 에서 ⏸ 로 남긴다 — 다음 방문(시연 동영상)과 묶을 수 있다.

## 6. 관문

### ① 중단 규칙

| 상황 | 할 일 |
|---|---|
| 안경 IP 가 `10.47.16.x` | 안경만 껐다 켬 → 다시 확인. 두 번째도 같으면 공유기를 껐다 켜고 1분 뒤 안경 |
| 촬영 도구가 `[카메라] 1024×768` 아님 | 🛑 촬영하지 않는다(펌웨어가 바뀐 것) — 사용자와 원인부터 |
| 저장 실패 🔴 | 🛑 그 장소 촬영을 멈추고 디스크부터 |
| C — 보면서 눌렀는데 미확인이 절반 이상 | 🛑 plan `2026-09-30` 🛑 4 — 사용자와 확인 창(2.0초) 값을 정한다 |
| E — 합격선 미달 | 한 번에 한 요인씩 끄고 다시(왜곡보정 → 손 모델 · §12.72-(12)). 펌웨어·설정은 바꾸지 않는다 |
| F — CH1 COM ↔ CH5 COM 도통 | 🛑 이 모듈로는 못 쓴다 — 가닥을 옮기지 않고 끝 |
| F — 굽기 뒤 `RUN` 에서 CH5 LED 꺼짐 | 굽기로 돌아간다(§11.7-3) |
| F — 가닥을 옮긴 뒤 정상에서 버튼이 안 옴 | 🛑 가닥을 브레드보드 GND 로 되돌려 버튼을 살리고 끝 → 원인은 집에서 |

### ② 🔒 홀드아웃

- **장소3 사진 = 시험 전용 봉인** — `~/data/capture_장소3/` 에만 둔다. 학습·검증·초벌 모델 고르기·문턱 정하기에 쓰지 않는다. 현장에서는 장수 세기만 한다(세기는 사진을 판정에 쓰지 않는다).
- 이번 작업은 모델·문턱·판정 코드를 바꾸지 않는다. CH5 는 아두이노 펌웨어만이고 파이 쪽 `interlock.py`·`fsm.py` 는 손대지 않는다(§11.3).

### ③ 검증 관문

- 촬영 — 장수 세기 ✅(장소마다).
- C·D — 결과를 표로 보고 → **사용자 판정**(공동 확인).
- E — 측정 결과(perf_log 원본)에서 합격선 대조.
- F — §11.5 7항목 + 디바운스 40/40(점검문서 §6.4) + 자가 테스트 전부(아두이노 꽂은 채 · 램프 변화 없음).
- 철수 — `[카메라] 1024×768` · 출발 전 기준선과 같은 자가 테스트 결과.
