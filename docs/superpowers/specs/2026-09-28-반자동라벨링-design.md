## 5. 초벌

### 5.1 버튼 — 조각 방식

- **문제** — 지금 방식(세로 768×1024 를 통째로 640×640 으로 늘림)은 학습 때(가로 VGA 를 640×640 으로 늘림)와 **늘어나는 방향이 반대**다(이전 코드 조사 §7.1-2). 그 결과 초벌 박스가 **세로로만 느슨**했고, 움직이는 장면에서 B3 를 EMO 로 잡는 일이 많았다(원자료 = 조사 폴더 `결과_*.txt`).
- **방법** — 세로 사진을 **가로 모양 두 조각**(위·아래, 각 768×576, 128px 겹침)으로 잘라 각각 640×640 으로 늘려 검출한다. 모델이 **학습 때와 같은 늘림 방향**을 본다.
- **합치기** — 같은 클래스 박스가 IoU 0.3 을 넘으면 하나만 남긴다(조각 경계에 잘리지 않은 것 → 점수 높은 것 순). 조각 경계에 닿아 **잘린 박스**가 같은 클래스의 온전한 박스 안에 넓이 50% 이상 들어가면 버린다.
- **점수 기준** = `config.YOLO_CONF_LOW`(실제 시연과 같은 값) ✋ — 점수를 라벨 파일에 함께 남겨 집계(§9)로 조정한다.
- **버린 대안** — 박스 높이만 줄이기(느슨함은 줄지만 B3↔EMO 는 그대로) · 정사각형 여백 채우기(조각보다 덜 맞는다). 둘 다 조사 폴더 `결과_초벌방식4가지.txt`.
- ⚠️ **한계** — 근거는 한 장소 세 장면의 **개수 대조 + 눈 확인**이다(정답 대조는 하지 않는다 — 실험 1 취소 §13). 조각 방식은 세로를 **몇 % 짧게** 그리는 치우침이 남는다(`결과_지금vs조각_윤곽문턱별.txt`) → 첫 묶음 집계에서 기계 검토 뒤에도 **아래 끝선이 짧게** 남았다(§6 ①). B4 는 여기서 박스 맞음을 재지 않았다(§6 에서 맞춘다).

### 5.2 공구 · 기존 라벨

- **공구** = `tool_v3.pt`(파이 CPU · `~/env/rfenv`) · 점수 기준 0.25 ✋ — 우리 환경에서 거의 못 잡으므로(초벌 미리보기) 낮게 두고 집계로 조정한다. **첫 라운드 공구는 사실상 수작업**이다.
- **기존 라벨이 있는 사진**(09-04 공구 PNG) = 그 라벨을 초벌로 쓴다(§10).
- 묶음 기록에 **모델 파일 · 방식 · 점수 기준**을 남긴다 — 라운드마다 무엇으로 만든 초벌인지 가르기 위해.

## 6. 기계 검토 — 버튼

> 근거 = Rpi5 `조사/기계검토-20260928/`(시험 스크립트·결과·사용자 표본 눈 검사). 🔴 **정답(사람 라벨)과 대조한 값이 아니다** — 검증은 묶음마다의 사용자 표본 눈 검사(§11)와 수정 집계(§9)다(실험 1 취소 — §13).

- **목적** — 버튼 박스는 기계가 확정하고, 사람은 **기계가 넘긴 것만** 본다. 공구는 이 단계 밖(사람이 전부).
- **① 박스 맞추기** — 초벌 박스 둘레 배경과의 색 거리(Lab)로 버튼 영역을 찾는다. 오츠 문턱으로 버튼 속을 찾고, **속 거리 중앙값의 35% 를 가장자리**로 삼아 외접 사각형을 새 박스로 한다 ✋(확대 사진 눈 비교로 정함 — 오츠만 쓰면 그늘진 가장자리를 잘라먹고, 20% 면 주변 빛 번짐까지 넣는다). **B4 포함** — 실콘솔 B4 는 윗면 전체가 파랗게 보인다.
  - 🔴 **35% 를 그대로 쓴다 — 사람 끝선에 맞추는 보정은 하지 않는다**(사용자 결정 2026-09-28 · 「크게 심각하진 않은거 같아」). 공식 문서에 없는 자체 약속이다(박스 여백 조사). 첫 묶음 b001 의 수정 집계와 표본 눈 검사에서 **자주 보이는 치우침 둘**이 확인됐다 — ⓐ 아래 끝선이 버튼 끝보다 위(B1 제외 전 버튼) ⓑ B4 만 위 끝선이 버튼 위 끝보다 위. 둘 다 **문턱·오프셋으로 고치지 않고, 검토 때 손으로 맞추지도 않는다.** 치우침은 버튼 크기에 비례하지 않고 박스마다 흩어짐이 커서, 한 값으로 맞추면 평균만 없어진다. 수치 = Rpi5 `조사/반자동라벨링-첫묶음/b001_결과.txt`(정본은 저널 새 절). 문턱을 바꾸게 되더라도 **여백을 더하는 쪽이 아니고**, 장소3 시험 라벨로는 맞추지 않는다(§11 시험 순환 금지).
- **② 이름 교차 확인** — 서로 다른 증거 셋.
  - **배치 틀** — 판에 고정된 버튼 5개의 상대 위치. 보이는 버튼이 2~3개면 닮음 변환(이동·회전·배율), **4개 이상이면 아핀 변환**(판 기울기·원근을 흡수)을 맞춰 각 박스의 자리를 정한다. **「어느 박스든 다른 자리로 배정한 경우」와 비용이 충분히 벌어질 때만** 자리를 믿는다. 2개면 버튼 간격 ÷ 크기 비로 배율을 따로 확인한다.
  - **색 계열** — 흰(B2) · 노랑(B1) · 파랑(B4) · 빨강 계열(B3·EMO).
  - **EMO 흰 테두리 무늬** — 빨강 계열에서만 본다. 움직이면 무늬가 흐려지므로 **확실할 때만 반대 증거**로 쓴다(무늬가 뚜렷한데 B3 · 무늬가 전혀 없는데 EMO).
- **③ 기계 확정 조건** — 초벌 이름 = 배치 틀 자리 · 색 계열 일치 · 무늬 반대 증거 없음 · 박스 맞추기 성공(배경으로 새지 않음 · 속이 찬 타원 · 배치 틀이 예상한 크기와 비슷) · 흐리지 않음. **하나라도 어긋나면 사람에게 넘기고 이유를 라벨 파일에 적는다.** 보이는 버튼이 1개인 사진은 전부 사람에게.
- **④ 빠진 자리 제안** — 버튼이 3개 이상 보일 때, 배치 틀이 가리키는 빈 자리에 제안 박스를 둔다 → 사람이 확정하거나 지운다.
- **⑤ 가려진 버튼** — 보이는 테두리로 원을 계산하지 **않는다**(비스듬히 보면 타원 · 흔들리면 잔상 — 사용자 지적). 가림이 감지되면(배경으로 샘 · 모양·크기 이상) 사람에게 넘긴다.
- **⑥ 검토 순서** — 파일 이름 앞 순서 표시로 X-AnyLabeling 목록에서 **사람 확인 박스가 있는 사진 → 빠진 자리 제안이 있는 사진 → 기계 확정만 있는 사진 → 흐림 후보** 순. 원래 이름은 뒤에 그대로 두고 묶음 기록에 대응표를 남긴다. 기계는 초벌 이름을 **자동으로 바꾸지 않는다**(틀린 라벨이 빠진 라벨보다 해롭다 — 자동 라벨링 조사).
- **⑦ 문턱** — 무늬 · 흐림 · 속 찬 정도 · 배치 틀은 장소1 정지 장면에서 만든다. 장소가 바뀌면(장소2 등) 그 장소 정지 장면으로 다시 만든다 ✋.
- ⚠️ **한계** — 한 장소·하루 촬영분에서 만들었다. 가장자리 35% 는 눈으로 정했고 사람 끝선에 맞추지 않았다(① — 알려진 치우침 둘). 배치 틀·문턱을 만든 정지 장면이 집계에도 들어 있어 정지 장면 값은 낙관적이다.

## 6-b. 박스 끝선 규칙 — 사람과 기계가 같은 선을 쓴다

> 근거 = `dev/ai_model/조사/reports/박스 여백 라벨링 기준 조사.md`. 공개 데이터셋 지침·Ultralytics·AWS 가 모두 「보이는 가장 바깥 픽셀에 붙인다」고 하고, 여백을 권하는 1차 공식 문서는 없었다.

- **여백은 두지 않는다** — 네 변을 버튼의 가장 바깥 보이는 픽셀에 붙인다. 그늘진 테두리는 넣고, 둘레의 빛 번짐·그림자·반사는 뺀다.
- **손끝 판정의 여유는 라벨이 아니라 실제 시연 프로그램의 링(`HAND_ROI_RING_PX_VGA`)으로 준다** — 라벨에 여백을 넣으면 작은 버튼의 판정 영역이 크게 부푼다.
- **이 규칙은 학습·검증·시험(대부분 기계가 그림)과 장소3 검증 표본(사람이 그림)에 똑같이 쓴다** — 작은 버튼에서는 한 변 1~2 px 차이가 정밀 지표를 크게 깎으므로, 두 라벨러(기계·사람)의 끝선이 같은지가 여백 여부보다 중요하다.
  - ⚠️ **기계 끝선에는 알려진 치우침 둘이 남는다**(§6 ① — 아래 끝선 짧음 · B4 위 끝선 넘침). 사람이 **새로 그리는** 박스는 이 규칙대로 그리고, 기계 박스의 이 두 치우침은 검토 때 고치지 않는다(사용자 결정 2026-09-28). 그래서 사람이 그린 검증 표본과 기계 라벨 사이에는 이만큼의 끝선 차이가 있다 — §7-b ④ 가 끝선을 채택 판정에 쓰지 않는 이유다.
- 라벨 가이드 문구 보강(번진 가장자리 · 손가락 가림 문구 · 예시 사진)은 **사용자 확인 뒤** `Rpi5/Demo/docs/labeling_guide.md` 에 반영한다(가이드는 사용자 확정 문서다).

## 7-b. 시험 세트(장소3) 만들기 — 기계 흐름 + 전체 검토 + 초벌 없는 검증 표본

> 사용자 승인 2026-09-28. 이유 — 시험 세트의 목적은 「처음 보는 장소에서도 되나」(2026-09-16 §4)이고, 필요한 것은 사람 손 라벨이 아니라 **그 장소에서 맞는 정답**이다. 기계 흐름을 쓰면 학습 라벨과 **끝선이 같아진다**(§6-b · 박스 여백 조사의 가장 큰 위험 제거). 남는 위험은 **내용 오류**(이름 · 빠짐 · 가짜)를 초벌을 보며 검토하다 같이 놓치는 것이고, 새 모델이 같은 흐름의 라벨로 배워 **같은 곳에서 같이 틀리면** 점수가 부풀려진다. 아래 순서가 그 위험을 잰다.

1. **검증 표본 먼저** — 장소3 촬영분을 §4 로 분류한 뒤, 세션별 무작위(시드 고정 · 최소 간격)로 **약 30장** ✋을 뽑는다. 사용자가 **초벌을 보지 않고** 처음부터 그린다. 이 표본의 초벌·기계 검토 결과는 사용자에게 보이지 않는다.
2. **나머지** — 초벌(지금 모델 `console_v2`·`tool_v3` — **평가받는 새 모델도, 라벨링 보조로 반복 학습한 `tool_rN`·`button_rN` 도 쓰지 않는다** · spec `2026-09-28-공구초벌-반복학습` §7 · spec `2026-09-29-버튼초벌-반복학습` §9) → 기계 검토(§6) → 사용자가 **모든 사진·모든 박스를 검토**(기계 확정분과 빠진 물체까지). 기계 확정도 시험에서는 확정이 아니다.
3. **검증** — 표본 30장에 같은 기계 흐름을 돌려(사람 검토 전 상태) 사용자 라벨과 대조한다: 클래스별 이름 틀림 · 빠짐 · 가짜 · 변마다 끝선 차이.
4. **채택 조건** — 이름 틀림 0 · 빠짐·가짜가 계획서에서 정한 기준 이하. 넘는 유형(예: 어두운 B3·EMO)은 **그 유형만 사람이 처음부터** 그린다. **끝선 차이는 기록만 하고 판정에 쓰지 않는다**(사용자 승인 2026-09-28 — 기계 끝선의 알려진 치우침(§6 ①)은 학습 라벨과 같아 시험 라벨과 서로 어긋나지 않는다 · 판정 기준이던 「사람 자기 반복 흔들림」은 실험 1 취소로 재지 않는다).
5. 🔴 **시험 사진으로 기계 검토를 맞추지 않는다** — 끝선·문턱은 조정하지 않는다(§6 ①). 표본 30장은 검증에만 쓴다.

## 9. 수정 집계 — 기계 검토 오류의 측정
