# 변경이력 문서 신설 — 설계

> 상태: ✅ 완료(2026-09-18) — 실행 = `plans/2026-09-18-변경이력-문서.md` · 결과 = `docs/변경이력.md` · 선행 = `2026-09-18-정본-구조재편-design.md`(뼈대 재편) · 결정 = 사용자 2026-09-18

## 1. 무엇을·왜

**통합문서에 현행 사실과 폐기된 사실이 섞여 있어, 폐기된 줄을 현행으로 읽는 사고가 실제로 났다.**

2026-08-29(커밋 `65534cb`) — 제출문서 작업 중 통합문서 §14.1(당시 §11.1)의 **낡은 서술**을 근거로 **버튼 수를 「8개」로 잘못 정정**했다. 실물은 2026-08-06 에 **5개**(B1~B4 + EMO)로 확정돼 있었고, 통합문서 4곳이 3주간 안 고쳐진 채였다. 같은 커밋에서 터치 디스플레이 「출력 전용」 오기도 함께 정정했다.

그때 재발 방지로 넣은 것이 §14.1 의 `📜 이력 — 모조 콘솔에는 8개가 있었고…` 한 줄인데, **2026-09-18 구조 재편에서 R5(사실은 한 곳에만)·R9(경위는 본문 밖)를 근거로 지웠다.** 지금 이 설계는 그 지운 내용이 갈 자리를 만드는 것이다.

🔴 **이 문서가 막는 것과 못 막는 것을 먼저 분명히 한다.**
- **막는 것** = `grep 버튼` 했을 때 현행과 폐기가 같은 결과에 섞여 나오는 것.
- **못 막는 것** = 2026-08-29 사고 자체. 그때 문제는 **정본이 3주간 낡은 채였던 것**이고, 이력을 어디 두든 §14.1 이 「8개」인 이상 똑같이 틀렸다. 그 문제(실물 변경 ↔ 정본 갱신의 시차)는 **별도 과제**다 — 이 설계에 넣지 않는다(§9).

## 2. 핵심 원칙 — 이 문서에는 **폐기된 사실만** 있다

```
통합문서   = 지금 맞는 것만        ← grep 하면 현행만 나온다
변경이력   = 더 이상 안 맞는 것만  ← 현행 값은 적지 않는다(포인터만)
```

→ 표에 「8개 → 5개」라고 쓰지 않는다. **「8개였다(폐기)」**만 쓰고 현행은 `§14.1 참조`로 둔다. **두 문서가 겹치는 값이 하나도 없다** — R5 를 형태로 강제한다.

## 3. 문서 형태

**파일** = `docs/변경이력.md` (신설)
**정렬** = 주제순. 작업로그는 시간순(그날 무엇을 했나), 이 문서는 주제순(이게 어떻게 변해왔나).

```markdown
# 변경이력 — 통합문서의 사실이 어떻게 바뀌어 왔나

> 🔴 여기에는 **폐기된 사실만** 있다. 지금 맞는 것은 `통합문서.md` 가 정본이다.
> 🔴 **측정 수치는 여기 없다** — §12 절의 `⛔ SUPERSEDED-BY` 마커와 갈래 색인이 정본이다(§4 경계).
> 작업 경위·누가 정했나 = `작업로그.md`. 작업 전 설계·버린 대안 = `docs/superpowers/specs/`.

## 1. 버튼 구성·배치
> 현행 = 통합문서 §5.4(배치) · §14.1(수량·색)

| 시점 | 폐기된 사실 | 폐기 시점 | 왜 | 근거 |
|---|---|---|---|---|
| 2026-06-09 | 아케이드 버튼 **8개**(좌 2×2 사용 B1~B4 / 우 2×2 미사용 확장) | 2026-08-06 | 실콘솔은 확장 2×2 를 두지 않기로 확정 | `65534cb` |
| 2026-06-09 | 버튼 배치 **Z자**(B1 좌상 → B4 우하) | 2026-08-10 | `console_v2` 학습 분포와 맞추려 반시계 U자로 | §12.33 |
| 2026-06 | 터치 디스플레이 = **출력 전용**(입력 아님) | 2026-08-29 | 오기였다 — 해제는 화면 터치로 한다 | `65534cb` |
```

- **주제 절은 맨 뒤에 덧붙이기만 한다** — 지운 번호는 재사용하지 않는다(R12 ① 과 같은 규약).
- 각 주제 절 머리에 **`> 현행 = §N`** 한 줄을 반드시 둔다. 이 줄이 없으면 읽는 쪽이 폐기 표를 현행으로 오해한다.
- **열 5개 고정** — 시점 · 폐기된 사실 · 폐기 시점 · 왜 · 근거. 「왜」는 한 줄, 길면 근거(커밋·작업로그)로 넘긴다(R9).

## 4. 경계 — 무엇이 어디로

| 내용 | 갈 곳 |
|---|---|
| 지금 맞는 사양·부품·기능 동작·판정 규칙·설계값 | `통합문서.md` |
| **폐기된** 사양·부품·기능 동작·판정 규칙·설계값 | **`변경이력.md`** 🆕 |
| 측정 수치 — 현행 | 통합문서 §12 `[CURRENT]` 표 |
| 측정 수치 — 폐기 | 통합문서 §12 절 + `⛔ SUPERSEDED-BY` 마커 (R6) |
| 그날 무엇을 했나·누가 정했나·정정 경위 | `작업로그.md` (R9) |
| 작업 전 설계·버린 대안 | `docs/superpowers/specs/` |

### 4.1 🔴 §12 경계 — 겹치지 않게 (사용자 지시 2026-09-18)

**`변경이력.md` 는 §12 를 다루지 않는다.** 측정 수치의 변경 이력은 §12 가 **이미 자기 방식으로 갖고 있고**(폐기 절이 본문에 남고 머리에 `⛔ SUPERSEDED-BY §12.N` 마커 · 갈래 색인 · `[CURRENT]` 표), 그것을 변경이력에 옮겨 적으면 **같은 이력이 두 곳이 되어 어긋난다.**

- 🔴 **「§12.6 → §12.21 → §12.34」 같은 승계 사슬을 변경이력에 적지 않는다.** 그 사슬은 각 절의 `⛔ SUPERSEDED-BY` 마커에서 그대로 읽힌다.
- 🔴 **갈래 색인을 변경이력에 복제하지 않는다.** 주제별로 측정 절을 모아 보는 기능은 §12 갈래 색인이 이미 한다.
- ✅ **변경이력 첫머리에 경계 한 줄만 둔다** — *「측정 수치는 여기 없다 — §12 마커·갈래 색인이 정본이다」*. 이것은 이력의 복제가 아니라 **길 안내**이며, README 역할표와 같은 성격이다.
- ✅ **근거 열에 `§12.N` 을 쓰는 것은 복제가 아니다**(포인터). 위 예시의 「배치 Z자 폐기 · 근거 §12.33」이 그것이다.

**수치가 바뀌어 현행 사실이 따라 바뀐 경우, 둘을 나눠 적는다:**

| 무엇 | 어디 |
|---|---|
| 「FPS 10.15 → 23.96」 (수치) | §12.34 + `[CURRENT]` 표 |
| 「NFR-1 판정이 🔄 미충족 → ✅ 충족으로 바뀌었다」 (현행 사실) | 폐기된 옛 판정만 `변경이력.md` · 현행 판정은 §11 |

→ 판정 기준은 **「이 줄이 §12 안에 있는가」** 다. §12 안의 것은 §12 가, 밖의 것은 변경이력이 맡는다.

## 5. 기록 시점 — `work-close` 2단계에 한 줄

> **정본의 현행 사실을 덮어쓸 때, 덮어쓰는 옛 사실을 `변경이력.md` 로 먼저 옮긴다.**

- 지우기 전에 옮기는 순서라 빠질 구멍이 작다.
- 새 절차를 만들지 않고 **이미 있는 마무리 절차(work-close 2.4 「완료 전환」)에 한 줄을 얹는다.**
- §12 측정 절은 이 규칙의 대상이 아니다(R6 가 담당 — §4.1).

## 6. 규칙 개정 4곳

### R2 (개정)

현행:
> **R2 이력 보존** — 지우지 않고 `⛔` 또는 취소선+정정으로 무효화한다. 분량은 제약이 아니다. 단, **장을 다시 짤 때 새 구조에서 쓰이지 않는 폐기 내용은 지운다** — 폐기 사실은 커밋 메시지·작업로그에 남는다(R9).

개정안:
> **R2 이력 보존** — 폐기된 사실은 **`변경이력.md` 로 옮긴다.** 통합문서 본문에는 **현행만** 둔다(옛 서술을 현행으로 오독하는 사고가 실제로 났다). **예외 = §12** — 측정 절은 본문에 남기고 머리에 `⛔ SUPERSEDED-BY §12.N` 마커를 단다(R6). 옮기지 않고 그냥 지우지 않는다.

### R3 (개정)

현행:
> **R3 쪼개지 않는다** — 문서를 나누거나 사본을 만들지 않는다. grep 대상이 나뉘면 한쪽만 읽고 놓친다.

개정안:
> **R3 쪼개는 축은 하나뿐** — 문서를 주제로 나누거나 사본을 만들지 않는다(grep 대상이 나뉘면 한쪽만 읽고 놓친다). **나누는 축은 「현행 / 폐기」 하나다** — 현행 = 이 문서, 폐기 = `변경이력.md`. 같은 사실을 양쪽에 두지 않는다.

### R12 ② (보완)

현행 R12 안의 *「기능 장은 현행 동작만 담고 바뀌면 그 자리를 고쳐 쓴다(이력·측정 = §12 · 경위 = 커밋·작업로그 R9)」* 에 **갈 곳을 명시**한다 — *「덮어쓴 옛 사실은 `변경이력.md` 로 옮긴다」*.

### README · work-close

- README 「문서별 역할·경계」 표에 한 줄: `| 폐기된 사실 — 예전엔 어땠나 | docs/변경이력.md |`
- `.claude/skills/work-close/SKILL.md` 2.4 「완료 전환」 표에 한 줄: 현행 사실 절을 덮어쓸 때 옛 사실을 `변경이력.md` 로 옮긴다.

🔴 **CLAUDE.md 는 고치지 않는다** — §3 이 「R1~R12 를 먼저 읽는다」로 가리키기만 하고 규칙 본문을 복제하지 않으므로, R2·R3 개정이 자동으로 반영된다.

## 7. 첫 채움 · 소급

**첫 채움(이번 작업)** — 빈 문서로 시작하지 않는다. 2026-09-18 구조 재편에서 지운 3건이 정확히 이 문서의 내용이다:

| 지운 것 | 출처 |
|---|---|
| `📜 이력 — 모조 콘솔 버튼 8개(좌 2×2 사용 / 우 2×2 미사용)` | 커밋 `d61650b` 이전본 |
| `⛔ 구 배치도 — 시연용 모조 콘솔`(Z자 2×2) · `이전 배치(2026-08-06 제작 당시, 폐기)` | 〃 |
| `배치 통일 경위 표`(모조 콘솔 ↔ 포맥스판 세 자리 어긋남) | 〃 |
| 터치 디스플레이 「출력 전용」 폐기 | 커밋 `65534cb` |

🔴 **경위 서술은 옮기지 않는다** — 「왜」 열 한 줄로 줄이고 상세는 근거(커밋·§12.N)로 넘긴다(R9). 배치 통일 경위 표는 **표 전체가 아니라 폐기된 배치 사실만** 옮긴다.

**소급(이후)** — 나머지는 **장별 검토 §4~ 를 하면서** 채운다. 장을 읽다 폐기·낡은 서술이 나오면 그때 이리로 옮긴다. 별도 소급 세션을 잡지 않는다.

## 8. 버린 대안

- **B안 — 장 끝마다 `📜 이 장의 변경 이력 = …` 포인터 한 줄** — 길을 놓칠 수 없다는 장점이 있으나, 이미 장 끝에 `⏸ 이 장에서 아직 안 된 것`(R12)이 있어 꼬리가 두 줄이 된다. **본문을 어지럽히지 않는 것이 이 작업의 목적**이라 버렸다. 포인터는 R2·R3·README·변경이력 첫머리에만 둔다.
- **C안 — 통합문서 부록(§17)으로 편입** — R3 를 안 건드리고 grep 대상이 하나로 유지되는 장점. 그러나 통합문서가 더 길어져(현재 6,500줄) 「통합문서 안이 어지럽지 않게」라는 목적과 어긋난다.
- **§12 승계 사슬·갈래 색인을 변경이력에 복제** — 초안에서 「§12 는 포인터만 모은다」로 제안했으나, 그 포인터 자체가 `⛔` 마커의 복제라 사용자가 배제했다(§4.1).
- **훅으로 강제** — 옮기기를 잊는 것을 기계로 막는 안. 같은 목표(문서 drift 방어)의 훅이 이 프로젝트에서 **세 번 실패**했다(CLAUDE.md §3). 절차로 돌려보고 실제로 빠뜨리면 그때 hookify 를 검토한다.

## 9. 약한 곳 · 이 설계가 안 하는 것

- ⚠️ **옮기기를 잊으면 사라진다.** 종전 R2 는 *지우지 말라*고 해서 잊어도 남았는데, 새 R2 는 *옮기라*고 해서 잊으면 없어진다(커밋 이력에는 남지만 주제별로는 못 찾는다). 완화 = `work-close` 절차에 얹기(§5). 강제 장치는 넣지 않는다(§8).
- ⏸ **실물 변경 ↔ 정본 갱신의 시차**(2026-08-29 사고의 진짜 원인)는 이 설계 밖이다. 별도 과제로 남긴다.
- ⏸ **주제 절의 입도**(얼마나 잘게 나눌지)는 첫 채움 3~4개로 시작해 장별 검토에서 굳힌다 — 미리 정하지 않는다.
