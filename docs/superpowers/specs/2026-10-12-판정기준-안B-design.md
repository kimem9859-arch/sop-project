## 1. 규칙 — 한 장마다 위에서부터

| 순서 | 판정 | 조건 | 결과 |
|---|---|---|---|
| 0 | 제외 | 정답 버튼 · 방금 누른 버튼 · EMO · 공구를 든 손(지금과 같음) | 없음 |
| 1 | 오입력 직전(안 B · 새로) | 틀린 버튼 **안쪽 상자**에서 **이 장에 실제로 본** 손끝(갭메우기로 채운 장 아님)의 속도 ≤ 문턱 | **즉시 경고** |
| 2 | 스침 | 1 이 아니고 안쪽 머문 시간 < 체류 | 없음 |
| 3 | 머무름 | 안쪽 체류 이상(대기 중 다음 버튼 위 손 포함 · 지금과 같음) | 경고 |
| 4 | 판단 불가 | 속도를 모름 | 3 기준 |

- **속도** = 이 장 손끝과 「직전 3장 안에서 손끝이 있는 가장 가까운 장(0.25초 이내)」 사이 거리 ÷ 시간 — 화면 기준 · 구역과 상관없이 직전 장. 오프라인 모의 판정기(`~/lab/판정처리분석-20261011/judge/rules.py` `annotate_speed` · `SpeedGate`)와 같은 정의다.
- **경고는 안쪽 상자에서만**(링은 지금처럼 체류 누적만) · 경고가 나면 체류 대상 버튼(`_dwell_roi`)을 세운 뒤 경고로 간다(세기의 정밀도 · 스침 계산 전제).

## 3. 구현

- **손끝 전달** — `camera_thread.roi_signal` 에 손끝(x, y · VGA 기준 = 화면 px ÷ `frame_orient.px_scale` · 없으면 NaN)을 더한다 → `safety_console._on_roi` → `fsm.update_vision(…, tip=)`(손 판정 끔이면 None). 2b 도 같은 `_process_frame` 이라 한 곳.
- **판정기** — `update_vision(roi, now, level, tip=None)` · 직전 3장의 (시각 · 손끝) 보관 · 오답 분기에서 1번 규칙 · 경고 이유 `last_warn_reason`(`slow` / `dwell`) · `reset` · `forget_observation` 에서 보관도 비움.
- **기록** — 경고 state 사건에 이유(`reason`) · session.json 설정에 새 상수.
- **시연 런처 기본 = 처리 설정 4**(`run_demo.sh` 가 2a 를 기본으로 켬 · 사용자 범위) — 측정 실행기는 번호대로(1~3 은 2a 끔을 명시).

## 4. 검증

- 판정기 단위 시험 — 느림 → 즉시 경고(이유 slow) · 빠름 → 체류로(이유 dwell) · 제외 버튼 · EMO · 방금 누른 버튼은 느려도 없음 · 링에서 느림은 없음 · 갭메우기 장은 속도 판정 없음 · 0.25초보다 오래된 직전 손끝은 속도 모름 · 문턱 0 = 지금 규칙.
- 신호가 바뀐 시험(카메라 · 콘솔 흐름 · 측정 콘솔) · 실행기 시험 · 전체 자가 테스트 0 fail.
- **재생 대조** — 오늘 기록(⑥근거 · 정상 2판 세션)을 새 판정기로 재생해 모의 판정기(SpeedGate 700 · 0.3)와 같은 경고가 나는지.
- 최종 리뷰 1회(시간 때문에 한 번).

## 5. 다시 재기(학교 · 오늘)

- ①정상 10판(세션 1) → ②위반A 14판 · ②위반B 13판(세션 2 · 위반 61) · 처리 설정 4 · 측정 기록 켬 · 음성 알림 끔 · 진행 도우미 · 녹화 없음 · 충전은 사용자 판단.
- 결과 = §4.1 판정(세기) · 경고 이유별 수 · 설정값 확인 → 정본은 공동 확인 뒤.
- 예상 — 위반 사전 차단율은 모의로 약 54~65%(목표 80% 에 못 미칠 가능성이 큼 · 못 본 손 · 빠른 손) · 헛경고 조금(한계로 보고 · D7).

## 6. 버린 대안

- 버튼 기준 속도(23/76) · 감속 비 규칙(헛경고 0 이지만 37/76 — D7 로 내림) · 속도 500 · 900 · 1,200 · 체류 0.2 · 갭 0.5 · 링 55 · 상자/초 단위.
- 처리 시간(`YOLO_MAX_MISS` · `YOLO_CONFIRM_HITS`)을 초 기준으로 바꾸기 — 오늘 범위 밖.
