# 공구 데이터셋 병합 (`tool_v3` 학습 데이터) — 설계 (2026-08-12)

> **구현 전 설계안.** 승인 후 구현한다(CLAUDE.md brainstorming-first HARD-GATE).
> 전제 정본: 통합문서 **§10.39**(ARCAD 실패 원인 = 출처 다양성 부족 / 후보 재선정).
> 선행 설계: [`2026-08-10-공구모델-tool_v1-design.md`](2026-08-10-공구모델-tool_v1-design.md).

## 1. 왜 하나

`tool_v1`·`tool_v2` 가 우리 도메인에서 무너진 원인이 **데이터**로 확정됐다(§10.39). ARCAD 5,203장은 실질 **출처 118개**였고, 모델은 「공구」가 아니라 「그 영상 속 장면」을 외웠다 — 학습 데이터엔 100% 정답, 우리 프레임엔 8%.

따라서 다음 수는 하이퍼파라미터가 아니라 **교재 교체**다. 다양성 1·2위이면서 우리 스패너 7장 실적도 1·2위인 두 데이터셋을 병합해 `tool_v3` 학습 데이터를 만든다.

🔴 **이 작업의 산출물은 데이터셋까지다.** 학습 실행·판정은 다음 작업.

## 2. 확정된 결정 (2026-08-12 사용자 결정)

| 항목 | 결정 | 근거 / 거부한 대안 |
|---|---|---|
| **구성** | `6-tool-dataset-bb0ug` v3 + `mechanical-tools-83ynn` v2 **2종만** | §10.39-(9) 후보 그대로. **거부: `vsisj` 동시 투입** — 164클래스 과세분화라 매핑이 복잡하고 공개 모델 실적이 3/7이라, 결과가 나쁠 때 원인을 가릴 변수가 하나 더 는다. `tool_v3` 판정 후 보강재로 남긴다 |
| **분할 단위** | **출처(source) 단위 · 90/10** | 같은 영상의 이웃 프레임이 갈리면 누출. **거부: 그룹(증강본) 단위** — 6-tool 의 `frame`(1,783장) 같은 영상 출처가 갈려 valid 점수가 거짓 상승한다(ARCAD 계열 함정). **거부: 80/10/10** — test 스플릿을 만들면 그 숫자를 우리 성능처럼 인용할 위험이 있다(§10.38 함정). **진짜 시험지는 파이 눈확인**이다 |
| **비대상 공구** | 라벨 지우고 **네거티브로 15% 섞음** | `tool_v2` 가 **빈 바닥을 conf 0.78 로 오검출**한 전례(§10.38-(4)). **거부: 전량 제외** — 배경·비대상 공구 오검출을 모델이 배울 기회가 없다. **거부: 전량 포함(28,600장)** — 네거티브가 절반을 넘어 재현율이 떨어지고 학습이 2배로 는다 |
| **중복 제거** | **증강본 1벌만** (pHash·출처상한 없음) | Roboflow 고정 증강은 ultralytics 매-epoch 증강과 겹치고, 증강본이 많은 사진의 **가중치만 커진다**(ARCAD 와 같은 구조). **거부: pHash + 출처당 상한** — 최대 출처 점유가 20%로 임계(50%) 미만이라 상한을 걸 근거가 없고, 4만 장 해싱은 파이에서 비싸다. 문제가 실제로 관찰되면 그때 추가 |
| **실행 위치** | **Colab CLI**로 파이 터미널에서 구동 | 아래 §6 |

## 3. 클래스 3종

`recipe.json` 의 시연 공구가 **드라이버 · 렌치/스패너 · 플라이어/펜치** 로 재선정됐다(§10.39-(6)). 큰 데이터셋은 하나같이 모든 렌치를 `wrench` 하나로 묶으므로 **몽키 별도 구분은 포기**했다.

| 새 인덱스 | 새 이름 | `ds_6tool` 원본 | `ds_mech83` 원본 |
|---|---|---|---|
| 0 | `driver` | `screwdriver` | `screwdriver` |
| 1 | `wrench` | `wrench` | `wrench` |
| 2 | `pliers` | `plier` | `pliers` |

버려지는 원본 클래스: `bolt-nut` · `hammer` · `other tool`(6tool) · `drill` · `hammer`(mech83). 이 라벨이 붙은 이미지는 폐기하지 않고 **네거티브 후보**로 넘긴다.

⚠️ 옛 `tool_v1` 클래스(`spanner`/`driver`/`wrench`)와 **다르다.** `spanner`(몽키)는 사라졌고 `pliers` 가 새로 들어왔다.

## 4. 병합 알고리즘

**산출물**: `dev/ai_model/tool_v1/build_tool_v3_dataset.py` (신설).
기존 `filter_tool_classes.py` 는 **건드리지 않는다** — 잘 돌고 테스트도 있으며 관심사가 다르다(그쪽 = 단일 데이터셋 클래스 필터, 이쪽 = 다중 데이터셋 병합·재분할). `dataset_diversity.py` 의 `load_names`·`group_key`·`source_key` 는 **재사용**한다(같은 척도를 써야 관문 검증이 의미를 가진다).

```
입력: 데이터셋 루트 N개  →  출력: <out>/{train,valid}/{images,labels} + data.yaml
```

| # | 단계 | 내용 |
|---|---|---|
| 1 | 클래스 매핑 | 각 데이터셋의 `data.yaml` `names` 를 읽어 §3 표대로 원본 인덱스 → 새 인덱스(0/1/2) 리맵. 매핑 밖 라벨 줄은 버린다 |
| 2 | 후보 분류 | 남은 라벨 ≥1 = **양성** / 0 = **네거티브 후보** |
| 3 | 증강본 1벌 | `group_key`(`.rf.` 앞)로 묶어 **정렬 첫 장**만 채택. 양성·네거티브 각각에 적용 |
| 4 | 네거티브 샘플링 | 3단계 후 양성 수의 **15%** 만 seed 고정 난수로 채택. 라벨은 빈 파일 |
| 5 | 출처 단위 분할 | `source_key` 로 묶어 seed 고정 셔플 → 누적 이미지 수가 **최종 목록(양성+네거티브) 전체의 10%** 를 채울 때까지 `valid`, 나머지 `train`. **한 출처는 절대 갈라지지 않는다** |
| 6 | 복사·`data.yaml` | 파일명에 데이터셋 접두어(`6tool_`·`mech83_`)를 붙여 충돌 방지. `data.yaml` 은 `names`(3종)·`nc: 3`·`path`·`train`·`val` |
| 7 | 리포트 | 클래스별 이미지·인스턴스 수, split 별 분포, 출처 수, **누출 건수(0이어야 함)**, 최종 파일목록 체크섬 |

**예상 규모** (실측 기반 추정)

```
양성   6-tool  20,597 → 8,404
       mech83   5,324 → 4,026
                        ───────  12,430
네거티브 (15%)                    1,865
                        ───────
합계                             14,295 장   (train ~12,865 / valid ~1,430)
출처 9,788 (감소 없음)
```

ℹ️ 6단계 접두어는 그룹·출처 판정에 **영향을 주지 않는다** — 데이터셋마다 상수를 앞에 붙일 뿐이라 묶음 관계가 그대로 보존되고, 오히려 두 데이터셋의 서로 다른 출처가 같은 키로 합쳐지는 것을 막는다. 그래서 §5-② 관문을 **산출물에 그대로 돌려도** 같은 판정이 나온다.

**재현성** — 모든 순회를 정렬하고 난수는 seed 고정. 같은 입력이면 파이와 Colab 에서 **같은 결과**가 나온다. 7단계의 체크섬으로 양쪽을 대조한다.

**알려진 한계** — 3단계에서 어느 증강본을 고를지는 파일명으로 구분할 수 없다(Roboflow 가 원본·변형을 같은 형식 `<원본>_jpg.rf.<해시>` 로 내보낸다). 회전·노이즈가 걸린 판이 뽑힐 수 있으나, ultralytics 가 매 epoch 다시 증강하므로 실질 영향은 작다고 본다.

## 6. Colab 연동 (2026-08-12 검증 완료)

Google 이 올해 공식 출시한 **Colab CLI**(2026-06-05, Apache 2.0)로 **파이 터미널에서 학습을 구동**한다. 브라우저·Drive 경유가 없어진다.

파이에서 실측 확인한 것: 설치(aarch64) ✅ · OAuth 인증 ✅ · **T4 15GB 할당** ✅ · 원격 실행 ✅ · 파일 회수 ✅ · VM 반납 ✅.

🔴 **함정 — 의존성 버전 미고정.** `colab-cli` 0.6.0 이 `jupyter-kernel-client` 를 고정 없이 의존해, 최신 1.0.x 가 딸려오면 `colab exec` 가 `AttributeError: KernelClient` 로 죽는다(1.0 에서 `JupyterKernelClient` 로 개명). **설치는 반드시:**

```bash
uv tool install google-colab-cli --with "jupyter-kernel-client<1.0"
```

학습 실행(다음 작업이지만 여기 적어 둔다):

```bash
colab run --gpu T4 --keep --timeout 21600 -s v3 train_tool_v3.py
colab download -s v3 /content/runs/detect/train/weights/best.pt Rpi5/Demo/models/tool_v3.pt
colab stop -s v3
```

- ⚠️ **`--keep` 필수** — 없으면 스크립트 종료 즉시 VM 이 반납돼 `best.pt` 를 가져올 기회가 사라진다.
- ⚠️ **`--timeout` 기본값이 30초**다. 학습에는 반드시 크게 준다.
- ⚠️ **`colab stop` 을 빠뜨리면** VM 이 계속 켜져 크레딧을 태운다.

`train_tool_v3.py` 는 `train_tool_v1.py` 구조 그대로(Roboflow 다운로드 → 병합 → 학습).
🔴 **하이퍼파라미터는 `tool_v1` 과 완전히 동일하게 둔다.** 바뀌는 변수가 **데이터 하나**여야 §10.39-(10) 의 *"다양성이 원인인가"* 에 답이 된다. 증강을 같이 만지면 또 무엇 때문인지 모르게 된다(`tool_v2` 에서 물린 것).
