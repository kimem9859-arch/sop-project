## 2. 범위

- **공구 3종(driver · wrench · pliers)만** — 버튼은 지금 초벌(`console_v2` + 기계 검토 · 반자동라벨링 설계 §5.1·§6)을 그대로 쓴다. 기계 확정 버튼의 이름 틀림이 없었고(§12.76), 버튼 모델을 바꾸면 기계 검토 동작이 달라져 표본 검사를 다시 해야 한다. **버튼 라벨은 버리지 않는다** — 데이터셋에 남아 ④ 최종 학습에 쓴다.
- **라벨링 보조 전용** — 이 설계로 만드는 모델(`tool_r1`, `tool_r2` …)은 초벌에만 쓴다(§6).
- 범위 밖 — ④ 최종 학습 설계 · 장소2·3 촬영 · 버튼 모델 반복(장소2 가 들어와 버튼 초벌이 흔들릴 때 따로 정한다).

## 3. 한 라운드

```
회수(collect_batch)  →  학습 데이터 만들기  →  학습  →  관문(떼어 둔 사진)  →  채택 또는 유지  →  다음 묶음(review_batch --tool-model)
```

- 라운드 N 의 모델 `tool_rN` = **출발 가중치 + 지금까지 회수한 전체**로 학습한다. **이전 라운드 모델에서 이어 배우지 않는다** — 한 라운드의 실수가 다음 라운드로 쌓이지 않게. 데이터가 작아 전체로 다시 배워도 시간이 크게 늘지 않는다(ICPR 2020 에서도 전체 학습이 새 묶음만 이어 배우기보다 약간 나았고 느렸다).
- **첫 라운드** = b001 로 `tool_r1` → b002(200장 · 장소1 남은 후보 + 봉인 풀린 실험 1 의 50장 · `--seal` 없이) 초벌 → 사용자 검토 → 회수·효과 측정 → `tool_r2` 여부.

## 4. 학습 데이터

- 원천 = 회수 결과 `~/data/label_dataset/<장소>/`(`labels/*.txt` 8종 번호 · `images.txt` 라벨 이름 → 원본 경로). **원본 사진**을 쓴다(데스크톱 사본·재압축본 아님).
- 공구만 남긴다 — 8종 번호 `driver 5 · wrench 6 · pliers 7` → `0 · 1 · 2`(`tool_v3` 순서와 같다). **공구가 없는 사진도 넣는다**(빈 라벨 = 「공구 없음」 예시 — 가짜 박스를 줄인다) ✋. exclude 사진은 회수 때 이미 빠져 있다.
- **떼어 둔 사진(관문용)** = 세션마다 프레임 번호 순서의 **마지막 20%** ✋ — 무작위로 섞으면 이웃 프레임이 양쪽에 들어가 관문이 부풀려진다. 떼어 둔 사진은 그 라운드 학습에 넣지 않는다.

## 5. 학습

- **출발 가중치 — 첫 라운드에서 둘 다 학습해 관문으로 고른다**: ⓐ `yolov8n`(COCO 사전학습) ⓑ `tool_v3`. 백지 학습은 하지 않는다(사전학습 출발이 적은 데이터에서 유리하다는 근거 — 머리 참조). `tool_v3` 가 낫다는 근거는 없다(b001 에서 거의 맞지 않았다) — 그래서 잰다. **이후 라운드도 두 출발점을 모두 학습한다**(개정 2026-09-28 — 1라운드 관문은 순이익 동점을 이름순으로 갈랐다 · 떼어 둔 공구 박스가 적어 한 번으로 굳히지 않는다 · Colab 에서 출발점당 약 3분).
- 설정 ✋ — `ultralytics`(파이 `~/env/rfenv`) · 입력 640(`tool_v3` 학습과 같다 · 학습·초벌 모두 비율 유지 여백 채우기) · 증강은 기본값 · 에폭 상한과 조기 종료는 계획서에서 정한다.
- 장소 = **Colab T4 GPU — 파이가 Colab CLI(`colab`)로 조작**(사용자 작업 없음 · 2026-08-13 검증된 흐름 · `tool_v3` 학습에 썼다): GPU 빌리기 → 학습 묶음(사진·라벨·출발 가중치) 올리기 → 학습 → 마지막 에폭 가중치 받기 → 반납. **관문 채점·고르기·기록은 파이**에서 한다. 개정 2026-09-28(사용자 승인) — 처음엔 파이 CPU 로 정했으나 1 에폭 4.8분 · 두 출발점 약 8시간으로 상한(§1)을 넘었고, Colab CLI 흐름을 설계 때 놓쳤다.
  - Colab CLI 함정 대응(저널 §12.41-(6)) — 프록시 토큰 1시간 만료 → **올리기부터 받기까지 1시간 안**(출발점마다 시간 상한을 둔다) · `colab exec` 는 예외에도 종료코드 0 → **성패는 로그 표지로** 판단 · 저장 경로가 문서와 다를 수 있다 → 학습 스크립트가 **실제 저장 경로를 출력**하고 그 경로에서 받는다 · 반납(`stop`)을 빠뜨리지 않는다.
  - T4 가 안 잡히면(무료 등급 제한) 멈추고 묻는다 — 대안 = 파이 CPU 밤새(시간 목표를 바꿔야 한다).
- 🔒 **개인정보 관문 — 사진을 Colab 에 올리기 전, 라운드마다** 새로 올리는 사진에 한다 · 통과한 사진 이름은 누적 목록(`~/data/label_train/privacy_cleared.txt`)에 적고, **목록에 없는 사진이 묶음에 있으면 도구가 올리지 않는다** · 개정 2026-09-28(사용자) — **촬영자가 「얼굴·개인정보를 찍지 않았다」고 확인한 세션은 얼굴 후보 검사를 하지 않고 그 확인으로 통과 목록에 올린다**(장소1 2026-09-23 세션 · 사용자 원문 「개인정보 관문은 할 필요 없어 사람 얼굴과 개인정보를 촬영하진 않았었어」). 새 장소·새 촬영은 촬영자 확인을 다시 받는다(09-16 설계 §9 절차: 얼굴 자동 검출로 후보만 → 후보는 전량 사람이 눈으로 확인 → 이름표·명찰·화면 속 개인정보도 눈으로 → 실제로 찍힌 사진은 학습 묶음에서 뺀다). 반자동라벨링 설계 §11 「외부에 올릴 때만」의 적용이다.

## 6. 관문 · 적용 · 기록

- **관문** — 떼어 둔 사진에서 새 모델과 지금 쓰는 모델(첫 라운드는 `tool_v3`)을 **초벌과 같은 점수 기준(0.25)** 으로 돌려, 같은 이름 IoU 0.5 이상인 「잡은 수」와 「가짜 수」를 센다. **순이익(잡은 수 − 가짜 수)이 더 큰 모델을 쓴다** ✋ — 잡은 박스 하나는 그리기 하나를 덜고, 가짜 하나는 지우기 하나를 더한다. 새 모델이 지면 지금 모델을 계속 쓴다. 채택한 모델은 **떼어 둔 사진 없이 배운 그대로** 쓴다(관문을 통과한 것을 쓰려고 — 전체로 다시 배우지 않는다) ✋. 떼어 둔 사진은 다음 라운드의 학습 데이터로 들어간다(그 라운드의 떼어 두기는 새로 정한다).
- 🔴 관문 값과 「잡아 준 비율」은 **같은 장소에서 잰 값이라 성능으로 인용하지 않는다.**
- **적용** — `review_batch` 에 공구 초벌 모델 인자를 더한다(기본 `tool_v3`). 묶음 기록(`manifest.json`)에 쓴 모델 경로·해시·점수 기준을 남긴다.
- **기록** — 모델은 `~/data/label_models/tool_rN.pt`(시연 프로그램 폴더 밖) · 옆에 `tool_rN.json` = 출발 가중치 · 학습·떼어 둔 사진 목록 · 설정 · 걸린 시간 · 관문 결과 · 채택 여부.
- **효과 측정** — 회수 도구가 「초벌이 잡아 준 비율」과 가짜 수를 한 줄로 낸다(§1 지표).

## 7. 지킬 선

- 🔴 **`tool_rN` 은 시연 프로그램에 넣지 않는다** — `Demo/models/` 에 두지 않고, 시연 프로그램은 계속 `tool_v3` 를 쓴다.
- 🔴 **장소3 시험 세트 초벌에 쓰지 않는다** — 최종 모델과 같은 데이터로 배운 모델이라 시험 순환이 된다. 반자동라벨링 설계 §7-b ② 에 한 줄을 더한다.
- **확인 편향** — 모델이 그럴듯하게 틀린 박스를 사람이 놓치면 다음 모델이 그 실수를 배운다. 공구는 기계 확정이 없어 **사람이 모든 공구 박스를 본다**(반자동라벨링 설계 그대로) — 이것이 방어다.

## 8. 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 파이 CPU 에서 학습 | 1 에폭 4.8분 · 두 출발점 약 8시간(2026-09-28 시간 재기) — 한 라운드 3시간 목표를 넘는다. T4 가 안 잡힐 때의 대비로만 남긴다 |
| 데스크톱 GPU 에서 학습 | 라운드마다 사용자가 파일을 옮기고 실행해야 한다 |
| 학습 없이 X-AnyLabeling 클릭 보조(SAM 등) | 박스마다 클릭해야 하고 라운드가 돌아도 나아지지 않는다 |
| 이전 라운드 모델에서 이어 배우기 | 실수가 라운드를 넘어 쌓인다 |
| 관문 없이 새 모델 바로 쓰기 | 나빠져도 모른다 — 다음 묶음 검토 시간을 날린다 |
| 버튼도 같이 반복 | §2 |
| 무작위로 떼어 두기 | 이웃 프레임이 양쪽에 들어가 관문이 부풀려진다 |
