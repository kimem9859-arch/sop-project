## 5. 학습

- **출발 가중치 — 둘 다 학습해 관문으로 고른다**(버튼·공구 모두).
  - ⓐ `yolov8n`(COCO) — 지금 기준. 공구 2라운드에서 이긴 출발점이다.
  - ⓑ **`yolo26s`(COCO)** — Ultralytics 최신 계열. 공식 표 COCO mAP 48.6(같은 계열 n 40.9 · YOLO11s 47.0) · 작은 물체 학습 개선(STAL). **라벨링 보조는 시연 프로그램과 달리 Hailo 제약(`yolov8n`)이 없다**(사용자 제안). 파이 `rfenv` 의 ultralytics 8.4.117 이 지원한다.
  - 둘을 모두 배우는 이유 ✋ — 적은 사진(학습 약 470장)에서 큰 모델이 늘 낫지는 않다 · 공구는 크기 효과와 데이터 효과를 가를 수 있다.
- **`yolo26m` 이상은 이번에 빼고, `yolo26s` 가 `yolov8n` 을 관문에서 크게 이기면 다음 라운드에 시도한다** ✋ — Colab 프록시 토큰 1시간 안에 올리기부터 받기까지 끝내야 하는데(공구 설계 §5) m 은 학습이 몇 배 길어 출발점 둘과 함께면 넘칠 위험이 있다. 파이 초벌 시간은 제약이 아니다(§6).
- 장소·설정 = 공구 설계 §5 그대로 — Colab T4(파이에서 `colab` CLI) · 640 · 비율 유지 여백 채우기 · 에폭 50 · 학습 중 성적 재기 끔 · 마지막 에폭 가중치 · 증강 기본값. **버튼과 공구는 따로 학습한다**(각각 1시간 안).
- 출발 가중치 파일은 Ultralytics 공식 배포본을 쓰고 기록에 해시를 남긴다.

## 6. 버튼 초벌 — 새 모델

- **사진 통째로 한 번** — 세로 768×1024 를 비율 유지 여백 채우기로 640 에 넣는다. 학습과 같은 방식이라 **조각 방식(반자동라벨링 §5.1)은 쓰지 않는다**(조각은 `console_v2` 의 학습·초벌 늘림 방향이 반대인 문제를 푸는 방법이었다).
- 점수 기준 = **0.50**(지금 버튼 초벌 `YOLO_CONF_LOW` 와 같은 값) ✋ — 묶음 기록에 남기고 수정 집계로 조정한다.
- 파이 CPU(`rfenv`)에서 돌린다 — **학습만 Colab, 초벌은 파이**(공구 `tool_rN` 과 같다).
- **배치 틀·문턱(정지 장면 30장)도 같은 모델로 만든다** — 기계 검토가 보는 박스가 모델마다 다르다.
- 기계 검토 규칙(가장자리 35% · 배치 틀 · 색 · 무늬 · 기계 확정 조건 · 빠진 자리 제안)은 **바꾸지 않는다.**
- 파이 초벌 시간(파이5 CPU · PyTorch · 640 · XGA 7장 평균 · 2026-09-29) — `yolov8n` 0.35초 · `yolo26s` 0.85초 · `yolo26m` 2.7초/장 → 묶음 하나(200장 + 배치 틀 30장) 약 1.3분 · 3.3분 · 10분.

## 7. 관문

- **버튼** — 떼어 둔 사진에서 후보마다(지금 방식 = `console_v2` 조각 · 출발점별 새 모델) **초벌 + 기계 검토를 모두 돌려** 사용자 최종 라벨(버튼만)과 대조한다. 짝짓기는 회수 집계와 같다(같은 이름 IoU 0.5 → 남은 것은 크게 조정 기준).
  - **기계 확정 틀림** = 기계 확정 박스 중 짝이 없는 것(이름 틀림 · 가짜).
  - **사람 몫** = 사람 확인 박스 + 빠진 자리 제안 + 놓침(최종 박스 중 어느 초벌과도 짝이 없는 것 = 사람이 새로 그릴 것).
  - **채택 조건** — ⓐ 기계 확정 틀림이 지금 방식 **이하** ⓑ 사람 몫이 지금 방식 **미만**. 둘 다 통과한 후보가 여럿이면 사람 몫이 가장 적은 것 · 같으면 작은 모델(빠르다) ✋. 통과한 후보가 없으면 `console_v2` 를 계속 쓴다.
- **공구** — 공구 설계 §6 그대로(순이익 · 지금 모델 = `tool_r2`).
- 🔴 관문 값은 **같은 장소에서 잰 값이라 성능으로 인용하지 않는다.**
- ⚠️ 떼어 둔 사진의 최종 라벨은 `console_v2` 초벌을 보며 고친 것이라 **지금 방식 쪽으로 기운다**(초벌이 함께 놓친 버튼은 정답에도 없다 → 새 모델이 그것을 잡으면 가짜로 센다). 새 모델에 불리한 쪽이라, 새 모델이 이기면 그 결과는 믿을 만하다.

## 9. 지킬 선

- 🔴 **`button_rN` 은 시연 프로그램에 넣지 않는다** — `Demo/models/` 에 두지 않는다. 시연은 계속 `console_v2`.

- **확인 편향** — 기계 확정 버튼은 사람이 훑기만 한다. 방어 = **묶음마다 기계 확정 표본 눈 검사(50칸)**. 모델을 바꾼 뒤 첫 묶음 b004 의 표본 검사가 공구 설계 §2 의 「버튼 모델을 바꾸면 표본 검사를 다시」를 겸한다. 이름 틀림이 하나라도 나오면 `button_rN` 을 내리고 `console_v2` 로 되돌린다(§1). **개정 2026-09-29(사용자)** — b004 표본 0/50 통과 뒤 b005 부터 표본 검사 생략 · 버튼 모델(`button_r2` 등)이나 장소가 바뀐 첫 묶음에서는 다시 한다(반자동라벨링 §11).
- 배치 틀·문턱은 장소1 정지 장면에서 만든다 — 장소가 바뀌면 다시 만든다(반자동라벨링 §6 ⑦ 그대로).
