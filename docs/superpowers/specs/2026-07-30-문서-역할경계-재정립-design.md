## 1. 배경 — 왜 지금 이것인가

### 발단
사용자가 `docs/` 폴더에서 **최근 갱신이 멈춘 문서**를 짚었다. 전수 조사 결과 3건이 정체 상태였다.

| 문서 | 내용상 최종 | 정체 성격 |
| --- | --- | --- |
| `프로젝트_기준문서_v9.md` | 2026-07-18 (인용 §10.17까지) | §10.18~§10.31 14절 미반영 |
| `claude-code-작업문서.md` | 2026-07-17 | 훅 구성·작업 방식이 현행과 불일치 |
| `타임라인.md` | 2026-07-18 | 이후 통합문서 변경 전건 미기록 |

### 관계망에서 드러난 것
문서 간 참조를 전수 집계하니 기준문서는 **인바운드 0 · 아웃바운드 0** 의 고립 노드였다. 그런데 스스로 「정본 우선순위 1위 = 기준문서」를 선언하고, `README.md` 도 `★ 정본` 으로 표기하고, **통합문서 자신이 머리말·꼬리말에서 "단일 기준 = 최신 기준 문서, 충돌 시 항상 기준 문서 우선"** 이라고 선언하고 있었다.

즉 **정본이 둘로 갈라진 채 오래된 쪽이 상위로 선언된 상태**였다. CLAUDE.md 의 "설계·사양 = 통합문서 단일 정본" 과 정면으로 충돌한다.

### 진짜 원인 — 나침반이 사실을 보유했다
기준문서가 죽은 이유는 나침반이라서가 아니다. **나침반이면서 요약(사실)을 함께 보유했기 때문**이다. 요약은 원본이 바뀌면 썩고, 덜어내는 규칙이 없으면 정체된다. 이것은 CLAUDE.md 가 2026-06-11~07-30 에 「현재 상태」 163줄로 자란 것과 **같은 병**이며, 같은 병이 세 번째로 재발한 것이다(① CLAUDE.md 현재상태 ② 기준문서 요약 ③ 작업문서 현황표).

## 2. 원칙 (사용자 지시, 2026-07-30)

> **CLAUDE.md 는 내용을 담는 곳이 아니라 "어느 문서를 읽어라"를 지시하는 얇은 층이다.**
> 중복이 발견되면 **CLAUDE.md 쪽을 남기고 원본을 지우는 방향으로 가지 않는다.** 반대로 한다 —
> 내용은 그 주제의 원본 문서로 옮기고, CLAUDE.md 에는 포인터 1줄만 남긴다.
> 이 원칙은 CLAUDE.md 만이 아니라 **모든 문서에 적용**한다. 각 문서는 자기 주제만 담는다.

이 원칙이 아래 결정 4건의 근거다. 특히 **결정 D는 "삭제"가 아니라 "이전"** 이라는 점이 이 원칙의 직접 적용이다.

### B. 기준문서 인용 앵커 처리 — 표기만 제거, 본문 유지
`docs/통합문서.md` 의 `기준문서`/`기준 문서` 언급 **28줄**을 두 갈래로 처리한다.

1. **머리말(23행)·꼬리말(2834행) = 정본 선언 2건** → **재작성.** "단일 기준 = 최신 기준 문서" → "**이 문서가 단일 정본**". 정본 충돌의 발원지가 여기이므로 이 둘이 이번 작업의 핵심이다.
2. **본문 26곳 = `(근거: 기준문서 §X)` 출처 표기** → **괄호만 제거, 문장은 그대로.** 통합문서 자신이 정본이 된 뒤에는 자기 사실에 상위 근거를 달 대상이 없다. 문장 뜻은 하나도 바뀌지 않는다.

```
전:  본 시스템은 FPV 단일 비전으로 한정한다. (근거: 기준문서 §3·§4.1)
후:  본 시스템은 FPV 단일 비전으로 한정한다.

전:  Hailo-8L은 주 사양으로 인용 금지 (§11·기준문서 §11)
후:  Hailo-8L은 주 사양으로 인용 금지 (§11)
```

금지·규칙 자재는 남고 끊긴 방향만 사라진다.

### C. `README.md` 를 나침반으로 전환 — 라우팅만, 요약 없음
기준문서 머리 「정보 출처 & 우선순위」 블록의 **역할만** 흡수한다. 45줄 → 약 70줄.

🔴 **README 에 사실(정의·팀·사양·수치·KPI)을 한 줄도 넣지 않는다.** 그것이 기준문서를 죽인 것이고, 넣는 순간 같은 병이 네 번째로 재발한다. README 는 "어디서 찾나"만 답한다.

구조:
```
# SOP 가디언 + 한 줄 정의            ← 기존 유지
## 🧭 무엇을 어디서 찾나              ← 신설 (라우팅 표 12행 + 정본 우선순위 3줄)
## 폴더 구조                          ← 기존, 기준문서 줄(16행) 삭제
## PoC 실행 (Step1)                   ← 기존 유지
```

라우팅 표가 가리킬 곳: 통합문서(설계·사양) · §10 `[CURRENT]`(수치) · 작업로그 `⏸`/`▶`(현재 위치) · 작업로그(프로젝트 이력) · CC작업로그(인프라 이력) · CLAUDE.md(규칙·함정) · specs/(설계 근거) · dev/interlock·glass(회로도) · Rpi5(런타임 코드) · Rpi5/Demo/docs(라벨링·데이터셋) · Drive(대용량, 정본 아님). 정본 우선순위 = 통합문서 > repo(회로도·코드) > Drive(정본 아님). ⚠️ 일정·작업 진행상태는 문서 범위 밖.

## 6. 검증 관문

주장 전에 명령을 돌려 출력으로 확인한다(`verification-before-completion`).

```bash
# ① 기준문서·타임라인 잔존 = 저널만
grep -rn "기준문서\|기준 문서\|타임라인" --include=*.md . --exclude-dir=.git --exclude-dir=Rpi5 --exclude-dir=.superpowers
#    허용: docs/작업로그.md 796·925·1009행, docs/claude-code-작업로그.md 과거 블록
#    불허: README·CLAUDE.md·통합문서·작업로그 머리말에 1건이라도 남으면 실패

# ② 「현재 상태」 라우팅 0
grep -rn "CLAUDE.md.*현재 ?상태" CLAUDE.md docs/작업로그.md

# ③ 링크 무결성 — 참조된 .md 가 전부 존재하는지 (폐기 2건이 어디서도 링크되지 않아야)
# ④ 통합문서 손실량 — 표기 제거분을 넘는 삭제가 없어야
git diff --stat docs/통합문서.md

# ⑤ CLAUDE.md 분량 — 목표 도달 확인
wc -l -m CLAUDE.md

# ⑥ 이전 무손실 — CLAUDE.md 에서 뺀 내용이 작업문서에 실제로 들어갔는지 키워드 대조
```

### 🔴 중단 규칙
- ①에서 **저널 외 잔존**이 나오면 커밋하지 않는다.
- ④에서 통합문서 삭제량이 **표기 제거분을 명백히 초과**하면 되돌린다(본문 문장이 함께 지워진 것).
- ⑥에서 **이전 누락**이 확인되면 CLAUDE.md 축약을 되돌린다 — 이전 없는 삭제는 정보 유실이며 §2 원칙 위반이다.
- CLAUDE.md 분량 목표(약 5,000자)를 **맞추려고 함정·금지 섹션을 깎지 않는다.** 그 3,184자는 "실제로 물린 것"이고 CLAUDE.md 가 원본이다.
