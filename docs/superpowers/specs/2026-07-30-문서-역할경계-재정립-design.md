## 1. 배경 — 왜 지금 이것인가

### 발단
사용자가 `docs/` 폴더에서 **최근 갱신이 멈춘 문서**를 짚었다. 전수 조사 결과 3건이 정체 상태였다.

| 문서 | 내용상 최종 | 정체 성격 |
| --- | --- | --- |
| `프로젝트_기준문서_v9.md` | 2026-07-18 (인용 §10.17까지) | §10.18~§10.31 14절 미반영 |
| `claude-code-작업문서.md` | 2026-07-17 | 훅 구성·작업 방식이 현행과 불일치 |
| `타임라인.md` | 2026-07-18 | 이후 통합문서 변경 전건 미기록 |

### 관계망에서 드러난 것
문서 간 참조를 전수 집계하니 기준문서는 **인바운드 0 · 아웃바운드 0** 의 고립 노드였다. 그런데 스스로 「정본 우선순위 1위 = 기준문서」를 선언하고, `README.md` 도 `★ 정본` 으로 표기하고, **통합문서 자신이 머리말·꼬리말에서 "단일 기준 = 최신 기준 문서, 충돌 시 항상 기준 문서 우선"** 이라고 선언하고 있었다.

즉 **정본이 둘로 갈라진 채 오래된 쪽이 상위로 선언된 상태**였다. CLAUDE.md 의 "설계·사양 = 통합문서 단일 정본" 과 정면으로 충돌한다.

### 진짜 원인 — 나침반이 사실을 보유했다
기준문서가 죽은 이유는 나침반이라서가 아니다. **나침반이면서 요약(사실)을 함께 보유했기 때문**이다. 요약은 원본이 바뀌면 썩고, 덜어내는 규칙이 없으면 정체된다. 이것은 CLAUDE.md 가 2026-06-11~07-30 에 「현재 상태」 163줄로 자란 것과 **같은 병**이며, 같은 병이 세 번째로 재발한 것이다(① CLAUDE.md 현재상태 ② 기준문서 요약 ③ 작업문서 현황표).

## 2. 원칙 (사용자 지시, 2026-07-30)

### 2.1 중복은 CLAUDE.md 쪽을 덜어낸다
> **CLAUDE.md 는 내용을 담는 곳이 아니다.**
> 중복이 발견되면 **CLAUDE.md 쪽을 남기고 원본을 지우는 방향으로 가지 않는다.** 반대로 한다 —
> 내용은 그 주제의 원본 문서로 옮긴다.
> 이 원칙은 CLAUDE.md 만이 아니라 **모든 문서에 적용**한다. 각 문서는 자기 주제만 담는다.

특히 **결정 D는 "삭제"가 아니라 "이전"** 이라는 점이 이 원칙의 직접 적용이다.

### 2.2 🔴 두 문서의 성격 분리 (2차 교정 — 이 설계의 중심 축)
초안은 CLAUDE.md 에 **문서별 포인터**(`훅 구성 = 작업문서 §1`, `세션마무리 절차 = SKILL.md`)를 남기는 방향이었다. 사용자가 이를 교정했다 — **그것은 여전히 CLAUDE.md 가 README 역할을 겸하는 것**이다.

| 문서 | 성격 | 담는 것 | 담지 않는 것 |
| --- | --- | --- | --- |
| **CLAUDE.md** | Claude Code 를 향한 **지시사항** | 무엇을 하라 / 하지 마라 — 절차·규율·금지·함정·답변 방식 | **정보의 위치**(파일·폴더·경로), 사실(정의·구성·상태·수치) |
| **README.md** | **포인터(나침반)** | 무엇이 어디 있나 — 문서·폴더·파일 위치, 문서별 역할, 실행법, 환경 구성 | 사실의 내용 자체(사양·수치·설계) — 그것은 통합문서 |

**CLAUDE.md 가 정보 위치를 알려야 할 때는 README.md 로 보낸다.** 문서 경로를 CLAUDE.md 에 열거하지 않는다.

**판별 질문 (1차안 — 불충분)**: *"~하라 / ~하지 말 것"* 형이면 CLAUDE.md. → 🔴 **구멍이 있다.** 이 기준으로는 작업문서 §3.0(*"훅을 만들기 전에 물어라"*)까지 CLAUDE.md 로 끌려온다.

### 2.2-b 🔴 판별 기준 (3차 교정 — 확정)
성격("~하라" 형인가)이 아니라 **위치가 값을 하는 시점**으로 가른다.

| 기준 | CLAUDE.md | 원본 문서(작업문서·통합문서·스킬) |
| --- | --- | --- |
| **판단하는 순간 눈앞에 있어야 하나** | ✅ 필요 — CLAUDE.md 만 자동 로드되므로 이 위치로만 보장된다 | ❌ 그 일을 시작하기로 정한 뒤 열면 된다 |
| 예 | 착수 시 자명/비자명 판단 · 측정 인용 함정 · 답변 방식 | 훅 설계 원칙(훅 만들 때만) · 훅 현황(인프라 볼 때만) · superpowers 갈래 상세 |

**트리거는 CLAUDE.md, 절차는 원본 문서.** 판단을 지배하는 한 문장만 자동 로드 위치에 두고, 그 판단이 "예"로 떨어진 뒤 필요한 절차는 원본에서 읽는다. 사용자 비유 — **계기판의 메모 스티커가 글러브박스를 가리키고, 설명서는 글러브박스에 있다.**

이 기준은 초안이 설명하지 못한 §3.0 의 위치까지 설명한다. §3.0 은 "훅을 만들기로 이미 정한 뒤" 여는 것이므로 작업문서가 맞다.

**따름정리 1 — 스킬은 경로가 필요 없다.** 스킬은 이름으로 호출되므로 CLAUDE.md 에는 발동 조건만 적고 경로(`.claude/skills/…/SKILL.md`)는 적지 않는다.

**따름정리 2 — 고유 결정의 기재는 「복제 금지」 위반이 아니다** (사용자 정식화 `b9acd09`, 3차 교정으로 행선지만 갱신).
외부 스킬·도구의 절차를 **복제**한 것과, 이 프로젝트가 **스킬 원문에 없는 결정을 더한** 것은 다르다.

| | 행선지 | 예 |
| --- | --- | --- |
| 외부 원문에 이미 있는 절차 | **원문에만** (복제 금지) | brainstorming 의 단계 구성, writing-plans 의 문서 형식, 테스트 방식 |
| 이 프로젝트가 정한 고유 결정 | **작업문서 §2** ※3차 교정 — 종전 안은 CLAUDE.md | 표준 갈래 확정 · SDD 는 기본이 아님(병렬성 있을 때만) · 계획서 150~250줄 · 관문 3종(중단 규칙·홀드아웃·검증 관문) · 워크트리 미사용 |
| 그 결정의 **근거·경위·실측** | **CC작업로그** | 창 판정 18시간 30분 · 에이전트 21개 · 리뷰가 52% |

즉 superpowers 불릿 1,667자 중 **고유 결정은 살아남고 근거만 CC작업로그로 나간다.** 이것이 *"절차를 여기 옮겨 적지 않는다"* 는 기존 규칙과 충돌하지 않는 이유다 — 그 규칙이 금지한 것은 **원문 복제**이지 고유 결정의 기재가 아니다.

🔴 **3차 교정이 바꾼 것은 「어디에 기재하나」 하나다.** 고유 결정을 기재한다는 원칙(따름정리 2)은 유지되고, 그 위치가 §2.2-b 기준에 따라 CLAUDE.md → 작업문서 §2 로 옮겨졌다. **CLAUDE.md 에는 그 결정을 읽게 하는 트리거와, 홉을 건너뛸 때 값을 물린 2줄만 남는다.**

🔴 **README 에 사실의 내용(사양·수치·KPI·설계 판단)을 한 줄도 넣지 않는다.** 그것이 기준문서를 죽인 것이고, 넣는 순간 같은 병이 네 번째로 재발한다. README 는 **"어디 있나"** 만 답하고, 무엇이 사실인지는 통합문서가 답한다. 예외적으로 "환경 구성"·"실행법"은 위치 정보의 일부로 본다(어느 머신에서 무엇이 돌아가나 = 어디 있나).

```

## 🧭 무엇을 어디서 찾나                     ← 신설 (라우팅 표 + 정본 우선순위)
## 📋 문서별 역할·경계                       ← CLAUDE.md「문서간 경계」표 이전
## 폴더 구조                                 ← 기존, 기준문서 줄(16행) 삭제
## 두 환경 (데스크톱 / 파이) · Rpi5 셋업     ← CLAUDE.md 2개 섹션 이전
## PoC 실행 (Step1)                          ← 기존 (CLAUDE.md 중복분 제거)
```

라우팅 표가 가리킬 곳: 통합문서(설계·사양) · §10 `[CURRENT]`(수치) · 통합문서 §7.1(모델 규약) · `dev/ai_model/README`(클래스맵·추론 규격) · 작업로그 `⏸`/`▶`(현재 위치) · 작업로그(프로젝트 이력) · CC작업로그(인프라 이력) · CC작업문서(훅 구성·설계 원칙) · CLAUDE.md(작업 규칙·함정) · `specs/`(설계 근거) · `dev/interlock`·`dev/glass`(회로도) · Rpi5(런타임 코드) · `Rpi5/Demo/docs`(라벨링·데이터셋·증강) · Drive(대용량, 정본 아님).

정본 우선순위 = 통합문서 > repo(회로도·코드) > Drive(정본 아님). ⚠️ 일정·작업 진행상태는 문서 범위 밖.

**⑥ 관문의 예외 처리 (자체검토에서 발견)**
현행 CLAUDE.md 의 `⛔ 채택 안 함: tasks/todo.md·lessons.md 신설` 줄은 *"만들지 말 것"* 형이라 지시처럼 보이지만, 실체는 **2026-07-19 에 거부한 대안의 기록**이다. 정본은 `2026-07-19-claude-md-정비-design.md` §거부한 대안이므로 **CLAUDE.md 에서 삭제**한다. 이로써 ⑥ 관문에 예외를 만들지 않고 통과시킬 수 있다.
(관문에 예외를 두면 다음 사람이 예외를 늘린다 — 예외 없이 통과하는 형태로 본문을 고치는 것이 옳다.)

### 🔴 중단 규칙
- ①에서 **저널 외 잔존**이 나오면 커밋하지 않는다.
- ④에서 통합문서 삭제량이 **표기 제거분을 명백히 초과**하면 되돌린다(본문 문장이 함께 지워진 것).
- ⑥에서 **README.md 외의 문서 경로가 CLAUDE.md 에 남으면** 실패다. §2.2 의 성격 분리가 지켜지지 않았다는 뜻이므로 그 줄을 README 로 옮길 때까지 커밋하지 않는다.
- ⑦에서 **이전 누락**이 확인되면 해당 축약을 되돌린다 — 이전 없는 삭제는 정보 유실이며 §2.1 위반이다.
- ⑧에서 항목 수가 **18 미만**이 되면 되돌린다. CLAUDE.md 분량 목표(약 4,500자)를 **맞추려고 함정·금지를 깎지 않는다.** 그 1,571자는 "실제로 물린 것"이고 CLAUDE.md 가 원본이다.
- 🔴 **분량 목표는 관문이 아니다.** ⑤는 참고 수치이며, ⑥⑦⑧을 모두 통과했는데 자수가 목표를 넘으면 **목표를 고친다**(본문을 깎지 않는다). 순서를 뒤집으면 이 설계가 막으려던 바로 그 일(원본 훼손)이 벌어진다.
