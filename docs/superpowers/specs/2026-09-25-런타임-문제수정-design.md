### 2.2 D3 맞물림 — 「단계 완료」를 글자 그대로 쓰지 않는 이유

서브 작업이 있는 단계(B1~B3)에서 「단계 완료」를 그대로 쓰면 **남은 10초 대기를 건너뛰는 우회로**가 된다(§10.32-(6)③ 과 같은 결함). 그래서 **경고 중 정답 버튼 = 경고 해제 + 평소 누른 것과 똑같이 처리**로 정한다.

| 경고가 났을 때 | 경고 중 정답 버튼을 누르면 |
| --- | --- |
| 그 단계의 서브 작업이 **일시정지 중** | 경고 해제 → 서브 작업을 **남은 시간부터 이어서** |
| 그 단계 버튼을 **아직 안 눌렀고** 서브가 있는 단계(B1~B3) | 경고 해제 → 서브 작업 **새로 시작** |
| 그 단계에 서브가 **없다**(B4) | 경고 해제 → **단계 완료**(P6) |

## 3. ②묶음 — GUI 상태 일치(`safety_console.py` · `sub_task.py` · `overlay*.py` 등)

### 3.1 G1 — 서브 작업과 판정기 상태를 묶는다(D5)

지금은 서브 작업 정리가 IDLE 분기에만 있어 경고·차단 중에도 10초 타이머가 따로 돈다(U1·U10).

| 판정기 상태 변화 | 서브 작업 | 해제한 뒤 |
| --- | --- | --- |
| → **WARNING** | **일시정지** — 시간이 흐르지 않는다. 게이지에 「일시정지」 표시 | 경고 해제(버튼 또는 D3)로 WARNING 을 벗어나면 **남은 시간부터** |
| → **BLOCK**(위반 · EMO 모두) | **취소** — 타이머·공구 판정 종료 · 눌림 기록 버림 | 위반 차단: **그 버튼부터 다시** 누른다 · EMO: D4 로 IDLE |
| WARNING 중 오답 눌림 → BLOCK | 멈춰 있던 서브도 **취소** | 차단 규칙 |
| → **IDLE** | 취소(지금과 같다) | — |

- `SubTask` 에 **일시정지·재개**를 넣는다 — 멈춘 동안의 시간을 경과에서 뺀다. 공구 단계(`wait_tool`)도 같은 시계를 쓴다.
- 결과: EMO 뒤 가짜 차단(U1) · 경고 중 진행이 조용히 사라짐(U10) · 차단 중 자동 커밋이 없어진다.

### 9.5 C18 — 고치지 않는다(안전 쪽 동작)

CH5 가 B1~B4 공통 GND 를 끊은 동안(BLOCK) 버튼을 누르고 있다가 해제하면 GND 가 다시 붙으며 새 눌림이 잡히고, 그 버튼이 오답이면 곧바로 다시 BLOCK 된다. **실제 장비라면 누르고 있던 오답 동작이 전원이 돌아오는 순간 실행된다** — 다시 막는 것이 맞는 동작이다. 코드는 두고 정본(통합문서 §8)에 이 동작을 한 줄 적는다. ⚠️ 이것은 CH5 가 실제로 GND 를 끊을 때의 코드 경로다 — 지금 실물은 릴레이 우회(통합문서 §12 🔓)라 일어나지 않는다(④ 최종 리뷰 Important 1). 되돌리기 = 해제 직후 눌림을 무시하는 한 줄 수정(사용자가 원하면).

### 9.6 하지 않는 것

- 판정기(`fsm.py`) · 측정 도구 · 펌웨어(인터락 `.ino` · ESP32) 수정.
- ACK 순번(C15 의 펌웨어 쪽 해법) · 이름이 고정된 경로(by-id)에서 3초 안에 다시 꽂을 때의 옛 핸들(M-5 가장자리 사례 — `st_rdev` 비교).
- ③ 리뷰 M-11 의 `Speaker.f` 죽은 속성 — 미룬 8건 목록 밖이고 시험 한 줄이 쓴다.
