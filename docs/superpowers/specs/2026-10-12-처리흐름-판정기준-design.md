## 3. 처리 흐름 1단계(D2)

원인 — 시연 프로세스는 파이썬 GIL 을 셋이 나눠 쥔다. 화면 확대(`safety_console._fit_to_label` 의 `QImage.scaled` · 약 20ms/장) · Hailo `InferVStreams.infer`(호출 동안 쥠 · 실측 `gil_test.py`) · 처리 스레드의 파이썬 코드. 화면 확대가 쥔 동안 처리 스레드가 멈춰 디코드가 4~5ms → 24ms 로 늘어난다(`fps/` 벤치). CPU 는 4코어 중 약 2코어가 논다.

| 안 | 바꾸는 곳 | 무엇을 | 되돌리기 |
| --- | --- | --- | --- |
| 안1 | `safety_console._fit_to_label` · `camera_label` | 원본 크기 그림을 라벨 비율로 **자르기만** 하고(값싼 `copy`) 확대는 `QLabel.setScaledContents(True)` 의 C++ 그리기에 맡긴다 — 그리기는 Qt 이벤트 루프(GIL 밖)에서 돈다 · `CAMERA_DISPLAY_FILL=False` 갈래는 종전 그대로 | config 스위치 하나(끄면 종전) |
| 안2 | `frame_orient` · `camera_thread` 보정 단계 | 반전 · 왜곡보정 · 회전을 **맵 하나로 합쳐 remap 한 번** — 반전·회전은 화소 자리 바꾸기라 합쳐도 보간은 한 번뿐 → **결과 화소가 같다**(벤치 30장 최대 차이 0) · 보정 파일이 없으면 종전 반전+회전 | config 스위치 하나 |
| 화면 덜 그리기 | `camera_thread` 화면 보내기 | 판정은 매 장 · 화면용 색 변환·`QImage` 복사·보내기는 N 장에 1장(기본 1 = 종전 · 비교 2) | config 값 1 |

- **바뀌지 않는 것** — 검출·손 모델에 들어가는 그림(안2 화소 동일 시험) · 판정 시각 기준(받은 시각) · 초로 정한 설정(체류 0.3 · 갭메우기 0.3).
- **뜻이 바뀌는 기록** — 측정 26 「화면」 시간(확대가 빠져 짧아짐) · `orient_ms`(remap 한 번) · 화면 덜 그리기면 카메라 영역 녹화가 N 장에 1장. 측정 기록 `session.json` 「설정」에 세 스위치 값을 남겨 섞어 인용하지 않는다.
- **장 수로 정한 설정** — 처리가 빨라지면 `YOLO_MAX_MISS`(5장) · `YOLO_CONFIRM_HITS`(2장)의 실제 시간이 짧아진다. 1단계에서는 바꾸지 않고 콘솔 비교에서 판정 결과(1 · 5 · 23)가 흔들리는지 본다 → 시간 기준 재맞춤은 판정 기준(§5) 때.
- **기대(근거 벤치 · 장담 아님)** — 14.5~17fps · 받기 → 판정기 지연 약 0.08초. 화면 덜 그리기의 몫은 재지 않았다(안1 뒤에는 작을 것으로 본다).
- **확인 못 한 것** — 실제 화면 그리기 비용(xcb) · 화면 덜 그리기 때 화면 FPS 표시가 화면 갱신 기준인지(그렇다면 처리 기준으로 바꿔야 함 — 계획서에서 코드로 확인).

## 5. 판정 기준 — 처리 개선 뒤 별도 계획(D1)

판정 틀(D5) — 한 장마다 위에서부터.

| 순서 | 판정 | 조건(첫 안 · 값은 근거 측정으로 확정) | 결과 |
| --- | --- | --- | --- |
| 0 | 제외 | 정답 버튼 · 방금 누른 버튼 · EMO · 공구 든 손(지금과 같음) | 없음 |
| 1 | 오입력 직전 | 틀린 버튼 안쪽에서 손끝이 느림(안 B · 화면 기준 ≤ 700px/s · 「들어오기 직전 장 → 안쪽 첫 장」으로 안쪽 1장이면 판단) | 즉시 경고 |
| 2 | 스침 | 느리지 않고 안쪽 머문 시간 < 0.3초 | 없음 |
| 3 | 머무름(헷갈림) | 안쪽 0.3초 이상 — 대기(서브작업) 중 다음 버튼 위 손도 여기(D9 · 지금 판정기도 대기 중 기대 버튼이 그 단계라 같다) | 경고 |
| 4 | 판단 불가 | 속도를 모름(화면 밖에서 바로 들어옴 · 가려짐) | 3번으로 |

- **안 B 를 고른 근거**(`judge2/grid.txt` · 조정 76 / 홀드아웃 40 · 스침 113 · 정상 판 19): 1단계 지연에서 47/76 · 27/40, 2단계 + 판정 처리 단축에서 59/76(78%) · 28/40, 헛경고 스침 3 · 정상 판 1, 「머묾」 경고 유지. 바꾼 틀(감속 비교)은 헛경고 0 이지만 37/76 · 45/76 에 그쳐 D7 로 내렸다.
- **px/s 단위** — 거리·해상도에 따라 달라진다 → 버튼 상자 크기로 나눈 단위로 바꿀지 근거 측정에서 정한다. 버튼 기준 속도(머리 움직임 상쇄)는 오늘 기록에서 상자 흔들림 때문에 오히려 낮았다 → 「고개 돌리기」 장면으로 다시 가린다.
- **시간으로 다시 맞출 설정** — `YOLO_MAX_MISS` · `YOLO_CONFIRM_HITS`(장 수) → 처리 속도가 정해진 뒤 초 기준으로.
- **기대 한계** — 못 본 7회 때문에 최대 약 91% · 경고 선행시간은 어떤 안으로도 0.06~0.20초(D11 로 유지 · 다시 본다).
- **추가 기능 후보(판정과 별개)** — 헷갈림의 망설임(방향 바꿈 · 고개 돌림)으로 경고 문구를 안내형으로 · 교육 기록.
