# 파이 · 데스크톱 역할별 파일 정돈 — 설계

## 1. 목적과 범위

**목적** — 파이와 데스크톱에 흩어진 파일을 **기기 역할에 따라 한 곳에만** 두고, 다른 기기의 사본은 지운다(사용자 2026-10-16).

| 기기 | 역할 | 두는 것 |
|---|---|---|
| 🖥️ 데스크톱 | 만들고 기록하는 곳 | 데이터셋 제작용 이미지 · 학습 스크립트 · 학습 실험 기록(가중치 포함) · 측정 원자료 · 끝난 실험 |
| 🍓 파이1 · 파이2 | 시연을 돌리는 곳 | 시연 코드 · 시연에 쓰는 모델 · 시연에 쓴 적 있는 모델 · 가상환경 · 시연 로그 · 진행 중인 작업의 재료 |
| 🍓↔🖥️ 발표 자료 | 파이에 한 벌 · 데스크톱은 원격으로 연다 | 사용자 2026-10-16 「파이에 있는 사본을 지우지 말고 발표 자료만 있는 폴더 안을 정리 · 데스크톱과 원격 공유」 — 4장 |

**가중치의 범위(사용자 결정 「나」 · 2026-10-16)** — 파이에는 **실제로 쓰는 · 쓴 모델만** 둔다. 학습 실험의 가중치는 그 실험의 설정 · 결과 그래프와 함께 데스크톱 `~/학습실험`에 둔다(한 실험 = 한 폴더 — 나중에 어느 설정에서 나온 모델인지 바로 따라갈 수 있게).

**범위 밖** — 노트북 · 구글 드라이브(사용자 「후순위」) · 데스크톱 안의 중복 정리(이번에는 목록만 — 부록 A) · git 저장소 안 파일 · 데스크톱에 있는 발표 자료 사본(지우지 않고 목록만).

## 2. 지키는 규칙

1. **git 저장소(sop-project · Rpi5 · project-docs)는 양쪽에 다 있는 것이 정상**이다 — 정돈 대상은 git 밖 파일뿐이다. 학습 스크립트(`Rpi5/학습/`)도 git 안이라 양쪽에 그대로 둔다.
2. **파이는 11월 말까지 시연 실물이다** — 시연 · 점검 도구가 쓰는 경로(현황 문서 「코드가 씀」 🔴)는 역할과 관계없이 파이에 둔다. 런타임이 파일을 쓰는 폴더(`Demo/recordings` · `scenario`)는 폴더는 남기고 **정돈 시작(2026-10-16) 전에 생긴 파일 전부**를 옮긴다. `logs` 는 옮기지 않는다(3.2).
3. **진행 중인 작업의 재료는 끝날 때까지 파이에 둔다** — 음성비서 개선(`lab/voice-capture`). 발표 자료는 끝난 뒤에도 파이에 둔다(4장).
4. **옮긴 뒤에만 지운다** — 순서는 「옮기기 → 양쪽 md5(내용 지문) 대조 → 폴더 단위로 전부 같을 때만 파이에서 삭제」. 하나라도 다르면 그 폴더는 지우지 않고 멈춘다.
5. **데스크톱에 이미 같은 파일이 있으면 옮기지 않는다** — 다시 보내 데스크톱 안에 중복을 만들지 않는다. 대신 「파이 원래 경로 → 데스크톱에 이미 있던 위치」를 대응표에 남긴다. 단, **캐시 · 가상환경 · 휴지통 안의 사본은 사본으로 치지 않는다**(언제든 지워진다 — 10장 대조에서 `best.hef` 사본이 D: 휴지통에만 있었다).
6. **두 기기에 같은 파일이 있어도 되는 예외 두 가지** — ① git 이 관리하는 파일 ② 시연 모델이 데스크톱 학습 · 변환 기록(`~/학습실험/변환` · `D:\Hailo_DFC`) 안에도 있는 경우(기록에서 빼면 그 실험 기록이 끊긴다). 그 밖에 데스크톱에 있는 시연 모델의 단순 사본(예: 데스크톱 `~/projects/Rpi5/Demo/models`)은 지운다.

## 4. 발표 자료 — 파이에서 정리하고 데스크톱과 원격 공유

**원칙** — 발표 자료는 **파이의 `~/project-docs/융합프로젝트/최종발표/` 한 벌이 정본**이다(교내 본선 PPT 도 여기서 만든다). 파이 쪽 사본은 지우지 않는다. 데스크톱은 이 폴더를 **네트워크로 직접 열어** 보고 고친다 — 복사본을 따로 만들지 않으니 「어느 쪽이 최신인가」가 생기지 않는다.

### 4.1 폴더 안 정리

지금 이 폴더에는 git 에 올라가는 **원본**(원고 · 설계 · 계획 · 대본 · 도구 · 틀 · 자산 · 작업본)과 git 에서 빠진 **내보낸 결과물**(PPT 7개 판 · PDF · 66 MB 조립본 HTML · 검수 캡처 316장)이 한 층에 섞여 있다.

| 무엇 | 정리 | 까닭 |
|---|---|---|
| 내보낸 결과물(`발표-결과중심-<날짜>.pptx` 판들 · `-본문.pdf/.pptx` · 조립본 `.html`) | 새 폴더 `내보내기/` 로 모은다 — 판마다 날짜 이름 그대로 · 어느 판이 최신인지는 `내보내기/README.md` 첫 줄에 적는다(같은 기기 안에 사본을 만들지 않는다) | 데스크톱에서 열 때 「무엇을 열면 되나」가 한눈에 보인다 |
| 검수 캡처 `검수/` | 그대로(이미 한 폴더) | — |
| git 원본(원고 · 설계 · 도구 · 틀 · 자산 · 작업본 등) | **자리를 바꾸지 않는다** | 조립 · 검사 도구와 발표 제작 규칙 · README 가 이 경로로 묶여 있다 — 옮기면 도구가 깨진다 |
| 도구 가상환경 `.venv`(381 MB) | 그대로 · 공유에서는 숨김 | 검사 도구용 |
| 교내 본선용 판 | 만들 때 `내보내기/` 에 `본선-<날짜>` 이름으로 | 10/14 수업 발표판과 구분 |

- `.gitignore` · README · 조립 · 내보내기 도구(`도구/pptx_만들기.py` 등)가 결과물을 쓰는 자리를 `내보내기/` 로 맞춘다 — 계획 단계에서 도구가 실제로 쓰는 경로를 확인한 뒤.

### 4.2 데스크톱에서 원격으로 열기 — 파일 공유(Samba) · Tailscale 안에서만

| 항목 | 정함 |
|---|---|
| 방식 | 파이1 에 Windows 파일 공유(Samba)를 켜고 이 폴더 하나만 공유한다 → 데스크톱 Windows 탐색기에서 `\\pi1\최종발표` 로 열어 PowerPoint · 브라우저로 바로 연다 |
| 접근 범위 | **Tailscale(우리 기기끼리의 사설망) 주소에서만** 받는다 — 학교 · 집 와이파이의 다른 기기는 못 본다 |
| 로그인 | 파이 사용자 `pi` 로 · 공유 전용 비밀번호는 사용자가 직접 정한다(`! sudo smbpasswd -a pi` — Claude 는 비밀번호를 보거나 정하지 않는다) |
| 공유하는 것 | `최종발표` 폴더 하나 · 숨김 폴더(`.venv` · `.git` 등)는 보이지 않게 |
| 되돌리기 | `sudo systemctl disable --now smbd` · 패키지 제거 — 파일은 그대로 |

- 파이1 은 시연 실물이라, 공유를 켜도 시연 프로그램 · 점검 도구가 그대로인지 자가 테스트 · 점검 도구로 확인한다.
- 데스크톱에 이미 있는 발표 자료 사본(예: `D:\Downloads\발표-결과중심 (1).html` · 바탕화면 「5월 융합프로젝트 발표자료 백업」)은 지우지 않고 목록만 남긴다 — 공유가 자리 잡은 뒤 사용자가 정한다.

## 5. 경로를 가리키는 곳 고치기

옮기는 경로를 이름으로 가리키는 코드 · 규칙 · 문서를 계획 단계에서 `grep` 으로 모두 찾아, 데스크톱 자리로 고치거나 「데스크톱으로 옮김(날짜)」을 단다. 지금 아는 것:

- `Rpi5/학습/학습.py` — 대조표에 「변환 모델 = 파이 `~/data/학습실험/`」을 적는다 · 대조표 신선도 시험이 있다
- `.claude/skills/데이터셋` · `측정도구` · 저널 · 통합문서 · 작업로그 — `data/` · `test/raw` 경로를 인용한다(저널 · 작업로그의 옛 기록은 고치지 않는다 — 그때의 기록)
- `docs/파이-홈-폴더규칙.md` — `data/` 의 뜻이 「데이터셋을 두는 곳」에서 「데이터셋은 데스크톱 · 파이에는 시연에 필요한 소량만」으로 바뀐다

## 6. 검증

| 시점 | 확인 |
|---|---|
| 옮긴 뒤 · 지우기 전 | 폴더마다 파이 쪽 md5 목록 = 데스크톱 쪽 md5 목록(파일 수 · 합계 크기 · 지문 전부) · 이미 있던 사본은 대응표의 데스크톱 파일 md5 로 확인 |
| 지운 뒤 | 파이 남은 공간(`df`) · 자가 테스트 전체 · 점검 도구 `--final` · 시연 불러오기 시험 |
| 끝 | 현황 문서에 「옮긴 것 · 대응표 위치」 · 파이-홈-폴더규칙 고침 · 데스크톱 `~/pi-data/README.md`(무엇이 어디서 왔나) |

## 7. 되돌리기

- 옮긴 자료는 데스크톱에 있고 대응표가 원래 경로를 알려 준다 — 필요하면 같은 방법으로 파이로 되돌린다.
- 지우기는 폴더 단위 대조가 끝난 뒤에만 한다 — 대조에 실패한 폴더는 그대로 남는다.

## 8. 버린 대안

| 대안 | 버린 까닭 |
|---|---|
| 가중치를 전부 파이로(사용자 선택지 「가」) | 실험 가중치가 설정 · 결과 그래프와 떨어져 어느 실험의 결과인지 따라가기 어렵다 |
| 파이 폴더를 통째로 다시 보냄(데스크톱 사본 무시) | 데스크톱 안에 중복이 새로 생긴다(라벨링 묶음만 약 3.6 GB) |
| 받는 곳 = Windows D: | 기존 파이 자료(`~/pi-data`) · 학습 실험(`~/학습실험`)이 WSL 홈에 있다 — 한곳에 모은다 · Windows 탐색기에서도 `\\wsl$` 로 보인다 |
