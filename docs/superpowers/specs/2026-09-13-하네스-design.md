## 0. 이 문서의 독자

이 저장소에서 **사람이 읽는 문서는 개발보고서·제작설계서뿐**이다. 나머지(통합문서·작업로그·지시문·설계 문서·이 문서)는 **Claude 가 읽고 일하기 위한 입력**이다(사용자 확인, 2026-09-13).
그러므로 문서의 품질 기준은 가독성이 아니라 **「Claude 가 무엇을 믿어야 하는지 갈리는가」** 다.

## 1. 배경 — 규칙 중심에 장치가 얇게 붙은 체계

공식 문서의 구분: *CLAUDE.md 는 컨텍스트이지 강제되는 설정이 아니다. Claude 의 판단과 무관하게 막으려면 훅을 써라* · *설정 규칙은 Claude 가 무엇을 하든 클라이언트가 강제한다* (code.claude.com `memory.md`).

현재 결정론적 장치(SessionStart 훅 2개·상태줄·권한 허용목록)는 **입력 주입까지만** 한다. 기록·설계 게이트·검증은 전부 Claude 가 기억해 지키는 규칙이다. 업계 기준으로 흔한 상태다(저장소 2,853개 조사에서 대부분이 지시문 파일 하나만 사용 — arXiv 2602.14690). 문제는 **규칙이 깨진 곳에 장치가 없다**는 것이다.

| 깨진 증거 | 드러난 구조 |
|---|---|
| 9월 병행 세션 기록 공백 — 세션 47개 중 25개가 두 로그에 ID 없음 | 마무리 규칙이 병행 세션에서 안 지켜진다 |
| 인터락 결선 실패가 미기록 → 09-07 세션이 「완료」로 알고 설계 | 실물 확인 없이 완료로 읽혔다 |
| 2026-09-13 재시작 배너가 **이미 끝난** 디스크 정리·소급을 대기로 주입 | 규칙(마무리)에 기대는 장치는 틀린 사실을 퍼뜨린다 |
| 2026-08-10 이전 세션 본문 확인 불가 | 원재료가 보존 기간 뒤 삭제된다 |

## 2. 목적 / 비목적

**목적**
1. **기록이 사라지지 않게 한다** — 대상 통로: 병행 세션 · 실패로 끝난 작업 · 저장소 밖 변경(결선·설정). 셋 다 **커밋이 없다**.
2. **사용자 구상이 계획·구현까지 변형 없이 건너가게 한다.**

마찰 감소는 목적이 아니라 **상한**이다. 사용자는 배너를 읽지 않으며 **확인 없이 자동으로 도는 것**을 원한다.

**비목적**
- 구현 결과를 「통과」로 판정하는 일의 자동화 — 최종 기능 구현 확인은 사용자와 Claude 가 **함께** 하며, 기계로도 Claude 단독으로도 판정하지 않는다(§3)
- 두 기계(데스크톱·파이)의 자동 메모리 공유 — 이번 범위에서 사용자가 제외
- 멀티에이전트 팀·자율 반복 루프를 **기본 작업 방식으로** 삼는 것 — 요청 시에는 쓴다(§9.1)

## 3. 역할 분담 (2026-09-13 사용자 확정)

| 단계 | 담당 |
|---|---|
| 기능 구상 | 사용자 |
| 계획·구현 | Claude |
| 구현 검토 — 자기 검토 + 별도 검토 에이전트(§6.5) | Claude |
| 구상 이해, 사용자 프롬프트의 모순·오류 잡기 | Claude |
| 기능 구현 검증 결과 확인 — Claude 의 검토·테스트 결과가 맞는지, 의도대로인지 | **사용자 + Claude** |
| 최종 기능 구현 확인 — 실물에서 동작하는지 | **사용자 + Claude** |

**공동 확인의 분담**(2026-09-13 사용자 수정) — 두 확인은 사용자 혼자 할 수 없어 Claude 가 돕는다. Claude 는 **확인 절차·통과 기준·대조할 로그와 증거를 준비**하고 결과를 대조한다. 사용자는 **물리 세계에서만 보이는 사실**(동작·소리·화면)을 관측한다.
🔴 **통과는 둘이 함께 선언한다. Claude 가 단독으로 「완료」를 쓰지 않는다** — 2026-09 인터락 완료 오인의 재발 방지.

## 4. Claude 의 검증 의무

사용자 프롬프트는 **틀릴 수 있다**(사용자 요청, 2026-09-13). 전적으로 믿지 않는다.

| 대상 | 처리 |
|---|---|
| 수치·경로·파일 상태·버전·날짜·세션 ID·인용·「완료됐다」는 전제 | **착수 전 정본·코드·로그로 대조** |
| 기능 구상·방향 | 검증하지 않는다. 단 **정본의 사실과 충돌하면 충돌을 알린다** |
| 결과를 바꾸지 않는 표현 차이·오타 | 넘어간다(잡음이 중요한 정정을 묻는다) |
| 물리 세계만 아는 것(결선·소리·눈으로 본 화면) | 믿거나 의심하지 않고 **증거(로그·사진·입력 프레임)를 요청** |

**모순 처리** — 고르라고 되묻지 않는다. **정정안 + 근거를 한 덩이로 말하고 진행**한다. 사용자가 틀렸다고 하면 그 줄만 고친다.

## 5. 장치로 올리는 기준

- **규칙이 실제로 깨진 곳만 올린다**(래칫). CC작업문서 §3.0 판별 질문 *「이 훅이 없으면 실제로 무엇을 잃나 · 보험 지급 실적은?」* 을 장치마다 기재한다.
- **모든 구성 요소에 「담긴 가정」을 적는다** — *every component in a harness encodes an assumption about what the model can't do on its own* (Anthropic, harness-design-long-running-apps). 모델이 바뀌면 가정을 재검토해 걷어낸다(§7).

## 6. 설계

### 6.1 보존 층 — 장치 🆕

- **트리거 = SessionStart 배너 훅이 배너를 만들기 전에 순차 호출한다**(sync-check 와 같은 방식). 배너가 **갱신된** 색인을 읽어야 하기 때문이다 — 백그라운드로 돌리면 갱신 전 색인을 읽어 §1 의 「낡은 주입」이 재현된다. 크래시·정전으로 끝난 세션도 다음 세션 시작 때 걸린다.
- **입력** — `~/.claude/projects/<slug>/*.jsonl`(slug = `CLAUDE_PROJECT_DIR` 의 `/`→`-`). `.trash/` 제외. 실제 user/assistant 메시지 ≤5 인 껍데기 제외(prune-stubs 와 같은 기준).
- **추출(판단 없음)** — 사용자 발화 원문 전부 · 편집·작성한 파일 경로 · 실행한 `git commit` 제목 · 시작/끝 시각 · 마지막 어시스턴트 응답 꼬리.
- **출력** — `~/lab/session-archive/<시작일>_<ID8>.md`(홈 폴더 규칙 `lab/<주제>`). 원본이 더 새로우면 갱신.
- **성능 실측(2026-09-13)** — 472MB·49세션 전체 파싱 1.6초, 최근 세션 1개 0.01초.
- **중복 실행 방지**(2026-09-13 사용자 요구) — 세션 시작 훅은 한 세션에서도 여러 번 발동한다(시작·재개·`/clear`·압축). 세 겹으로 막는다.
  1. **동시 실행** — `flock -n`. 다른 세션이 돌리는 중이면 즉시 건너뛰고 기존 색인을 읽는다.
  2. **반복 실행** — 마지막 스캔 시각을 기록해 **30분 안이면 스캔 자체를 하지 않는다.** 세션 도중 `/clear`·압축으로 다시 발동해도 돌지 않는다.
  3. **같은 세션 재기록** — **현재 세션은 보존 대상에서 뺀다**(아직 자라는 중이다). 이미 보존한 세션은 원본이 더 새로울 때만 다시 쓴다.
  - 30분의 대가 — 새 세션 시작 30분 안에 끝난 세션은 그 배너에 안 뜬다. 다음 스캔에서 잡히므로 기록은 잃지 않는다. 증분 스캔은 0.01초 수준이라 훅 제한시간(30초) 안에 든다.
- **견고성** — CC작업문서 §3.4(fail-open·exit 0·timeout·`core.quotepath=false`).
- **§3.0 판별** — 잃는 것 = 보존 기간 뒤 원재료. 실적 = 2026-08-10 이전 세션 본문을 이미 잃었다.
- **한계** — 기계 로컬(SD 고장 시 소실). 두 기계가 각자 보관한다.

### 6.2 색인 — 장치 🆕 (파생 파일, 저장소 밖)

🔴 **CC작업문서 §3.5 「의미 없는 색인보다 의미 있는 요약」과의 충돌을 검토했다.** 폐기된 SessionEnd 매핑 훅이 죽은 이유는 셋이다 — ①**커밋 기반**이라 누락 세션(커밋 없음)에 무력 ②**저널에 써서** 자기참조 증식 ③세션마무리가 **이미 하던 일**의 중복.
이 색인은 ①대화 기록 기반 ②**저장소에 쓰지 않는다** — 보존 폴더 안의 파생 파일이며 언제든 재생성 ③세션마무리가 **못 하는** 병행 세션 판정을 한다. → §3.0 통과. 보험 실적 = 2026-09-11 수동 점검의 누락 25건.

- **위치** — `~/lab/session-archive/INDEX.tsv`. 한 세션 한 줄, 탭 구분.
- **열** — 시작일 · ID8 · 첫 지시(60자) · 편집 수 · 커밋 수 · **기재 여부**(전체 UUID 를 `docs/작업로그.md`·`docs/claude-code-작업로그.md` 에서 검색).
- **자동 커밋·푸시 없음** → 자기참조 증식과 두 기계 간 병합 충돌이 원천적으로 없다.

### 6.4 권한 금지 목록 — 장치 🆕

`.claude/settings.json`(저장소 공유 → 두 기계 동일)에 추가.

| 목록 | 규칙 | 막는 실패 |
|---|---|---|
| deny | `Bash(git add -A *)` · `Bash(git add --all *)` · `Bash(git add . *)` | 2026-08-21 백업 docx 29MB 통째 커밋 |

- 공식 문서 근거 — 끝의 ` *` 는 인자 없는 명령도 포함 · deny 는 복합 명령의 하위 명령에도 적용(`permissions.md`).
- **푸시 확인(ask)은 넣지 않는다**(2026-09-13 정정·사용자 동의) — 요청 없는 푸시는 한 번도 일어나지 않아 §5 기준을 통과하지 못하고, 승인 한 번이 마찰로 더해진다. 「푸시는 사용자 요청 시」는 규칙으로 둔다.
- 지시문의 「`git add -A` 금지」 줄은 「권한 설정이 강제한다」 포인터로 줄인다.

### 6.5 기능 완료 시 별도 검토 — 규칙 🆕

- 기존 스킬 `superpowers:requesting-code-review` 를 쓴다(새로 만들지 않음). 세션 이력 없이 기준만 받는 서브에이전트다.
- **시점** — 계획서 마지막 태스크 뒤, 사용자에게 넘기기 전 **1회**. 매 커밋이 아니다(CC작업문서 §3.6 — 커밋 검사 LLM 훅 12회 0적발).
- **기준** — 계획서 요구사항 + **사용자 구상 원문**(보존 층에서 인용).
- 근거 — *When asked to evaluate work they've produced, agents tend to respond by confidently praising the work* (Anthropic).

**검토 보고 방식**(2026-09-13 사용자 결정) — superpowers 의 설계 문서 사용자 검토 관문은 **유지**한다. 단 사용자에게 파일을 열게 하지 않고 **대화로 요약 보고**한다. 요약에서 빠진 것은 검토 기회가 사라져 관문 우회가 되므로 형식을 고정한다 — ①절마다 한 줄, 빠짐없이. **그 절에서 사용자가 말하지 않았는데 Claude 가 정한 것은 같은 자리에 표시한다**(따로 모으면 사용자가 앞 칸을 다시 읽어야 한다 — 2026-09-13 사용자 수정) ②버린 대안 ③확인 질문. 계획 문서는 사용자 검토 대상이 아니다(writing-plans 원문).

### 6.7 세션마무리 확인 관문 완화 — 규칙 변경 🔁

`session-wrap` SKILL §2 의 *「묻지 않고 임의 소급 금지」* 를 바꾼다 — **사실 기재**(커밋·세션 존재·색인이 판정한 미기재)는 **확인 없이 소급 블록 작성**. 원인 해석처럼 **판단이 갈리는 것만** 확인한다. 소급 블록의 한계 표기는 유지.

## 8. 실구현 확인 상태 — 이번엔 장치로 만들지 않는다

처음 설계는 색인에 「실구현 확인」 열을 두려 했다. **철회한다.** 계획서 6개를 확인한 결과 관문 통과 여부가 **기계로 읽히는 형식이 아니다**(사람용 표·체크박스가 제각각). 장치로 만들려면 모든 계획서 형식을 바꿔야 해 범위를 넘는다.

- **이번 대응(규칙)** — 「완료」라고 쓸 때 **관문 결과 출처**를 붙인다. 실HW 미검증은 ⏸ 에 그렇게 적는다(기존 관행).
- **올리는 조건(래칫)** — 완료 오인이 **한 번 더** 나면 관문 표 형식을 통일하고 배너 주입으로 올린다.
