### 버린 대안

- **시스템 없이 폰만 찍고 경고 시각을 대본대로 연출** — 실제 기록과 달라져 D15 원칙·공고문 「제출 자료와 일치」에 어긋난다.
- **안경 카메라 박스를 폰 화면에 옮겨 그리기** — 두 카메라 위치가 달라 박스가 어긋난다.
- **시험본의 세로 + 양옆 패널 배치** — D8 로 버림. 세로 완성본은 쇼츠로 올라갈 위험도 있다.
- **3인칭 → 1인칭 전환 오프닝** — D13 으로 버림.
- **측정 기록이 안 되면 GUI 로그(1초 단위)로 대신** — D23 으로 버림. 시각 맞춤 정확도가 떨어진다.

## 5. 연출과 UI

방향 = 테크 데모 HUD(D10). 지금 시연 프로그램의 색 체계(초록 = 정상 · 노랑 = 경고 · 빨강 = 차단 · 버튼별 색 B1 노랑 · B2 흰 · B3 분홍 · B4 파랑 — `Rpi5/Demo/theme.py`)를 유지하고, 배경에 묻히지 않게 글자 테두리·패널 뒤 흐림으로 선명하게 한다(D12).

- 🔴 **모양(배치·색·글꼴)은 글로 정하지 않는다** — 구현에서 **UI 시안을 먼저** 만들어 Studio 화면으로 보이고 확인(G3)받은 뒤 전체를 만든다. 시안 전에 `impeccable` · `frontend-design` 을 먼저 거친다(메모리 「조판 전 디자인 스킬 먼저」).
- 연출은 **보여 주는 방식만** 바꾼다 — 박스 위치 · 경고·차단 시각 · 공구 판정은 모델·기록 그대로. 배속은 반드시 표기(경고 선행시간 오해 방지).

## 6. 제작 흐름

```
폰 원본(4K60 HEVC) ──사용자가 옮김──▶ 데스크톱
  ├─(필요하면) 흔들림 보정 ──▶ 보정 원본          ※ 보정은 반드시 검출 전에(박스가 보정된 화면 기준이 되게)
  ├─ 검출용 사본 1280×720 ──ssh──▶ 파이1 임시 폴더
  │                                  └─ 검출(버튼 · 공구 · 손 21점 · 같은 시연 모델) ──▶ dets.json
  └─ 소리 ──▶ 누름 소리·부저 시각
파이1 측정 기록(단계·경고·차단·누름 ms) ──▶ timeline.json ──┐
누름 소리 ↔ 누름 기록 · 부저 ↔ 차단 ──▶ 시각 차(offset) ──────┤
                                                             ▼
                          Remotion(dev/video) — 장면 조립 · 자막 · 배속 → 1920×1080 30fps
```
