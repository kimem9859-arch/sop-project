## 1. 목표와 성공 기준

- **목표** — 장소2 촬영 전에, 장소1 데이터(`place1_v1`)로 공구 모델의 **학습 방식**(학습률 · 학습률 일정)과 **가설 증강**을 정해 「새 기준 설정」을 만든다. 2단계(장소2 뒤)는 이 새 기준에서 출발한다. 한 단계에서 한 갈래만 바꿔 좋아진 이유를 가릴 수 있게 한다. 아울러 **ONNX·HEF 변환을 백지에서 조사**해 우리에게 맞는 변환 방법을 정하고, 장소1 로 배운 모델을 **모의 변환**해, 2단계 최종 모델을 NPU 로 옮길 길을 미리 연다.
- **성공 기준**
  1. 학습 방식을 Optuna 로 탐색하고, 그 상위 후보를 **채택 판정 규칙**(§3)으로 채택하거나 기각해 새 기준을 정했다.
  2. 가설 증강 2개(cutmix · 흐림)와 SGD 한 칸을 새 기준 위에서 같은 규칙으로 판정했다.
  3. ONNX·HEF 변환의 공식 기본값과 근거를 백지에서 조사해 「우리에게 맞춘 스크립트가 필요한가」를 결론 내고, 그 결론으로 쓴 스크립트로 장소1 모델(버튼·공구)을 HEF 로 바꿔 파이 Hailo 에서 읽고 추론했다.
  4. 결과(채택·기각 · 변환 조건)를 저널 · 장부 · 통합문서 [CURRENT] 에 남겼다.

## 2. 범위

- **안** — ① Optuna 탐색 도구(데스크톱 · 1단계 실행기 대기열에 얹음) ② 확인 실험 ③ 가설 실험 설정 · 흐림 증강을 위한 데스크톱 환경 변경(albumentations) ④ ONNX·HEF 변환 백지 조사(공식 기본값·근거·우리 상황) · 이전 변환과 대조(참고) · 우리 변환 스크립트 · 장소1 모델 모의 변환과 파이 Hailo 확인. 데이터는 모두 장소1 `place1_v1`(b001~b009).
- **밖(2단계 · 장소2 촬영 뒤 별도 설계)** — 장소2 를 넣은 나눔 새 판 · 버튼 모델 재판정 · 밝기·색·시점·위치 증강 · 최종 학습 · 최종 모델 HEF 변환·채점(장소2) · 장소3 봉인 시험 · 시연 폴더에 HEF 배치·배선. 그 밖에 모델 크기 변경(yolov8n 고정 · 사용자) · 시연 프로그램 입력 변경 · 공구 NPU 이전 런타임 배선.
- **시작 조건** — 없음(장소1 데이터 · 데스크톱만 있으면 지금 시작할 수 있다).

## 3. 근거 요약

- **1단계(저널 §12.85 · §12.86)** — 하나씩 바꾼 실험에서 공구는 학습률 0.0005 만 렌치가 시드 3회 모두 기준 위였고, 768×1024 와 둘의 조합은 갈리지 않았다. 버튼은 장소1 채점 사진에서 기준이 천장이라 가릴 수 없었다.
- **에폭 고정 확인(2026-10-04 · 640 입력 · 저널 기록 예정)** — 일찍 멈춤을 끄고 120 에폭 끝까지 돌리자 기준이 드라이버·렌치·오검출 모두 좋아졌고, 학습률 0.0005 의 렌치 이점은 갈리지 않았다 → **학습률 일정을 끝까지 도는 것이 가장 큰 손잡이**였다. 768×1024·조합 결과는 같은 날 저녁에 나온다(§12).
- **공식 문서** — 미세조정은 기본값이 강한 출발점이고 이유 있을 때만 바꾼다 · 체계적 탐색 `model.tune()` = 조합마다 학습 1번 · 기본 300회 · 「짧거나 작은 규모로 튜닝한 값은 실제 학습에 최적인 경우가 드물다 — 조건을 맞춰라」 · Ray Tune = Optuna TPE + ASHA. **학습 없이 최적 조합을 계산하는 방법은 없다.**
- **Optuna TPE** — 처음 10회 무작위 뒤, 좋은 쪽/나머지 분포 비가 큰 값을 다음에 시험한다 · multivariate 는 파라미터를 함께 본다(입력 크기 × 학습률 같은 상호작용).
- **채택 판정 규칙(사용자 2026-10-04 · 1단계 설계 §15)** — 후보 시드 3회 · 같은 운용 조건 기준 3회 · 어떤 지표에서 **후보 최저 > 기준 최고** · 다른 지표에서 아래로 갈림 없음 → 채택(설정만 채택 · 운 좋은 한 번의 가중치를 고르지 않는다).

## 4. 진행 순서

| 단계 | 바꾸는 것 | 고정 | 판정 |
|---|---|---|---|
| ① 탐색 | 학습 방식만 — lr0 · lrf · cos_lr · close_mosaic | 증강 = 1단계 기본 · AdamW · 입력(§12) · 120 에폭 끝까지 | Optuna 목표값(검증 몫) |
| ② 확인 | 탐색 상위 3개 | 〃 | 채택 판정 규칙(채점 292장) → 이긴 설정 = **새 기준** |
| ③ 가설 | 새 기준 위에 cutmix · 흐림 · (SGD 한 칸) 각각 따로 | 새 기준 나머지 | 같은 규칙 · 채택되면 학습률만 짧게 재확인 |
| ④ HEF | 학습은 바꾸지 않음 — 백지 조사(공식 기본값·근거) → 이전 변환과 대조 → 우리 스크립트 → 장소1 모델 모의 변환 | — | 변환 관문 3개(§8.4) |

- 데이터는 모두 장소1 `place1_v1`(1단계와 같은 나눔 · 채점 292장).
- ④ 는 학습 설정과 무관해 ①~③ 과 따로 진행한다 — 조사(§8.1~8.2)는 언제든, 변환(§8.4)은 데스크톱에 학습이 없는 시간에 ✋.
- ✋ 한 단계에서 한 갈래만 바꾼다 — 1단계 E7(조합)처럼 좋아져도 어느 쪽 덕인지 가릴 수 없게 되는 것을 막는다.

## 5. ① Optuna 탐색

### 5.1 무엇을 탐색하나
| 파라미터 | 범위 | 이유 |
|---|---|---|
| lr0 | 0.0002 ~ 0.003 (로그) | 1단계 0.0005·0.001·0.002 를 품고 양쪽으로 한 칸씩 ✋ |
| lrf(마지막 학습률 비율) | 0.01 ~ 0.3 (로그) | 일정 끝의 학습률 — 에폭 고정 확인에서 일정이 가장 큰 손잡이였다 ✋ |
| cos_lr | 끔 / 켬 | 선형 대 코사인 감소 |
| close_mosaic | 0 · 10 · 20 | 마지막 N 에폭 모자이크 끔 — 일정 끝 구간 |

- **고정** — AdamW(옵티마이저까지 넣으면 30회로 범위가 너무 넓다 ✋) · 증강 1단계 기본 · 120 에폭 · patience 0 · 포화 0 · warmup 3 · batch 16 · 손실 가중치 기본.
- **무리** — 공구만 ✋. 버튼은 장소1 에서 천장이라 탐색 점수가 갈리지 않는다 → 2단계.
- **횟수** — 30회(처음 10회 무작위 · TPE multivariate · 시드 0 하나) · 640 입력이면 2개 동시로 약 3시간(공구 120 에폭 ≈ 11분) — 하룻밤 안. 768×1024 가 들어가면(§12) 약 1.3배.

### 5.2 목표값 — 학습 중 검증 몫 · 채점 사진은 쓰지 않는다
- 목표 = 검증 몫(177장 · 공구 박스 렌치 155 · 펜치 37 · 드라이버 26)에서 conf 0.65(config) 운용점의 **종류별 재현율 평균**(driver · wrench · pliers 같은 무게) ✋ — mAP50-95(ultralytics fitness · 함정③)가 아니라 운용 지표로 고른다.
- 채점 사진 292장은 ② · ③ 에서만 쓴다 — 탐색이 시험지에 맞춰지지 않게.
- ⚠️ 한계 — 드라이버 26개라 1개 = 3.8%p · 시드 한 번이라 운이 섞인다 → **상위 3개를 ② 에서 시드 3회로 다시 거른다**. 상위 3개는 검증 몫 precision 이 E0c 검증 몫 최저보다 낮지 않은 것 중에서 고른다 ✋.

### 5.3 도구 — 1단계 체계에 얹는다
- **데스크톱 탐색기 `tune.py`**(새 파일 · 독립 프로세스 · 세션과 무관하게 돈다) — Optuna `ask` → 실험 설정(1단계 기본 + 이번 값)을 실행기 대기열에 넣음 → 학습·채점이 끝나면 검증 몫 목표값을 읽어 `tell`. 동시 개수·안전장치·끊김 복구·기록은 **1단계 실행기를 그대로 쓴다**(새로 짜지 않는다).
- **연구 기록** — Optuna study 를 데스크톱 SQLite 에 둔다(중간에 끊겨도 이어서). 시도마다 결과 폴더는 1단계와 같은 꼴(`학습/결과/E8-tool-t###/`) · 장부에 그대로 쌓인다(id 머리 E8 = 탐색 ✋).
- **채점** — `train_one` 이 best.pt 를 검증 몫으로도 채점해 `채점_검증.json` 을 남긴다(채점 292장 결과는 지금처럼 `채점.json`).
- **파이 명령** — `학습.py 탐색 <탐색설정.yaml>`(걸기) · `학습.py 탐색상태`(지금까지 최고 · 남은 횟수). 받기·장부는 그대로.
- **판 고정** — optuna 를 데스크톱 `~/학습실험/venv` 에 판을 고정해 설치하고 판을 결과 요약 「판」에 남긴다.
- **멈춤** — 1단계 안전장치 그대로(진행없음 · 시간상한 · 점수0 · 오류 → 대기열 멈춤 → 탐색기도 멈춤 · `재개` 로 이어감).
- **중단 규칙** ✋ — 첫 10회(무작위) 중 3회 이상이 이상 종료하거나, 10회 목표값이 모두 E0c 검증 몫 범위 아래면 탐색을 멈추고 범위를 다시 정한다(사용자 보고).

### 5.4 기준
- ② 의 기준 = 같은 운용 조건(멈춤 · 나눔 · conf · 판)의 E0c 3회. 결과의 「판」(ultralytics · torch · CUDA · GPU · albumentations)에 optuna 는 들어가지 않고 학습에도 영향이 없으므로 E0c 를 다시 돌리지 않고 **검증 몫만 다시 채점**한다(계획 작성 때 고침 · 2026-10-04). albumentations 를 까는 흐림 실험(§7)은 「판」이 바뀌므로 새 기준을 3회 다시 돈다.

## 6. ② 확인
- 탐색 상위 3개 × 시드 3회(약 1.7시간 · 640) → 채점 292장에서 E0c(같은 판) 3회와 채택 판정 규칙으로 판정.
- 둘 이상 채택되면 목표값 평균이 높은 쪽 ✋ · 하나도 없으면 **새 기준 = E0c 설정**(1단계 기본 + 120 에폭 끝까지).
- 결과 = 저널 새 절 · 장부.

## 7. ③ 가설 실험 (새 기준 위)
| 실험 | 값 | 가설 | 비용 |
|---|---|---|---|
| cutmix | 0.3 ✋ | 누르는 순간 손에 가린 버튼(§12.67-(11)) — 공식: 「현실적인 가림 상황을 만든다」 | 3회 |
| 흐림 | albumentations 설치 + 직접 준 변환 목록 = Blur · MotionBlur 만(흑백 변환 없음 — 공식: 직접 준 목록이 기본 목록을 통째로 대체) ✋ | 1인칭 흔들림 흐림 · 지금 학습엔 흐림 증강이 전혀 없다 | 3회 + 판이 바뀌므로 새 기준 3회 다시 |
| SGD | lr0 0.01 · 나머지 새 기준 | 끝까지 학습하면 SGD 가 AdamW 와 비슷하거나 낫다는 경우가 있다 — 우선순위 낮음 | 3회 |

- 채택되면 그 위에서 **학습률만 짧게 재확인**(새 기준 학습률 대 바로 옆 값 하나 · 3회) — 증강이 세지면 알맞은 학습률이 달라질 수 있다.
- 흐림의 albumentations 는 공식 기본 변환(Blur · MedianBlur · ToGray · CLAHE 각 1%)을 쓰지 않는다 — ToGray 가 버튼 색 구별을 해칠 수 있다(1단계 가이드 대조).

## 8. ④ HEF 변환 조사 · 장소1 모의 변환

> 사용자 — 「onnx, hef 변환 스크립트는 이전 변환 스크립트를 그대로 사용하는 것이 아닌 백지 상태에서 다시 ultralytics 학습 기본값 조사 했던거와 같이 조사 과정이 필요해 우리에 맞는 스크립트 코드가 있는지 아니면 상관없는지 확인을 하고 싶어」

### 8.1 백지 조사 — 공식 기본값과 그 근거 (1단계 §3 과 같은 방식)
- **답할 질문**
  1. **ONNX 내보내기** — ultralytics `export(format="onnx")` 의 인자(opset · imgsz · dynamic · simplify · nms · half 등) 기본값은 무엇에 맞춰져 있고, Hailo 변환에 넣을 ONNX 에는 무엇이 맞나.
  2. **DFC 세 단계** — 파싱(끝 노드) → 최적화(정수 변환 · 캘리브레이션 장수 · 최적화 수준 · 압축 수준 · 입력 정규화를 모델에 넣는 방법) → 컴파일의 기본값과 근거.
  3. **Hailo Model Zoo 의 yolov8n 기준 설정**(네트워크 설정 · 모델 스크립트 · NMS 후처리 설정)은 무엇에 맞춘 값인가(COCO 80종 · 입력 꼴 · 점수 문턱 등).
  4. **우리 상황**(버튼 5종 · 공구 3종 · 640×640 늘리기 입력 · 1인칭 · 작은 물체 · 정수 변환 손실)에서 — 기본값으로 충분한 것 / 바꿔야 하는 것과 이유 / 함정.
  5. **결론** — 우리에게 맞춘 변환 스크립트가 필요한가, 공식 기본 흐름(예: Model Zoo)을 그대로 부르면 되는가.
  6. **DFC 판** — 지금 데스크톱 = DFC 3.33.1 · Model Zoo 2.18.0 / 파이 = HailoRT 4.23.0(`hailo-all` 5.1.1). 첫 확인(2026-10-04 · Model Zoo 공식 릴리스 목록): Hailo-8/8L 갈래(Model Zoo v2.x · DFC v3.x)에 **v2.19.0 = DFC 3.34.0** 이 나왔고 v2.19.1 이 그 뒤다 · Hailo-10H/15 는 DFC 5.x 로 다른 갈래다. 조사할 것 = 3.34 에서 바뀐 점 중 우리(yolov8n · 정수 변환 · NMS)에 닿는 것 · **3.34 로 만든 HEF 가 파이 HailoRT 4.23 에서 도는지**(판이 어긋나 HEF 가 안 열린 사례가 공식 커뮤니티에 있다) · 파이용 HailoRT 새 판 패키지가 있는지 · 판을 올리면 이전 HEF·1-2단계 모의 변환과의 비교가 어떻게 되는지. 판을 올릴지는 8.1 결론을 보고 **사용자가 정한다**(데스크톱·파이 환경 변경).
  7. **DFC 의 GPU 사용** — 이전 변환은 GPU 가 아닌 **CPU 로** 했다 — RTX 5060 을 DFC 가 지원하지 않아 GPU 를 쓰지 못했다(사용자 · 작업로그 2026-10-03 「hailomz 원격 실행 가능(CPU)」). 조사할 것 = DFC 3.33.1·3.34 가 요구하는 GPU 조건(CUDA·cuDNN·딥러닝 프레임워크 판 · 지원 GPU 세대)과 **RTX 5060(Blackwell) 지원 여부가 바뀌었는지** · GPU 가 있으면 무엇이 달라지나(최적화 단계의 시간 · 쓸 수 있는 최적화 수준 · 정수 변환 품질) · CPU 로만 할 때의 제약 · GPU 를 쓰면 학습(같은 GPU)과 시간을 어떻게 나누나. GPU 를 쓰도록 환경을 바꿀지는 결론을 보고 사용자가 정한다.
