# 측정 중 보관용 녹화 — 1인칭 원본 영상 + 로그(오버레이는 나중에 그린다) · 녹화 구간 비교

> **상태** — 설계 · 사용자 검토 전 (2026-10-09 · 세션 8572c720)
> **관련** — 측정 도구 정합 설계(`2026-09-27-측정도구-정합-design.md`) D14(녹화는 1단계 측정에서 뺀다 → 지금 = 표시만) · D23(이번 측정 조건부) · 시나리오표 `Rpi5/Demo/measure/시나리오/`

## 1. 사용자 요청(원문 요지)

- 「정본 8개로 판정하고 녹화는 시나리오 세션별 1판씩만(NG 제외) 기록(보관)용으로 할 수 있게 녹화 기능을 부분 사용 … 시연 영상을 위한 데이터(영상, 로그 데이터)로 사용」
- 「녹화 시 기존 측정 데이터와 무엇이 달라지는지 … 녹화 시 측정본과 미녹화 시 측정본을 비교해 기록」
- 「1인칭 영상(오버레이 미포함) 영상만 있어도 버튼, 공구, 손 탐지에 대한 로그 데이터가 남으므로 로그 데이터에 바탕으로 1인칭 영상 위에 오버레이를 그리거나 할 수 있어?」 · 「3인칭 영상은 이제 필요 없어졌어」 · 「손 뼈대 기록은 제외」

## 2. 지금 상태(확인)

| | 지금 | 문제 |
|---|---|---|

## 5. 관문 · 중단 규칙

- 관문 ① 자가 테스트 0 fail(새 시험 — 녹화기: 넣은 번호 그대로 대응표 · 넘치면 버린 번호 남김 · 정지 때 파일 마무리(가짜 ffmpeg) / 세기: 구간 안 기록은 값에서 빠지고 비교 표에만 · 끔 사건 없으면 끝까지 · 구간 없으면 표 없음 / 콘솔: 원본 녹화 켜고 끄면 on·off 사건 · 세션 폴더에 파일) ② 실물 — 안경 충전 뒤 녹화 1판: 대응표 줄 수 = 영상 프레임 수 · 세기 ⑤ 비교 표 · 오버레이 다시 그린 PNG 가 실제 화면과 맞는지 눈으로 ③ 최종 리뷰 1회
- 🛑 중단 — 녹화 중 처리 FPS 가 절반 아래로 떨어지면(⑤ 비교) 멈추고 인코딩 설정을 다시 정한다 · 디스크 여유 0.5GB 아래면 녹화 시작을 거부(측정 실행기 1GB 경고와 별도)
- 🔒 홀드아웃 — 해당 없음

## 6. 버린 대안

- **시나리오 판 하나를 녹화하고 속도 값만 빼기** — 녹화 부하가 그 판의 경고 타이밍 같은 판정 값까지 흔들 수 있다.
- **시연영상 촬영(3벌) 그대로** — 1:1 이 아니고 디스크(약 390MB/회)·창 모드(측정 실행기는 전체화면)와 맞지 않는다.
- **오버레이 켠 1인칭 영상** — 나중에 모양을 바꿀 수 없다 · 사용자는 원본 + 로그를 원했다.
- **손 뼈대(21점) 기록** — 사용자 제외(프레임 기록 약 3배).
- **영상 시각을 실제 시각대로(가변 프레임률)** — 파이프 입력이 고정 프레임률이라 복잡해진다 · 대응표의 받은 시각으로 나중에 맞춘다.
