## 2. 목표 / 비목표

**목표** — brainstorming 으로 시작한 작업은 공동 확인(또는 중단 합의) 뒤 **정본 기록 → 세션 마무리 → push 가 끊기지 않고** 이어진다. 세션을 떠나 마무리가 빠져도 **다음 세션이 찾아 멈춘 지점·경과 시간과 함께 이어받는다.**

**비목표** — 새 훅 · 세션 종료 훅(강제 종료 시 보장 없음 — CC작업문서 §3.6) · 미계획 작업 기록 형식 · 외부 산출물 되먹임 · 기존 §10 슬림화(③-a2, 별도) · 공동 확인·설계 승인 관문 제거.

## 3. 설계 ① — 작업 마무리 흐름과 스킬 구조 (사용자 승인)

```
설계 승인 → spec 검토 → 계획 → 실행 → 최종 리뷰 → [공동 확인] ─┬→ work-close
                                                    [중단 합의] ─┘   ① 결말 확인  ② 정본 기록
                                                                     ③ 세션 마무리(session-wrap)  ④ push  ⑤ 끝 보고
```

| 구성 | 내용 |
|---|---|
| `.claude/skills/work-close/SKILL.md` 🆕 | 절차 정본 — ①결말 확인(완료 / 실패·중단) ②정본 기록(§4) ③session-wrap 호출 ④push ⑤끝 보고(정본에 쓴 것 절별 요약 · 작업로그 블록 요약 · push 결과 · 남은 로컬 변경) |
| `.claude/commands/작업마무리.md` 🆕 | 「절차 정본 = work-close」 — 사용자 직접 호출 |
| CLAUDE.md §2 발동 표 | 행 추가 — 「공동 확인 직후 · 실패·중단 합의 직후 → `work-close` → 바로」 |
| CLAUDE.md §2 「세션 마무리」 줄 | work-close 가 이어서 부른다 · 직접 불러도 된다 |
| CLAUDE.md §4 커밋 | 「push 는 사용자 요청 시」 → **「push 는 work-close 마지막에 한 번. 그 밖에는 사용자 요청 시」** (사용자 결정) |
| `session-wrap` SKILL | 맨 앞 안전판 — 「이번 작업 단위에 정본 기록이 안 됐으면 work-close 부터」 |
| CC작업문서 §2.1 | 표준 갈래 `… → 최종 리뷰 1회 → 공동 확인 → work-close` · executing-plans 끝의 `finishing-a-development-branch` 는 **work-close 로 대신한다**(main 에 경로 지정 커밋 · 브랜치 미사용) |
| CC작업문서 §2.4 | **계획서 마지막 태스크 = work-close 실행** 필수 |

**경우별** — 계획대로 끝남 = 마지막 태스크 · 계획 중 실패·중단 = 중단 합의 → 발동 표 · 계획서 없이 끝난 bounded 작업 = 공동 확인 직후 발동 표 · 한 세션 작업 여러 개 = **작업 단위마다** · 「세션 마무리」만 호출 = session-wrap 안전판 · 세션을 떠남 = §5 이어받기.

**push 단계** (Claude 결정 · 대화 표시) — 이번 작업 단위에서 커밋이 생긴 저장소만 · `git fetch` 로 원격에 새 커밋이 있으면 **push 하지 않고 멈춰 보고**(병합 판단은 사람) · 커밋 안 한 변경은 대상 아님(보고만) · 실패 시 작업로그는 두고 보고에 재시도 방법.

**Claude 결정** — 정본 기록 내용은 별도 승인 관문 없이 끝 보고에서 절별 요약(틀리면 사용자가 지적) · 스킬 이름은 기존 영문 관례(`session-wrap`·`session-resume`)를 따름.

## 4. 설계 ② — 정본 기록 형식 (사용자 승인)

**대상 문서** — 프로젝트 작업 = `docs/통합문서.md` · Claude Code 인프라 작업 = `docs/claude-code-작업문서.md` · 결과 사실이 없는 작업(조사·질문) = 기록 없음(작업로그만).

| 경우 | 정본에 쓰는 것 | 과정 |
|---|---|---|
| **A. spec·plan 있음** | ①결과 사실을 제자리에(측정 → §10 새 절 + 마커 + `[CURRENT]` + 색인 · 부품 §11.1 · 핀·채널 §12 · 설계값 해당 절 · 남은 일 🔓 미결) ②결과의 **중심 자리 한 곳**에 작업 요약 2~3줄 + `spec: … · plan: …` ③나머지 자리는 `(작업: plan 경로)` 포인터 | spec(설계) · plan(제작) |
| **B. 계획 문서 없이 끝남** (brainstorming bounded) | 결과 사실은 A 와 같이 + 중심 자리에 **정리된 진행 내용 전체**(무엇을·어떻게·왜 · 커밋 해시) | 정본 (사용자 결정) |
| **C. 실패·중단** | 결과 자리에 **❌ 실패** / **🛑 중단** + 이유(원인 규명 여부) + 현재 상태 + 재개 조건 · 재개할 일이면 🔓 행 | spec·plan 머리 상태 줄 「🛑 중단(날짜) — 이유 · 멈춘 태스크」 (사용자 결정 A안: 정본에 기록) |

**완료 전환** — §10 = 새 결과 절 + 옛 절 `⛔ SUPERSEDED-BY §10.N` · §11·§12 등 현행 절 = 완료 사실로 덮어쓰고 이력 한 줄(「2026-09-05 ❌ 결선 실패 → 날짜 완료」) · 🔓 행 삭제 + 근거 절에 결론 · spec·plan 상태 줄 「🛑 → ✅(날짜)」.

**공통 규칙** — **원천에서 옮긴다**(코드·로그·원본 대화·측정 파일. 점검 문서·작업로그·대화 속 요약에서 옮기지 않는다 — 2026-09-14 ③ 리뷰 4곳의 원인) · **날짜 = 작업한 날(현지)**, 세션 시작일 아님 · CLAUDE.md §3 규칙(조건 병기 · 구성 사실 단일정본 · 새 §10 절은 마커·색인·`[CURRENT]`) · 커밋 `docs(정본): <결과 한 줄>`.

**자가 점검(커밋 전)** — 기존 §10 본문은 마커 줄 외 불변 · 핀·채널 복제 없음(spec `2026-09-13-정본-구조` S1) · 🔓 행 근거 절 실재 · 새 §10 절 색인 등재.

**Claude 결정** — 표시 기호 **🛑 중단 · ❌ 실패**(⛔ 는 폐기·SUPERSEDED·금지값에 이미 쓰임) · 요약은 중심 자리 한 곳에만(복제 방지) · CC 인프라는 CC작업문서에.

## 5. 설계 ③ — 이어받기 보강 (사용자 승인)

**G1 판정** (`session_archive.py`)

| 딱지 | 판정 |
|---|---|
| 진행중 | 원본 60분 내 변경 (유지) |
| 기재 | UUID 가 작업로그에 있고 **그 세션 커밋이 전부 해시로 작업로그에 있음** |
| **부분 기재** 🆕 | UUID 는 있으나 **작업로그에 없는 커밋이 남음** |
| 미기재 | UUID 가 작업로그에 없음 (유지) |

- 세션 커밋 = 보존본이 모으는 **커밋 제목** → 두 저장소 `git log` 제목 일치로 해시 변환. 기록 행위 커밋(`docs(세션마무리)`·`docs(작업로그)`) 제외.
- 제목으로 해시를 못 찾으면 **부분 기재**(Claude 결정 — 놓치는 쪽이 더 위험).

**G2 진행중** (`session-resume`) — 거부하지 않고 「`<ID8>` · 마지막 활동 N분 전 · 마지막 지시 『…』 — 다른 창에서 작업 중인가요, 떠난 세션인가요?」를 **한 번** 묻는다. 「떠남」이면 부분 기재·미기재와 같은 길. 「작업 중」이면 건드리지 않는다(병행 세션 기록 겹침 방지).

**G3 시간** — `INDEX.tsv` 에 **마지막 활동(현지 시각) 열을 맨 뒤에** 추가(기존 열 번호 유지 — Claude 결정) · 보존본 시작·끝 시각을 현지 시각으로 · `/이어하기` 보고 첫 줄 = 「지금 YYYY-MM-DD HH:MM · 이전 세션 마지막 활동 YYYY-MM-DD HH:MM (N시간 전 · 어제/오늘)」 · work-close·session-wrap 기록 날짜 = 작업한 날(현지).

**G4 멈춘 지점** (부분 기재 · 미기재 · 「떠남」) — 작업로그에 없는 커밋(해시·제목·시각) · 그 세션이 편집한 `docs/superpowers/plans/*` 의 체크박스 상태 · 마지막 발화 3개 + 응답 꼬리 · 커밋 안 한 변경. 추천 1순위 = 「이어서 끝낼까요, 중단으로 확정할까요?」(이어서 → 남은 태스크 → 공동 확인 → work-close / 중단 → work-close 🛑). 계획서 태스크가 전부 체크돼 있고 정본 기록만 없으면 묻지 않고 「work-close 부터」.

**배너·마무리** — 📭 행 문구 「미기재 세션」 → **「기록 안 끝난 세션」**(미기재 + 부분 기재 — Claude 결정) · session-wrap §2 소급 대상에 부분 기재 포함.

**미계획 작업** — G1~G4 로 **찾아내는 데까지만**. 기록 형식은 별도 계획.
