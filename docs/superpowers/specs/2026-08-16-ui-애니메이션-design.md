# 글라스 UI 애니메이션 — 설계

- **날짜**: 2026-08-16
- **대상**: `Rpi5/Demo/` 글라스 UI 오버레이
- **상위 UI 정본**: `2026-08-03-uiux-글라스-design.md` (배치 §1·색 §3·패널 §4)
- **상태**: 설계 확정, 구현 전

## 1. 무엇을 하나

오버레이가 상태를 **툭 바꿔 표시**하던 것을 **움직여 표시**하도록 바꾼다. 표시하는 정보와
배치·색은 그대로다 — 바뀌는 것은 「전환의 표현」뿐이다.

목업(`anim_mockup.py`, 임시 확인용·미추적)에서 4종을 실기동 확인했고 사용자가 채택했다.

| # | 장면 | 지금 | 바꿀 것 |
| --- | --- | --- | --- |
| ① | 단계 전환 | 글자·막대가 즉시 바뀐다 | 끝난 줄이 완료색으로 한 번 반짝, 새 현재 줄의 왼쪽 막대가 자라며 자리 잡는다 |
| ② | 게이지 채움 | 200ms 주기로 계단처럼 뛴다 | 표시값이 목표를 따라 이어서 차오른다 + 완료 시 색 전환 |
| ③ | 공구 확인 | 글자만 바뀐다 | 상태 줄이 초록(쥠)·주황(오답)으로 번졌다 가라앉는다 |
| ④ | 경고·차단 | 배너가 즉시 나타난다 | 아래에서 미끄러져 올라온다. 차단은 테두리가 맥박한다 |

### 하지 않는 것 (YAGNI)
- 위젯 추가·배치 변경·색 변경 — 상위 design 문서의 §1·§3을 건드리지 않는다
- 메뉴·설정·알림 시트의 열림/닫힘 연출 — 이번 범위 밖
- 영상(카메라 프레임) 자체에 대한 어떤 처리도 하지 않는다

## 2. 구조 — `anim.py` 신설

애니메이션 도우미와 지속시간 상수를 **한 모듈에 모은다**. 색을 `theme.py`로, 폰트를
`config.py`로 뺀 것과 같은 결이다. 값 재조정이 예정돼 있어(사용자: "완성물 확인 후 값
재수정") 상수가 한 곳에 모이는 이점이 크다.

```
anim.py     tween / flash / slide_in / Pulse + 지속시간 상수 + ON·OFF 게이트
overlay.py  각 위젯이 「직전 상태」를 들고 있다가 달라졌을 때만 anim 을 부른다
config.py   UI_ANIMATION (환경변수 SOP_UI_ANIM=0 으로 끔) · SHOW_FPS
safety_console.py  실측 FPS 계측(프레임 도착 간격) + 조건부 표시
```

### 2.1 끕 스위치는 모듈이 게이트한다
`config.UI_ANIMATION` 이 False 면 **도우미가 최종 상태를 즉시 적용하고 리턴**한다.
호출부에 `if` 를 흩지 않는다 — 분기가 위젯마다 퍼지면 끄는 경로가 검증 불가능해진다.
기본값 True(적용이 이번 작업의 목적). 환경변수 `SOP_UI_ANIM=0` 으로 끈다
(`USB_CAMERA_ENABLED` / `SOP_USB_CAMERA` 가 쓰는 방식 그대로).

### 2.2 🔴 QGraphicsEffect 계열을 쓰지 않는다
`QGraphicsDropShadowEffect` 를 패널 자식 라벨마다 걸었다가 페인터 충돌로 **화면이 안
그려지고 클릭도 안 먹었다**(CPU 60%, 2026-08-03 → `overlay.py:73 _glow()`).
`QGraphicsOpacityEffect` 도 같은 계열이라 쓰지 않는다. 투명도는 **QSS 색의 알파를
`QVariantAnimation` 으로 굴려서** 낸다.

### 2.3 🔴 테두리 두께를 애니메이션하지 않는다
목업 1차에서 차단 맥박을 두께 1→5px 로 굴렸더니 **레이아웃이 밀려 글자가 흔들렸다.**
두께는 고정하고 색 알파만 바꾼다.

## 3. 트리거 — 「바뀔 때만」 게이트

🔴 **이 설계의 핵심이다.** `_sub_timer` 가 **200ms 주기(초당 5회)** 로
`gauge_panel.update_view()` 와 공구 배너 경로를 반복 호출한다
(`safety_console.py:224`·`1073`·`1083`). 갱신 함수 안에서 무조건 애니메이션을 시작하면
**초당 5번 재시작돼 끝나지 않는 반짝임**이 된다. 목업은 상태가 바뀔 때만 호출되는
가짜 시나리오라 이 문제가 드러나지 않았다.

→ 각 위젯이 **직전 값을 자기 안에 들고 비교**한다. 같은 값이 다시 들어오면 아무 일도
하지 않는다.

| 위젯 | 비교할 값 | 연출 |
| --- | --- | --- |
| `StatusPanel` | `expected_step` | 직전 현재 줄 완료색 반짝 → 새 현재 줄 막대가 자람 |
| `GaugePanel` | `progress` 목표값 | 표시값이 목표를 따라감(다음 목표가 200ms 뒤 오므로 끊기지 않는다) |
| `GaugePanel` | `tool_ok` · `wrong_tool` | 공구 상태 줄만 초록/주황 번짐 |
| `AlertBanner` | `mode` | 슬라이드 등장. `block` 이면 맥박 시작 |

### 3.1 🔴 맥박은 반드시 멈춘다
`block` 을 벗어나거나 배너가 숨겨지면 즉시 정지한다. 무한 반복 애니메이션이 살아남으면
QSS 를 계속 재적용해 CPU 를 태운다 — `_glow()` 와 같은 종류의 실패다. 정지 경로를
테스트로 못 박는다(§5).

### 3.2 relayout 충돌
`_update_sub_view()` 가 200ms 마다 `_relayout()` 을 부르고, `place()` 는 `setGeometry` 로
위치를 다시 앉힌다. 배너 슬라이드(260ms) 도중 이것이 끼면 **위치가 튄다.**
→ **애니메이션 중인 위젯은 relayout 이 목표 위치만 갱신하고 geometry 는 건드리지 않는다.**

## 4. FPS 계측 — 코드만 넣고, 측정은 시나리오 테스트 때

지금 카메라를 쓸 수 없어 **측정은 이번 범위 밖**이다(사용자 결정, 2026-08-16).
계측 수단만 넣어 두고, 카메라가 돌아오는 시나리오 테스트에서 잰다.
이것으로 ⏸ G6(「런타임에 FPS 계측 코드가 없어 잴 수단이 없다」)의 **수단 부재**가 해소된다 —
측정 자체는 아직이다.

- **재는 것**: 프레임 도착 간격(이미 있는 `_note_frame` 에 얹는다). 카메라가 없으면 값이
  나오지 않는다 — 이는 정상이며, 애니메이션 동작에는 영향이 없다.
- **표시**: 기본은 로그에 10초 주기 기록만(시연 화면에 숫자를 띄우지 않는다).
  `SOP_SHOW_FPS=1` 이면 우하단에 작게 표시한다(측정할 때만).

### 4.1 🔴 이번 작업이 끝나도 성능은 미판정이다
「애니메이션을 넣었고 잘 돈다」와 「FPS 를 깎지 않는다」는 다른 주장이다.
측정 전까지 **어떤 성능 주장도 하지 않는다.** 끕 스위치가 그때까지의 유일한 대비책이다.

## 5. 관문

- **검증 관문** — `Demo/selftest/test_anim.py` 가 전부 통과해야 한다. 실패하면 그 상태로
  진행하지 않는다.
  1. `UI_ANIMATION=False` 면 최종 상태가 **즉시** 적용된다(애니메이션 없이 결과가 같다)
  2. 같은 값으로 반복 호출해도 애니메이션이 **재시작되지 않는다**(200ms 주기 함정)
  3. `block` 이탈·`hide_all` 시 맥박이 **정지**한다
- **실기동 관문** — `run_demo.sh` 로 실제 기동한다. `@pyqtSlot` 시그니처 불일치처럼
  **import 검사로 못 잡는 런타임 오류**가 있고, 실제로 GUI 가 기동 즉시 죽은 적이 있다.
- **중단 규칙(유예)** — 시나리오 테스트에서 같은 조건 ON/OFF 실측 시,
  **FPS 하락 10% 초과면 기본값을 False 로 돌리고 원인을 재분석**한다.

## 7. 거부한 대안

- **`overlay.py` 안에 함수로 추가** — 파일이 이미 530여 줄이고, 색·폰트를 굳이 밖으로 뺀
  이 프로젝트의 취향과 어긋난다. 값 조정 때마다 위젯 코드를 헤집게 된다.
- **`safety_console.py` 에서 바깥에서 입힘(목업 방식)** — 「무엇이 바뀌었는지」를 아는 곳은
  위젯의 `update_view()` 내부다. 바깥에서 하면 그 판단을 한 번 더 구현하게 되고 정본이
  둘이 된다. 목업은 가짜 시나리오라 가능했다.
- **애니메이션 값을 config 로 노출** — 지금은 `anim.py` 상수로 충분하다. 실기동하며
  조정하다 값이 굳으면 그때 옮긴다(YAGNI).
