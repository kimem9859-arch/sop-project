# 글라스 UI 2차 수정 — 설계

> **선행 정본** = `2026-08-03-uiux-글라스-design.md`. 여기는 그 위에 얹는 **2차 수정 7건**만 담는다.
> 색·폰트·배치 비율의 정본은 선행 문서와 `theme.py`·`config.py`다. **여기에 값을 복제하지 않는다.**

**날짜** 2026-08-04 · **대상 코드** `Rpi5` 브랜치 `feature/glass-ui`

## 1. 배경

Task 1~16 을 마친 글라스 UI 를 사용자가 실기동해 확인한 **7건**이다. 6건은 이미 만든 것의 결함·다듬기이고, 1건(§9 연결 상태 표시바)은 새 기능이다.

**원인은 전부 코드에서 확인했다** — 아래 각 절의 「원인」은 추정이 아니라 실측이다.

## 2. 손대지 않는 것

- 🔴 **FSM·인터락·GPIO 배선** — 이번 수정은 전부 표시 계층이다.
- 🔴 **안전 UI 3종** — BLOCK 해제 거부(EMO 미복귀) · 인터락 폴트 경고창 · 종료 확인창.
- **메뉴·알림 창 자체의 닫기 방식** — 「같은 버튼(☰/🔔) 재클릭」을 유지한다(선행 §4.7 의 2026-08-04 결정). ✕ 는 **그 아래 항목 패널에만** 단다(§7).

## 3. 알림 배지 잘림

**증상** 🔔 우상단 숫자 배지가 경계에서 잘려 보인다.

**원인** 배지가 버튼의 **자식**인데 좌표가 버튼 밖으로 나가 있다. Qt 는 자식을 부모 경계로 잘라낸다.
실측 — 버튼 `(179,640,58,44)` / 배지 `(45,-6,19,18)` → 위로 6px, 오른쪽으로 6px 초과.

**결정** 버튼에 안쪽 여백을 두고 **배지를 버튼 안쪽 우상단**에 넣는다. 잘림이 원천적으로 사라진다.

**거부한 대안** — 배지를 버튼의 부모로 재부모화해 걸침을 유지하는 방식. 폰 앱 느낌(꼭짓점에 절반 걸침)은 살지만, 버튼이 움직일 때마다 배지 좌표를 따로 갱신해야 해 배치 코드가 두 곳으로 갈라진다. 얻는 것에 비해 비싸다.

## 4. 메뉴 박스

**증상** 폭이 좁아 항목 글자가 오른쪽 경계에 닿는다. 제목 「메뉴」와 추후 자리 「＋」에 회색 배경 박스가 보인다.

**결정**
- 폭 **1.5배**(선행 §4.7 의 `_MENU_POS["width"]`). **글자 크기는 유지**한다 — 답답함의 원인이 폭이지 글자가 아니고, 멀리서 보는 화면이라 줄이면 가독성을 잃는다(사용자 결정).
- 제목·「＋」 라벨에 **배경 투명을 명시**한다.

🔴 **회색 박스의 원인은 미확정이다 — 고치기 전에 진단한다.**
처음에는 「selector 없는 시트 스타일시트가 자식에 상속된 것」으로 봤으나, **제목과 「＋」 라벨에는 이미 `background: transparent` 가 걸려 있어**(`theme.text_qss`) 그것만으로는 설명되지 않는다. 후보는 ①그 라벨에 배경 지정이 실제로 빠져 있다 ②시트의 `padding` 이 만든 여백에 시트 배경이 드러난다 ③「＋」 자리 표시 자체가 불필요하다 — 셋 중 어느 것인지 **화면과 실제 스타일시트를 대조해 확인한 뒤** 최소 수정을 한다(계획서 Task 2 Step 5).

## 5. 점검 패널이 첫 열기에만 깨진다

**증상** 작업 시작 **전**에 메뉴 → 점검을 열면 패널이 납작하게 눌려 글자가 겹친다. 작업 시작 후에는 정상이다.

**원인** `_open_check()` 가 **숨겨진 패널에 항목을 채운 직후** 배치를 계산하는데, 그 시점에 레이아웃이 아직 계산되지 않아 높이가 실제의 1/5 로 잡힌다.
실측 — 첫 열기 `높이 89`(행 높이 2px, 5행) / 두 번째 `높이 496`(행 높이 77px). 두 경우 모두 `sizeHint` 는 496 이다.
**즉 "작업 시작 전"이 원인이 아니라 "처음 여는 것"이 원인이다.** 작업 시작 후가 멀쩡했던 것은 그 전에 이미 한 번 열려 레이아웃이 확정돼 있었기 때문이다.

**결정** 항목을 채운 뒤 **레이아웃을 확정시키고** 배치한다.

**같은 함정을 가진 곳** — `place()` 는 높이를 지정하지 않으면 `sizeHint` 를 읽는다. 내용을 채운 직후 배치하는 패널은 전부 같은 문제를 가진다(녹화 패널도 `set_state()` 로 내용이 바뀐다). **점검만 고치지 말고 내용 갱신 → 배치 순서를 쓰는 패널을 함께 본다.**

## 6. 설정 패널의 빈 공간

**증상** 작업 시작 전에는 「ⓘ 작업 중에는 변경할 수 없습니다」 문구가 없는데 **그 자리만 빈칸으로 남아** 공구 항목과 테마 항목 사이가 벌어져 보인다.

**원인** 문구 라벨이 빈 문자열이어도 높이를 차지한다(실측 37px).

**결정** 문구가 없으면 **라벨을 숨긴다** — 공간까지 함께 사라진다. 문구가 필요한 상태(작업 중)에서는 지금처럼 나온다.

## 7. 하위 패널 닫기 ✕

**증상** 메뉴에서 항목을 고르면 그 패널이 열리는데, 닫으려면 ☰ 를 다시 눌러야 한다.

**결정** **점검·녹화·설정·로그** 패널 우상단에 ✕ 를 단다.
- 🔴 **캘리브레이션은 그대로 둔다** — 별도 대화상자라 자체 닫기가 있다(사용자 지정).
- 메뉴·알림 창 **자체**는 기존대로 같은 버튼 재클릭으로 닫는다. ✕ 를 없앤 2026-08-04 결정(선행 §4.7)은 **자기 버튼이 보이는 창**에 대한 것이고, 항목 패널은 자기 버튼이 따로 없어 사정이 다르다.
- ✕ 는 **공통 코드 한 곳**에서 만든다 — 네 패널이 같은 모양·같은 자리여야 한다.

## 8. 알림 아이콘

**증상** 알림 목록이 글자 덩어리로 읽힌다.

**원인** 종류 기호가 `✓ ▶ ⚠` 같은 **흑백 글리프**라 본문 글자와 구별되지 않는다(`⛔` 만 컬러).

**결정** 종류 4가지를 **컬러 이모지**로 바꾼다 — 점검 ✅ / 작업 ▶️ / 경고 ⚠️ / 위험 ⛔. 종류 구분(키 4개)과 색 토큰은 그대로 둔다. 이모지가 종전 기호보다 넓으므로 **아이콘 칸 폭을 함께 넓힌다**(실측 20px → 26px).

## 9. 연결 상태 표시바 (새 기능)

**목적** 지금은 무엇이 끊겼는지 알려면 메뉴 → 점검을 열어야 한다. 상시로 보이게 한다.

**형태** 화면 **우하단**에 아이콘 3개를 가로로 — 📷 카메라 · 🔌 인터락 · 🔘 GPIO. **상태는 아이콘 색으로만** 구분한다(연결=초록 / 끊김=빨강 / 확인 중=회색). 글자는 넣지 않는다(사용자 결정 — 영상을 덜 가린다).

**🔴 상태 출처는 점검 기능과 같은 것을 쓴다** — 카메라 프레임 수신 시각, 인터락 연결 여부, GPIO 사용 가능 여부. 별도로 판단하면 **표시바와 점검 화면이 서로 다른 말을 하게 된다.**

**갱신** 1초 주기. 색만 바꾸는 갱신이라 부하는 무시할 수준이다(선행 실측에서 글라스 UI 자체가 1%).

**범위 밖** — 클릭해서 점검 열기, 끊김 이력, 알림 연동. 필요해지면 그때 만든다.

## 10. 검증

- 각 항목의 **관문 4개**는 선행 계획서와 같다(셀프테스트 → `test_imports` → `test_fsm`·`test_recipe` → `run_demo.sh` 실기동).
- 🔴 **`offscreen` 셀프테스트만으로는 이번 7건 중 대부분을 못 잡는다** — 잘림·겹침·빈칸은 **그려 봐야** 보인다. 2026-08-04 에 쓴 방식(가상 디스플레이 Xvfb + 화면 캡처)으로 **눈으로 확인**한다.
- 크기·좌표처럼 **수치로 잡히는 것은 셀프테스트로** 굳힌다(배지가 버튼 안에 있는가, 점검 패널 높이가 sizeHint 와 같은가, 빈 문구 라벨이 숨겨지는가).
