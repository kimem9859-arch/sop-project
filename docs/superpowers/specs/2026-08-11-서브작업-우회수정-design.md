# 서브작업 우회 구멍 수정 (A-1) — 설계 (2026-08-11)

> **구현 전 설계안.** 승인 후 구현한다(CLAUDE.md brainstorming-first HARD-GATE).
> 결함 원출처: 통합문서 **§10.32-(6)③**. 서브작업 정본: [`2026-08-03-uiux-글라스-design.md`](2026-08-03-uiux-글라스-design.md) §5·§6.

## 1. 무엇이 잘못됐나

`safety_console._press_button`(`safety_console.py:957`)이 서브 작업 진행 중에 **들어온 버튼을 가리지 않고** FSM 으로 넘긴다.

```python
# 서브 작업 진행 중이면 어떤 버튼이든 FSM 으로 보낸다 → 오답이면 위반 판정
if self._sub is not None and self._sub.is_active:
    self._commit_button(button)
    return
```

서브 대기 중에는 `fsm.expected_step` 이 아직 안 올라가 있으므로 `fsm.correct_roi` 는 **여전히 그 버튼**이다. 따라서 **같은 버튼을 다시 누르면 FSM 이 "정답"으로 받아 `_step_complete()` 로 단계를 올린다.**

→ **`SubTask.can_advance`(시간 AND 공구) 검사가 통째로 우회된다.** 2단계의 *"N2 퍼지 30초 + 스패너 지참"* 이 **둘 다** 뚫린다.

🔑 **의도는 원래 옳게 적혀 있었다.** 같은 함수 docstring 이 *"대기 중 **다른** 버튼을 누르면 …오답 판정"* 이라고 쓰고 있다. **구현만 "아무 버튼"이라 주석과 코드가 어긋나 있었다.**

## 2. 무엇이 되어야 하나

서브 진행 중 입력을 **세 갈래**로 나눈다.

| 입력 | 동작 | 근거 |
|---|---|---|
| **그 서브의 버튼 재입력** | 🆕 **무시 + 로그** | 같은 버튼 재입력은 **순서 위반이 아니라 조급함**이다. 화면엔 이미 게이지가 돌고 있어 상황이 보인다 (2026-08-11 사용자 결정) |
| **다른 버튼** | `_commit_button` → 오답 판정 | **기존 동작 유지** — 설계 의도 그대로 |
| **EMO** | `_commit_button` → `_emo_stop` | **기존 동작 유지** — 비상정지는 어떤 상태에서도 통과해야 한다 |

## 3. 변경 (4줄 추가, 1파일)

```python
if self._sub is not None and self._sub.is_active:
    # 🔴 같은 버튼 재입력은 FSM 에 보내지 않는다 — 보내면 can_advance
    #    (시간 AND 공구) 검사를 건너뛰고 단계가 올라간다(§10.32-(6)③ 결함).
    #    EMO 는 여기 걸리지 않는다 — _sub_button 은 레시피 단계 버튼(B1~B4)만
    #    담으므로 EMO 와 같아질 수 없고, 아래 _commit_button 으로 그대로 간다.
    if button == self._sub_button:
        self._append_log(f"[서브] {button} 재입력 무시 — {self._sub.label} 진행 중")
        return
    self._commit_button(button)
    return
```

**손대지 않는 것**: `_commit_button` · `_finish_sub` · `SubTask` · `fsm.py` · `recipe.json`.

### 설계 판단 두 가지

- **`self._sub_button` 으로 판정한다** — `fsm.correct_roi` 도 같은 값이지만 간접적이다. `_sub_button` 은 *"지금 어느 버튼의 서브가 도는가"* 를 직접 담고 있어 의도가 코드에 드러난다.
- **EMO 전용 가드를 넣지 않는다** — `_sub_button` 에는 `_begin_sub()` 를 통해 **레시피 단계 버튼만** 들어가므로 EMO 와 같아질 수 없다. 가드를 넣으면 **절대 실행되지 않는 죽은 코드**가 된다. 대신 **테스트로 EMO 통과를 증명**한다(아래 검증 2).

## 4. 거부한 대안

| 대안 | 거부 사유 |
|---|---|
| **재입력도 오답 판정(BLOCK)** | 정답 버튼을 다시 누른 것을 순서 위반으로 보는 것이라 시연에서 과하게 보인다. SOP 상 순서를 어긴 것이 아니다 |
| **재입력 시 안내 알림 표시** | 연타하면 알림이 쌓인다. 게이지가 이미 진행 상황을 보여주고 있어 정보 가치가 낮다 |
| **`SubTask` 에 재입력 처리 책임을 넘김** | `SubTask` 는 Qt·FSM 을 모르는 순수 상태 객체다(그 파일 주석의 설계 원칙). 버튼 라우팅은 콘솔의 책임이다 |
| **`fsm.press_button` 에서 막기** | FSM 은 서브 작업을 모른다 — 그것이 이 설계의 핵심(*"FSM 을 고치지 않는다"*, `sub_task.py` docstring). FSM 에 서브 개념을 넣으면 설계가 무너진다 |

## 6. ⚠️ 알고 있어야 할 부작용

이 수정 후 **`wait_tool` 단계(2단계 B2)는 정상 경로로 통과할 수 없게 된다.** 지금까지는 재입력 우회 덕분에 "어쨌든 넘어가지던" 것이 막히기 때문이다.

원인은 **A-2 — `SubTask.set_tool()` 을 호출하는 코드가 없다**(공구 감지 모델 미구현, §10.32-(6)③ 연관 미결). 설정 메뉴의 **수동 공구 지정으로는 통과**되므로 시연이 막히지는 않는다.

→ **이것은 퇴행이 아니라 결함의 정직한 노출이다.** A-1 수정 후 **A-2 가 유일하게 남은 구멍**이 되어 경계가 뚜렷해진다. A-2 는 `tool_v2` 판정 후 별도 설계로 다룬다.
