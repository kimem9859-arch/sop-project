## 1. 목적과 범위

**목적** — 기기마다 같은 뼈대의 폴더 규칙을 정하고, 흩어진 프로젝트 파일을 **같은 기기 안에서** 제자리로 모은다. 데스크톱은 Windows 쪽 프로젝트 파일을 WSL 로 옮기고, WSL 에서 열거나 실행할 수 없거나 두기에 맞지 않는 것만 `D:\SOP가디언\` 한 곳에 둔다(사용자 10/16).

| 기기 | 범위 |
|---|---|
| 파이1 · 파이2 | 파일 시스템 전체(시스템 · 프로그램은 보기만) |
| 데스크톱 WSL | WSL 전체(`/` — 시스템 · 프로그램은 보기만) |
| 데스크톱 Windows | `C:\` · `D:\` 전체에서 프로젝트 파일 |

**손대지 않는 것**
- 프로젝트와 관련 없는 폴더 이름 · 게임 · 앱 바로가기 · 굿즈 · 이력서(`D:\resume`) · 사진 · 음악 같은 개인 파일(사용자).
- `AI_Manager`(바탕화면 · `D:\` 두 벌) · 「나노종합기술원」 · 반도체 수업 자료(산화막 레시피 · 박막 실습교안 · Sputter 보고서 · 8D Report · 기말 퀴즈) · `D:\문서\카카오톡 받은 파일`(사용자 「추정 맞아」).
- 프로그램 · 시스템 · 캐시 — 지울 후보 목록에만 올린다.
- OneDrive(학교 · 개인) — 파일이 클라우드에만 있다 → 3단계.
- **애매한 파일**(이름만으로 프로젝트인지 갈리지 않는 그림 · 캡처 · 받은 파일) — 건드리지 않고 「확인 목록」에만 올린다(개인 파일 보호가 먼저).

**이 단계에서 하지 않는 것** — 기기 사이로 옮기기(파이 ↔ 데스크톱 ↔ 파이2 — 2단계).

## 2. 지키는 규칙

1. **공통 뼈대 = 파이1 폴더 규칙의 「무엇이냐」 축**([`파이-홈-폴더규칙.md`](../../파이-홈-폴더규칙.md)). 꼭대기 폴더는 기기마다 3장 표로 정하고, 거기 없는 꼭대기 폴더를 새로 만들지 않는다.
2. **Windows 파일을 가르는 기준**

   | 파일 종류 | 갈 곳 | 까닭 |
   |---|---|---|
   | 한글(`.hwp` · `.hwpx`) · Office(`.docx` · `.pptx` · `.xlsx`) · draw.io(`.drawio`) 원본 | `D:\SOP가디언\문서\` | WSL 에 이 프로그램이 없다 — 고칠 때 Windows 프로그램으로 연다 |
   | Windows 실행 파일(`.exe`) | `D:\SOP가디언\도구\` | WSL 에서 실행되지 않는다 |
   | Windows 가상환경(`venv`) | 옮기지 않음 → 지울 후보 | 만든 자리 경로가 박혀 있어 옮기면 실행되지 않는다 · `requirements.txt` 로 다시 만든다 |
   | 그 밖 — 데이터셋(사진 + 라벨) · 영상 · 사진 · PDF · 모델 · 로그 · 코드 · 글 | WSL 역할 폴더 | WSL 에서 읽고 쓰는 데 문제가 없다 |

   - **폴더는 쪼개지 않는다** — 폴더 하나는 「주로 무엇으로 여나」로 한 곳에 보낸다(예: 수행일지 = 한글 27 + PDF 5 → 통째로 `D:`). 흩어진 낱개 파일만 종류로 가른다.
   - **원본과 그 PDF 는 같이 간다** — 같은 이름의 `.hwp`/`.pptx` 와 `.pdf` 는 원본 쪽(`D:`)으로.
3. **WSL 안 자리는 홈의 역할 폴더**다(`~/data` · `~/lab` · `~/_archive`). `~/projects` 는 파이와 맞춰 쓰는 git 저장소라 넣지 않는다. 옮긴 묶음은 **원래 폴더 이름을 그대로** 둔다(어디서 왔는지 바로 알게).
4. **진행 중인 작업 파일은 끝난 뒤에 옮긴다** — `시안17_최종_1080p_단계명변경.mp4`(본선 영상 편집 · 10/19 제출까지 — 편집 프로그램이 영상 위치를 기억한다) · 서식2 작품설명서 `.hwp` · `.pdf`(10/19 메일 제출까지).
5. **코드가 무는 경로는 그대로 둔다** — 파이1 폴더 규칙 §6 · 시연 런타임 폴더(`Rpi5/Demo/test/raw` · `recordings` · `scenario`) · 파이1 `data/학습실험`(`학습.py` 가 쓴다) · WSL `~/학습실험`(학습 도구가 이 자리를 쓴다) · **가상환경 전부**(`~/hailo-venv` · `~/hailo-ul-venv` · `~/학습실험/venv` · `~/projects/.poc_venv` · `~/env/*` — 옮기면 깨진다 · 학습 · 변환 도구가 `~/hailo-venv` 를 부른다). 2단계에서 다시 본다.
6. **git 저장소 안은 손대지 않는다** — git 이 관리하지 않는 큰 파일(`~/projects/dev/ai_model/.venv` 8 GB 등)도 이번엔 목록만.
7. **지우기는 후보 목록 → 사용자 확인 뒤에만.** 「사본 있음」은 내용 지문(md5)이 같은 것만 말한다. 휴지통 비우기도 사용자가 정한다. Windows 파일을 WSL 에서 지우면 휴지통을 거치지 않으므로, 복사 → 지문 대조가 끝난 것만 지운다.
8. **애매하면 건드리지 않는다** — 1장 「애매한 파일」.

## 5. 옮기는 방법

| 경우 | 방법 | 확인 |
|---|---|---|
| 같은 파일 시스템 안(파이1 · 파이2 · WSL 안 · `D:` 안) | 이름 바꾸기(`mv` — 내용 복사 없음) | 옮긴 뒤 원래 자리에 없고 새 자리에 있음 |

## 7. 되돌리기

- 이름 바꾸기는 반대로 바꾼다 · 복사-지우기는 기록표의 새 자리에서 원래 자리로 복사한다.
