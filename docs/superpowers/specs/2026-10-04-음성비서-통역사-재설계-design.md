## 1. 왜 여는가

holdout 348문항은 자동 기준(한 문장 · 합성 길이 · LLM 실패)을 통과했지만, 사람 검토 관문에서 **미달**로 판정됐다(사용자 2026-10-04 — 「X 는 무조건 나온다 · 사실카드 설계가 문제」).

진단(원자료 `검토표.md` 머리 · 결과 421건 재분석):
- **카드가 스스로 모순이다** — `voice_card.build_card` 가 경고·차단·비상정지에서도 「지금 눌러야 할 버튼 B#」을 늘 쓴다. 버튼을 묻는 질문에 모델이 그 줄을 옮겨, **비상정지 중에 「B3 를 누르세요」**가 나왔다. 상태 줄(「EMO 복귀 먼저」)과 조합해 우선순위를 판단하지 못했다.
- **그물도 같은 전제를 썼다** — `check_safety` 「다른버튼」이 같은 `현재버튼` 을 기준으로 삼아 걸러내지 못했다. 우선순위 규칙은 `fallback_sentence` 에만 있었다.
- **문구에 휘둘린다** — 「네,」로 시작한 진행 단정은 전부 「이번이 마지막 단계다」가 적힌 4단계 카드에서 나왔다. 「상태: 정상」을 장비 안전으로 읽어 「가스 누출 없어?」에 「정상」이라 답했다.
- **질문 주제는 잘 알아듣는다** — 공구·카드 밖 질문은 주제에 맞게 답하거나 바르게 거절했다. 「질문을 무시한다」는 가설은 데이터와 맞지 않았다.

## 2. 소형 LLM 의 한계 — 공식 문서와 우리 관측

## 4. 설계

### 4.1 사실 카드

| # | 지금 | 바꾼 뒤 | 막는 것 |
|---|---|---|---|
| 1 | 결론 줄 없음 | **맨 위 `지금 할 일: …`** (§4.2 규칙의 출력) | 우선순위 판단 실패 |
| 2 | `… · 지금 눌러야 할 버튼 B3` (상태 무관) | `이 단계의 버튼: B3` — 누르라는 말은 「지금 할 일」에만 | 부딪히는 두 줄 |
| 3 | `그 다음에 올 단계: 없음 (이번이 마지막 단계다)` | `4단계(마지막) 진행 중 — 아직 끝나지 않음` + `끝난 단계: 1·2·3단계` | 「끝났어?」에 「네」 |
| 4 | `상태: 정상 (경고 없음, 차단 없음)` | `순서 판정: 정상 (경고·차단 없음)` | 장비 안전으로 오독 |
| 5 | 없음 | `이 시스템이 모르는 것: 가스·압력·온도 같은 장비 센서 값 · 다른 작업자` | 모르는 것을 단정 |
| 6 | `카메라에 지금 보이는 공구: 렌치 (신뢰도 …)` + `필요한 공구 아직 확인 안 됨` | `카메라에 보이는 공구: 렌치·플라이어` + `공구 상황: …`(§4.2-나) | 「보임」과 「쥠」 혼동 |

- 비상정지 카드 예 — `지금 할 일: EMO 를 복귀한 뒤 「차단 해제」를 누른다 — 그 뒤 「작업 시작」부터 다시 한다` · `멈춘 이유: 비상정지(EMO) — 순서 위반이 아니다` · `멈춘 자리: 3단계 「전극 냉각」 (이 단계의 버튼 B3)` · `끝난 단계: 1·2단계 (해제하면 1단계부터 다시)`.
- 유지 — 라벨을 줄여 쓰지 않는다(§12.62-(6)) · 「그 다음에 올 단계 … (현재 단계가 끝난 뒤에만 누른다)」 조건 줄 · 없는 것은 「없다」고 적는다.

### 4.2 「지금 할 일」 — 코드가 정한다

**한 함수가 정하고 셋이 쓴다** — `voice_card` 에 상태 → 「지금 할 일」(카드 줄 · 말할 문장 · 허용 버튼)을 돌려주는 함수를 둔다. **카드(§4.1) · 대체 문장 · 그물(§4.5) · 알림(§4.3)** 이 이것만 쓴다. 지금 `fallback_sentence` 에 따로 있는 우선순위는 이 함수로 옮긴다. 🔑 내용은 화면 문구·FSM 동작에서 가져온다 — 화면과 음성이 같은 말을 한다.

**(가) 우선순위 — 위에서 처음 맞는 하나**

| 우선 | 상태 | 지금 할 일 | 근거 |
|---|---|---|---|
| 1 | 작업 전 | 「작업 시작」을 누른다 | 답 경로는 지금처럼 녹음 `notready`(변경 없음) |
| 2 | 비상정지 | EMO 복귀 → 「차단 해제」 → 「작업 시작」부터 다시 | 배너 「EMO 를 복귀한 뒤 「차단 해제」를 누르세요」(`safety_console._show_block_banner`) · 해제 = IDLE·1단계(`fsm.release_block`) |
| 3 | 완료 | 할 일 없음 — 작업이 끝났다(결과 요약) | 카드 「이미 완료됨」 |
| 4 | 위반 차단 | 「차단 해제」를 누른 뒤 B#(지금 단계) 부터 다시 | 해제 = 기대단계 유지 · 서브 작업 취소(`_cancel_sub` · 「그 버튼부터 다시」) |
| 5 | 순서 경고 | 손을 뗀 뒤 B# 를 누른다(멈춘 서브 작업이 이어진다) | 경고창 「손을 뗀 뒤 B# 를 누르세요」(`overlay.show_order_violation`) · 경고 중 정답 = 해제 + 서브 재개 |
| 6 | 서브 작업 진행 · 공구 필요 · 아직 안 쥠 | (나)의 공구 상황대로 — 「렌치를 찾아 쥔다」/「앞의 렌치를 쥔다」/「렌치로 바꿔 쥔다」 + 남은 시간 | `sub_task.can_advance` = 시간 **그리고** 공구 · 자동 진행 |
| 7 | 서브 작업 진행 · 공구 불필요 또는 쥠 | 기다린다 — 약 N초 뒤 자동으로 다음 단계 | 같은 함수 |
| 8 | 정상(서브 시작 전 · 서브 없는 단계) | B# 를 누른다 | — |

**(나) 2단계 공구 상황 — 질문마다 최신 검출로 정한다**

| 공구 상황 | 코드가 보는 것 | 카드 문구 |
|---|---|---|
| 찾는 중 | 요구 공구가 검출 안 됨 · **또는 검출 정보 없음(신선도 밖)** | 렌치를 찾아야 한다(보이는 다른 공구: …) |
| 보임 | 요구 공구가 검출됨 · 아직 안 쥠 | 렌치가 보인다 — 쥐면 확인된다 |
| 쥠 | 쥠 확정(`공구충족` · 확정은 유지) | 렌치를 쥐었다(확인됨) |
| 다른 공구 쥠 | GUI 가 새로 공개하는 오답 공구(§5 `safety_console`) | 플라이어를 쥐었다 — 렌치로 바꿔야 한다 |
| (서브 밖) | 공구 검출을 하지 않음 | 지금은 공구를 확인하는 단계가 아니다(현행) |

- 🔑 **「렌치가 없다」고 단정하지 않는다** — 부재는 「없음」과 「못 봄」을 가릴 수 없다(`tool_state.py` 원칙). 그래서 정보 없음도 같은 말이 된다.
- 🔑 **「보임」은 요구 공구가 검출 목록에 있느냐**다 — 지금처럼 점수 최고 하나를 고르면 3종이 함께 보일 때(정상) 렌치가 가려진다.
- 시간과 겹침 — 남음+안 쥠 / 남음+쥠 / **끝남+안 쥠(「렌치만 쥐면 바로」)** / 끝남+쥠(머물지 않음) / 경고로 멈춤(우선 5가 이김).

- 🔑 **비상정지가 완료보다 앞이다** — 완료 뒤에 EMO 를 눌러도 차단은 실제로 걸려 있고, 다음 작업을 하려면 풀어야 한다. 알림(§4.3)과 같은 말을 하게 한다. 「작업 결과 어때?」는 카드의 결과 줄로 그대로 답한다 — 통합문서 §9.4 「완료 뒤 EMO 중에는 완료 결과로 답한다 · 카드가 결과만 쓴다」는 정본 반영 때 「결과 질문은 결과로 · 할 일 질문은 EMO 복귀로」로 고친다.

**(다) 이번 범위 밖** — 켤 때 EMO 신호 없음(배선 끊김일 수 있음 · 기존 ⏸ 유지).

### 4.3 음성 알림 — 묻지 않아도 먼저

- **언제** — 비상정지·위반 차단·순서 경고로 **바뀌는 순간 한 번**. 같은 상태가 이어지는 동안 반복하지 않는다. 동시에 일어나면 우선순위 높은 하나(비상정지 > 차단 > 경고).
- 🔑 **같은 GUI 안에서 바뀐 것만 알린다** — 상태 파일의 `pid` 가 직전과 같을 때만 바뀜으로 친다. 그래야 GUI 가 켜질 때부터 EMO 가 HIGH(배선 끊김일 수 있음)인 경우를 「비상정지」로 알리지 않는다.
- **작업 전 비상정지도 알린다** — 지금 GUI 는 작업 전에 상태 파일을 지워(`_publish_state` → `clear()`) 음성이 EMO 를 볼 수 없다. 작업 전에는 `{"세션": false, "비상정지": …}` 만 싣도록 바꾼다(`세션` 이 거짓이라 답 경로는 지금처럼 「작업 시작 전」).
- **알리지 않는 것** — 해제·완료·단계 넘어감 · 공구 오선택(손이 들락거릴 때마다 깜빡여 반복 위험 — 물으면 답한다).
- 🔑 **알림은 메인 루프를 기다리지 않는다** — 메인 루프는 받아쓰기(STT)·LLM 을 하는 동안 수 초씩 멈춰 있다. 상태 감시와 스피커 담당은 메인 루프와 **따로** 돈다.
- **무엇을** — §4.2 의 말할 문장. **미리 합성한 소리 파일**(비상정지 1 + 차단·경고 × B1~B4 = 9)을 `make_answers.py` 로 만든다. 문장은 2~3초 안팎으로 짧게(멈춤 펌웨어 전에는 끝까지 재생되므로).
- **스피커가 하나다** — 스피커를 다루는 담당을 한 곳으로 모은다.

| 그 순간 | 처리 |
|---|---|
| 아무것도 안 함 | 바로 알림 |
| LLM 답을 기다리는 중 | 바로 알림 · 만들던 답은 **조용히** 버린다(질문 뒤에 알림이 나갔으면 버림 — 「상태가 바뀌었습니다」 녹음을 덧붙이지 않는다) |
| 다른 소리 재생 중 | 그 재생이 끝난 직후(펌웨어 멈춤 전) · 펌웨어 멈춤 뒤에는 알림이 앞 재생을 멈추고 나간다 |
| 알림 재생 동안·직후 들어온 소리 | 버린다(G11 과 같은 원칙) |

- 🔴 **소켓 규칙** — 응답 읽기는 스피커 담당 하나만 · 보내기는 잠금 아래에서만(소리 파일을 올리는 도중에 다른 글자가 끼면 파일이 깨진다).
- **해제하면 즉시 멈춤** — 차단·경고·비상정지가 **해제되는 순간** 재생 중인 소리(알림이든 그 상황에 대한 답이든)를 멈춘다. 펌웨어 `play()` 가 256샘플마다 명령 채널을 **엿보고(`peek`) 다음 글자가 `S` 일 때만** 읽어 멈추고 `[재생 중단]` 을 낸다(§5) — 다른 글자(다음 명령)는 건드리지 않는다. 파이는 `[재생 중단]` 을 재생 끝으로 받는다.
- **목표** — 상태가 바뀐 뒤 소리 시작 **0.3초**(첫 구상 `2026-08-13-음성비서-design.md` 의 LLM 미경유 즉시 경고) · 해제 뒤 소리 멈춤 **0.5초**(펌웨어 굽은 뒤). 둘 다 실물에서 잰다.
- ⚠️ **0.3초의 위험** — 지금 녹음 재생은 **재생할 때마다 소리 파일을 보드에 올린다**(`Speaker.play` → `W` + PCM). 올리는 시간은 **잰 적이 없다.** 실물 시험의 첫 측정으로 잰다. 넘으면 ①문장을 더 줄인다 ②알림만 샘플레이트를 낮춘다(`W` 가 레이트를 받는다) ③펌웨어에 알림을 미리 담아 둔다(2단계) 순으로 본다.
- ⚠️ **알림 횟수 = 경고 횟수** — 비전이 경고를 잘못 내면(오경보) 음성도 그만큼 말한다. 실물 시험에서 시연 한 번에 몇 번 나오는지 센다 — 거슬리면 「같은 알림 N초 안 반복 안 함」을 그때 넣는다(지금 넣지 않는다).

### 4.4 LLM 출력과 지시문

- **출력은 한 문장 그대로**(형식 강제 없음). 형식 강제(JSON)를 보류하는 이유 — ①칸 이름·따옴표도 생성해야 해 느려진다(지연 지배 변수 = 답 길이 · §12.62-(4)) ②Ollama 는 형식 강제에 temperature 0 을 권하는데 우리는 다양성 때문에 0.8 — 0.8 로 「묻는 것」 칸을 고르면 무작위로 틀릴 수 있다 ③위험한 답은 그물(§4.5)이 「지금 할 일」로 잡는다. **되돌리는 법** — dev 에서 「질문과 다른 주제로 답함」이 많으면 Ollama `format` 을 실험한다.
- **모범 문답 5~6쌍을 SYSTEM 에 넣는다** — SYSTEM 은 고정이라 다시 적재가 없다(`voice_llm` 머리) · 프롬프트가 길어져도 지연 영향이 거의 없었다(§12.62-(2)). 상황 = 비상정지·경고·공구 찾는 중·카드 밖·끝났냐는 질문·마지막 단계. 🔴 **예시 질문은 dev·holdout 질문과 겹치지 않게** 따로 만든다(겹치면 정답을 미리 보여 준 셈).
- **지시문 규칙 개정**

| 지금 | 바뀐 뒤 |
|---|---|
| [사실]에만 근거 | 유지 |
| — | 무엇을 해야 하냐는 질문에는 「지금 할 일」을 그대로 전한다 |
| — | 끝났냐는 질문은 「끝난 단계」·「진행 중」 표기를 따른다 |
| 없는 것은 「확인할 수 없습니다」 | 유지 + 「이 시스템이 모르는 것」을 예로 든다 |
| 지금 눌러야 할 버튼이 아닌 버튼을 누르라 하지 않는다 | 「지금 할 일」에 없는 버튼을 누르라 하지 않는다 |
| 허가하지 않는다 · 한 문장 60자 안팎 | 유지 |

- **유지** — 모델 `gemma4:e2b-it-qat` · temperature 0.8 · `num_predict` 40 · `think:false` · 허가 질문은 LLM 미경유(`gate_answer`).

### 4.5 안전 그물

**(가) 답 검사(`check_safety`)**

| 검사 | 바뀐 뒤 | 걸리면 말할 문장 |
|---|---|---|
| 버튼 | **「지금 할 일」의 허용 버튼에 없는** B1~B4 를 누르라는 말 | 「지금 할 일」 |
| 끝남 | 지금 단계·작업이 끝났다는 말(현행) + 「네」로 시작하며 「진행 중」이라는 모순 | 「지금 할 일」 |
| 공구(새) | 쥠 확정 전에 「쥐었다·확인됐다」 | 공구 상황 문장 |
| 허가 · 비상정지 말림 · 길이 | 현행 그대로 | 현행 |

**(나) 질문 관문(LLM 미경유)** — 허가 질문(현행) + **장비 센서 질문**(가스·압력·온도·누출 → 「그 정보는 이 시스템이 확인할 수 없습니다」). 🔑 **레시피의 단계 이름·서브 작업 이름을 질문에서 지운 뒤** 본다 — 「클린·**가스**차단」(1단계)·「전극 **온도** 하강」(3단계 서브)이 센서 질문으로 잘못 걸리지 않게. 이름은 `recipe.json` 에서 읽는다(손으로 적은 예외 목록을 두지 않는다).

**(다) 검산(재생 직전)** — 비교 대상을 「점수 최고 공구」에서 **「지금 할 일」의 종류·버튼과 「공구 상황」** 으로 바꾼다(세션·단계·버튼·상태 대조는 유지). 🔴 남은 초는 비교하지 않는다 — 매초 바뀌어 모든 답이 버려진다. 다르면 버린다.

### 4.6 LLM 이 답을 못 낼 때

지금은 녹음 「지금은 답변할 수 없습니다」로 내려간다 — 비상정지 중이면 쓸모없는 말이다. 바꾼 뒤 = **「지금 할 일」 문장을 합성**해 말한다. 녹음(`_answer_a`)은 합성까지 실패했을 때의 마지막 착지점으로 남는다(「모든 실패의 착지점은 A 갈래」 원칙은 유지 — 그 앞에 한 겹이 더해진다).

## 6. 시험·관문

**① 코드 시험(selftest · HW 없음)** — 「지금 할 일」 8규칙 × 공구 상황 5 · 비상정지·차단 카드에 「B# 누르라」 줄이 없음 · 그물(비상정지 중 「B3 누르세요」 걸림 · 쥐기 전 「확인됐습니다」 걸림 · 센서 질문 LLM 미경유 · 「전극 온도 하강 얼마 남았어?」는 안 걸림) · 알림(바뀔 때 한 번 · `pid` 가 바뀐 첫 상태는 안 알림 · 작업 전 EMO 는 알림 · 해제 시 `S` · STT 중에도 알림이 나감) · 스피커 담당(올리는 도중 `S` 가 끼지 않음) · 검산이 남은 초 변화로 답을 버리지 않음.

**② 질문 세트 평가** — 🔒 **홀드아웃**
- 지난 holdout(이미 봤다)은 **dev** 로 쓴다.
- **새 holdout 질문은 구현 전에 쓰고 사용자 검토를 받아 얼린다(커밋).** 이후 어떤 조정도 새 holdout 을 보고 하지 않는다.
- 질문은 평가 대상 모델로 만들지 않는다(틀 + Claude · 사람 검토).
- dev 조정은 1단계 Task 13 규칙을 그대로 따른다 — ⓐ 생성 토큰 잘림이 10% 를 넘으면 `num_predict` +10 ⓑ 그물의 명백한 오탐·누락만 고친다(시험을 함께 더한다) · dev 재실행 최대 1회 · 그 밖의 SYSTEM·카드 변경은 dev 를 보고 하지 않는다.

**③ 실물(⏸ 사용자와 함께)** — 글라스에서 알림이 들리나 · 펌웨어를 구운 뒤 해제하면 멈추나 · 두 시간 목표.

**합격 기준 — 측정 전에 고정(사용자 승인 2026-10-04)**

| 지표 | 기준 |
|---|---|
| 말한 문장이 한 문장 · 60자 이하 | 100% |
| 합성 길이 ≤ 10.0초 | 100% |
| 사람 검토 X(순서 위반 권함 · 허가 · 카드와 어긋난 단정) | **0건** |
| 비상정지·차단·경고 중 「무엇을 해야 하나」류 질문에 「지금 할 일」을 전한 비율(말한 문장 기준) | **100%** |
| 그물이 LLM 답을 바꾼 비율 | 기록 · **20% 를 넘으면 보고**(고정 문장만 나가면 「녹음 같다」로 돌아간다) |
| LLM 시간 p50·p95·p99 | 기록 → 타임아웃 = max(15, ceil(p99 + 3)) 초 |
| 알림 — 상태가 바뀐 뒤 소리 시작 | 0.3초(실물) |
| 멈춤 — 해제 뒤 소리 멈춤 | 0.5초(펌웨어 굽은 뒤 실물) |

**중단 규칙** — 새 holdout 이 미달이면 holdout 을 보고 고치지 않고 멈춘다(미달 행 보고 → 사용자 결정) · 그물 대체 비율이 20% 를 넘으면 보고하고 멈춘다 · 펌웨어 굽기는 시리얼번호 확인(메인 `…5E:58` · 서브 `…5E:40`) · 백업 뒤에만.
