## 1. 목표 · 쓰임

- **라벨링을 모르는 사람이 이 문서만 보고** 설치 → 묶음 받기 → 검토 → 올리기 → 보고까지 할 수 있다.
- **사람이 바뀌어도 같은 기준으로 고친다** — 사용자가 옆에 없을 때 찾아보는 참고서다. 사용자의 기준 맞추기(첫 10장 확인)와 함께 쓴다.
- 🔑 **이해하기 쉽게** — 한 문장에 한 가지 · 새 낱말은 처음 나올 때 풀어 쓴다 · 절차는 번호 단계로 · 판단은 표와 예시 사진으로.

## 2. 전제 (사용자 확인)

| 항목 | 내용 |
|---|---|
| 검토자 | 3~4명 교대 · 기록에는 이름 대신 **검토자 A·B·C·D** ✋(GitHub 저장소에 이름을 남기지 않는 규칙) |
| 컴퓨터 | 각자 Windows |
| 주고받기 | **구글 공유 드라이브** — 묶음을 거기서 받고, 검토 결과를 거기에 올리고, 사용자에게 보고 → 사용자가 Claude 에게 확인하라고 알린다 |
| 기준 맞추기 | 본격 검토 전에 검토자마다 **첫 10장 정도**를 사용자가 보고 알려 준다 |
| 개인정보 | 새 장소(장소2·3)도 얼굴·개인정보를 찍지 않고 촬영한다(사용자) — 안내서에 개인정보 절차는 넣지 않는다 |

## 3. 문서 구성 — 원본 한 곳 · 아티팩트는 원본에서

- **원본 = Rpi5 `Demo/docs/labeling_guide.md`** — 규칙문을 안내서로 키운다. 검토자가 보는 판은 **이 원본에서 만든 아티팩트(claude.ai 웹 페이지)** 다(사용자 결정) — 고치면 **같은 주소가 최신으로** 바뀌어, 옛 판이 도는 일(09-16 PDF 가 그대로 남은 일)이 없다. 지금 PDF 생성기(`~/lab/labeling-guide/make_guide.py`)는 문구를 따로 들고 있어 원본과 어긋났다 — 이번에는 원본을 읽어 만든다 ✋.
- 공유 — 아티팩트는 처음에 사용자만 본다. 검토자에게는 사용자가 claude.ai 공유 설정으로 링크를 준다. 로그인 없이 볼 수 없으면 **같은 원본에서 PDF 를 만드는 것**이 대안이다(되돌리는 법).
- 목차:
  0. 이 문서 쓰는 법 · **전체 흐름 한 장**(받기 → 설치·설정 → 검토 → 올리기 → 보고)
  1. **설치** — 공식 다운로드 위치(GitHub Releases) · 받을 파일(`X-AnyLabeling-v4.0.6-CPU.exe`) · 실행 · 한국어(Language 메뉴) · 다크 모드(Theme 메뉴)
  2. **설정** — 자동 저장 확인(File → Auto Save · 기본 켜짐) · **「검토함」 칸 보이게 하기**(설치 직후에는 안 보인다 — 설정 파일 `C:\Users\<이름>\.xanylabelingrc` 의 `flags` 에 `검토함` 을 넣고 다시 켠다) · **단축키 표**와 **바꾸는 법**(Ctrl+0 → Shortcuts · 예: 박스 차례로 확대를 F 로)
  3. **묶음 받기** — 공유 드라이브의 묶음 폴더를 내려받아 `images` 폴더를 연다(File → Image File Directory · Ctrl+U)
  4. **화면과 박스 읽는 법** — 이름 8종과 `exclude` · 박스 설명 세 가지(「기계 확정」 · 「확인: 이유」 · 「공구 초벌 — 확인」) · **이유 낱말의 뜻**(배치 불확실 · 박스 맞추기 실패 · 색≠초벌 · 무늬≠초벌 · 흐림 · 크기 이상 · 가림·모양 이상 · 버튼 1개 · 배치≠초벌) · 파일 이름 앞 순서(`a_check` → `b_propose` → `c_auto` → `d_blur`)
  5. **검토 방법** — 사진 종류별로 무엇을 얼마나 볼지 · 고치는 법(옮기기·크기·이름 바꾸기·지우기·새로 그리기) · 🔴 **기계 박스의 알려진 끝선 치우침은 고치지 않는다**(아래 끝선이 조금 짧음 · B4 위 끝선이 조금 넘침 — 반자동라벨링 설계 §6 ①) · 알아볼 수 없는 사진은 `exclude` · **사진마다 「검토함」 체크**
  6. **라벨 규칙** — 지금 규칙문을 최신으로(B4 = **검정 버튼 윗면 전체에 파란 테이프를 모양대로 잘라 붙임**(사용자) · 여백 0 세부 · 공구 한 부분만 보이면 그 부분만 · 책상 위·배경 공구도 그림)
  7. **올리기·보고** — 묶음의 **`.json` 파일 전부(200개)** 를 공유 드라이브에 올린다(사진은 파이에 원본이 있어 올리지 않는다 ✋) · 보고할 것 = 묶음 이름 · 검토자 · 특이사항
  8. **첫 투입** — 앞 10장을 먼저 올려 사용자 확인을 받고 이어서 한다
  9. **막히면** — 「검토함」 칸이 없다 · 저장이 안 된다 · 박스를 잘못 지웠다(Ctrl+Z) · 모르는 사진
- **화면 캡처** — X-AnyLabeling 화면은 사용자가 캡처해 보낸다. 받기 전까지 해당 자리에 「그림 자리」를 두고 글로 설명한다.
- **예시 사진** — 규칙 예시(초록 = 정답 · 빨강 X = 틀림 · 주황 = 그리지 않음)는 지금 11장을 쓰고, 옛 가로 촬영본·모조 콘솔이라는 한계는 적어 둔다. 실콘솔 세로 사진으로 바꾸는 것은 범위 밖(§6).

## 4. 운영에서 바뀌는 것

- **검토 확인 = 사진마다 「검토함」 체크** ✋(사용자 「좋은 것 같아」) — 여러 명이면 어느 사진을 실제로 봤는지 파일에 남아야 한다. 회수는 **「다 봤다」 확인(`--viewed-all`) 없이** 받는다 → 체크하지 않은 사진은 회수 도구가 「미검토」로 돌려보낸다(지금 코드 그대로 · 고칠 것 없음). 되돌리는 법 = 예전처럼 `--viewed-all`.
- **회수 경로** — 공유 드라이브의 결과 `.json` 을 파이의 `~/data/label_batches/<묶음>/returned/` 로 옮긴 뒤 지금 회수 도구를 쓴다. 옮기는 방법(구글 드라이브 연결 도구로 Claude 가 직접 받기 · 안 되면 사용자가 내려받아 보냄)은 계획서에서 첫 묶음으로 확인한다.
- **묶음 안내문(`안내.txt`)** — 묶음마다 들어가는 짧은 안내를 이 안내서와 맞춘다(주고받기 = 공유 드라이브 · 「검토함」 체크 · 안내서 PDF 를 가리킴). `scp` 명령은 사용자용으로만 남긴다.

## 5. 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 문서 둘(규칙서 + 작업 설명서) | 두 문서를 오가야 하고 서로 어긋나기 쉽다 |
| 배포용 PDF(처음 설계) | 고칠 때마다 다시 만들어 올려야 하고 옛 판이 돈다 — 아티팩트는 같은 주소가 최신 · PDF 는 공유가 안 될 때의 대안으로 남긴다 |
| 묶음 `안내.txt` 만 늘리기 | 설치·규칙까지 담기에 짧다 · 묶음마다 복사된다 |
| 검토자가 끝나고 「다 봤다」고 말하기(지금 방식) | 여러 명이면 어느 사진을 봤는지 남지 않는다 |
| 사진까지 함께 올리기 | 묶음마다 수백 MB · 파이에 원본이 있다 |
| 숫자 단축키 안내 | v4.0.6 에서 동작하지 않았다(사용자) |

## 6. 범위 밖 · 미결

- 예시 사진을 실콘솔 세로 사진으로 바꾸기 — 이번에는 한계만 적는다.
- 공유 드라이브에 묶음을 올리는 쪽(파이 → 드라이브) — 계획서에서 첫 묶음으로 방법을 정한다.
- ⏸ X-AnyLabeling 화면 캡처 — 사용자 제공 대기.
