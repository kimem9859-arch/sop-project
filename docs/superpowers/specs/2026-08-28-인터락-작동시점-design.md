# 인터락 작동 시점·기능 재정의 — 현황 진단과 후보군

- **날짜**: 2026-08-28
- **대상**: 통합문서 §1·§3·§4.1(FR-3)·§4.3·§8·§9.1·§9.2 / `dev/interlock/결선도_초안.md` / `Rpi5/Demo/interlock.py`·`fsm.py`
- **관련 근거**: 통합문서 §10.22-정정(층2 제기) · §10.31(E2E 오경보·사전 차단율) · §10.47(놓친 위반 분해) · §12(전장 E2E 검증)

## 0. 왜 이 문서를 쓰나

"인터락을 **어느 시점에** 걸어야 하는가"를 정하려다, **시점보다 「무엇을 끊는가」가 먼저**라는 것이
드러났다. 현행 정의가 시점을 이미 결정해 버리고 있기 때문이다(§2-P2).

통합문서 §1은 2026-07-29에 이미 *"층2(누르기 전 물리 차단)는 미설계"* 라고 못 박아 뒀다.
이 문서는 **그 미설계 상태가 왜 생겼고, 풀려면 무엇을 바꿔야 하는지**를 정리한다.

## 1. 지금 인터락은 무엇인가

### 1.1 정의 (문서)

| 위치 | 문구 | 끊는 대상 |
| --- | --- | --- |
| §4.1 **FR-3** | 오조작 강행 시 **장비로 가는 전기 신호를 차단**(인터록) | 콘솔 → 장비 (**출력**) |
| §3 AS-IS/TO-BE | 오조작 강행 시 **인터록으로 전기 신호 차단** | 〃 |
| §4.3 | 위반 강행 시 인터록으로 **전기 입력을 차단**하는 구조 | ⚠️ **주어 없음** |
| §9.1 BLOCK | 인터록으로 **전기 입력 차단** (시연=타워램프 시각화) | ⚠️ **주어 없음** |

→ 정의의 실체는 **출력 차단**이다. 콘솔의 입력(버튼)을 끊는다는 뜻이 아니다.

### 1.2 트리거 (FSM §9.2)

```
MONITOR ──오답 버튼 실제 눌림──▶ BLOCK          ← 인터락은 여기서만 걸린다
MONITOR ──오답 체류 0.3초 + 박스 안(C1)──▶ WARNING   ← 전기를 끊지 않는다
WARNING ──오답 버튼 눌림──▶ BLOCK
어느 상태든 ──EMO──▶ BLOCK (즉시·판정 우회)
```

통합문서가 세 곳(§8 연결규칙 · §9.3-5 · §10.22-정정)에서 *"인터락은 눌린 뒤에만 걸린다"* 를
반복해 명시하고 있다.

### 1.3 실물 (결선도 §3·§4, `interlock.py`)

```
버튼 B1~B4 (무전원 접점) ──▶ Pi GPIO 5/6/13/19   ← 릴레이 없음. 항상 살아 있다
EMO (NC쌍) ────────────────▶ Pi GPIO 26
Pi ──USB Serial 115200──▶ Arduino UNO R4 ──D4~D7──▶ 릴레이 4ch ──▶ 12V 타워램프
                                                     (적·황·녹·부저)
```

- 프로토콜은 `RUN`/`WARN`/`BLOCK` 세 줄. **BLOCK만 ACK로 실행을 확인**하고, 무ACK면 폴트 경고창.
- **BLOCK이 물리적으로 하는 일 = 녹색 OFF + 적색·부저 ON.** 그 외에 끊기는 전기는 없다.
- 8채널 모듈에서 4채널만 사용 → **여유 4채널 확보**(결선도 §3.2).
- 전장 E2E 검증은 2026-07-15에 통과(§12) — 버튼·EMO 입력, ACK 4/4, 타워램프 실점등, 폴트 3종.

## 2. 문제점

### 🔴 P1 — 차단 대상이 실재하지 않는다

실장비가 없으므로 "장비로 가는 신호"는 존재한 적이 없다. 현재 끊기는 유일한 전기는
**타워램프 12V**이며, 그것은 차단이 아니라 **차단됐다는 표시**다. 시연에서 실제로 막히는
작업자 동작은 하나도 없다.

### 🔴 P2 — 정의가 층2를 원천 봉쇄한다

**누르기 전에는 「장비로 가는 신호」가 아직 없다. 없는 것은 끊을 수 없다.**

§1의 *"층2 미설계"* 는 누락이 아니라 **현행 정의의 필연적 귀결**이다.
정의를 그대로 두면 시점을 아무리 논의해도 층2는 성립하지 않는다.

### 🔴 P3 — 「사전」 성분을 경고 혼자 지고 있다

두 지표를 혼동하지 말 것(CLAUDE.md 「지표 이름 혼용 금지」).

| | 값 | 성격 |
| --- | --- | --- |
| BLOCK 자체의 확실성 | 사실상 100% | GPIO 눌림 기반이라 놓칠 수 없다. **단 사후** |
| **위반 사전 차단율** | **74.9%** (§10.31) | 실체는 **눌리기 전 경고가 떴는가**. 목표 ≥80% 미달 |

즉 **확실한 쪽은 사후이고, 사전인 쪽은 74.9%다.**
§10.47이 놓친 46건을 분해한 결과 손 미검출은 2건뿐이고 **65%가 「체류 임계에 0.08초 모자란」**
경우다 — 사람이 dwell 0.3초에 닿기 전에 눌러 버린다. **임계를 낮춰서 넘을 수 없다**
(0.25초 이하는 편익 2%p·헛경고만 증가, §9.4).

> 🔴 **74.9%·15.46회/분은 옛 구성 값이다** — 모조 콘솔 · 서브 작업 없는 연속 눌림 · 9.1fps.
> 현 구성(포맥스판 실콘솔 · 대기 10초 + 공구 게이트 · 23.96fps)에서 재측정 전까지
> **조건 병기 없이 인용하지 않는다.** 정본은 통합문서 §10 머리 `[CURRENT]` 표.

### ⚠️ P4 — §9.1·§4.3 문구가 오독을 부른다

*"전기 입력 차단"* 은 주어가 없어 **「콘솔의 입력을 끊는다」로 읽힌다.**
FR-3의 «장비로 가는» 과 충돌한다. 어느 방향을 택하든 **문구 정밀화는 별도로 필요하다.**

### ⚠️ P5 — 오경보 블로커가 「콘솔 전체 차단」 전제 위에 서 있다

§10.31은 *"오경보 15.46회/분 → 층2 성립 불가"* 로 판정했고, 그 근거는
*"오경보 1건마다 **전기가 끊기면** 분당 15회는 운용 불가"* 다.
**이는 차단 대상이 콘솔 전체라는 가정에서만 성립한다.**

차단 대상이 **오답 버튼 하나**로 좁혀지면 전제가 무너진다 — 오경보는 정상 세션에서
**오답 ROI**에 뜬 것이고, ROI 오분류는 3세션 전부 0건(§10.29)이다. 그 순간 손이 향하던
정답 버튼은 살아 있으므로 **정상 작업 방해가 0**이 된다.

## 3. 시점 축 — 무엇이 언제 가능한가

```
T0  손이 오답 버튼 링(25px) 진입        ── 접근
T1  손끝이 검출 박스 안(2단계) 진입      ── 위험
T2  체류 0.3초 도달                    ── 현행 WARNING 발화 (C1)
T3  버튼 물리 눌림                     ── 현행 BLOCK (인터락)
T4  눌린 뒤                            ── 사후
```

- **T2 트리거는 §10.47의 65%를 원리적으로 놓친다** — 사람이 T2 전에 눌러 버린다.
- **T0/T1 트리거는 경고로 쓰면 시끄럽다** — 오경보가 늘어난다(C2안이 폐기된 이유, §10.22).
- 🔑 **그러나 차단은 경고와 다르다 — 되돌릴 수 있다.** 손이 떠나면 복구되므로
  **이르게 걸어도 조용하다.** 이것이 T0/T1을 차단 트리거로 쓸 수 있게 하는 핵심 차이다.

## 4. 후보군

| | 차단 지점 | 트리거 | 오경보 대가 | 비전 필요성 | 재결선 | 사전성 |
| --- | --- | --- | --- | --- | --- | --- |
| **A** 현행 유지 + 문구 정밀화 | 램프(표시) | T3 | — | 경고에만 | 없음 | ❌ |
| **B** 상태 기반 상시 입력 차단 | 오답 버튼 접점 **전부** | 단계 전환 | 0 | ❌ 불필요 | 릴레이 4ch | ✅ 완전 |
| **C** 선택적 사전 입력 차단 ⭐ | **접근한 오답 버튼 1개** | **T0/T1** | 0 | ✅ 필수 | 릴레이 4ch | ✅ |
| **D** 소프트 차단 | Pi가 입력을 무시 | T0/T1 | 0 | ✅ 필수 | **없음** | ✅(논리) |
| **E** 콘솔 전체 차단 | 콘솔 입력 전부 | T2 | **치명** | ✅ | 릴레이 | ✅ |

### A — 현행 유지 + 문구 정밀화

위험 0·비용 최소. §9.1·§4.3의 주어를 채우고 *"시연에서는 램프로 시각화"* 를 정직하게 병기한다.
**한계**: P1~P3이 그대로 남고, *"그래서 실제로 무엇을 막았나"* 에 답이 없다.

### B — 상태 기반 상시 입력 차단

기대단계 외 버튼을 평상시 죽여 둔다. 100% 확실하고 오경보와 무관하다.
🔴 **치명적 약점 — 비전이 없어도 성립한다.** *"FSM만 있으면 되는데 AI가 왜 필요한가"* 가
바로 나온다. §1 프레이밍(비전 AI가 핵심)과 정면 충돌한다. 또 §6.1.1 서브 작업이 이미
"버튼만으로는 못 넘어간다"를 만들고 있어 **얹는 값이 작다.**

### C — 선택적 사전 입력 차단 ⭐ (현재 추천)

비전이 오답 버튼 링 진입을 보는 **즉시** 그 버튼 접점만 연다. 손이 떠나면 복구한다.

- **P2 해소** — 입력을 끊으므로 누르기 전에 걸 수 있다.
- **P3 해소** — T2가 아니라 T0/T1을 쓰므로 「모자란 체류」 65%를 되찾는다.
- **P5 해소** — 죽는 것은 어차피 눌리면 안 되는 버튼이라 정상 작업 방해가 0이다.
  **오경보 15.46회/분을 낮추지 않고도 성립한다** — 블로커가 사라지는 것이 아니라
  블로커였던 **이유**가 사라진다.
- **비전이 없으면 성립하지 않는다** — "어느 버튼을 죽일지"는 손을 봐야 정해진다(B의 약점 회피).
- **비용**: 릴레이 4채널을 버튼 접점선에 직렬 투입(여유 채널 있음) +
  🔴 **「눌러도 안 먹힘」을 알리는 시각 피드백 필수** — 없으면 작업자가 고장으로 오인한다.

### D — 소프트 차단

C와 로직이 같고 차단 지점만 Pi 내부다(GPIO 눌림을 FSM에 전달하지 않는다).
**재결선 0 · 하드웨어 위험 0 · 즉시 착수 가능.**
약점은 *"물리 차단이 아니다"* 라는 반론. **C의 선행 단계이자 안전판으로 적합하다.**

### E — 콘솔 전체 차단 (기각)

§10.31이 이미 성립 불가로 판정했다. 오경보 1건마다 작업이 멈춘다. **후보에서 제외한다.**

## 7. 하지 않는 것 (YAGNI)

- **후보 E(콘솔 전체 차단)를 설계하지 않는다** — §10.31에서 기각됐다.
- **오경보 저감을 층2의 선행 과제로 삼지 않는다** — 후보 C에서는 전제가 성립하지 않는다.
  (오경보 저감 자체는 경고 품질 과제로 별도 유지)
- **dwell·링 폭 임계를 손대지 않는다** — 이번 논의는 차단 지점·시점의 문제이지 임계의 문제가 아니다.
- **EMO 경로를 손대지 않는다** — EMO는 판정을 우회하는 별도 경로이며 fail-safe(NC)가 이미 성립한다.
- **옛 구성 데이터(`hoi.db`·봉인 홀드아웃)로 새 파라미터를 튜닝하지 않는다**(§10 머리 경고).
