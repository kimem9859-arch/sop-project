> 2026-09-03 · 공모전 제출용 시연영상 제작 갈래
> 측정 정본 = 통합문서 §10 `[CURRENT]` · 제출문서 자체는 `../hanium-docs`
> 🔴 **이 문서는 「왜 이렇게 정했나」다.** 확정 측정·사양 수치는 여기 두지 않는다(포인터만).

---

## 1. 무엇이 필요한가

공모전 시연영상을 편집하려면 **같은 연기 한 번에서 여러 각도의 소재**가 동시에 나와야 한다.
따로 찍으면 연기가 매번 달라 편집에서 붙지 않는다.

사용자가 요구한 소재는 다섯이다.

| # | 영상 | 쓰임 |
|---|---|---|
| ① | GUI 전체 (1인칭 영상이 보이는 상태) | 제품이 실제로 도는 모습 |
| ② | GUI UI만 (카메라 자리 검정) | UI 동작만 보여주는 컷 |
| ③-a | 1인칭 풀스크린 · 오버레이 O | AI가 무엇을 보는지 |
| ③-b | 1인칭 풀스크린 · 오버레이 X | 작업자 시점 원본 |
| ④ | USB 웹캠 3인칭 | 작업자 전체 동작 |

시나리오는 **정상 1회 · 오답(순서 위반) 1회**. 제일 잘 나온 것을 채택하고 NG는 지우지 않고 보관한다.

### 이미 있는 것 / 없는 것

- **있음** — 녹화 기능 1개(`safety_console.py` §녹화). 한 번에 한 파일, 메뉴에서 수동 시작.
  `run_scenario.sh` 가 `ffmpeg` 로 화면·웹캠을 동시에 찍는 길을 이미 검증해 뒀다.
- **없음** — 동시 다중 녹화 · UI만/검정 영상 · 오버레이 유무 두 벌 · 한국어 파일명 · 채택/NG 보관.

---

## 2. 요구사항 (사용자 제시, 2026-09-03)

1. **한 번 실행 = 5개 파일이 동시에** 저장된다.
2. **촬영 시작은 「GUI가 실행된 이후」** — 로딩 화면·바탕화면이 앞에 찍히면 안 된다.
3. **작업표시줄·제목표시줄이 찍히면 안 된다.**
4. **오버레이 = 객체 박스 + 손 랜드마크 둘 다**를 뜻한다.
5. **④ USB 3인칭은 검출을 일절 하지 않는다** — 순수 촬영본.
6. **③만 오버레이 유/무 두 벌.** GUI(①②)는 나누지 않고 **회차를 두 번**으로 얻는다.
7. **파일명은 한국어 + 날짜·시간.**
8. **NG는 삭제하지 않고 보관.**
9. 🔴 **버벅임 대책은 이번에 넣지 않는다** — 먼저 그대로 만들어 실제로 얼마나 버벅이는지 본다.

## 3. 왜 이렇게 나눴나

### 3.1 GUI 밖(ffmpeg) 2개 · GUI 안 3개

| 영상 | 찍는 주체 | 근거 |
|---|---|---|
| ① GUI 전체 | `ffmpeg` x11grab (창 영역만 크롭) | 별도 프로세스라 GUI 스레드 부담이 없다. 가장 중요한 영상에 위험을 지우지 않는다 |
| ② GUI UI만 | GUI 안 (Qt 창 grab → 카메라 영역 검정) | 화면 캡처로는 만들 수 없다. 창을 떠서 덧칠해야만 나온다 |
| ③-a/③-b | ESP32 카메라 스레드 | 프레임을 이미 그 스레드가 만든다. GUI 스레드를 거치지 않는다 |
| ④ USB 3인칭 | `ffmpeg` v4l2 직접 | 🔴 OpenCV 로 열면 MJPG 지정이 무시돼 1080p 5fps 로 떨어진다(2026-07-22 실측, `run_scenario.sh` 주석) |

④를 ffmpeg 가 잡으므로 GUI 의 `UsbCameraThread` 는 띄우지 않는다(`SOP_USB_CAMERA=0`).
장치가 하나뿐이라 둘이 동시에 열 수 없고, 이러면 요구사항 5(검출 없음)도 자동으로 지켜진다.

### 3.2 오버레이를 「표시」와 분리한다

지금은 **화면에 켤 때만 그린다**(`camera_thread._process_frame`).
그러면 오버레이 OFF 회차에서 ③-a 가 빈 영상이 된다.

→ **그리기는 항상 하고, 화면에는 회차 설정대로 보여준다** 로 뒤집는다.
깨끗한 사본을 뜨는 자리는 이미 있다 — 공구 추론용 `tool_frame = frame.copy()`.
같은 자리에서 한 벌 더 뜬다.

### 3.3 영상 길이를 실제 시간과 맞춘다

ESP32 프레임 간격은 일정하지 않다(§10.34 조건 참조).
오는 대로 고정 fps 파일에 쓰면 **영상 길이가 실제와 어긋난다.**

→ ②③ 은 **15fps 타이머가 「지금 최신 프레임」을 가져다 쓴다.** 새 프레임이 없으면 직전 것을 한 번 더 쓴다.
1분 촬영이 정확히 1분 영상이 된다. ①④ 는 ffmpeg 가 같은 일을 이미 한다.

### 3.4 시작·종료를 GUI 가 쥔다

요구사항 2 때문이다. 런처가 ffmpeg 를 먼저 띄우면 GUI 로딩 화면이 앞에 찍힌다.

```
런처 → main.py(촬영 모드) 실행
          ↓
GUI: 창 표시 → 첫 카메라 프레임 도착 → 🔴 5개 동시 시작 (ffmpeg 2개도 GUI 가 띄운다)
          ↓
GUI 종료 → 5개 동시 정지
          ↓
런처: 채택/NG 질문 → 폴더 이동
```

**시작 기준 = 첫 카메라 프레임 도착.** 창만 떴을 때 시작하면 1인칭 영상이 검은 화면으로 시작한다.
⚠️ ESP32 가 안 붙으면 영영 시작 못 하므로 **10초 안에 프레임이 없으면 그냥 시작**한다.

### 3.5 작업표시줄을 빼는 법

- 지금 `SOP_FULLSCREEN=1` 은 진짜 전체화면이 아니라 **최대화**다(`main.py:25`).
  일부러 그렇다 — 진짜 전체화면은 제목표시줄이 없어져 창을 닫을 수 없고, 녹화 종료가 GUI 종료에 묶여 위험하다.
- → 화면 전체가 아니라 **창의 내용 영역만 잘라서** 찍는다. GUI 가 자기 좌표·크기를 ffmpeg 에 넘긴다.
- 촬영 모드에서는 창을 **1920×1080 고정**으로 띄운다. 16:9 라 편집 규격 그대로이고, 잘라낼 좌표가 딱 떨어진다.
  모니터가 1920×1280 이라 제목표시줄까지 넣어도 들어간다.
- ⚠️ **잘라낸 사각형 안에 다른 창이 겹치면 찍힌다.** 시작 시 GUI 를 맨 앞으로 올리고 런처 터미널은 뒤로 보낸다.

③ 도 같은 **1920×1080** 캔버스에 레터박스로 얹어 5개 규격을 통일한다.
원본이 480×640 이라 확대해 넣는 것이므로 **화질이 좋아지지는 않는다** — 편집 편의를 위한 통일이다.

### 3.6 실행 진입점 — 기존 GUI 를 그대로 쓴다

시연영상에 찍혀야 하는 것은 **실제 제품 화면**이다. 촬영용 GUI 를 따로 만들면 그것은 실제와 다른 화면이다.
새로 만드는 것은 **얇은 셸 런처와 바탕화면 바로가기 하나뿐**이고, GUI 는 촬영 모드일 때만 녹화가 켜진다.
평소 실행(`SOP 가디언 Demo` 바로가기)은 **지금과 완전히 동일**하다.

## 6. 관문

- 🔒 **중단 규칙** — 5개 파일 중 하나라도 안 생기거나, 영상 길이가 실제 시간과 **10% 넘게** 어긋나면 촬영을 시작하지 않는다.
- ⭐ **`run_demo.sh` 실기동 확인 필수** — `@pyqtSlot` 시그니처 불일치처럼 **import 검사로 못 잡는 런타임 오류**가 있다(실제로 GUI 가 기동 즉시 죽은 적 있음).
- ⭐ **평소 실행 회귀 확인** — 촬영 모드가 아닐 때 GUI 가 지금과 동일하게 뜨고 녹화가 켜지지 않는지.
- ⭐ **부하 실측** — 촬영 중 CPU·프레임률·버린 프레임 수를 기록한다. **대책은 이 수치를 본 뒤에 정한다**(요구사항 9).

## 7. 곁가지로 함께 고친 것 — 박스 중복

촬영 중 **한 프레임에 같은 버튼 박스가 둘 그려지는** 현상을 사용자가 지적했고, 코드에서 원인이 확인됐다.

`camera_thread._update_tracks` 는 ①짝을 못 찾은 옛 트랙을 최대 `YOLO_MAX_MISS` 프레임 더 살려두고
②짝을 못 찾은 새 검출을 **같은 클래스가 이미 있는지 보지 않고** 새 트랙으로 추가한다.
박스가 크게 튀면 둘이 동시에 일어나 중복이 된다.

→ 실물 콘솔에 B1~B4·EMO 는 각각 하나뿐이므로 **클래스당 트랙 1개**로 강제한다(`_one_per_class`).
남길 하나는 **이번 프레임에 검출된 것(miss == 0) 우선**, 동률이면 점수 우선.
점수만 보면 갱신이 멈춘 옛 트랙이 이겨 박스가 뒤처진다.

판정(FSM)에는 영향이 없고 표시와 ROI 판정이 오히려 안정된다.
