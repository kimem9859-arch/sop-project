# 파이 홈 디렉터리 폴더 정리 — 설계

- **날짜**: 2026-08-18
- **대상**: Pi#1(`sop-pi`) 홈 디렉터리 `/home/pi` 최상위
- **성격**: 분류·이동 + 규칙 수립. 🔴 **삭제 없음**

---

## 1. 문제

홈 최상위에 성격이 다른 것 22개가 평평하게 널려 있다. 실험이 끝날 때마다
`tool_eyeball_v2_0.65` 같은 폴더가 하나씩 늘었고, 어떤 것이 데이터셋이고
어떤 것이 산출물이고 어떤 것이 런타임인지 이름만 봐서는 갈리지 않는다.
스크린샷 24장은 홈에 그대로 떨어져 있다.

**목적은 용량 확보가 아니다.** 분류해서 앞으로도 깔끔하게 유지되는
**생성 규칙**을 만드는 것이다.

## 2. 제약 — 이동하면 깨지는 것

조사에서 확인한 실측 사실이다.

### 2.1 실행 코드가 경로를 물고 있다

| 파일 | 상수/값 | 현재 경로 |
| --- | --- | --- |
| `Rpi5/Demo/config.py:211` | `HAND_MODELS_DIR` | `~/hoi_probe/hailo8` |
| `Rpi5/Demo/config.py:212` | `HAND_BLAZE_DIR` | `~/hoi_probe/blaze_app_python` |
| `Rpi5/Demo/config.py:262` | `TOOL_WORKER_PYTHON` | `~/rfenv/bin/python` |
| `Rpi5/Demo/test/tool_live.py:63` | `SHOT_DIR` | `~/tool_live_shots` |
| `Rpi5/Demo/test/hoi_probe.py:33-34` | `_BLAZE`·`_MODELS` | `~/hoi_probe/…` |

### 2.2 옮기면 안 되는 것 (표준 위치)

| 폴더 | 옮기면 깨지는 것 |
| --- | --- |
| `bin/` | `.profile:20`이 `$HOME/bin`을 PATH에 자동 추가 → `arduino-cli` 미검출 |
| `Arduino/` | arduino-cli 스케치북 기본 경로 |
| `Desktop`·`Documents`·`Downloads`·`Music`·`Pictures`·`Public`·`Templates`·`Videos` | XDG 표준. 데스크톱 환경·`Rpi5/scripts/yolo_camera.py`가 참조 |
| `thinclient_drives` | RDP 세션이 자동 생성 |
| `sop-project/`·`_archive/` | 정본 repo / 기존 보관소 — 위치 유지 |

### 2.3 rfenv는 이동 내성이 있다

`~/rfenv/bin/*` 중 `/home/pi/rfenv` 절대경로가 박힌 스크립트는 **0개**이고,
`pyvenv.cfg`의 `home`은 uv 파이썬(`~/.local/share/uv/…`)을 가리킨다.
→ 폴더째 옮겨도 venv 자체는 동작한다. 고쳐야 하는 것은 **venv를 부르는 쪽**뿐이다.

**과거 기록 문서도 갱신한다.** 근거 — 경로는 측정 수치와 달리 「그때 그랬다」가 아니라
**「지금 어디 있나」를 가리키는 포인터**다. 옛 경로를 남기면 다음에 명령을 그대로
따라 쳤을 때 없는 폴더를 만난다. 옛↔새 대응표를 따로 두는 방식은 볼 곳이 둘로
갈라지므로 쓰지 않는다. **이동 사실은 `작업로그.md`에 1블록**으로 남긴다.

⚠️ **수치·조건은 손대지 않는다.** 이 갱신은 `~/경로` 문자열만 대상으로 한다.

### 4.4 별건 — 이미 깨져 있던 것

`~/.bashrc:119`의 `alias esp32`가 `/home/pi/claude-project/camera_stream_tcp`를
가리키는데 **그 경로는 존재하지 않는다**(`_archive`로 옮겨졌고 이름도 다르다).
이번에 실제 경로로 고친다. 대상 스케치의 실위치는 착수 시 확인한다.

## 5. 폴더 생성 규칙 (신설 문서)

**정본** = `sop-project/docs/파이-홈-폴더규칙.md`, **포인터** = `~/README.md` 한 줄.
repo에 두어 git으로 백업·양 머신 공유하고, 홈에서도 발견되게 한다.

담을 것:

1. **최상위에 새 폴더를 만들지 않는다** — `data`/`lab`/`env`/`shots`/`_archive` + 표준 폴더가 전부
2. **판단표** — 데이터셋 → `data/`, 실험 산출물 → `lab/<주제>/`, 도구·런타임 → `env/`,
   스크린샷·잡파일 → `shots/`, 끝난 것 → `_archive/`
3. **`lab/` 새 주제는 케밥케이스 소문자**(`tool-detect`). 그 안 개별 산출물은 기존 이름 유지
4. **홈에 파일을 직접 떨구지 않는다**
5. **예외 목록** — §2.2 표(옮기면 무엇이 깨지는지 포함)
6. **코드가 무는 경로 목록** — §4.1 표. 여기 있는 폴더를 옮길 땐 코드도 같이 고친다

### 5.1 스크린샷 저장 위치 — 조사 후 결정

규칙 4가 저절로 지켜지려면 스크린샷 기본 저장 위치가 `~/shots`여야 한다.
그런데 이 파이의 `~/.config/openbox/rpd-rc.xml`·`~/.config/labwc/rc.xml`에
스크린샷 키바인딩이 **없다**(데스크톱 기본 동작으로 홈에 저장되고 있다).

→ 착수 시 실제 바인딩 위치를 찾는다. **찾으면 `~/shots`로 바꾸고, 못 찾으면
규칙 문서에 「스크린샷은 찍은 뒤 `~/shots`로 옮긴다」를 수동 항목으로 명시**한다.
설정을 억지로 만들어 넣지 않는다.

## 6. 검증

- **유실 없음** — 이동 전후 각 대상의 `du -sb` 바이트 수 대조. 🔴 `rm` 계열 명령을 쓰지 않는다
- **경로 상수** — `~/env/rfenv/bin/python -c "import ultralytics"` 통과 /
  `config.py`가 가리키는 새 경로 4곳의 실존 확인
- ⭐ **`run_demo.sh` 실기동** — import 검사로 못 잡는 런타임 오류가 실제로 있었다(CLAUDE.md §5).
  카메라가 없어 손·공구 추론까지는 못 가므로 **GUI 기동 + 경로 해석까지**만 확인하고,
  그 한계를 결과에 함께 적는다
- **잔여 참조 0** — `grep -rIn "~/\(rfenv\|hoi_probe\|tool_live_shots\|ds_\|tool_\|neg_screening\)"`가
  갱신 후 옛 경로를 하나도 잡지 않을 것

### 중단 규칙

- `run_demo.sh` 기동이 실패하면 **되돌린다**(이동은 `mv`라 역방향 `mv`로 복원 가능).
  경로 수정만 남기고 이동을 강행하지 않는다.
- 이동 전후 바이트 수가 어긋나면 **즉시 멈추고 원인부터 규명**한다.
