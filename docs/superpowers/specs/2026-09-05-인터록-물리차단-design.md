# 인터록 물리 차단 — 설계

## 1. 배경 — 보고서가 주장하는 것이 코드에 없다

개발보고서가 **릴레이로 전기 신호를 차단한다**고 여러 곳에서 말한다.

| 쪽 | 문구 |
|---|---|
| p6 | 「오조작 시 **전기 신호를 물리적으로 차단**하는 인터록」 |
| p8 | 「인터록 차단 회로 — 릴레이를 통한 **장비 전기 신호 차단**」 **진척도 100%** |
| p9 | 「릴레이 구동으로 **오조작 버튼의 전기 신호 차단**」 |
| p11 | 「순서 위반 확정 시 **전기 신호 차단** / **물리 인터록 실행부**」 |
| p3 [그림1] | 「오답 버튼이 실제로 눌리면 **전기 신호 차단**」 |
| p5 [그림2] | 「차단(BLOCK) — 인터록 **장비 전기신호 차단**」 |

🔴 **현 구현에는 끊는 회로가 없다.** 릴레이 4채널은 전부 타워램프 적·황·녹·부저이고, 모조 콘솔의 버튼 B1~B4 는 Pi GPIO 입력이라 끊을 부하 자체가 없다. 지금의 「차단」은 **램프 색 + 소프트웨어 무시**다:

```python
# fsm.py:220
if self.state == State.BLOCK:
    return   # 차단 중 입력 무시
```

버튼 신호는 GPIO → gpiozero → Qt 시그널 → `_press_button()` 까지 **끝까지 들어와 로그·통계에 기록되고**, 마지막 `if` 한 줄에서만 버려진다. 차단 중 버튼을 눌러 보면 화면 로그에 `[버튼] B2 눌림` 이 계속 쌓인다.

🔑 **이 설계의 목적은 그 주장을 사실로 만드는 것이다.** 문구를 고치는 대안(텍스트 5곳 + 그림 2장 수정)은 사용자가 기각했다 — 아래 §8.

## 2. 목표 / 비목표

**목표**
- BLOCK 진입 시 **B1~B4 의 전기 신호를 물리적으로 끊는다.**
- 해제(터치)하면 원상 복귀한다.
- 보고서의 차단 관련 문구 7곳이 **수정 없이 사실이 된다.**

**비목표 (🔴 이 설계는 여기에 손대지 않는다)**
- **「누르기 전에 끊기」(층2)** — 경고 단계에서의 차단. 선행 블로커가 미해소다: E2E 오경보 **15.46회/분**(≈4초에 1회, §10.31). 경고 단계에서 끊으면 정상 작업 중에도 콘솔이 4초마다 먹통이 된다. ⚠️ 게다가 그 값은 **옛 구성 기준선**이고 현 구성에서 재측정되지 않았다 — 지금 오경보가 몇인지 모른다.
- 감지·판정 로직 개선. FSM 은 한 줄도 바꾸지 않는다.

⚠️ **첫 오답 눌림은 이 설계로도 막지 못한다.** 눌려야 오답인 줄 알기 때문이다. 막는 것은 **차단 상태에서의 추가 조작**이다. 이것이 보고서 [그림1] 의 *"오답 버튼이 **실제로 눌리면** 전기 신호 차단"* 과 정확히 같은 순서다.

## 3. 하드웨어

### 3.1 릴레이 모듈 — 4채널 → **8채널 교체**

차단 채널을 더하면 5채널이 필요해 4채널 모듈로는 부족하다. **여분의 8채널 모듈(SZH-RLBG-009)로 교체**한다(4채널은 예비로 물러남).

🔑 **채널 배정을 1:1 로 유지**해 이설을 단순화한다 — IN1→IN1, IN2→IN2 … 순서를 바꾸지 않는다.

| Arduino | 릴레이 | 부하 | 상태 |
|---|---|---|---|
| D7 | IN1 | 타워램프 **적** | 기존 유지 |
| D6 | IN2 | 타워램프 **황** | 기존 유지 |
| D5 | IN3 | 타워램프 **녹** | 기존 유지 |
| D4 | IN4 | 타워램프 **부저**(갈) | 기존 유지 |
| **D3** | **IN5** | **버튼 공통 GND 차단** | 🆕 신설 |
| — | IN6~8 | 여유 | — |

📌 D3/IN5 는 결선도 §3.2 가 **이미 확장용으로 예약**해 둔 자리다(종전 「12V LED 파일럿 — 최종 확장 후보」). 그 자리를 차단이 가져간다.

### 3.2 버튼 GND 결선

```
B1 GND ─┐
B2 GND ─┤  와고 5P  ├─ 1가닥 ─→ [CH5  COM─NC] ─→ Pi GND
B3 GND ─┤
B4 GND ─┘
```

- 와고 5P = 버튼 4구 + 출력 1구
- **NC(평상시 닫힘) 접점**을 쓴다 → 코일 OFF 일 때 통전 = 버튼 정상

🔴 **EMO(GPIO26)는 와고에 넣지 않는다.** NC 배선 fail-safe 라 끊으면 비상정지가 죽는다. 차단 중에도 EMO 는 살아 있어야 한다. (5P 라 자리도 없어 구조적으로 방지된다.)

### 3.3 🔴 결선 전 필수 점검 — COM 공통 여부

기존 CH1~4 는 **COM 에 12V(−)** 가 물려 있다(결선도 §3.3). CH5 는 **Pi GND(3.3V 로직)** 를 다룬다.

> **모듈 안에서 COM 이 공통 레일로 묶여 있으면 12V(−) 와 Pi GND 가 연결된다.** 결선 전에 **테스터로 CH1 COM ↔ CH5 COM 도통을 반드시 확인**할 것. 도통되면 이 설계를 그대로 쓸 수 없고, 별도 릴레이 모듈 또는 반도체 스위치로 바꿔야 한다.

SZH-RLBG-009 는 채널별 독립 Form C 로 알려져 있으나 **실물 확인 없이 진행하지 않는다.**

### 3.4 전류

| 상태 | 동시 ON 채널 | 코일 전류 |
|---|---|---|
| RUN | 녹 | ~75 mA |
| WARNING | 황 | ~75 mA |
| **BLOCK** | 적 + 부저 + **차단** | **~225 mA** |

결선도 §6 실측 = 채널당 71.4mA·69Ω. 종전 최대 2채널(150mA)에서 3채널(225mA)로 는다. **방법 A(Arduino 5V 급전) 유지** — USB 급전 500mA 한계 안이다. 코일 전원 분리(방법 B) 불필요.

## 4. 동작

| 명령 | 적 | 황 | 녹 | 부저 | **차단(CH5)** | 버튼 |
|---|---|---|---|---|---|---|

## 7. 위험

**① 🔴 접점 미세전류 (기술적으로 가장 불확실한 것)**
GPIO 내부 풀업은 약 66µA 만 흘린다. 10A 급 파워 릴레이 접점은 이렇게 작은 전류에서 **산화막 때문에 접촉 불량**이 날 수 있다(wetting current 부족).
- 완화 = BLOCK/해제를 반복하면 접점이 자체 세척된다. 시연 기간에는 문제 가능성이 낮다.
- 증상이 나오면 **버튼 신호선에 외부 풀업 4.7kΩ** 을 달아 전류를 약 10배로 올린다.
- **검증 5번(해제 후 10회 반복)이 이 위험의 관문이다.**

**② 타워램프 4선 이설**
2026-07-15 E2E 검증을 마친 배선을 새 모듈로 옮긴다. 채널 순서를 1:1 로 유지해 위험을 줄였다(§3.1). 검증 3·7번으로 되확인.

**③ HW 부재**
2026-09-05 현재 결선·검증 불가. 마감 9/8.

**④ fail-safe 방향 — 의도된 선택**
NC 접점이라 **아두이노·릴레이 전원이 죽으면 버튼이 살아난다**(차단이 풀린다). 산업 인터록 표준(de-energize to trip)과 반대 방향이다.
- 이유 = 시연 안정성. 시리얼이 끊긴 이력이 있고(§10.44 포트 경합), 그때 콘솔 전체가 먹통이 되면 시연이 멈춘다.
- 🔴 **이 시스템을 fail-safe 라고 부르지 않는다** — 통합문서 §1 프레이밍 메모가 *"fail-safe 는 EMO NC 배선 등 실제로 그러한 부분에만 한정해 쓴다"* 고 이미 못박아 두었고, 이 설계는 그 범위를 넓히지 않는다.

## 8. 거부한 대안

| 안 | 내용 | 거부 사유 |
|---|---|---|
| **보고서 문구 수정** | 「※본 시연은 타워램프로 시각화」 단서 추가 (통합문서 FR-3 방식) | 사용자 기각. 텍스트 5곳 + **그림 2장 재생성**이 필요해 구현보다 비싸고, 차별점이 약해진다 |
| **4채널 유지 + 적·부저 병합** | 적과 부저는 항상 동시 ON 이라 한 채널로 묶고 남는 1채널로 차단 | 8채널 모듈을 쓰기로 하면서 불필요해졌다. 부저 독립 제어 여지도 보존하는 편이 낫다 |
| **버튼 4개 개별 차단** | CH5~CH8 로 B1~B4 를 각각 끊기. p9 「**오조작 버튼의**」에 글자 그대로 부합 | BLOCK 은 어차피 전 버튼을 막는 상태라 기능적 이득이 없다. 동시 ON 6채널 ≈ 450mA 로 **코일 전원 분리(방법 B)** 가 필요해져 마감 3일 전 위험이 크다. 📌 나중에 넓힐 때 **배선만 추가**하면 되고 보고서 수정은 불필요하다 |
| **8채널 증설(4채널 병존)** | 기존 배선 무손상 | 보고서에 「모듈 2개」를 설명해야 해 지저분하다. 이설이 1:1 이라 교체 위험이 낮다 |
