## 1. 배경 — 보고서가 주장하는 것이 코드에 없다

개발보고서가 **릴레이로 전기 신호를 차단한다**고 여러 곳에서 말한다.

| 쪽 | 문구 |
|---|---|
| p6 | 「오조작 시 **전기 신호를 물리적으로 차단**하는 인터록」 |
| p8 | 「인터록 차단 회로 — 릴레이를 통한 **장비 전기 신호 차단**」 **진척도 100%** |
| p9 | 「릴레이 구동으로 **오조작 버튼의 전기 신호 차단**」 |
| p11 | 「순서 위반 확정 시 **전기 신호 차단** / **물리 인터록 실행부**」 |
| p3 [그림1] | 「오답 버튼이 실제로 눌리면 **전기 신호 차단**」 |
| p5 [그림2] | 「차단(BLOCK) — 인터록 **장비 전기신호 차단**」 |

🔴 **현 구현에는 끊는 회로가 없다.** 릴레이 4채널은 전부 타워램프 적·황·녹·부저이고, 모조 콘솔의 버튼 B1~B4 는 Pi GPIO 입력이라 끊을 부하 자체가 없다. 지금의 「차단」은 **램프 색 + 소프트웨어 무시**다:

```python
# fsm.py:220
if self.state == State.BLOCK:
    return   # 차단 중 입력 무시
```

버튼 신호는 GPIO → gpiozero → Qt 시그널 → `_press_button()` 까지 **끝까지 들어와 로그·통계에 기록되고**, 마지막 `if` 한 줄에서만 버려진다. 차단 중 버튼을 눌러 보면 화면 로그에 `[버튼] B2 눌림` 이 계속 쌓인다.

🔑 **이 설계의 목적은 그 주장을 사실로 만드는 것이다.** 문구를 고치는 대안(텍스트 5곳 + 그림 2장 수정)은 사용자가 기각했다 — 아래 §8.

## 2. 목표 / 비목표

**목표**
- BLOCK 진입 시 **B1~B4 의 전기 신호를 물리적으로 끊는다.**
- 해제(터치)하면 원상 복귀한다.
- 보고서의 차단 관련 문구 7곳이 **수정 없이 사실이 된다.**

**비목표 (🔴 이 설계는 여기에 손대지 않는다)**
- **「누르기 전에 끊기」(층2)** — 경고 단계에서의 차단. 선행 블로커가 미해소다: E2E 오경보 **15.46회/분**(≈4초에 1회, §10.31). 경고 단계에서 끊으면 정상 작업 중에도 콘솔이 4초마다 먹통이 된다. ⚠️ 게다가 그 값은 **옛 구성 기준선**이고 현 구성에서 재측정되지 않았다 — 지금 오경보가 몇인지 모른다.
- 감지·판정 로직 개선. FSM 은 한 줄도 바꾸지 않는다.

⚠️ **첫 오답 눌림은 이 설계로도 막지 못한다.** 눌려야 오답인 줄 알기 때문이다. 막는 것은 **차단 상태에서의 추가 조작**이다. 이것이 보고서 [그림1] 의 *"오답 버튼이 **실제로 눌리면** 전기 신호 차단"* 과 정확히 같은 순서다.

## 3. 하드웨어

### 3.1 릴레이 모듈 — 4채널 → **8채널 교체**

차단 채널을 더하면 5채널이 필요해 4채널 모듈로는 부족하다. **여분의 8채널 모듈(SZH-RLBG-009)로 교체**한다(4채널은 예비로 물러남).

🔑 **채널 배정을 1:1 로 유지**해 이설을 단순화한다 — IN1→IN1, IN2→IN2 … 순서를 바꾸지 않는다.

| Arduino | 릴레이 | 부하 | 상태 |
|---|---|---|---|
| D7 | IN1 | 타워램프 **적** | 기존 유지 |
| D6 | IN2 | 타워램프 **황** | 기존 유지 |
| D5 | IN3 | 타워램프 **녹** | 기존 유지 |
| D4 | IN4 | 타워램프 **부저**(갈) | 기존 유지 |
| **D3** | **IN5** | **버튼 공통 GND 차단** | 🆕 신설 |
| — | IN6~8 | 여유 | — |

📌 D3/IN5 는 결선도 §3.2 가 **이미 확장용으로 예약**해 둔 자리다(종전 「12V LED 파일럿 — 최종 확장 후보」). 그 자리를 차단이 가져간다.

### 3.2 버튼 GND 결선

```
B1 GND ─┐
B2 GND ─┤  와고 5P  ├─ 1가닥 ─→ [CH5  COM─NC] ─→ Pi GND
B3 GND ─┤
B4 GND ─┘
```

- 와고 5P = 버튼 4구 + 출력 1구
- **NC(평상시 닫힘) 접점**을 쓴다 → 코일 OFF 일 때 통전 = 버튼 정상

🔴 **EMO(GPIO26)는 와고에 넣지 않는다.** NC 배선 fail-safe 라 끊으면 비상정지가 죽는다. 차단 중에도 EMO 는 살아 있어야 한다. (5P 라 자리도 없어 구조적으로 방지된다.)

### 3.3 🔴 결선 전 필수 점검 — COM 공통 여부

기존 CH1~4 는 **COM 에 12V(−)** 가 물려 있다(결선도 §3.3). CH5 는 **Pi GND(3.3V 로직)** 를 다룬다.

> **모듈 안에서 COM 이 공통 레일로 묶여 있으면 12V(−) 와 Pi GND 가 연결된다.** 결선 전에 **테스터로 CH1 COM ↔ CH5 COM 도통을 반드시 확인**할 것. 도통되면 이 설계를 그대로 쓸 수 없고, 별도 릴레이 모듈 또는 반도체 스위치로 바꿔야 한다.

SZH-RLBG-009 는 채널별 독립 Form C 로 알려져 있으나 **실물 확인 없이 진행하지 않는다.**

### 3.4 전류

| 상태 | 동시 ON 채널 | 코일 전류 |
|---|---|---|
| RUN | 녹 | ~75 mA |
| WARNING | 황 | ~75 mA |
| **BLOCK** | 적 + 부저 + **차단** | **~225 mA** |

결선도 §6 실측 = 채널당 71.4mA·69Ω. 종전 최대 2채널(150mA)에서 3채널(225mA)로 는다. **방법 A(Arduino 5V 급전) 유지** — USB 급전 500mA 한계 안이다. 코일 전원 분리(방법 B) 불필요.

## 7. 위험

**① 🔴 접점 미세전류 (기술적으로 가장 불확실한 것)**
GPIO 내부 풀업은 약 66µA 만 흘린다. 10A 급 파워 릴레이 접점은 이렇게 작은 전류에서 **산화막 때문에 접촉 불량**이 날 수 있다(wetting current 부족).
- 완화 = BLOCK/해제를 반복하면 접점이 자체 세척된다. 시연 기간에는 문제 가능성이 낮다.
- 증상이 나오면 **버튼 신호선에 외부 풀업 4.7kΩ** 을 달아 전류를 약 10배로 올린다.
- **검증 5번(해제 후 10회 반복)이 이 위험의 관문이다.**

**② 타워램프 4선 이설**
2026-07-15 E2E 검증을 마친 배선을 새 모듈로 옮긴다. 채널 순서를 1:1 로 유지해 위험을 줄였다(§3.1). 검증 3·7번으로 되확인.

**③ HW 부재**
2026-09-05 현재 결선·검증 불가. 마감 9/8.

**④ fail-safe 방향 — 의도된 선택** ⛔ **2026-09-11 뒤집힘 → §11**
NC 접점이라 **아두이노·릴레이 전원이 죽으면 버튼이 살아난다**(차단이 풀린다). 산업 인터록 표준(de-energize to trip)과 반대 방향이다.
- 이유 = 시연 안정성. 시리얼이 끊긴 이력이 있고(§10.44 포트 경합), 그때 콘솔 전체가 먹통이 되면 시연이 멈춘다.
- 🔴 **이 시스템을 fail-safe 라고 부르지 않는다** — 통합문서 §1 프레이밍 메모가 *"fail-safe 는 EMO NC 배선 등 실제로 그러한 부분에만 한정해 쓴다"* 고 이미 못박아 두었고, 이 설계는 그 범위를 넓히지 않는다.

🔴 **2026-09-04 04:42 에 사용자가 이미 NO 로 정했다**(세션 `11fd399e`).
> *"아두이노가 죽은 상태에서는 버튼 또한 죽는게 맞다고 생각해. 소프트웨어로 차단한다고 하더라도 콘솔 내의 한 기능이 마비 되었다면 전체 기능이 중단되는 게 맞다 생각해, 그러므로 **NO(산업 표준)**으로 해서 아두이노가 죽었을 때 버튼이 안 먹히고 아두이노가 다시 살아나면 버튼도 살아나는지 확인해보자"*

2026-09-11 에 사용자가 같은 방향을 재확인했다 → **NO 로 확정.**

### 11.2 무엇이 달라지나

| | 개정 전 (NC) | **개정 후 (NO)** |
|---|---|---|
| 평소 코일 | OFF | **ON** |
| 차단 시 코일 | ON | **OFF** |
| 아두이노·릴레이 전원이 죽으면 | 버튼이 산다 (차단 해제) | **버튼이 죽는다 (차단 유지)** |
| 동시 ON 코일 최대 | 3 (적+부저+차단 ≈225mA) | **2** (정상: 녹+차단 / 차단: 적+부저 ≈150mA) |
| 성격 | energize to trip | **de-energize to trip = 산업 표준** |

🔴 **감수하는 위험** — 시리얼이 끊기거나 아두이노가 리셋되면 **버튼 4개가 전부 죽어 콘솔이 먹통**이 된다. §10.44 포트 경합 이력이 있다. 사용자가 *"한 기능이 마비되면 전체가 중단되는 게 맞다"* 로 감수를 명시했다.
✅ **EMO 는 영향 없다** — 와고에 넣지 않아 릴레이를 거치지 않는다(§3.2). 차단 중에도, 아두이노가 죽어도 살아 있다.

### 11.3 고칠 곳 — `Rpi5/arduino/console_interlock/console_interlock.ino`

**코드 2줄.** 파이 쪽(`interlock.py`·`fsm.py`)은 손대지 않는다 — 「차단」의 뜻은 그대로이고 전기적 방향만 바뀐다.

| 위치 | 지금 | 고칠 것 |
|---|---|---|
| `setRelays()` | `digitalWrite(PIN_CUT, cut ? RELAY_ON : RELAY_OFF);` | `digitalWrite(PIN_CUT, cut ? RELAY_OFF : RELAY_ON);` |
| `setup()` (pinMode 앞) | `digitalWrite(PIN_CUT, RELAY_OFF);` | `digitalWrite(PIN_CUT, RELAY_ON);` |

**주석도 함께 고친다** — 파일 머리 주석이 NC 를 전제로 *"NC 접점이라 전원이 죽으면 버튼이 살아난다 · 의도된 선택 · fail-safe 라고 부르지 않는다"* 라고 적고 있다. 개정 후에는 **반대 서술**이 되며, `PIN_CUT` 줄의 `ON = 버튼이 끊긴다` 도 `OFF = 버튼이 끊긴다` 로 바뀐다.

⚠️ **부팅 순간** — `pinMode` 전에는 핀이 떠 있고 active-LOW 모듈은 그것을 ON 으로 읽는다(2026-09-05 실측). NO 에서 코일 ON = 접점 닫힘이므로 **부팅 중에도 버튼은 살아 있다.** 개정 전과 같다.

### 11.4 결선 — 한 가닥만 옮긴다

```
  B1 GND ─┐                     ┌─────────────────┐
  B2 GND ─┤  버튼 와고 5P       │ CH5   NO  ←─────┼── 버튼 공통 1가닥  🆕 (종전 NC)
  B3 GND ─┤  ─1가닥─────────────┤       COM ──────┼──→ 파이 GND 핀   (변경 없음)
  B4 GND ─┘                     │       NC  (비움) │  🆕 비운다
                                └─────────────────┘
  EMO GND ───→ 파이 GND 직결 (와고에 넣지 않음, 변경 없음)
```

- **COM = 파이 GND** 는 그대로다. 12V(−) 쪽에 물리면 안 된다 — 타워램프 4채널의 COM 이 12V(−) 이고, 두 계통은 만나면 안 된다(§3.3).
- 🔴 **§3.3 의 COM 공통 도통 점검은 여전히 필수**다. 아직 실시 기록이 없다.

**순서** — 펌웨어를 먼저 굽고, 그다음 가닥을 옮긴다.
지금은 가닥이 브레드보드 GND 에 직결(릴레이 우회)돼 있어 버튼이 살아 있다. 펌웨어를 먼저 고쳐 두면 중간에 버튼이 죽는 구간이 없다. 반대로 하면 개정 전 펌웨어 + NO 조합이 되어 **버튼이 전부 죽는다 — 2026-09-05 에 실제로 그렇게 됐다.**

### 11.5 검증 (§6 을 대체)

| # | 확인 | 통과 기준 |
|---|---|---|
| 1 | COM 도통 점검(§3.3) | CH1 COM ↔ CH5 COM **비도통** |
| 2 | 정상 상태 | B1~B4 눌림이 파이에 전부 도달 |
| 3 | 차단 명령 | B1~B4 눌림이 **하나도** 도달하지 않음 |
| 4 | 차단 중 EMO | **살아 있음** |
| 5 | 해제 복귀 | 정상 명령 후 B1~B4 재동작, 10회 반복 |
| 6 | 🆕 **전원 상실** | USB 를 뽑으면 버튼이 **죽고**, 다시 꽂으면 **살아난다** ← 이번 개정의 목적 |
| 7 | 회귀 | 타워램프 적·황·녹·부저 종전대로 |

### 11.6 문서에 미칠 영향

개정이 반영되면 **§7-④ 의 「fail-safe 가 아니다」 서술이 바뀐다.** 통합문서 §1 프레이밍 메모가 *"fail-safe 는 실제로 그러한 부분에만 한정해 쓴다"* 로 범위를 묶어 두었으므로, 버튼 차단 경로가 de-energize to trip 이 되면 **그 범위에 들어온다.** 다만 판정은 검증 6번을 통과한 뒤에 한다 — 지금 쓰면 §5 「과장 금지」 위반이다.


### 11.7 🆕 실작업 체크리스트 (2026-09-11 기록 — 사용자가 HW 앞에 설 때 그대로 따른다)

> 순서를 지킨다. **펌웨어가 먼저다** — 반대로 하면 2026-09-05 처럼 버튼이 전부 죽는다.

**0. 준비** — 12V 커넥터를 뽑는다. 버튼 공통 가닥은 지금 브레드보드 GND 에 있다(릴레이 우회, 버튼 살아 있음). 그대로 둔다.

**1. 🔴 COM 공통 도통 점검** (§3.3, 아직 한 번도 안 했다)
테스터 도통 모드로 **CH1 COM ↔ CH5 COM**.
- 소리 없음 = 채널별 독립 → 계속 진행
- 소리 남 = **여기서 멈춘다.** 12V(−) 와 파이 GND 가 모듈 안에서 붙는다. 이 모듈로는 이 설계를 못 쓴다

**2. 펌웨어 수정·굽기** (§11.3)
`console_interlock.ino` 2줄 반전 + 주석 방향 정정 → `arduino-cli upload --fqbn arduino:renesas_uno:minima`
⚠️ 업로드는 1200bps 터치 → DFU. udev 룰은 설치돼 있다.

**3. 굽기 직후 확인** — 파이에서 `RUN` 을 보내고 **CH5 LED 가 켜지는지** 본다.
- 켜짐 = 정상(NO 방식은 평소 코일 ON)
- 안 켜짐 = 반전이 안 들어갔다. 2번으로 돌아간다

**4. 결선** (§11.4)
- 버튼 와고 출력 1가닥 → **CH5 `NO`**
- **CH5 `COM`** → 파이 40핀 헤더 **물리 25번(GND)** ← 설계서 34쪽 값
- `NC` 는 비운다 · EMO 는 건드리지 않는다

**5. 검증** (§11.5 7항목) — 정상에서 B1~B4 전부 도달 / 차단에서 하나도 안 옴 / 차단 중 EMO 생존 / 해제 복귀 10회 / **USB 뽑으면 버튼이 죽고 다시 꽂으면 살아난다** / 타워램프 4색 회귀

**6. 🆕 디바운스 판정** (점검문서 §6.4)
`config.GPIO_BOUNCE_SEC` 를 **0.2** 로 바꿔 둔 상태에서 B1~B4 를 각각 5회씩 누른다 → 로그에 **정확히 5줄**이면 확정.

**7. 기록** — 결과를 통합문서 §10 새 절 + 작업로그 블록으로. 검증 6번을 통과해야 「전원이 끊기면 차단이 유지된다」를 쓸 수 있다(§11.6).
