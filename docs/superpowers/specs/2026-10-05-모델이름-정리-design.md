# 모델·실험 이름 정리 — 설계

> 2026-10-05 · 세션 1aecfe30 · 사용자 요청 「구분이 되게 버튼은 "B" 공구는 "T"를 사용해주고 나머지는 작업에 또는 목적에 맞게 정리」 · 범위 = 「지금 쓰는 것만 바꾸고 + 대조표」(사용자 「이대로 진행」) · 보고 = 「소급하지 못한 모델명은 대조표의 변경된 모델명으로 구분할 수 있게 알려줘」 · 사용자 정정 = 「E0b, E0c … 구분이 필요한 명들은 이들」 · 「변환 모델도 구분은 해줘야해」 · 추가 = 「통합문서에 모델에 대한 목록표 — 모든 학습 모델과 변환모델에 대해서 짧은 설명」(사용자 「이대로 진행」).

## 1. 목적·범위

- **목적** — 이름만 보고 ① 버튼 모델인지 공구 모델인지(B/T) ② 어떤 방식으로 학습했고 무엇을 바꿨는지 ③ 변환 모델이면 어떤 방식으로 바꿨는지를 안다. 특히 `E0b`·`E0c`·`B0`·`U2`·`MZ`·`UL` 처럼 뜻이 안 보이는 이름을 없앤다.
- **바꾸는 것(실제 이름)** — 시연 모델 파일과 그것을 가리키는 살아 있는 코드·안내 · 1-3단계에서 새로 만드는 실험 · 변환 모델 파일(파이 `~/data/학습실험/`)과 변환 기록 · 1-3 설계서·계획서의 후보 이름 · 1-2 계획서 Task 15·21 의 변환 이름.
- **바꾸지 않는 것(대조표로)** — 끝난 실험 결과 폴더·설정 파일 99개(1-3 버튼 기준 `E15-button-base*` 포함 — §7) · 장부 · 저널 · 작업로그 · 옛 커밋 · 데스크톱 `runs/` 폴더 · 측정 기록(json·csv·md).
- **보고 규칙** — 대화·보고·새로 쓰는 문서에서는 **새 이름**으로 부른다. 실제 파일 경로를 적을 때만 실제 이름을 쓴다.

## 2. 이름 규칙 (정본 = 통합문서 §6.4 로 옮긴다)

### 2.1 종류 접두

- **B = 버튼 모델 · T = 공구 모델.**
- 🔴 **B·T 바로 뒤에 숫자를 붙이지 않는다** — `B1`~`B4` 는 버튼 **종류** 이름(레시피 B1 클린·가스차단 … B4 챔버 벤트)이다. 모델 이름은 B·T 뒤에 `_` 또는 `-` 를 둔다. 같은 이유로 1-3 버튼 후보는 「B0~B4」가 아니라 **기준 · 색 · 좌우 · 가림 · 흐림**으로 부른다(지금 설계서 표에 「B3 분홍 ↔ EMO」와 「B3 가림」이 함께 나온다).

### 2.2 학습 모델(실험) — `<B|T>-<학습 방식>-<바꾼 것>[-<꼬리>]-s<시드>`

| 칸 | 값 | 뜻 |
|---|---|---|
| 학습 방식 | `early` | 일찍 멈춤 방식 — 1단계(최대 200 에폭 · patience 20 · 포화 멈춤) |
| | `full` | 120 에폭 끝까지 — 1-2단계 결론 · 지금 공통 기준(`기본.yaml`) |
| | `check` | 멈춤 장치·탐색기 동작 확인용 짧은 학습(점검 · 스모크) — 받기·장부에서 뺀다 |
| 바꾼 것 | 영문·숫자·`.` 한 낱말 | 기준에서 바꾼 하나(`color` `noflip` `cutmix03` `blur` `lr0005` `in1024`) · 둘을 합치면 붙여 쓴다(`in1024lr0005`) · 없으면 `base` · 탐색 시도는 `S<회차>t<시도>` |
| 꼬리 | `old` · `albu` | 같은 이름이 둘 생길 때만 — `old` = 멈춤 문턱이 옛 값이라 다시 돌린 첫 기준 · `albu` = 증강 라이브러리(albumentations) 설치 뒤 같은 설정으로 다시 돈 기준 |
| 시드 | `-s0` `-s1` `-s2` | 언제나 끝에 적는다 |

- **실험 번호(E<n>)는 새 이름에 쓰지 않는다** — 대조표의 「옛 이름」 칸에만 남는다. 앞으로 만드는 설정 파일 이름 = 새 이름.
- 🔴 **이름과 설정이 어긋나면 거부한다** — `full` 인데 일찍 멈춤(patience > 0 또는 포화_향상 > 0)이 켜져 있거나 `early` 인데 patience 0 이면 `trainconf.resolve` 가 ValueError. 무리(group)는 접두에서(B→button · T→tool · 설정의 group 과 다르면 거부).
- **옛 이름 → 새 이름 변환**(대조표 생성 · `학습/이름.py` 순수 함수): 무리 `button`→`B` · `tool`→`T` · 학습 방식 = 결과 `설정.json` 의 멈춤 조건(포화_향상 0 → `full` · 아니면 `early`) · `E9` = `check` · 끝의 `s<n>` 을 시드로 떼어 실제 시드와 대조(다르면 멈춤) · 남은 낱말 앞의 `f120` 은 학습 방식이 말하므로 뗀다 · `both` → `in1024lr0005` · 탐색 `T1t<nnn>`(E8)·`t<nnn>`(E10) → `S1t<nnn>` · 비면 `base` · 꼬리 `E0` → `old` · `E13` → `albu`. 시험 적용(99개) = 규칙 밖 0 · 겹침 0 · 학습 방식 ↔ 실제 patience 어긋남 0.
- 대표 대응 — `E0b-button-s0` → `B-early-base-s0` · `E0c-tool-f120` → `T-full-base-s0` · `E0-tool-s1` → `T-early-base-old-s1` · `E13-tool-base` → `T-full-base-albu-s0` · `E15-button-base` → `B-full-base-s0` · `E4c-tool-f120lr0005s1` → `T-full-lr0005-s1` · `E8-tool-T1t002` → `T-full-S1t002-s0` · `E10-tool-t002s1` → `T-full-S1t002-s1` · `E9-button-sat` → `B-check-sat-s0`.
- 코드는 **옛 꼴과 새 꼴을 모두 읽는다**(옛 결과를 판정 기준으로 계속 쓴다). 새 설정 파일은 새 꼴로만 만든다(시험이 막는다).
- 탐색 회차는 `S<n>`(T 는 공구) — 지금 `탐색/T1.json` = S1 · 스모크 `T0` = S0. 탐색 시도 이름을 만드는 코드(`tune.py` 28 · `학습.py` 441)는 **다음 탐색을 설계할 때** 새 꼴로 바꾼다(지금 걸 탐색이 없다).

### 2.3 변환 모델 — `<학습 모델 새 이름>_<변환 방식>.hef`

| 변환 방식 | 뜻 |
|---|---|
| `ours-L2` · `ours-L1` | 우리 변환 스크립트(`학습/hef_convert.py`) · 최적화 수준 2 · 1 |
| `zoo` | Hailo 공식 Model Zoo `hailomz compile` |
| `ultra` | ultralytics 공식 `export(format="hailo")` |

| 지금(파이 `~/data/학습실험/`) | 새 파일 |
|---|---|
| `E0b-button-s0/model.hef` | `E0b-button-s0/B-early-base-s0_ours-L2.hef` |
| `E0b-button-s0/MZ/model.hef` | `E0b-button-s0/zoo/B-early-base-s0_zoo.hef` |
| `E0b-button-s0/UL/model.hef` | `E0b-button-s0/ultra/B-early-base-s0_ultra.hef` |
| `E0c-tool-f120/model.hef` | `E0c-tool-f120/T-full-base-s0_ours-L2.hef` |

- 변환 기록(결과 폴더) = `변환_<방식>.json` — `변환.json` → `변환_ours-L2.json` · `변환_L1.json` → `변환_ours-L1.json`(지금 없음) · `변환_MZ.json` → `변환_zoo.json` · `변환_UL.json` → `변환_ultra.json`(git mv). 공구 기록(커밋 전)도 처음부터 새 이름.
- **`학습.py 변환` 의 받기**가 이 이름으로 받고 기록한다(`hef_name(id, 수준)` 순수 함수 · 옛 id 는 대조표 변환 함수로 새 이름을 얻는다). 데스크톱 작업 폴더 안의 `model.hef` 는 그대로(사용자가 보지 않는다).
- 실험 HEF 를 시연에 올리면 §2.4 의 판 이름(`B_v3.hef` …)이 되고 출처(학습 모델 · 변환 방식)를 §6.4 목록에 적는다.

## 3. 통합문서 §6.4 — 모델 목록 (사용자 추가 요청)

- 자리 = §6 「인식 — 비전 파이프라인」 끝 새 소절 **§6.4 모델 목록 — 학습 모델·변환 모델**(R12 · ⏸ 블록 앞). §6.1 의 「🔖 모델 네이밍 규약(정본, 3단계)」은 이 소절을 가리키게 바꾸고, 옛 규약 문단(person_v1 → console_v1 → console_v2)은 `변경이력.md` 로 옮긴다(R2).
- 내용 = ① 이름 규칙(§2 요약) ② **시연 모델** 표(새 이름 · 옛 이름 · 짧은 설명 · 지금 쓰임) ③ **학습 모델** 표 — 시드 3개를 한 줄로 묶은 「모델 묶음」 단위(새 이름 · 옛 이름 · 무리 · 학습 방식 · 바꾼 것 한 줄 설명 · 쓰임(기준 · 대체됨 · 기각 · 진행 중 · 점검)) ④ **변환 모델** 표(새 파일 · 학습 모델 · 방식 · 짧은 설명) ⑤ 전체 id 대조 = `Rpi5/학습/이름대조표.md`(자동 생성) 가리킴.
- 🔴 **수치를 넣지 않는다**(R5 — 측정 수치 정본 = §12 `[CURRENT]` 표 · 저널). 쓰임 칸의 「기각」·「기준」은 판정 결과 낱말과 근거 절(§12.N · 장부)만.
- 설명은 설정 파일 `메모` · 결과 `바꾼것` · 장부 · 저널 절에서 옮긴다 — 지어내지 않는다. 출처를 못 찾은 항목은 「설명 출처 없음」으로 두고 보고한다.

## 4. 대조표 — `Rpi5/학습/이름대조표.md`
