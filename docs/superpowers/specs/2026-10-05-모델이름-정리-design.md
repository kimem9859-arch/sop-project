# 모델·실험 이름 정리 — 설계

> 2026-10-05 · 세션 1aecfe30 · 사용자 요청 「구분이 되게 버튼은 "B" 공구는 "T"를 사용해주고 나머지는 작업에 또는 목적에 맞게 정리」 · 범위 = 「지금 쓰는 것만 바꾸고 + 대조표」(사용자 「이대로 진행」) · 보고 = 「소급하지 못한 모델명은 대조표의 변경된 모델명으로 구분할 수 있게 알려줘」.

## 1. 목적·범위

- **목적** — 이름만 보고 ① 버튼 모델인지 공구 모델인지(B/T) ② 무엇을 위한 것인지(바꾼 것 · 변환 방식)를 안다.
- **바꾸는 것(실제 이름)** — 시연 모델 파일과 그것을 가리키는 살아 있는 코드·안내 · 1-3단계에서 새로 만드는 실험 · 변환 비교 기록(MZ·UL) · 1-3 설계서·계획서의 후보 이름 · 1-2 계획서 Task 21 의 변환 이름.
- **바꾸지 않는 것(대조표로)** — 끝난 실험 결과 폴더·설정 파일 99개(지금 도는 버튼 기준 B0 = `E15-button-base*` 포함 — 아래 §6) · 장부 · 저널(통합문서) · 작업로그 · 옛 커밋 · 데스크톱 `runs/` 폴더 · 측정 기록(json·csv·md).
- **보고 규칙** — 대화·보고·새로 쓰는 문서에서는 **대조표의 새 이름**으로 부른다. 실제 파일 경로를 적을 때만 실제 이름을 쓴다.

## 2. 이름 규칙 (정본)

### 2.1 종류 접두

- **B = 버튼 모델 · T = 공구 모델.**
- 🔴 **B·T 바로 뒤에 숫자를 붙이지 않는다** — `B1`~`B4` 는 버튼 **종류** 이름(레시피 B1 클린·가스차단 … B4 챔버 벤트)이다. 모델·실험 이름은 B·T 뒤에 `_` 또는 `-` 를 둔다(`B_v2` · `B-E16-…`). 같은 이유로 1-3 버튼 후보는 「B0~B4」가 아니라 **기준 · 색 · 좌우 · 가림 · 흐림**으로 부른다(지금 설계서 표에 「B3 분홍 ↔ EMO」와 「B3 가림」이 함께 나온다).

### 2.2 시연 모델 파일 — `<B|T>_v<판>[_<꼬리>].<pt|hef>`

| 지금 | 새 이름 | 비고 |
|---|---|---|
| `console_v1.hef` | `B_v1.hef` | git 추적 |
| `console_v2.hef` | `B_v2.hef` | git 추적 · 시연 기본(config) |
| `best.pt` | `B_v1.pt` | git 추적 · `dev/ai_model/README.md` 25~28행 = Colab `button_v1` 가중치(구현 때 해시로 다시 확인 · 다르면 멈춤) |
| `tool_v1.pt` · `tool_v2.pt` · `tool_v3.pt` · `tool_v3_last.pt` | `T_v1.pt` · `T_v2.pt` · `T_v3.pt` · `T_v3_last.pt` | git 밖(.gitignore) · 시연 기본 = `T_v3.pt` |
| `tool_v4_partial_e31.pt` · `…e38.pt` | `T_v4_partial_e31.pt` · `…e38.pt` | git 밖 |
| `yolov8n.pt` · `yolov8s.pt` | 그대로 | 우리 모델이 아니다(COCO 출발 가중치) |

- 옛 이름 사본(심볼릭 링크)을 남기지 않는다 — 두 이름이 함께 살면 구분이 다시 흐려진다. 옛 명령(기록 속)은 대조표로 읽는다.
- git 밖 파일(T_*)은 이 파이에서만 바꾼다 — 다른 머신에 사본이 있으면 대조표의 한 줄 명령으로 같은 이름으로 바꾼다.

### 2.3 학습 실험 — `<B|T>-E<번호>[a-z]-<목적>-s<시드>`

- **목적** = 기준에서 바꾼 것(영문·숫자·`.` · 예 `color` `noflip` `cutmix03` `blur` `lr0005` `f120`) · 바꾼 것이 없으면 `base`. **시드는 언제나 끝에 `-s<n>`**(시드 0 도 적는다 — 지금은 `-s0` 과 `f120s1` 이 섞여 있다).
- 번호(E<n>)는 지금처럼 전체에서 하나씩 늘린다 — 다음 = E16.
- **옛 이름 → 새 이름 변환 규칙**(대조표 생성): 무리 `button`→`B` · `tool`→`T` · 끝의 `s<n>` 을 시드로 떼고(없으면 실제 설정의 시드 — 이름과 다르면 멈춤) · 남은 목적이 비면 `base` · 탐색 표기 `T1t<nnn>`(E8) · `t<nnn>`(E10 = T1 시도 확인)은 `S1t<nnn>`. 예: `E0b-tool-s2` → `T-E0b-base-s2` · `E0c-tool-f120s1` → `T-E0c-f120-s1` · `E8-tool-T1t002` → `T-E8-S1t002-s0` · `E15-button-base` → `B-E15-base-s0`. 시험 적용(99개) = 규칙 밖 0 · 겹침 0.
- 코드는 **두 꼴을 모두 읽는다**(옛 결과를 판정 기준으로 계속 쓴다) — 새 설정 파일은 새 꼴로만 만든다.

### 2.4 탐색 회차 — `S<n>`

- T 는 공구이므로 탐색(search) 회차는 `S<n>`. 지금 `탐색/T1.json` = 대조표상 S1. 탐색 시도 이름을 만드는 코드(`tune.py` 28 · `학습.py` 441)는 **다음 탐색을 설계할 때** 새 꼴로 바꾼다(지금 걸 탐색이 없다).

### 2.5 변환 방식

| 지금 | 새 이름 | 뜻 |
|---|---|---|
| U2 | `ours-L2` | 우리 변환 스크립트(`hef_convert.py`) · 최적화 수준 2 |
| U1 | `ours-L1` | 같은 스크립트 · 수준 1(이번에는 뺐다) |
| MZ | `zoo` | Hailo 공식 Model Zoo `hailomz` |
| UL | `ultra` | ultralytics 공식 `format=hailo` |

- 실험 하나의 변환 기록 = `변환.json`(ours-L2 · 코드가 만드는 기본 이름 그대로) · `변환_L1.json`(코드 그대로) · **`변환_MZ.json` → `변환_zoo.json` · `변환_UL.json` → `변환_ultra.json`**(손으로 만든 기록 · git mv). 파이 데이터 폴더 `~/data/학습실험/E0b-button-s0/{MZ,UL}` → `{zoo,ultra}`.
- 표·보고에서 변환 HEF 는 「실험 새 이름 · 방식」으로 부른다 — 예 `B-E0b-base-s0 · zoo`.

## 3. 대조표 — `Rpi5/학습/이름대조표.md`

- 한 장에 다섯 묶음: ① 규칙 요약 ② 시연 모델 파일 ③ 실험·점검 전부(옛 id → 새 이름 · 결과 폴더가 있는지) ④ 탐색 회차 ⑤ 변환 방식 · 1-3 버튼 후보.
- ③ 은 손으로 쓰지 않는다 — `학습/이름.py` 의 순수 함수 `new_name(old_id, seed)` 와 생성 명령(`python3 학습/학습.py 이름표`)이 설정 파일·결과 폴더를 읽어 만든다. 시드는 실제 설정에서 읽고 이름의 시드와 대조한다.
- 대조표 머리말에 「다른 머신 사본 이름 바꾸기 한 줄」(§2.2)과 「이 표가 정본 — 기록 속 옛 이름은 이 표로 읽는다」.

## 4. 살아 있는 곳 고치기

- **config.py** — `PT_MODEL_PATH`(`B_v1.pt`) · `HEF_MODEL_PATH`(`B_v2.hef`) · `TOOL_MODEL_PATH`(`T_v3.pt`)와 주석.
- **코드** — py·sh 의 기본값·도움말·안내 문구 중 지금 쓰는 경로(console_v2 19 · console_v1 7 · tool_v3 14 · best.pt 7 파일 — 구현 때 하나씩 「살아 있는 경로 / 기록 설명」으로 가른다). 기록을 설명하는 주석(「v1 과 대조하려면」 등)은 새 이름으로 고치되 뜻을 바꾸지 않는다.
- **안내 문서** — Rpi5 `CLAUDE.md` · README · `.claude/` 규칙·스킬 · `dev/ai_model/README.md` 의 지금 쓰는 경로.
- **trainconf** — `ID_RE` 가 새 꼴(`^[BT]-E\d+[a-z]?-[A-Za-z0-9.]+-s\d+\Z`)도 받는다 · 무리 = 접두에서(B→button · T→tool · 설정의 group 과 다르면 거부) · 점검 예약 `E9-` 건너뛰기(`ledger.py` · `학습.py` 의 SKIP)는 새 꼴 `[BT]-E9-` 도 건너뛴다.
- **1-3 설계서·계획서** — 후보 이름(기준·색·좌우·가림·흐림) · Task 6 의 설정 파일 이름 `B-E16-color-s0` … `B-E19-blur-s2` · 합치기 `B-E20-combo-s<n>` · 기준 비교 대상은 옛 id `E15-button-base*`(= 대조표 B-E15-base-s0~s2) 그대로.
- **1-2 계획서 Task 21** — 변환 이름 ours-L2 · zoo · ultra · 파일·폴더 새 이름.

## 5. 보고 규칙을 남길 곳

- 「대조표 새 이름으로 부른다」는 매 세션 알아야 하는 것이 아니라 **모델·학습 작업을 할 때** 필요하다 → `.claude/rules/규칙배치.md` 의 배치 기준을 따라 둔다(구현 때 확인 · 후보 = `.claude/rules/` 의 학습 파일 규칙 또는 `데이터셋`·`측정도구` 스킬). memory 에도 한 줄(feedback).

## 6. 정한 것 · 버린 것

- **B0(`E15-button-base*`)는 대조표로 둔다** — 앞서 「끝난 뒤 바꾼다」고 말씀드렸으나, 이미 옛 이름으로 데스크톱에서 돌고 있어 결과 폴더·설정·데스크톱 폴더·장부를 함께 바꾸는 이름 바꾸기 도구가 따로 필요하다. 대조표의 새 이름 `B-E15-base-s0~s2` 로 부르고, 1-3 의 새 후보(E16~)부터 실제 이름을 새 꼴로 만든다.
- 버린 것 — 전부 소급(사용자 결정) · 옛 이름 심볼릭 링크(구분이 흐려짐) · 지금 `tune.py` 고치기(걸 탐색 없음).
