## 1. 목표와 성공 기준

- **목표** — ①기본값을 그대로 쓰던 학습을 **근거 있는 시작값**으로 바꾸고 ②그 값을 **기록해 최종 학습까지 다시 쓰며** ③**한 번에 하나씩 바꿔 가며** 우리에게 맞는 값을 찾는 체계를 만든다. 학습은 **여러 세션에 걸쳐 이어지고**, 세션을 닫아도 계속 돌며, **시간만 버리는 학습은 스스로 멈춘다.**
- **1단계 성공 기준**(이 설계의 실행 범위)

| 흐름 | 파이에서 걸기 → 데스크톱에서 학습·채점 → 파이로 받기 → 장부 한 줄이 **세션을 닫았다 연 뒤에도** 이어진다(실제로 한 번 세션 경계를 넘겨 확인) |

## 3. 근거 요약 — 조사 결과 (원문 = 조사보고서.md · 학습이론.md 에 옮긴다)

### 3.1 ultralytics 기본값은 무엇에 맞춘 값인가

- **학습률·모멘텀·색/모양 증강**(lr0 0.01 · hsv 0.015/0.7/0.4 · mosaic 1.0 …) = YOLOv5 `hyp.scratch-low.yaml` 과 같은 숫자 = **「COCO 를 사전학습 없이 300 에폭」** 용. 뿌리는 YOLOv3(2019) COCO 유전 알고리즘 진화값이고 ultralytics `default.yaml` 은 2022-12 이후 숫자가 그대로다. 출발 가중치 `yolov8n.pt` 자체도 COCO 를 처음부터 SGD 500 에폭으로 배웠다(가중치 안 `train_args` 직접 확인).
- **근거 비공개** — 손실 가중치 box 7.5 · cls 0.5 · dfl 1.5(비공개 R&D 브랜치) · epochs 100 · batch 16. optimizer auto 의 문턱(10,000 반복)과 학습률 식도 「내부 실험」이라고만 한다.
- **공식 파인튜닝 권고** — 「기본값이 강한 출발점이고 **이유가 있을 때만 바꿔라**」 · patience 10~20 · 큰 모델을 작은 데이터로 미세조정할 때 `optimizer=AdamW, lr0=0.001` · 1,000장 미만 권고(mosaic 0.5 · freeze 10 · 50 에폭 + patience 20)는 YOLO26 문서 기준이라 우리(약 1,600장)에 그대로 맞는다는 근거는 없다.
- **판 고정의 효과** — 8.4.117 ↔ 8.4.171 `default.yaml` 의 학습 숫자 · optimizer auto 규칙 · fitness 정의는 같다(두 판 소스 직접 비교). 판을 올려도 기본값은 안 바뀐다.

### 3.2 기본값 함정 4개 (우리 상황에서 실제로 걸리는 것)

| # | 함정 | 소스 근거(8.4.171) | 대응 |
|---|---|---|---|
| ① | `optimizer=auto` 면 **적어 준 lr0·momentum 을 무시**하고, 반복 수(⌈사진 수/64⌉ × 에폭)가 10,000 을 넘으면 AdamW → MuSGD 로 **조용히 바뀐다** | trainer.py 324 · 1175~1177 | optimizer 를 적는다(§6) |
| ② | `patience` 100 = 기본 에폭 100 과 같아 **일찍 멈춤이 사실상 꺼짐** · 최고점이 **조금이라도** 오르면 카운트가 처음으로(최소 향상폭 없음) | torch_utils.py `EarlyStopping` | patience 20 + 포화 조건(§7) |
| ③ | 가장 좋은 에폭을 고르는 점수(fitness)가 **mAP50-95 하나뿐** — 우리 관심(운용 문턱의 재현율)과 다르다 | metrics.py `w=[0,0,0,1]` | 고르기는 그 점수로 하되 **판정은 우리 채점 도구로**(§8) |
| ④ | optimizer 를 직접 적으면, auto 일 때 0 으로 바뀌던 **워밍업 편향 학습률이 0.1 로 돌아간다**(Adam 계열에 「0.01 이하」 주석) | trainer.py 529 · 1177 | 0 으로 적는다(§6) |

### 3.3 모델 크기 — yolov8n 고정 (사용자 결정)

- 공식 체크포인트는 클수록 증강을 세게 학습했다(YOLOv8 n·s = scale 0.5 · mixup 0 / m 이상 = scale 0.9 · mixup 0.1~0.15 — 가중치 안 `train_args` 직접 확인) — 「큰 모델은 과적합을 늦추려 더 강한 규제」(공식). 파인튜닝의 lr·에폭·freeze 는 **크기가 아니라 데이터 크기 기준**(공식 가이드).
- Hailo-8 에서 칩에 한 번에 올라가는(단일 컨텍스트) 검출 모델은 v8n·v8s 뿐 · 우리 PCIe = 2세대 1레인 · 비슷한 규모 데이터셋 100개(평균 약 1,600장)에서 v8 n/s/m 차이 ≤ 1.9 mAP(RF100-VL 논문). → 크기 대신 데이터·입력을 본다.

### 3.4 모델 입력 해상도 — 상한 768×1024 (가로×세로 · 카메라 원본)

- 크기는 32 의 배수(`check_imgsz`) · 카메라보다 크면 얻는 것이 없어 **상한 = 768×1024**.
- 파이 Hailo-8 실측(시험 · 결과.txt): 640×640 · 640×832 · 768×1024 **모두 단일 컨텍스트** · 손 모델 2개와 함께 30fps 유지 · 한 프레임 증가 **+1.1ms(640×832) · +3.6ms(768×1024)**(Hailo 지연 증가 − CPU 준비 감소). 시연 루프가 직렬이라 시연 속도 추정 약 −0.3 / −1fps(추론).
- 지금 버튼 경로는 768×1024 를 **640×640 으로 늘려(찌그러뜨려)** 넣는다(`detector.py` 110행) — 768×1024 입력이면 찌그러짐도 없어진다.

- **WSL 이 꺼지지 않게** — 공식 문서(Microsoft WSL)를 확인한 뒤 설정한다. 확인 전에는 「데스크톱 항상 켬」(사용자)과 실행기의 살아 있음 표시(§7)로 끊김을 알아챈다.

### 4.2 전송 — 데스크톱 → 파이 큰 조각 문제

- 2026-10-03 발견: 데스크톱 → 파이 방향에서 SSH 데이터 약 1,100B 이상 조각이 버려진다(파이 → 데스크톱은 정상). 지난 세션의 「최신 암호 방식에서 접속이 멈춤 → curve25519 고정」도 같은 증상으로 보인다(추론).
- **원인부터 규명해 고친다**(CLAUDE.md 근본원인 우선) — 데스크톱 WSL 쪽 경로 MTU · Tailscale 설정을 공식 문서로 확인. 데스크톱 Windows 쪽 조치가 필요하면 사용자에게 명령을 드린다.
- 못 고치면 **중계(`mss_proxy.py` · ssh ProxyCommand · TCP 최대 조각 900B)** 를 파이 `~/.ssh/config` 의 `wsl-train` 에 정식으로 둔다 — 시험에서 14MB 11초 · 해시 일치. 시스템 설정을 바꾸지 않고, 줄 하나를 지우면 원래대로 돌아간다.
- 파이 → 데스크톱(데이터 보내기)은 지금도 정상이다(rsync).

- **목록 고정** — 나눔 판은 몫별 이름 목록 + 해시를 담은 파일(Rpi5 `학습/나눔/place1_v1.json`)로 고정한다. b010~b014 회수로 사진이 늘어도 `place1_v1` 은 움직이지 않는다 — 새 사진은 새 판(`place1_v2` …)으로.
- **학습용 배경** = 학습 몫에서만 그 무리의 배경(찾을 물체 없는 사진)을 10% 로(무작위 · 시드 고정 · 사용자 2026-10-03 결정 유지). 학습 중 검증 · 채점 몫은 그대로.
- **개인정보 관문을 두지 않는다** — 사용자 「개인정보 관문은 없어도 되 사진에는 얼굴이나 개인정보를 찍은 사진은 없어」 · 데스크톱은 우리 기기다. 외부 서비스(Roboflow·Colab)에 올릴 때의 관문(spec ②)은 이 설계 밖이라 그대로다.
- **입력 방식**(학습 · 학습 중 검증 · 채점에 같은 방식 — 고칠 것 ②)
  - `늘리기640` — 사진을 640×640 으로 늘린다(`detector.py` 110행과 **같은 호출** `cv2.resize(frame, (640, 640))`) → `imgsz=640`. 공구도 NPU 로 옮길 예정(사용자)이라 같은 방식 ✋ — 그래서 공구 채점의 JPEG q80 재압축(지금 CPU 경로)은 하지 않는다 ✋.
  - `원본768x1024` — 사진 그대로 → 학습 `imgsz=1024`(긴 변) · 채점은 `imgsz=(1024, 768)`(세로, 가로 — 덧댐 없이 원본).
  - 변환은 데스크톱에서 한다 — 파이는 원본 사진과 나눔 목록만 보낸다(파이 디스크 여유 5.6G).

## 7. 실행기와 안전장치

- **실행기**(데스크톱 · 독립 프로그램) — 파이의 「걸기」가 데스크톱에 띄운다. SSH 연결 · Claude 세션과 무관하게 돈다(시험에서 SSH 가 끊겨도 데스크톱 변환이 끝까지 돌았다). 실행기는 하나만 뜬다(잠금 파일) — 학습은 그 안에서 최대 2개(아래 동시 실행).
- 실행기는 **대기열**의 실험을 순서대로 학습 → 채점(§8)하고, **30초마다** 학습 기록(에폭마다 한 줄 쌓이는 `results.csv`)과 경과 시간을 보고 **상태 파일**(살아 있음 시각 · 지금 실험 · 에폭 · 남은 시간 어림 · 최근 손실 · 학습 중 검증 점수 · GPU 사용률 · 남은 대기열)을 쓴다.
- **멈춤 조건**(사용자 검토 2026-10-03)

| 구분 | 조건 | 그 뒤 |
|---|---|---|
| 정상 종료 | ultralytics 일찍 멈춤(20 에폭 동안 최고점 갱신 없음) · **포화 = 최근 30 에폭 동안 최고점 향상 < 0.005** · 최대 200 에폭 | 채점 → 다음 실험 |
| 이상 종료 | **15분** 동안 에폭 진행 없음 · 학습이 오류로 끝남(손실 NaN·무한대 포함) · **10 에폭** 뒤 학습 중 검증 mAP50 < 0.05 · 실험 시간 상한 초과(상한 = 첫 속도 측정의 에폭당 시간 × 최대 200 에폭 × **2**) | 학습을 끄고 **대기열 전체를 멈춤** · 상태에 「멈춤 · 이유 · 마지막 에폭」 → 이어서 / 바꿔서 / 건너뛰기를 그때 정한다 |
| 걸기 전 | 묶음 예상 총 시간(최대 에폭 기준) **24시간** 초과 | 걸지 않고 확인 요청 |

- 포화 문턱 0.005 는 잠정값이다 — **묶음 1(E0)에서 흔들림 폭을 잰 뒤 그 값에 맞춰 다시 정한다**(사용자 검토 때 약속).
- **어디서 판단하나** ✋
  - 포화(정상) · 10 에폭 점수 0(이상) — 학습 안의 에폭 끝 콜백(`on_fit_epoch_end`)이 판단해 `trainer.stop` 을 세운다. 8.4.171 은 이 콜백을 「멈출지 확인」 바로 앞에 부르므로(trainer.py 679 → 688행) ultralytics 의 정상 종료 경로(best.pt 로 마지막 검증 · 그림 저장)로 끝난다. 점수 0 은 종료 이유를 「이상」으로 남겨 실행기가 대기열을 멈춘다. 마지막 검증 때 같은 콜백이 한 번 더 불리므로(1014행) 그 호출은 건너뛴다.
  - 손실 NaN — ultralytics 가 스스로 `last.pt` 에서 최대 3번 되살리고, 그래도 안 되면 오류로 끝낸다(`_handle_nan_recovery` 1080~1099행) → 실행기는 「오류로 끝남」으로 본다. 따로 감시하지 않는다.
  - 진행 없음 · 시간 상한 — 학습이 멈춰 있어도 판단해야 하므로 실행기(부모)가 본다.
- 실행기 자체가 죽으면(데스크톱·WSL 꺼짐) 살아 있음 시각이 오래된 것으로 「갑자기 끊김」을 알아챈다 → `last.pt` 에서 이어 학습(`resume`)할 수 있다.
- **동시 실행 — 최대 2개**(사용자 「병렬세션으로 최대 2세션으로 … GPU 자원이 부족하다면 하면 안되고」 · 평소 GPU 사용률 10% 미만 · 게임 등 무거운 프로그램 사용 예정 없음 — 사용자)
  - 첫 속도 측정에서 입력 방식마다 **1개 단독과 2개 동시**를 재서(에폭당 시간 · GPU 메모리 최고치 · GPU 사용률) 2개 동시가 **메모리 안에 들고 전체 처리량이 늘 때만** 그 입력 방식을 2개로 돌린다 ✋. 640 학습 하나 ≈ 1.92GB(console_v2 가이드 실측) · 768×1024 는 미측정.
  - 실행기는 두 번째 학습을 띄우기 전에 **남은 GPU 메모리**(`nvidia-smi`)를 그 입력 방식의 측정 최고치 + 여유 1GB 와 비교해, 모자라면 앞 학습이 끝날 때까지 기다린다 ✋.
  - 한 학습이 이상 종료하면 함께 돌던 학습은 **끝까지 마치게 두고** 새 학습만 시작하지 않는다(대기열 멈춤) ✋.
  - 시간 상한 · 진행 없음 판단은 학습마다 따로 한다. 시간 상한의 에폭당 시간은 그 동시 개수에서 잰 값을 쓴다.

## 8. 채점·판정

- **채점 도구는 다시 짜지 않는다** — 계산은 Rpi5 `Demo/test/score_lib.py`(evaluate · operating_point · confusion)를 그대로 쓴다. 데스크톱에는 걸 때 그 파일을 같이 보내고 git 해시를 결과에 적는다. 사진마다 추론하는 부분은 `조사/재학습확인-20261003/채점_pt.py` 와 같은 규칙(추론 conf 0.001 · 이름으로 짝짓기)으로 새 채점 모듈에 둔다.
- **운용 문턱은 config 에서 읽는다** — 버튼 `YOLO_CONF_HIGH` · 공구 `TOOL_CONF`. 파이의 「걸기」가 config 값을 읽어 실험에 실어 보낸다(측정도구 규칙).
- **지표** — 버튼 = 운용점 precision · recall · 버튼끼리 오분류 · 정답과 안 맞는 검출 / 공구 = 종류별 재현율(driver · wrench · pliers) · precision. mAP50 은 보조. IoU 0.5.
- **판정** — 묶음 1 의 시드 3개(기준)가 만든 지표별 **최소~최대 범위**를 「흔들림 폭」으로 삼는다. 실험값이 그 범위 밖이면 「나아짐 / 나빠짐」, 안이면 「차이 없음」 ✋.
- 🔴 **인용 조건** — 「장소1 참고값 · 같은 날 · 공구 채점 양성 한 세션 · 채점 라벨 = 형제 모델(`button_r1`) 초벌 흐름 · `.pt`(HEF int8 전)」을 함께 적는다(§12.84 조건과 같음).

## 13. 지킬 선

- 🔴 **채점 사진(292장)은 고르기·멈춤·포화 판단에 쓰지 않는다** — 학습 중 검증 몫만 쓴다.
- 🔴 **나눔 판은 덮어쓰지 않는다** — 사진이 늘면 새 판.
- 🔴 **결과 폴더가 없는 학습 결과는 쓰지 않는다**(spec ① 규칙 유지).
- 🔴 **1단계 수치는 「장소1 참고값」 조건 없이 인용하지 않는다**(§8).
- 🔴 **원본 가중치·기존 학습 환경을 건드리지 않는다** — `.poc_venv` · `console_v2.pt/onnx` · 시연 `Demo/models/` 그대로. 새 결과는 `Demo/models/` 에 두지 않는다.
- 데스크톱 시스템 설정(SSH · WSL · 네트워크)을 바꿀 때는 백업과 되돌리는 법을 먼저 남긴다.

## 14. 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 내장 자동 조정(`model.tune`) 바로 쓰기 | 1회 = 학습 1회 전체 · 기본 300회 → 우리 규모로 수십~100시간 · 공식 문서도 「실제 학습과 비슷한 데이터·조건에서」 — 장소2(검증)가 생긴 뒤 범위를 좁혀 쓸지 판단 |
| 공식 소규모 권고값 그대로 채택 | 근거 조건(1,000장 미만 · YOLO26)이 우리와 다름 → E3·E5 실험 후보로만 |
| Colab 계속 쓰기 | 무료 · 한 번 48분 · 토큰 1시간 · 매번 업로드 — 예비로만 |
| 기존 학습 함수(`train_tool_round.train_colab`) 고쳐 쓰기 | Colab 전용 구조(빌리기·올리기·반납). 데이터 만들기(`tool_round`)·채점(`score_lib`)은 그대로 다시 쓴다 |
| 가장 좋은 에폭을 재현율로 고르게 trainer 상속 | 코드 상속 필요 · 이득 불확실 → 고르기는 공식 점수, 판정은 우리 채점 |
| 장소1 로 최적값까지 찾기(②) | 공구가 한 세션뿐이라 한 세션에 맞춘 값이 될 위험 · 장소2 에서 다시 해야 함(사용자 ① 선택) |
| 모델 크기 키우기(v8s) | 비슷한 규모 데이터에서 이득 작음 · Hailo 비용(사용자 결정) |
| 세션 시작 배너에 학습 상태 한 줄 | 사용자 「넣지 않아도」 |
| 데스크톱 → 파이 문제를 바로 중계로 덮기 | 근본원인 우선 — 원인 규명을 먼저, 중계는 못 고칠 때 |

## 15. 미결

- 포화 문턱(0.005) — 묶음 1 흔들림 폭으로 다시 정한다.
- 768×1024 의 2개 동시 가능 여부 — 첫 속도 측정(GPU 메모리 최고치)으로 정한다.
- 렌치 2종 나눠 재기 — 라벨이 한 이름이라 지금은 불가.
- 2단계 나눔 판(장소2 의 몫 · 장소1 채점 몫을 학습으로 돌릴지) — 장소2 촬영 뒤 짧은 설계.
- `원본768x1024` 를 채택할 때의 시연 프로그램 변경 · HEF 캘리브레이션 사진 — 범위 밖, 결과를 보고.
