# 글라스 UI 3차 수정 — 설계

> **선행 정본** = `2026-08-03-uiux-글라스-design.md` · `2026-08-04-글라스-UI-2차수정-design.md`.
> 여기는 그 위에 얹는 **3차 수정 7건**만 담는다. 색·폰트·배치 비율의 정본은 선행 문서와 `theme.py`·`config.py`다.

**날짜** 2026-08-04 · **대상 코드** `Rpi5` 브랜치 `feature/glass-ui`

## 1. 배경

2차 수정(Task 1~8)을 마친 화면을 사용자가 다시 보고 확인한 **7건**이다. 6건은 배치·정렬을 다듬는 것이고, 2건(§7 폴더 열기 · §8 확인 팝업)은 동작이 늘어난다.

## 2. 손대지 않는 것

- 🔴 **FSM·인터락·GPIO 배선** — 이번 수정도 전부 표시 계층이다.
- 🔴 **안전 UI 3종** — BLOCK 해제 거부(EMO 미복귀) · 인터락 폴트 경고창 · 종료 확인창.
- **메뉴·알림 창의 닫기 방식**(같은 버튼 재클릭)과 **항목 패널의 ✕**(2차 §7).

## 3. 연결 상태바를 영상 영역으로

**증상** 상태바가 영상이 아니라 **오른쪽 검정 레터박스**에 앉는다.

**원인** `ConnBar.relayout()` 이 `place(..., right=0.03, bottom=0.04)` 로 **창 전체**를 기준으로 삼는다. 영상은 가운데 4:3 이라 창 오른쪽 끝은 레터박스다.

**결정** **영상 사각형을 기준으로 배치한다.** 콘솔이 `camera_label` 의 실제 사각형을 넘겨주고, 상태바는 그 안 우하단에 붙는다. 창 비율이 바뀌어 레터박스 폭이 달라져도 따라간다.

⚠️ `relayout(parent_rect)` 규약은 유지한다 — 다른 오버레이와 호출 방식이 달라지면 `_relayout` 을 읽는 사람이 헷갈린다. **콘솔이 넘기는 사각형만 바꾼다.**

## 4. 알림 아이콘 세로 정렬

**증상** 아이콘이 알림 행의 **좌상단 꼭짓점**에 붙어 제목과 어긋나 보인다.

**원인** `NotifyPanel.push()` 가 아이콘에 `AlignTop` 을 준다.

**결정** **제목 줄과 세로 중앙을 맞춘다.** 부가 설명이 있어 행이 2줄이어도 아이콘은 **제목 옆**에 온다(행 전체의 중앙이 아니다 — 2줄일 때 아이콘이 제목과 설명 사이에 뜬다).

## 5. 메뉴 글자 들여쓰기

**증상** 폭을 1.5배로 넓혔더니(2차 §4) 글자가 **왼쪽에 치우쳐** 보인다.

**결정** 폭은 그대로 두고 **항목 글자만 오른쪽으로** 옮긴다(현재 좌측 여백 2px). 제목·「＋」·「시스템 종료」도 **같은 값**으로 맞춰 세로선이 하나로 보이게 한다.

## 6. 점검 「재연결」 버튼 위치

**증상** 버튼이 패널 **오른쪽 끝**으로 밀려 항목 이름과 멀다.

**원인** 이름 칸이 `addLayout(col, 1)` 로 남는 공간을 모두 가져가 버튼을 끝으로 민다.

**결정** 버튼을 **내용 쪽으로 당긴다.** 항목 이름과 버튼 사이가 화면 폭에 따라 벌어지지 않게 한다.

## 7. 녹화 패널 — 가로 배치 + 저장 폴더 열기

**증상** ①시작 버튼 2개가 세로로 쌓여 **가로로 지나치게 길다** ②녹화본이 어디 저장되는지 화면에서 알 수 없다.

**결정**
- 시작 버튼 2개를 **가로 배치**로 바꾼다. 글자는 짧게 줄인다(가로로 나란히 놓이므로).
- 아래에 **저장 경로 문구 + 폴더 열기**를 단다. 누르면 파일관리자로 `config.RECORDING_SAVE_DIR` 을 연다.
- 🔴 **실패해도 GUI 가 멈추면 안 된다** — 파일관리자가 없거나 실행이 실패하면 **경로를 로그에 남기고 조용히 넘어간다.** 시연 중에 예외로 죽는 쪽이 훨씬 나쁘다.
- 폴더를 여는 것은 **외부 프로그램 실행**이다. 기존 종료 처리(`subprocess.Popen`)와 같은 방식을 쓰고, 예외를 삼킨다.

## 8. CCTV 전환 확인 팝업

**증상** 메뉴에서 「CCTV 전환」을 누르면 **바로** 카메라가 바뀐다.

**결정** 전환 전에 **「CCTV로 전환하시겠습니까?」**를 묻고 예/아니요를 받는다. 🔴 **기본 선택은 「아니요」** — 실수로 카메라가 바뀌면 감지가 끊긴다. 종료 확인창과 **같은 패턴**(`QMessageBox.question`)을 쓴다(이 프로젝트의 확인창 관례).

⚠️ 전환 방향은 **양쪽 모두** 묻는다(ESP32→CCTV, CCTV→ESP32). 문구는 향할 카메라 이름으로 바꾼다.

## 9. 설정 라디오 글자 통일

**증상** 「없음 (글자만 — AR 글라스 느낌)」과 「있음」의 글자 **위치·크기가 어긋나** 보인다.

**결정** 라디오 4개(테마 2 + 배경 2)의 **글자 크기와 왼쪽 시작점을 하나로** 맞춘다.

## 10. 검증

- **관문 4개**는 2차와 같다(셀프테스트 → `test_imports` → `test_fsm`·`test_recipe` → `run_demo.sh` 실기동).
- **수치로 잡히는 것은 셀프테스트로** — 상태바가 영상 사각형 안에 있는가, 녹화 버튼이 가로로 나란한가, 확인을 거절하면 카메라가 안 바뀌는가.
- 🔴 **정렬·치우침은 그려 봐야 보인다** — 2차와 같은 방식(Xvfb + 화면 캡처)으로 **눈으로 확인**한다.
- 🔴 **팝업은 테스트에서 화면을 멈춰 세운다** — 확인창을 띄우는 코드를 그대로 테스트하면 모달이 응답을 기다리며 멎는다. **묻는 부분과 바꾸는 부분을 분리**해, 테스트는 「예/아니요를 받은 뒤」의 동작만 검사한다.

## 11. 미결 (이번 범위 밖)

- **화이트 테마 글자 대비**·**패널 배경 기본값** — ESP32 연결 후 결정(2차 §11 그대로).
- **마우스·터치로 실제 클릭한 검증** — 관문 4의 실기동은 기동·생존만 본다.
