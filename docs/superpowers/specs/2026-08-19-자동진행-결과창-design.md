## 1. 무엇을 하나

시연 흐름에서 **사람이 눌러야 넘어가던 「다음 단계 진행」 버튼을 없애고**, 조건이
채워지면 스스로 넘어가게 한다. 마지막 단계가 끝나면 **무슨 일이 있었는지 요약해
보여준다.** 함께 오버레이의 표시 문제 3건을 고친다.

| # | 무엇 | 지금 | 바꿀 것 |
| --- | --- | --- | --- |
| ① | 단계 전환 | 대기가 끝나면 「다음 단계 진행」 버튼이 떠, **사람이 눌러야** 넘어간다 | 조건이 채워지는 순간 **자동으로** 넘어간다. 버튼은 사라진다 |
| ② | 대기 시간 | 30초 | **10초** (B1·B2·B3) |
| ③ | 공정 완료 | 아무 표시 없이 IDLE 로 돌아간다 | **결과 안내창**이 뜬다 (순서·소요시간·위반·인터락·공구·검출) |
| ④ | 탐지 박스 | 항상 그린다. 끌 수 없다 | 설정에서 **켜고 끈다** |
| ⑤ | 탐지 박스 색 | 전부 초록 한 색 | **클래스별 색** — 버튼은 실물 색, 공구는 종류별 |
| ⑥ | 공구 문구 | 영상 위에 글자만 떠 밝은 배경에서 묻힌다 | **검정 판 50%** + 흰 글자 + 문구 **맥박** |

「작업 시작」 버튼은 **그대로 유지한다** — 없애는 것은 「다음 단계 진행」뿐이다.

### 바뀐 흐름

```
작업 시작 → B1 → 대기 10초 ──(자동)──▶ B2 → 대기 10초 + 렌치 쥠 ──(자동)──▶
          B3 → 대기 10초 ──(자동)──▶ B4 → 【결과 안내창】
```

### 하지 않는 것 (YAGNI)

- **FSM(`fsm.py`)을 고치지 않는다** — 서브작업 우회 설계(§5)의 핵심 전제다
- **`can_advance` 규칙을 바꾸지 않는다** — 「시간 AND 공구」 그대로다. 버튼만 없앤다
- **결과를 파일로 남기지 않는다** — 화면 표시 전용 (사용자 결정, 2026-08-19)
- **오탐지(false positive) 건수를 세지 않는다** — §3.4 참조
- 손 검출·공구 검출 알고리즘, ROI 판정, 인터락 회로는 손대지 않는다
- 배치(%)·테마 색 토큰은 상위 design §1·§3 그대로 (추가만, 변경 없음)

## 2. 자동 진행 — 「다음 단계 진행」 제거

### 2.1 원리

지금은 **버튼 클릭**이 `fsm.press_button()` 을 부르는 방아쇠다. 이것을
**`can_advance` 가 참이 되는 순간**으로 옮긴다. 조건 자체는 손대지 않는다.

```
[지금]  물리버튼 → SubTask 시작 → (대기) → can_advance → 버튼 표시 → 사람이 클릭 → fsm.press_button()
[변경]  물리버튼 → SubTask 시작 → (대기) → can_advance ─────────────────────────▶ fsm.press_button()
```

### 2.2 코드 접점 (`safety_console.py`)

| 위치 | 변경 |
| --- | --- |
| `_update_sub_view()` | 끝에서 `if sub.can_advance: self._finish_sub(); return`. 「다음 단계 진행」으로 글자를 바꾸던 줄은 삭제 |
| `_on_cta()` | 서브작업 분기 삭제 — CTA 는 **「작업 시작」 전용**이 된다 |
| `_sync_cta_visibility()` | `show = (self.fsm.state == State.IDLE)` 로 단순화. 서브작업 분기 삭제 |
| `_finish_sub()` | 그대로 (자동 호출로 바뀔 뿐) |
| `recipe.json` | B1·B2·B3 의 `sub.sec` **30 → 10** |

`_finish_sub()` 는 `self._sub = None` 을 먼저 하므로 `_tick_sub()` 의 이른 리턴에
걸려 **재진입하지 않는다.** 별도 플래그를 두지 않는다.

### 2.3 🔴 알고 시작하는 부작용 — 위반 감지 창이 10초로 줄어든다

순서 위반을 잡아내는 장치가 바로 이 **대기 구간**이다. 대기 중에는 기대단계가 아직
올라가지 않아, 다른 버튼을 누르면 FSM 이 자동으로 오답 판정한다(§5 우회설계).

- **지금**: 사람이 버튼을 누를 때까지 그 창이 **무한히** 열려 있다
- **변경 후**: 창이 **10초**로 닫힌다

이는 요청된 변경에 내재된 결과이며 그대로 진행한다. **시연에서 위반 시연은 그 10초
안에 해야 한다.** B2 는 예외적으로 렌치를 쥘 때까지 창이 열려 있다(시간 AND 공구).

### 2.4 B2 에서 시간만 찼을 때

**쥘 때까지 대기한다**(사용자 결정, 2026-08-19). 게이지는 「완료」로 멈춘 채
공구 칸만 맥박한다(§6). 별도 경고 배너를 띄우지 않는다 — 이미 화면에 요구가 떠 있다.

## 3. 작업 완료 결과창

### 3.1 언제 뜨나

마지막 단계(B4)의 정답 눌림으로 공정이 완료될 때. 판정은 `_commit_button()` 에서 한다:

```python
before = self.fsm.expected_step
self.fsm.press_button(button, time.time())
...
if before == self.fsm.step_count and self.fsm.state == State.IDLE:
    self._show_result()          # 완주
```

`_step_complete()` 는 마지막 단계에서만 `expected_step=1` + `IDLE` 로 간다.
**작업 초기화**는 `fsm.reset()` 을 직접 부르므로 이 경로를 타지 않는다 — 결과창이
뜨지 않는다(의도).

### 3.2 🔴 함정 — IDLE 진입 시 CTA 를 직접 show() 하는 코드

`_on_state_change()` 는 `new == State.IDLE` 일 때 `btn_cta.show()` 를 **직접** 부른다.
결과창이 떠 있는데 그 위/아래로 「작업 시작」이 비쳐 나온다. 반드시 다음을 함께 고친다:

- `btn_cta.show()` → `self._sync_cta_visibility()`
- `ResultPanel` 을 `_sheets()` 목록에 추가 → 열려 있는 동안 CTA 가 자동으로 숨는다

이 규칙은 이미 코드에 못박혀 있다("기억하지 말고 상태에서 그때그때 계산한다").
같은 함정을 되풀이하지 않기 위해 여기 적는다.

### 3.3 담는 내용

| 구획 | 내용 |
| --- | --- |
| **판정** | `완주 성공` / `위반 있었음` |
| **누른 순서** | `B1 → B2 → B3 → B4`, 각 눌림 시각 |
| **소요 시간** | 총 시간 + 단계별 시간(눌림~다음 눌림) |
| **순서 위반** | 번호 · 시각 · `기대 B2 → 실제 B4` · 경고/차단 구분 |
| **인터락 작동** | 경고 N건 · 차단 N건, 각 작동 시각 `2026.08.19 14:32:05` |
| **공구 서브작업** | 요구 공구, 쥐기까지 걸린 시간, 다른 공구를 집은 횟수·종류 |
| **AI 검출** | 클래스별(B1~B4·EMO / 손 / 공구 3종) **검출된 프레임 수**와 평균 신뢰도 |

### 3.4 🔴 검출 항목에 조건을 반드시 병기한다

CLAUDE.md §5 가 못박은 두 가지가 그대로 걸린다.

1. **오탐지 건수는 넣지 않는다.** 오탐 판정에는 정답 라벨(ground truth)이 필요하고,
   실시간 데모 중에 프로그램이 그것을 알 방법이 없다. 숫자를 만들면 근거 없는 수치가
   된다. (사용자 결정, 2026-08-19)
2. **비율(%)을 쓰지 않는다.** "프레임 단위 손 검출률을 성능 지표로 쓰지 말 것 — 손이
   없는 프레임이 분모에 섞여 값이 오염된다." 그래서 `검출 프레임 / 전체 프레임` 의
   **두 수를 그대로** 적고 나눈 값을 보이지 않는다.
3. 결과창 하단에 **다음 문장을 화면에 그대로 적는다**:
   > 이 값은 이번 1회 시연에서 관측된 수치이며 모델 성능이 아닙니다.

### 3.5 새 파일 2개

`safety_console.py` 는 이미 1,495줄이다. 여기에 집계와 UI 를 더 넣지 않는다.

```
session_stats.py    집계만. Qt 비의존 · 시각은 인자 주입 → 단독 시험 가능
overlay_result.py   ResultPanel(_Sheet) — 결과 표시 UI
```

`session_stats.py` 가 Qt 에 의존하지 않고 시각을 인자로 받는 것은 `fsm.py`·
`sub_task.py` 와 같은 규약이다(테스트가 10초를 실제로 기다리지 않게).

```python
class SessionStats:
    def start(self, recipe_name, step_count, now=None)
    def button_pressed(self, button, expected, ok, now=None)
    def step_done(self, order, button, name, now=None)
    def sub_started(self, button, spec, now=None)
    def sub_done(self, button, now=None)
    def tool_grasped(self, key, ok, now=None)      # 오답 공구 포함
    def violation(self, expected, actual, level, now=None)   # level: warn | block
    def interlock(self, engaged, now=None)
    def frame(self, names_scores)                  # 프레임 1장의 검출 목록
    def finish(self, now=None) -> dict
```

### 3.6 데이터가 어디서 오나

| 항목 | 출처 (기존 신호) |
| --- | --- |
| 버튼 눌림·단계 진행 | `_press_button()` · `_commit_button()` |
| 순서 위반 | `_on_state_change()` 의 `WARNING`·`BLOCK` 진입 |
| 인터락 | `_on_interlock(engaged)` |
| 공구 | `_on_tool()` · `ToolState.phase` 전이 |
| 버튼·EMO 검출 | `camera_thread.yolo_detections_signal` → `_on_yolo_detections()` |
| 공구 검출 | `camera_thread.tool_signal` → `_on_tool()` |
| **손 검출** | **없다 — 새 신호가 필요하다**(아래) |

`roi_signal` 은 손끝이 든 **ROI 라벨**만 준다. 손이 보이는데 ROI 밖이면 빈 문자열이라
「손이 없다」와 구별되지 않는다. 그래서 `camera_thread.py` 에 신호 하나를 더한다:

```python
hand_signal = pyqtSignal(bool)      # 이 프레임에서 손이 검출됐는가
```

`_process_frame()` 에서 `fingertip` 을 이미 계산하므로 `self.hand_signal.emit(fingertip is not None)`
한 줄이다. **판정에는 쓰지 않는다 — 집계 전용이다.**

## 4. 탐지 박스 표시 켜기·끄기

### 4.1 무엇을 끄나

**버튼 박스 · 공구 박스 · 손 랜드마크를 함께** 끈다. 목적이 「영상을 가리지 않고
보는 것」이므로 일부만 끄면 목적을 이루지 못한다.

### 4.2 🔴 표시만 끈다 — 판정은 그대로 돈다

박스가 화면에 없어도 순서 위반 감지·공구 확인은 정상 작동한다. **이 문장을 설정
화면에 함께 적는다.** 적지 않으면 "박스를 끄면 감시도 꺼지나?"를 반드시 묻게 된다.

### 4.3 코드 접점

| 파일 | 변경 |
| --- | --- |
| `config.py` | `SHOW_DETECT_BOXES = True` (초기값) |
| `camera_thread.py` | `set_draw_boxes(bool)` — `_lock` 으로 보호. `CameraThread._process_frame()`(§441)과 `UsbCameraThread._process_frame()`(§590) **두 곳 모두** 게이트 |
| ↳ | 버튼 박스 = `_draw_yolo()` 호출 생략 / 공구 박스 = `_draw_tools()` 호출 생략 / 손 = `self._hand.detect(frame, draw_on=None)` |
| `overlay_menu.py` | `SettingsPanel` 에 「탐지 박스 표시 — 있음 / 없음」 라디오 + 안내 문구 |
| `safety_console.py` | 시그널 연결 → 두 카메라 스레드에 모두 전달 |

🔴 **`draw_on=None` 으로 넘겨도 검출은 그대로 한다** — `hand_tracker.detect()` 의
반환값(손끝)은 ROI 판정에 계속 쓰인다. 그리기만 건너뛴다.

## 5. 탐지 박스 색상

### 5.1 색표 (확정)

| 클래스 | 색 | 근거 |
| --- | --- | --- |
| B1 | `#FFD400` 노랑 | 실물 버튼 색 (통합문서 §5.3) |
| B2 | `#FFFFFF` 흰 | 실물 |
| B3 | `#FF69B4` 핑크 | 실물 |
| B4 | `#2E7DFF` 파랑 | 실물 — 파랑 원 스티커(통합문서 §10.12) |
| EMO | `#FF3B30` 빨강 | 실물 비상정지 |
| 드라이버 | `#00E5FF` 시안 | 버튼 5색과 겹치지 않게 |
| 렌치 | `#B36BFF` 보라 | 〃 |
| 플라이어 | `#7CFF4F` 라임 | 〃 |

### 5.2 어디에 두나

`config.py` 에 둔다 — `theme.py` 가 아니다. `theme.py` 는 **Qt 오버레이 위젯**의
테마 토큰이고, 이 색은 **cv2 가 영상에 직접 그리는** 색이다. 성격이 다르고 테마
전환(다크/화이트)을 따르지도 않는다(영상은 테마가 없다).

```python
DETECT_BOX_COLORS = {"B1": "#FFD400", ...}     # 버튼·EMO
TOOL_BOX_COLORS   = {"driver": "#00E5FF", ...} # 공구
DETECT_BOX_FALLBACK = "#00FF00"                # 표에 없는 클래스
```

⚠️ **cv2 는 BGR 이다.** 16진수 → BGR 튜플 변환 헬퍼를 `camera_thread.py` 에 한 개
두고 모든 호출이 그것을 쓴다. 두 군데에서 각자 뒤집으면 반드시 한쪽이 틀린다.

⚠️ 클래스 이름의 출처가 둘이다 — 버튼은 `detector.class_name()`, 공구는 워커가 주는
키(`driver`/`wrench`/`pliers`). 표에 없으면 조용히 폴백색을 쓴다(죽지 않는다).

## 6. 공구 문구 시인성 — 검정 판 + 맥박

### 6.1 왜 색만 바꿔서는 안 되나

배경이 **밝은 노란 책상**이라 밝은 회색(`#e6e8ea`)도 노랑(`#ffd75c`)도 그 위에서
묻힌다. 어떤 색을 골라도 그와 비슷한 배경이 오면 다시 안 보인다. 목업 4안을
실기동 비교했고(§9 결정 이력) **검정 판**이 채택됐다.

### 6.2 확정 사양

| 항목 | 값 |
| --- | --- |
| 판 | `rgba(0, 0, 0, 0.50)` · `border-radius: 6px` · 공구 칸(`_tool_box`)에만 |
| 판 안쪽 여백 | 레이아웃 `contentsMargins(10, 8, 10, 8)` |
| 글자 | 요구 문구 = 흰색 `#ffffff` / 상태줄 = 기존 토큰(`current`·`done`·`warn`) |
| 맥박 대상 | 요구 문구 + 상태줄 (**「중」 강도** — 🔧 아이콘은 제외) |
| 맥박 주기 | 1.6초 (밝아졌다 어두워지는 한 바퀴) |
| 맥박 폭 | 알파 `0.40 ↔ 1.00` |
| 멈추는 때 | 공구를 쥐었을 때(`tool_ok`) · 오답 공구 경고 중 |

🔴 **판 여백을 QSS `padding` 으로 주지 않는다** — 위젯의 `sizeHint` 와 어긋나 글자가
잘린다(목업에서 실제로 잘렸다). 레이아웃 `contentsMargins` 로 준다.

🔴 **패널 높이가 늘어나므로 스타일을 먼저 적용하고 배치를 나중에 계산한다.**
순서가 반대면 판이 글자를 자른다.

### 6.3 판은 두 테마 공통이다

`theme.py` 는 다크/화이트 대칭을 원칙으로 하지만, 이 판은 **영상 위 대비**가 목적이고
영상은 테마를 따르지 않는다. 두 테마 모두 검정 판 + 흰 글자로 간다.

```python
"tool_plate":      "rgba(0, 0, 0, 0.50)",   # 다크·화이트 동일
"tool_plate_text": "#ffffff",
```

⚠️ `selftest/test_theme.py` 가 테마 간 대비를 강제한다 — 이 토큰이 그 검사에 걸리면
**검사에 예외를 뚫지 말고** 여기 근거를 참조해 검사 쪽에 의도를 명시한다.

### 6.4 맥박 구현 — `anim.py` 에 추가

```python
class TextPulse:
    """글자색 알파를 반복 보간. Pulse(테두리)와 같은 결이다."""
    def __init__(self, widget, base_qss_fn, color_hex, floor=0.40, ms=1600)
    def start(self); def stop(self); def active(self)
```

- 🔴 **`stop()` 을 반드시 부른다** — 살아남으면 QSS 를 계속 재적용해 CPU 를 태운다
  (`Pulse` 주석에 이미 못박힌 것)
- 🔴 **상태가 바뀔 때만 start/stop 한다** — `_sub_timer` 가 200ms 마다 갱신 함수를
  부르므로, 비교 없이 걸면 초당 5번 재시작돼 끝나지 않는 애니메이션이 된다
- 🔴 **크기·두께를 애니메이션하지 않는다** — 레이아웃이 밀려 글자가 흔들린다
- `config.UI_ANIMATION = False`(`SOP_UI_ANIM=0`)면 최종 상태만 적용하고 리턴

## 8. 검증

### 8.1 자동 시험 (`selftest/`)

| 파일 | 무엇 |
| --- | --- |
| `test_session_stats.py` (신규) | 시각 주입으로 순서·소요시간·위반·인터락·검출 집계. **10초를 실제로 기다리지 않는다** |
| `test_console_flow.py` (보강) | 대기가 차면 **버튼 없이** 다음 단계로 가는가 / B2 는 공구 없이 넘어가지 **않는가** / B4 후 결과창이 뜨는가 / 작업 초기화로는 **뜨지 않는가** |
| `test_recipe.py` (보강) | `sec: 10` 로 바뀐 레시피가 그대로 통과하는가 |
| `test_overlay.py` (보강) | 공구 칸에 판이 켜졌을 때 **글자가 잘리지 않는가**(높이 비교) |
| `test_theme.py` | 새 토큰 추가 후에도 통과하는가 |
| `test_imports.py` | 신규 2개 모듈 포함 |

### 8.2 🔴 실기동 확인 (생략 금지)

`run_demo.sh` 로 실제로 띄운다. **import 검사로 못 잡는 런타임 오류가 있다** —
`@pyqtSlot` 시그니처 불일치로 GUI 가 기동 즉시 죽은 적이 있다(CLAUDE.md §5).

확인 항목:
1. B1 → 10초 후 **자동으로** B2 로 넘어가는가
2. B2 에서 렌치를 안 쥐면 **멈춰 있는가**, 쥐면 넘어가는가
3. B4 후 결과창이 뜨고, 내용이 로그(`_append_log`)와 **일치하는가**
4. 대기 중 다른 버튼을 누르면 여전히 **차단되는가** (§2.3 이 살아 있는가)
5. 탐지 박스를 끄면 화면에서 사라지고, **끈 상태에서도 순서 위반이 잡히는가**
6. 공구 칸 판이 글자를 **자르지 않는가** (다크·화이트 양쪽)
7. 결과창이 열린 동안 「작업 시작」 버튼이 **비쳐 나오지 않는가** (§3.2)

### 8.3 성능

맥박은 스타일시트를 반복 재적용한다. 애니메이션 FPS 영향은 **아직 미판정**이며
(카메라 부재로 측정이 시나리오 테스트로 밀려 있다) 이 작업으로도 판정되지 않는다.
문제가 보이면 `SOP_UI_ANIM=0` 으로 끈다 — 코드를 고칠 필요가 없다.
