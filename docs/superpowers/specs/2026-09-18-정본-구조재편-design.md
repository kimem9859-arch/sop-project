# 통합문서 구조 재편 — 설계

> 상태: 🔄 진행 중(2026-09-18) · 결정 경위 = `docs/정본검토-기록.md` §2·§3 행 + 「📐 문서 구조 지도 §4~§14」 절

## 1. 무엇을·왜

사용자가 §4~§14 의 **내용 배치를 파악할 수 없다**고 했고(2026-09-18), 훑어 보니 **같은 사실이 여러 장에 흩어져 있고**(부품 3곳·확장 3곳·흐름도 2곳) **기능인데 자리가 없는 것**(GUI 운용·음성비서)이 있었다. 장별 검토(§4 부터)를 시작하기 전에 **뼈대를 먼저 세운다.**

**주제 분리 기준 = A안(사용자 2026-09-18)** — 기능 / 비기능 / 구현 수단 3분. 「구현 수단」을 따로 두는 이유 = 부품·핀맵·환경은 기능도 비기능도 아니며, 비기능에 넣으면 지금처럼 성능 장이 비대해진다.

## 3. 신설·삭제

**신설 2**
- **§8 제어·피드백·GUI** — 제어 경로(인터락·타워램프)와 작업자 화면(운용 조작·해제 버튼·키보드 우회)을 한곳에. 지금은 옛 §8 그림과 옛 §6.3 에 흩어져 있다.
- **§9 음성비서** — 측정 11개 절(옛 §10 갈래⑥)과 부품(옛 §11.3)은 있으나 **기능 설명이 어느 장에도 없다.** 무엇을 하는 기능인지·갈래(A/B)·관문 상태를 쓴다. 🔴 수치는 §12 포인터.

**삭제·흡수 3**
- 옛 §8 다리 절 → §7 에 흡수(내용이 §7·§9·§6.1 재요약)
- 옛 §5.3 구성 요소 요약 → 부품은 §14, 버튼 배치도는 §5, **배치 변경 경위·폐기 배치도는 삭제**(R9·R2 단서)
- 옛 §7.4·§9.5 확장 목록 → §10 한 곳으로

## 4. 참조 치환

`§N` 참조 = 통합문서 안 **1,164곳**(그중 옛 §10 가리킴 848곳) + 저장소 문서·스킬 **60곳**.

- 옛→새 대조표로 **기계 치환**한다. 치환은 **장 번호가 큰 것부터**(§14→§16, §13→§10 …) 적용해 충돌을 피한다. 🔴 두 단계로 한다: ①옛 번호를 임시 표식(`§@N`)으로 ②임시 표식을 새 번호로.
- 옛 §10 저널 안의 참조도 고친다 — **참조는 「당시 표기」가 아니라 길잡이**이기 때문(R8 예외, 사용자 확인 2026-09-18).
- 소절 번호(`§10.31` → `§12.31`)도 같은 규칙으로 바꾼다. **소절 안 번호(10.31 의 31)는 유지**한다 — §10 갈래 색인·`[CURRENT]` 표·작업로그가 그 번호로 절을 가리킨다.
- 치환 뒤 **깨진 참조 0** 을 확인한다: 존재하지 않는 장·소절을 가리키는 `§N.M` 이 없어야 한다.

## 5. 지키는 것

- 문서 규칙 R5(사실은 한 곳에만) — 재편 뒤 부품 = §14.1 · 핀·채널 = §15 · 측정 = §12 `[CURRENT]` · 설계값 = 해당 절
- R9(경위는 본문 밖) — 이동 중 발견되는 경위 서술은 걷어내고 커밋 메시지에 남긴다
- §2·§3 작성 방법(굵은 주장 한 줄 · `####` 묶음 · 「→」 요점 · 출처는 절 끝) — **신설 2개 장에 적용**. 이동만 하는 장은 이번에 문체를 바꾸지 않는다(장별 검토 때).
- 측정 절(옛 §10.x) 본문은 **번호 외에는 건드리지 않는다.**

## 6. 버린 대안

- **번호 유지 + 묶음 머리만 삽입** — 참조를 건드리지 않아 싸지만, 장 순서와 묶음 순서가 어긋난 채 남는다(§5 가 Ⅲ 인데 §4 와 §6 사이). 사용자가 「기존 구성을 따르지 않아도 된다」고 하여 버림.
- **기능/비기능 2분** — 구현 수단이 비기능에 섞여 지금 문제가 유지된다.
- **§8 다리 절 유지** — 고유 정보가 적어 유지 근거가 약하다.

## 7. 확인할 것 (실행 중)

- 신설 §9 음성비서의 **사실 출처** = Rpi5 코드·`Demo/voice/` 문서·옛 §10 갈래⑥ 절. 🔴 추측 금지, 확인 못 한 것은 `⏸ 미확인` 으로 남긴다.
- 옛 §5.3 의 버튼 배치도에 붙은 「학습 분포와 맞춘 결정 근거」는 **사실(왜 이 배치인가)** 이라 유지, 「배치 통일 경위 표·폐기 배치도」는 삭제.

## 8. 이어서 기록하는 구조 (사용자 요청 2026-09-18)

장을 옮기는 것만으로는 같은 문제가 다시 생긴다 — 지금 §10 만 「갈래 끝에 새 절」 규약이 있고, 나머지 장에는 **새 사실을 붙일 자리가 없어서** 옛 §7.4·§9.5 같은 임시 소절과 옛 §5.3 의 폐기 배치도·경위가 쌓였다. 재편과 함께 **장 안쪽 규약**을 정한다.

1. **소절 번호는 덧붙이기만** — 새 소절은 맨 뒤 번호로 추가하고, 지운 소절 번호는 비워 둔다(재사용 금지). 작업로그·커밋이 가리킨 번호가 계속 유효해야 한다.
2. **기능 장(§5~§9)은 현행 동작만** — 바뀌면 그 자리를 고쳐 쓴다. 이력은 쌓지 않는다(측정·이력 = §12 · 경위 = 커밋·작업로그 R9).
3. **장마다 끝에 `⏸ 이 장에서 아직 안 된 것`** — 미구현·검토 중 항목은 여기에만 덧붙인다. 확장으로 확정되면 §10(범위와 향후 확장)으로 옮긴다. 옛 §7.4·§9.5 가 하던 일을 모든 기능 장에 같은 이름으로 둔다.
4. **§12 성능은 지금 규약 유지** — 갈래 끝에 새 절 · `[CURRENT]` 표 · 갈래 색인 · 🔓 미결 함께 갱신(R6).
5. **새 갈래·새 장** — §12 에 새 주제면 갈래 ⑦… 추가, 기능이 통째로 새로 생기면 Ⅰ 묶음 끝(§10 앞)에 장 추가.
6. **신설 §9 음성비서는 갈래를 나눠 둔다**(A 규칙 기반 / B LLM) — 갈래가 늘어도 자리가 있게.

→ 이 여섯 가지를 통합문서 「📐 문서 규칙」에 **R12** 로 넣는다(문서 전체·§10 규약만 있고 장 안쪽 규약이 없었다).
