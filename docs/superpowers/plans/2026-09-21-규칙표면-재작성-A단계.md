> **For agentic workers:** `superpowers:executing-plans` 로 태스크 단위 실행. 🔴 **`subagent-driven-development` 를 쓰지 않는다** — 모든 태스크가 **같은 원장 파일 한 개**를 쓰므로 병렬성이 없다(CC작업문서 §2.2).

**목표:** 감사 완료분 3곳(`CLAUDE.md` · `Rpi5/CLAUDE.md` · auto memory)을 원자화·판정해 원장에 올리고, **그 분포로 목표 구조와 규칙 문서 관리 규칙을 도출**해 승인받은 뒤 집행한다.

**접근:** B 단계와 같다 — 판정과 집행을 분리한다. 대상을 원자화·판정해 원장을 채우고(Task 1~4), 분포를 사용자에게 보고해 **구조·관리 규칙·경위 경계를 승인받은 뒤**(Task 5 관문) 집행·검증한다(Task 6~8).

🔴 **먼저 만들지 않는다** — 규칙 문서 관리 규칙(경위·길이·중복·폐기 이관)은 **A 분포를 보고** 만든다. 분포 없이 먼저 만든 것이 G1~G4 였고 **적용 대상 정의에 자기가 적힌 문서를 빠뜨린 채** 태어나 제거됐다(spec §8 의 「구조를 미리 못 박지 않는다」와 같은 원칙).

**Spec:** `docs/superpowers/specs/2026-09-20-규칙표면-재작성-design.md` — **§5(순환 차단)·§7(순서)·§8(목표 구조)을 먼저 읽는다.**

## Global Constraints

- 판정 6종 = 유지 / 이동 / 수정 / 병합 / 승격 / 제거. **「제거」의 행선지는 반드시 `docs/변경이력.md`**(spec §3.3 · R2).
- 🔴 **공식 문서(`code.claude.com/docs`) 원문만으로 1차 판정한다.** 기억·추측 금지 — `llms.txt` 로 목록을 받고 해당 `.md` 를 직접 읽는다. 프로젝트 규칙끼리 서로 판정하지 않는다(spec §5.2).
- 🔴 **공식 기준으로 「제거·수정」이 나와도 그 규칙이 실제 사고에서 나온 것이면 제거하지 않고 「사례」로 표시**해 사용자 판단으로 올린다(spec §5.2). 확인처 = `docs/작업로그.md` · `docs/claude-code-작업로그.md`.
- 🔴 공식↔프로젝트 **충돌은 건별로 사용자에게 올린다.** 일반 규칙을 세우지 않는다(spec §5.3).
- 원장의 모든 행은 **「새 자리」 또는 「변경이력.md」** 중 하나를 가져야 한다.
- 이 계획서와 원장에 **측정 수치·사양을 쓰지 않는다**.
- 🔴 **auto memory 는 파이1 로컬이다** — 데스크톱에서는 이 작업의 Task 3 를 실행할 수 없다. 파이1에서 한다.
- 🔴 **`Rpi5` 는 별도 저장소다** — 대상 ②의 집행 커밋은 `Rpi5` repo 에, 원장·계획서는 `sop-project` 에 한다(CLAUDE.md §4).
- 커밋 서명 = `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`. `git add` 는 **경로를 지정**한다(CLAUDE.md §5).
