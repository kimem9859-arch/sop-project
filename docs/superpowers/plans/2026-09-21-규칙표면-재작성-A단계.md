# 규칙 표면 재작성 — 로드되는 면으로 통합 (A + B 재배치) 계획

> **For agentic workers:** `superpowers:executing-plans` 로 태스크 단위 실행. 🔴 **`subagent-driven-development` 를 쓰지 않는다** — 모든 태스크가 **같은 원장 파일 한 개**를 쓰므로 병렬성이 없다(CC작업문서 §2.2).

**목표:** 규칙 표면 338행 전부를 **Claude Code 가 실제로 로드하는 면**(`CLAUDE.md` · `.claude/rules/` · `.claude/skills/` · auto memory)으로 옮기고, **그 면에 적용되는 공식 기준으로** 검토한 뒤 집행한다.

**왜 계획을 두 번 고쳤나 (사용자 지적 2026-09-21)**

1. *"점점 작업을 진행할수록 점검 기준이 달라지는 것 같은데"* — 기계 확인 결과 사실이었다. **B 189행에 분포 축이 없고, 338행 어디에도 유효성 판정이 없었다.**
2. *"공식 근거가 있는 범위로만 좁혀줘"* — 확인해 보니 공식의 작성 기준(`Specificity`·`Consistency`)은 **`## CLAUDE.md files` 아래 절**이라 CLAUDE.md 계열 전용이었다. **일반 `.md` 문서(CC작업문서·README·통합문서 📐)에는 적용할 공식 근거가 없다.**
3. *"일반 .md 문서의 규칙·지시사항을 Claude Code 가 로드할 수 있는 곳으로 옮기자. 단 일반 .md 에 적용되는 규칙이므로 연결이 되어야"* — **이것이 근본 해법이다.** 옮기면 공식이 다루는 면이 되고, 검토 기준이 A·B 에 똑같이 선다. 연결은 `paths:` 가 기계로 보장한다.

**Spec:** `docs/superpowers/specs/2026-09-20-규칙표면-재작성-design.md` — §5(순환 차단) · §7(순서) · §8(목표 구조)

🔴 **spec §7 과의 차이** — spec 은 A → C 순서였으나, 이번에 **B 를 로드되는 면으로 재배치**하면서 C 단계의 일부(`.claude/rules/` 신설)가 앞당겨진다. C 에 남는 것은 **커맨드 · `settings.json` · hookify · §3.0 훅 실적 관문**이다.

## 판정 잣대 (확정 — 여기서 더 늘리지 않는다)

🔴 **잣대를 도중에 추가하지 않는다.** 새 잣대가 필요해 보이면 **작업을 멈추고 사용자에게 올린다.** 이번 계획이 두 번 고쳐진 원인이 「진행 중 잣대 추가」였다.

| 단 | 필터 | 묻는 것 | 결과값 |
| --- | --- | --- | --- |
| 1 | **원자화** | 한 줄이 한 규칙인가 | 원장 행 |
| 2 | **축 4개** | 머신 / 로드 시점 / 성격 / 강제 가능 | `[전 머신/매 세션/규칙/안내만]` |
| 3 | **면 배정** | **어느 로드 면으로 가나** | `CLAUDE.md` / `rules` / `skill` / `memory` / `문서에 남김` |
| 4 | **면별 공식 기준** | 그 면의 기준에 맞나 | 아래 표 |
| 5 | **안전판** | 실제 사고에서 나왔나 | `사례`(사용자 판단 대기) |

**순서가 중요하다** — 🔴 **면 배정(3단)이 검토(4단)보다 먼저다.** 어느 면으로 가느냐가 **어떤 기준으로 볼지를 정하기 때문**이다.

### 4단 — 면별 공식 기준 (공식 근거가 있는 것만)

| 면 | 적용 기준 | 공식 근거 |
| --- | --- | --- |
| **`CLAUDE.md`**(양 저장소) | **낡음**(outdated) · **충돌**(conflicting) · **모호**(not verifiable) · 200줄 | memory.md §Write effective instructions — *"concrete enough to verify"* · *"remove outdated or conflicting instructions"* · *"target under 200 lines"* |
| **`.claude/rules/`** | **한 파일 한 주제** · 상시 필요 없으면 스킬로 · **낡음 · 충돌** | memory.md §Organize rules — *"Each file should cover one topic"* · *"For task-specific instructions that don't need to be in context all the time, use skills instead"* · Consistency 가 `.claude/rules/` 를 명시적으로 포함 |
| **`.claude/skills/`** | **500줄** · **본문 간결 — 로드되면 턴마다 비용** · 상세는 보조 파일 | skills.md — *"Keep the body itself concise… every line is a recurring token cost"* · *"Keep SKILL.md under 500 lines"* |
| **auto memory** | **코드에서 파생 가능한 것 금지** · **`CLAUDE.md` 가 이미 말한 것 금지** · 색인 200줄·25KB | memory.md §Auto memory — *"skips anything it can derive from the codebase… anything your CLAUDE.md files already say"* |
| **일반 `.md` 에 남는 것** | **기준 없음** | 🔴 공식이 다루지 않는 면이다. **그래서 규칙을 여기 두지 않는다** — 남는 것은 규칙이 아닌 정보(폴더 지도·실행법·사실)뿐이다 |

🔴 **「모호」는 `CLAUDE.md` 계열에만 적용한다** — `Specificity` 는 `## CLAUDE.md files` 아래 절이라 rules·skills·memory 에 걸 공식 근거가 없다.

### 3단 — 면 배정 규칙 (공식 그대로)

| 이런 규칙이면 | 이 면으로 | 공식 근거 |
| --- | --- | --- |
| 매 세션 알아야 하는 사실·관례·「항상 X 한다」 | `CLAUDE.md` | *"Keep it to facts Claude should hold in every session"* |

| 다단계 절차 · 가끔 필요한 참조 자료 | `.claude/skills/` | *"multi-step procedure → skill"* · *"reference material Claude needs sometimes"* |
| 절대 일어나면 안 되는 것 | `settings.json` deny · 훅 | *"Put guardrails in hooks… a request, not a guarantee"* — 🔴 **이번에 만들지 않는다(C 단계)**. 후보 목록만 |

### 「연결」의 정의 (사용자 조건)

🔴 **규칙이 다루는 문서를 열면 그 규칙이 자동으로 붙어야 한다.** 포인터로 잇지 않는다 — `paths:` 가 기계로 보장한다(*"Path-scoped rules trigger when Claude reads files matching the pattern"*).

**연결 검사** — 옮긴 규칙마다 ①`paths:` 글롭이 그 대상 문서를 실제로 매치하는가 ②원본 문서에 규칙이 남아 있지 않은가(중복). 둘 다 Task 15 가 기계로 확인한다.

## Global Constraints

- 판정 6종 = 유지 / 이동 / 수정 / 병합 / 승격 / 제거 + `사례`. **「제거」의 행선지는 반드시 `docs/변경이력.md`**(spec §3.3 · R2).
- 🔴 **공식 판정은 `code.claude.com/docs` 원문만으로 한다.** 프로젝트 규칙끼리 서로 판정하지 않는다(spec §5.2).
- 🔴 **검토 판정은 정본·코드·환경만으로 한다.** 기억으로 「아직 맞을 것이다」 하지 않는다 — 확인할 수 없으면 `확인필요`다.
- 🔴 **공식 근거가 없는 판단에는 「프로젝트 재량」을 표기한다.** 공식으로 잘못 인용하지 않는다.
- 🔴 공식↔프로젝트 **충돌은 건별로 사용자에게 올린다**(spec §5.3).
- 🔴 **auto memory 작업은 파이1에서만** 가능하다(머신 로컬).
- 🔴 **`Rpi5` 는 별도 저장소다** — 집행 커밋은 `Rpi5` repo 에, 원장·계획서는 `sop-project` 에.
