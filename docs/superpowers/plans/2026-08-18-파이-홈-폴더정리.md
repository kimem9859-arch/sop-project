# 파이 홈 폴더 정리 실행 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pi#1 홈 최상위를 역할별 5분류로 재편하고, 앞으로 유지되도록 폴더 생성 규칙을 문서화한다.

**Architecture:** 물리 이동(`mv`) → 코드 경로 갱신 → 실기동 관문 → 문서 갱신 → 규칙 신설 순. 이동과 코드 수정 사이에는 시스템이 잠시 어긋난 상태가 되므로 **Task 3의 실기동 관문을 통과할 때까지 다른 작업을 끼워 넣지 않는다.**

**Tech Stack:** bash(`mv`·`du`·`grep`) · Python 3.13(Demo 런타임) · `~/env/rfenv`(ultralytics CPU)

**Spec:** `docs/superpowers/specs/2026-08-18-파이-홈-폴더정리-design.md`

## Global Constraints

- 🔴 **삭제 없음.** `rm`·`trash` 계열 명령을 이 계획의 어느 단계에서도 쓰지 않는다. 이동은 `mv`뿐이다.
  - **유일한 예외** = Task 1 Step 4의 `rmdir` 2회. `rmdir`은 **비어 있을 때만 성공**하므로 내용이 남아 있으면 실패해서 알려준다. 이 성질이 안전장치다.
- 🔴 **수치·조건을 건드리지 않는다.** 문서 갱신은 `~/경로` 문자열만 대상으로 한다(단일정본 규칙).
- **커밋 구분** — 파이 코드는 `Rpi5` repo, 통합문서·설계·규칙 문서는 `sop-project` repo.
- 커밋 끝에 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- **표준 위치는 옮기지 않는다** — `bin` `Arduino` `Desktop` `Documents` `Downloads` `Music` `Pictures` `Public` `Templates` `Videos` `thinclient_drives` `sop-project` `_archive`.

### 중단 규칙

- **Task 3(실기동)이 실패하면 되돌린다.** 이동을 강행하지 않는다. 역방향 `mv`로 복원하고 원인부터 규명한다.
- **바이트 수가 어긋나면 즉시 멈춘다.** 유실을 확인하기 전에는 다음 태스크로 가지 않는다.
