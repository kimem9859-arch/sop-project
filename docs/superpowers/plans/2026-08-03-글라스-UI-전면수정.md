# 글라스 UI 전면 수정 — 구현 계획

> **실행 방법:** `superpowers:executing-plans`(인라인)로 태스크 단위 실행. 체크박스로 진행 추적.
> ⚠️ **`subagent-driven-development`는 쓰지 않는다** — 태스크가 `safety_console.py` 한 파일로 수렴해 병렬성이 없다(CC작업문서 §2.2).

**Goal:** 콘솔형 2단 UI를 **스마트 글라스 관점의 Full Screen 오버레이 UI**로 교체하고, 서브 작업(대기·공구)·알림·설정·테마를 추가한다.

**Architecture:** `safety_console.py`의 레이아웃 계열 약 160줄만 교체한다. FSM·인터락·GPIO 배선과 **안전 UI 3종은 손대지 않는다.** 흩어진 폰트(7곳)·색(9곳)을 `theme.py` 한 곳으로 모으고, 서브 작업 진행은 **Qt에 의존하지 않는 `sub_task.py`** 로 분리해 GUI 없이 시험한다.

**Tech Stack:** PyQt6 6.11 · Python 3.13 · Pretendard 1.3.9 · 기존 `fsm.py`/`recipe.py`

**정본 문서:** `docs/superpowers/specs/2026-08-03-uiux-글라스-design.md` — **수치·색·배치는 전부 거기가 정본**이다. 이 계획서에 값을 복제하지 않는다.

> ⚠️ **이 계획서에 코드 전문이 없는 것은 의도적이다.** CC작업문서 §2.3 — 창 판정 계획서 1,325줄(코드 전문 복붙)이 과했고, 그중 하나가 **수학적으로 불가능한 테스트**여서 구현자가 16만 토큰을 태워 발견했다. 값이 필요하면 **design 문서의 해당 절을 열어서** 그대로 옮긴다.

## Global Constraints

- 🔴 **안전 UI 3종을 건드리지 않는다** — BLOCK 해제 거부(EMO 미복귀) · 인터락 폴트 경고창 · 종료 확인창. 전부 사고를 겪고 만든 방어물이다.
- 🔴 **FSM·인터락·GPIO 배선을 바꾸지 않는다.** 서브 작업은 **FSM에 새 상태를 만들지 않고** GUI 측 `sub_task.py`가 관리한다.
- 🔴 **성능 대응을 미리 넣지 않는다** — `FastTransformation`·프레임 솎기 모두 **적용 금지**. 만든 뒤 측정한다(사용자 결정).
- **작업 브랜치**: `feature/fsm-interlock`에서 딴다. ⚠️ Rpi5의 `origin/main`은 `075f6db "Ver 1.1"`에 멈춰 있고 실제 트렁크가 `feature/fsm-interlock`이다.
- **테스트는 pytest가 아니다** — `selftest/*.py`는 `if __name__ == "__main__"` 형식의 단독 스크립트다. 기존 스타일을 따른다.
- 커밋 서명은 `CLAUDE.md`「작업·커밋 규칙」을 따른다.

## 관문 (매 태스크 공통)

각 태스크의 마지막 단계는 항상 이 순서다. **하나라도 실패하면 커밋하지 않는다.**

1. 그 태스크의 셀프테스트 통과
2. `python3 selftest/test_imports.py` 통과 — GUI 진입점 import 이름이 실재하는지 AST로 대조. **`camera_thread`·`config`의 최상위 이름을 바꿨다면 반드시 돌린다**(2026-07-22에 이걸로 GUI가 통째로 죽었다)
3. `python3 selftest/test_fsm.py` · `test_recipe.py` 통과 — 판정부 회귀 방지
4. 🔴 **`./run_demo.sh` 실기동** — 창이 뜨고 **30초 유지**된 뒤 정상 종료. import 검사로 못 잡는 런타임 오류(`@pyqtSlot` 시그니처 불일치 등)가 실제로 있었다

## 중단 규칙

- **실기동에서 GUI가 죽으면** → 그 태스크를 되돌리고 원인부터 찾는다. 다음 태스크로 넘어가지 않는다.
- **안전 UI 3종의 동작이 하나라도 달라지면** → 즉시 중단. 이 계획의 어떤 목표도 그보다 우선하지 않는다.
- **FSM 셀프테스트가 깨지면** → 판정 로직에 손이 닿은 것이다. 되돌린다.
- **Task 8(레이아웃 교체) 후 실기동이 안 되면** → 롤백하고 Task 5~7의 위젯을 기존 레이아웃에 하나씩 얹어 원인을 좁힌다.

| `Demo/precheck.py` | 1·2차 점검 실행과 결과 | **신설** |
